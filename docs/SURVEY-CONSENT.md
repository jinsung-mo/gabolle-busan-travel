## 0. 용어 — 이 문서에서 처음 쓰는 말

| 말 | 뜻 |
|---|---|
| **고지문**(notice) | *무엇을 모으고 왜 모으고 언제 지우는지를 참여자에게 미리 알리는 글.* 동의를 받기 **전에** 보여 준다 |
| **동의문**(consent) | *참여자가 "알겠다, 참여하겠다" 를 실제로 누르는 자리의 글.* 고지문을 읽었다는 전제 위에 있다 |

| **재식별**(re-identification) | *따로 보면 누군지 모르는 조각들을 합쳐서 사람을 되찾는 것.* 나이대 + 동행 + 응답 시각이면 좁은 집단에서는 한 명으로 좁혀질 수 있다 |
| **짝 비교**(paired comparison) | *조건이 다른 두 가지를 나란히 놓고 하나를 고르게 하는 것.* 여러 사람이 여덟 번씩 고르면 각 조건에 얼마나 무게를 두는지 역산할 수 있다 |
| **진행자** | *이 설문을 실제로 돌리고 응답을 받는 사람 한 명.* **장효준** 이다 (2026-09-10 에 팀이 정했다) |

### 2.3. 🔴 "낸 뒤에는 빼 드릴 수 없습니다" — 이걸 먼저 말한다

응답에 이름이 없다는 것은 좋은 일이지만, **그래서 어느 것이 당신 응답인지 우리도 모른다.**
"제 응답 빼 주세요" 라고 해도 **찾을 방법이 없다.**

이건 나중에 곤란해질 사실이라 **동의를 누르기 전에** 말한다.

> **낸 뒤에는 그 응답 하나만 빼 드릴 수 없습니다.**
> 이름을 안 받기 때문에 어느 것이 누구 응답인지 우리도 알 수 없어서예요.
> **제출 버튼을 누르기 전까지는** 언제든 창을 닫으시면 아무것도 저장되지 않습니다.

**바꿔 말하면 이 설문의 철회 방법은 "제출 전에 그만두기" 하나뿐이다.** 그래서 제출 버튼
바로 위에도 한 줄이 더 있다 — *"제출하면 되돌릴 수 없어요."*

| **안 해도 불이익이 없다** | "평가 · 수료 · 성적 · 팀 배정 · 그 밖의 어떤 것과도 관계가 없습니다" — **뭉뚱그리지 않고 열거한다.** 같은 교육기관 안에서 돌리는 설문이라 이 문장이 특히 필요하다 |
| **압력이 없다** | 경품 없음 · 채널에 참여자 명단 없음 · 미참여자에게 다시 안 보낸다 ([5.4](#54-다시-보내지-않는다)) |
| **중간에 그만둘 수 있다** | "창을 닫으시면 됩니다 — 제출 전에는 아무것도 저장되지 않습니다" |
| **나이** | 🔴 **20대 ~ 70대** (2026-09-12, S15P21E201-867 에서 좁혔다). 원래는 *"만 14세 이상"* 이었는데, 그건 법이 정한 하한이지 **이 설문이 답을 받을 수 있는 범위가 아니었다** — 나이대 칸이 `20~30대 · 40~50대 · 60~70대` 셋뿐이고 필수라, 14~19세와 80세 이상은 설문을 다 채운 **뒤에** 막혔다. 범위를 화면에 맞춰 **시작하기 전에** 알 수 있게 했다. 동의 체크를 안 하면 시작 버튼이 안 눌리므로 이 문구가 곧 차단이다 |
| **읽을 기회가 있었다** | 자세한 고지(2.2)가 같은 화면의 "자세히 보기" 안에 있다. 링크로 딴 데 보내지 않는다 |

🔴 **동의 체크 자체를 저장하지 않는다.** 체크를 저장하려면 "누가 동의했는지" 를 남겨야
하고, 그건 익명을 깬다. 동의는 **시작 버튼이 눌렸다는 사실**로 갈음한다. 응답 한 줄에는
`"consented": true` 만 들어간다 — 누가 눌렀는지는 없다.

### 3.3. 이 설문이 기관 심의를 받아야 하나

🔴 **팀이 판단해서 넘어갔다 (2026-09-10). 확인한 것이 아니다.**

이 둘은 다르고, 그 차이가 나중에 중요해진다.

| | 무슨 뜻인가 |
|---|---|
| ❌ **"확인했다"** | SSAFY 나 학교에 물어봤고 *"안 받아도 된다"* 는 답을 받았다. **그런 일은 없었다** |
| ✅ **"판단해서 넘어갔다"** | 물어보지 않았다. 팀이 *"학교 프로젝트 내부 설문이고, 이름 · 이메일을 안 받고, 결과를 합쳐서만 쓰니 심의 대상이 아닐 것"* 이라고 **스스로 판단**하고 진행했다 |

**왜 이렇게 적나.** 나중에 누가 *"심의는 확인하셨어요?"* 라고 물었을 때, 문서에
"확인했다" 고 적혀 있으면 아무도 다시 안 본다 — 그리고 **확인한 사람은 없다.**
없는 확인을 있었던 것으로 만들어 두는 것이 이 문서가 할 수 있는 가장 나쁜 일이다.

**언제 다시 봐야 하나** — 이 응답을 **학교 프로젝트 발표 밖**에서 쓰게 되는 날.
논문 · 대외 공개 · 다른 기관 제출이 그날이다. 그때는 판단이 아니라 확인이 필요하다.

## 4. 표본이 치우쳐 있다는 것을 숨기지 않는다

이 설문의 응답자는 **SSAFY 교육생**이다. 그 집단은 이렇게 치우쳐 있다.

| 속성 | 이 표본 | 우리 서비스가 노리는 사용자 | 어긋나면 무엇이 틀리나 |
|---|---|---|---|
| 나이 | 20대 중후반 ~ 30대 초반이 대부분 | 20 ~ 60대 | 계단 · 경사를 견디는 정도가 **과대**하게, 조용한 곳 선호가 **과소**하게 나온다 |
| 국적 · 언어 | 거의 전원 한국인 | 외국인이 절반 이상일 수 있다 | 음식(맵기 · 해산물) · 유명세 · 영어 메뉴 필요 — **방향까지 다를 수 있다** |
| 소득 | 낮다 (교육생) | 다양하다 | 가격 눈금이 **아래로 쏠린다.** "4만원" 이 이 표본에서는 비싸고 실제 사용자에게는 보통일 수 있다 |
| 동행 | 혼자 · 친구 | 가족 · 연인 · 부모 동반 | 1인 숙박비 눈금과 이동 감수 정도가 다르다 |
| 부산 경험 | 부울경 캠퍼스라 **부산을 이미 안다** | 첫 방문자가 많다 | 유명 관광지 선호가 **과소**하게 나온다 — 아는 사람은 동네를 고른다 |
| 직군 | IT | 무관 | 여행 취향과는 무관할 것으로 본다. 앱 조작 능숙도만 다르다 |

**C 파트 인구통계 세 문항은 이 표를 채우기 위해 있다.** 나이대 · 동행 · 여행 횟수를
받아 두면 나중에 *"우리 표본은 20대 · 혼자 여행 · 연 3회 이상이 78% 였다"* 를 숫자로
쓸 수 있다. **안 받으면 치우침을 "느낌" 으로만 말하게 된다.**

> 🔴 **"치우침" 은 우리끼리 쓰는 분석 용어다. 참여자 화면에는 그 말을 안 쓴다.**
> 2026-09-10 까지 `survey-recommend` 화면에는 *"응답한 분들이 **어느 쪽으로 치우쳐
> 있는지**를 나중에 재려고 여쭙습니다"* 라고 적혀 있었다. 뜻은 이 절 그대로인데,
> 읽는 사람에게는 **자기를 겨누는 말**로 들린다 — 답하기도 전에 "치우친 사람" 이 된다.
> 그래서 화면 문구를 *"**어떤 분들이 답해 주셨는지**를 나중에 살펴보려고 여쭙습니다"*
> 로 바꿨다 (`survey-recommend/index.html`).
>
> **문장을 통째로 빼지는 않았다.** 왜 나이대를 묻는지 설명이 없으면 *"이름도 안
> 받는다면서 나이는 왜 묻지"* 가 되어 오히려 더 이상해진다. 설명은 남기고 말만 골랐다.

### 4.1. 🔴 치우침을 고칠 수 있는 것과 없는 것

| | 방법 | 한계 |
|---|---|---|
| **일부 고칠 수 있다** — 나이대 · 동행 · 여행 횟수의 분포 차이 | 각 무리에 실제 비율만큼 무게를 다시 준다 | 한 무리에 **5명 미만**이면 무게를 다시 주는 것이 오히려 잡음을 키운다 |
| **못 고친다** — 외국인의 크기 | 없다 | **표본에 0명이다. 0 에 무엇을 곱해도 0 이다.** 방향만 쓰고 크기는 "아직 못 잼" 으로 남긴다 |
| **못 고친다** — 첫 방문자의 유명세 선호 | 없다 | 표본이 부산을 안다. 이건 설문이 아니라 나중의 실제 사용 기록이 고친다 |
| **못 고친다** — 고령 · 가족의 이동 감수 | 없다 | 표본에 없다 |

**결과를 쓸 때 이 표를 같이 적는다.** 적지 않으면 다음 사람이 이 가중치를 전 사용자에게
그대로 쓴다.

### 4.2. 몇 명이 답해야 쓸모가 있나

| 선 | 인원 | 무엇 |
|---|---|---|
| **계산이 돌아가는 하한** | 8명 | 이보다 적으면 계산 프로그램이 스스로 멈춘다 (`bigData` 의 조건부 로짓 추정기가 정해 둔 하한) |
| **목표** | **30명** | 진짜 7쌍 × 30명 = 210번의 선택. 🔴 지금 설계(두 벌, S15P21E201-884)가 스스로 계산한 하한은 계수 11개 × 관측 20 = **220개, 사람으로 32명**이다 (2026-09-13 `design-v4.mjs --check` 실측). 30명은 그보다 두 명 모자라다 — 목표는 팀 결정이라 여기서 올리지 않았고, 모자라면 모자란 대로 적는다 |
| **무리를 갈라 보려면** | **60명** | 예: 20대 vs 30대를 따로 재려면 각 무리가 단독으로 하한을 넘어야 한다 |
| 뿌려야 하는 인원 | **제한 없음** (2026-09-10 결정, 7절 P8) | 🔴 목표 응답률을 안 정했다는 뜻이 아니라, **인원을 막지 않는다**는 뜻이다. 링크를 본 사람은 누구나 낼 수 있다. 그래서 위의 8 · 30 · 60 은 여전히 유효한 선이고, 못 미치면 못 미쳤다고 적는다 |

🔴 **30명에 못 미치면 못 미쳤다고 적는다.** 억지로 숫자 하나를 뽑지 않는다.

## 5. 수집 절차 — 누가 언제 어떻게

### 5.1. 🔴 Mattermost 가 익명을 깨는 지점

문제는 설문 화면이 아니라 **응답이 우리에게 오는 길**이다.

```
   참여자 폰                진행자
  ┌──────────┐            ┌──────────┐
  │ 설문 화면 │            │          │
  │  ↓       │            │          │
  │ 응답 코드 │──DM──────▶│ 코드만 옮김│──▶ 파일 한 개
  └──────────┘            └──────────┘
        │
        └─🔴 채널에 붙여넣으면 아이디 + 응답이 영원히 붙는다
```

| 위험 | 무슨 일이 나나 | 막는 법 |
|---|---|---|
| **채널에 코드를 올린다** | 아이디와 응답이 채널 기록에 **영구히** 붙는다. 나중에 지워도 누군가는 이미 봤다 | 채널 글에 🔴 굵게 "채널에 붙여넣지 말아 주세요" ([2.4](#24-mattermost-채널에-올릴-글-초안)). 그래도 올라오면 **진행자가 즉시 지우고 그 응답은 버린다** |
| **DM 이 남는다** | 진행자 대화방에 아이디-코드 대응표가 그대로 있다 | 진행자가 코드를 파일에 옮긴 **직후 DM 을 지운다.** [5.2](#52-진행자가-하는-일--순서대로) 의 3번 |
| **아이디-코드 대응표를 만든다** | "누가 냈나" 를 되찾을 수 있게 된다 = 익명이 아니게 된다 | **만들지 않는다.** 중복 제출은 응답 안의 난수로 거른다 — 아이디가 필요 없다 |
| **참여자 수를 세려고 명단을 만든다** | 같은 문제 | 명단 대신 **받은 코드 개수**를 센다 |
| **재식별** — 나이대 + 동행 + 여행 횟수 + 응답 시각 | 좁은 집단에서는 한 명으로 좁혀질 수 있다 | 응답 시각을 **날짜까지만** 남긴다(시:분:초 없음). 그리고 결과를 **합쳐서만** 발표한다 |

### 5.2. 진행자가 하는 일 — 순서대로

**진행자는 한 명이다.** 여러 명이면 그만큼 대응표가 여러 벌 생긴다.

| # | 언제 | 무엇 | 확인 |
|---|---|---|---|
| 1 | 올리기 전 | 이 문서의 [7절](#7-정해야-함--이-문서가-지어내지-않은-것) "정해야 함" 이 **전부 채워졌는지** 확인. 하나라도 비면 올리지 않는다 | 🟢 **열 칸이 2026-09-10 에 전부 채워졌다.** 다만 기관 심의(P7)는 **확인이 아니라 판단**이다 ([3.3](#33-이-설문이-기관-심의를-받아야-하나)) |
| 2 | 올릴 때 | [2.4](#24-mattermost-채널에-올릴-글-초안) 의 글을 채널에 올린다. **설문 주소만** 올린다 | |
| 3 | 오는 대로 | DM 으로 온 코드를 파일에 한 줄씩 옮기고 **그 DM 을 지운다** | 옮긴 뒤 바로. 몰아서 하지 않는다 — 몰아서 하면 대응표가 며칠씩 남는다 |
| 4 | 마감 때 | 받은 개수를 센다. 30개에 못 미치면 **못 미쳤다고 적는다** | [4.2](#42-몇-명이-답해야-쓸모가-있나) |
| 5 | 계산 | 응답 파일로 가중치를 계산한다. 안 읽고 찍은 응답(함정 문항을 틀렸거나 너무 빨리 답한 것)을 **여기서** 거른다 | 🔴 **화면에서 거르지 않는다.** 거르는 기준은 나중에 바뀌지만 안 받은 데이터는 못 만든다 |
| 6 | 결과 | 결과에 [4절](#4-표본이-치우쳐-있다는-것을-숨기지-않는다) 의 치우침 표를 **같이** 적는다 | |
| 7 | 삭제일 | 응답 파일을 지우고 **지운 날짜를 팀 문서에 적는다** | **응답을 받은 날로부터 1년 뒤** |

### 5.3. 응답이 지나가는 곳 — 전부

| 어디 | 무엇이 있나 | 얼마나 오래 |
|---|---|---|
| 참여자 브라우저 | 답한 내용. **제출 버튼을 누르기 전까지만.** 서버로 아무것도 안 간다 | 창을 닫으면 사라진다 |
| Mattermost DM | 코드 한 줄 | 진행자가 옮긴 직후 지운다 |
| 진행자 PC 의 파일 | 응답 전체 | **받은 날로부터 1년** |
| **그 밖** | **없다.** 외부 설문 서비스 · 구글 폼 · 클라우드 문서 · 팀 채팅방 첨부를 쓰지 않는다 | |

🔴 **설문 화면은 서버가 없다.** 응답을 어디에도 자동으로 보내지 않는다.
이건 게으름이 아니라 **응답이 우리 손 밖으로 나가는 경로를 아예 안 만드는 것**이다.
서버를 붙이기로 하면 이 문서의 5.1 · 5.3 을 **다시 써야 한다** — [7절](#7-정해야-함--이-문서가-지어내지-않은-것).

### 5.4. 다시 보내지 않는다

한 번 올리고 **한 번만 상기시킨다.** 그 이상은 압력이다. 개인 DM 으로 참여를 부탁하지
않는다 — 같은 교육기관 안에서 개인 DM 은 거절하기 어렵다.

### 5.5. 경품은 없다

경품을 걸면 **연락처를 받아야 하고**, 그 순간 "이름·연락처를 안 받는다" 는 전제가 깨진다.
추첨을 하려면 누가 참여했는지도 알아야 한다. 경품 하나로 이 문서의 절반이 무너진다.

대신 **결과를 돌려준다** — 집계된 결과를 채널에 한 번 올린다. *"응답 N명, 사람들은
역에서 5분 더 걷는 것보다 20분 줄 서는 것을 더 싫어했습니다"* 같은 것. 참여한 사람이
자기가 무엇에 기여했는지 보는 것이 경품보다 정직하다.

> 🔴 **위 두 문단은 `survey-place` 이야기다. 지금 돌리는 `survey-recommend` 는 둘 다 반대다**
> (2026-09-10 결정, 7절 P5 · P9).
>
> | | `survey-place` (위) | **`survey-recommend` (지금 돌리는 것)** |
> |---|---|---|
> | 경품 | 없다 | **있다.** 그래서 전화번호를 **선택으로** 하나 받는다 — 안 적으셔도 제출된다 |
> | 결과 공유 | 집계 결과를 채널에 한 번 올린다 | **집계 결과를 채널에 안 올린다. 추첨 결과만 올린다** |
> | 주소 | 아직 없다 | `https://j15e201.p.ssafy.io/survey/` |
>
> **왜 집계 결과를 안 올리나.** 이 설문의 답은 *"어디를 왜 추천하는가"* 라 집계해도
> **적은 사람이 자기 글을 알아본다** — 추천한 가게 이름이 그대로 남기 때문이다.
> 짝 비교처럼 숫자로 뭉개지지 않는다. 그래서 채널에는 **추첨 결과만** 올리고,
> 합친 숫자는 학교 프로젝트 발표 안에서만 쓴다.
> 🔴 **결과를 올리겠다고 고지문에 쓴 적이 없으므로 약속을 어기는 것이 아니다.**
> 화면의 「결과를 알려주나」 칸이 이대로 적혀 있다.

### 5.6. `survey-recommend` 의 응답이 오는 길 — 서버가 받는다

**2026-09-10 결정 (7절 P6).** 위 5.1 · 5.3 은 *"설문 화면에 서버가 없다"* 는 전제
위에 있고, 그래서 응답 코드를 **DM 으로 받아 진행자 PC 의 파일에 옮기는** 절차였다.
지금 돌리는 `survey-recommend` 는 그 전제가 아니다. **셋 중 「서버로 받는다」를 골랐다.**

```
   참여자 브라우저                      팀 서버
  ┌────────────────┐                ┌──────────────────────────┐
  │ 적는 동안       │                │                          │
  │  → 아무것도     │                │  ① 서버가 내용을 검사      │
  │    안 나간다     │                │     (형식 · 개인정보)      │
  │                │   제출 누를 때   │                          │
  │ [제출하기] ─────┼── JSON 한 번 ──▶│  ② 이 설문 전용 DB 에 넣음 │
  └────────────────┘   (https)      └──────────────────────────┘
        │                                        │
        └─🟢 DM 없음 · 진행자 PC 없음 ·             └─ 🔴 하루 한 번 사본을
           아이디-코드 대응표 자체가 안 생긴다          서버 밖으로 (아래)
```

| | |
|---|---|
| **몇 번 보내나** | **딱 한 번.** 제출 버튼을 누를 때 적으신 내용 전체가 JSON 하나로 간다. 중간 저장 · 자동 전송이 없다 |
| **누가 검사하나** | **서버가 한다.** 화면도 같은 검사를 하지만, 화면만 믿으면 주소창으로 직접 보내는 것을 못 막는다 (`server.mjs` 의 `check`) |
| **어디로 들어가나** | 팀 서버의 **이 설문 전용** 데이터베이스. 운영 서비스 DB 와 컨테이너 · 볼륨 · 네트워크가 전부 따로다 |
| 🟢 **익명이 더 나아진 점** | **Mattermost DM 을 안 쓴다.** 5.1 이 걱정하던 세 가지(채널에 코드가 올라옴 · DM 에 대응표가 남음 · 진행자가 대응표를 만듦)가 **경로 자체가 없어서** 안 생긴다 |
| 🔴 **대신 생긴 것** | 응답이 **팀 서버**에 있다. 진행자 PC 한 곳이 아니라 서버 한 곳이다. 그래서 아래 백업이 필요하다 |

**진행자가 하는 일도 달라진다.** 5.2 표의 3번(DM 을 파일에 옮기고 지운다)은
`survey-recommend` 에서는 **할 일이 없다** — 옮길 DM 이 아예 없다. 나머지 줄
(1 · 2 · 4 · 5 · 6 · 7)은 그대로다.

#### 5.6.1. 백업 — `pg_dump` 를 하루 한 번, 서버 밖에

**2026-09-10 결정 (7절 P10).** 처음에 나온 안은 **RAID 1**(**디스크 두 장에 같은
내용을 동시에 쓰는 것. 한 장이 고장 나도 다른 장에 그대로 있다**)이었다.
**그것으로는 이 설문이 잃는 방식을 못 막는다.**

| | RAID 1 이 막나 | 왜 |
|---|---|---|
| 디스크 한 장이 고장 난다 | ✅ 막는다 | 다른 장에 그대로 있다 |
| **실수로 `DELETE` 를 날린다** | ❌ **못 막는다** | 지우는 것도 **두 장에 똑같이** 반영된다 |
| **잘못된 쿼리로 값을 덮어쓴다** | ❌ **못 막는다** | 같은 이유 |
| **볼륨을 통째로 지운다** (`docker volume rm`) | ❌ **못 막는다** | 같은 이유 |
| 서버 자체가 없어진다 | ❌ 못 막는다 | 두 장이 같은 기계 안에 있다 |

RAID 는 **지금 이 순간의 사본**이라 사고까지 같이 복사한다. 우리가 잃는 방식은
디스크 고장보다 **사람 손**이 훨씬 잦다. 그래서 **시간이 다른 사본**이 필요하다.

**그래서 이렇게 한다.**

| | |
|---|---|
| 무엇 | `pg_dump`(**데이터베이스 내용을 파일 하나로 통째로 받아 내는 프로그램**) |
| 얼마나 자주 | **하루 한 번** |
| 어디에 | **그 서버 밖.** 같은 기계 안에 두면 기계가 없어질 때 같이 없어진다 |
| 얼마나 오래 | 응답과 같다 — **받은 날로부터 1년.** 사본만 더 오래 남기지 않는다 |
| 🔴 한계 | 하루 한 번이라 **마지막 사본 이후의 응답은 못 되찾는다.** 최대 하루치를 잃을 수 있다는 뜻이고, 이 설문에서는 그 값을 받아들인다 |

🔴 **고지문에도 적었다.** 화면의 「어디에 두나」 칸에 *"하루 한 번 사본(백업)을 떠서
그 서버 밖에 둡니다"* 와 *"사본도 같이 지웁니다"* 가 들어가 있다. 백업은 **응답이
한 곳 더 생기는 일**이라, 안 적으면 "한 곳뿐" 이라던 고지가 거짓이 된다.

## 8. 이 문서에서 쓴 말

| 말 | 뜻 |
|---|---|
| 고지문 | 무엇을 모으고 왜 모으고 언제 지우는지를 **미리** 알리는 글 |
| 동의문 | 참여자가 실제로 "참여하겠다" 를 누르는 자리의 글 |
| 익명 / 가명 | 응답만 보고는 누군지 알 수 없다 / 대응표가 있으면 되찾을 수 있다 (익명이 아니다) |
| 재식별 | 따로 보면 누군지 모르는 조각들을 합쳐 사람을 되찾는 것 |
| 짝 비교 | 조건이 다른 두 가지 중 하나를 고르게 하는 것 |
| 진행자 | 설문을 실제로 돌리고 응답을 받는 사람 한 명 |
| 함정 문항 | 한쪽이 모든 조건에서 분명히 나은 문항. 여기서 반대를 고르면 안 읽고 찍은 것으로 본다 |
