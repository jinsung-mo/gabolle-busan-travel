# 05 — 용어표

모르는 말이 나오면 여기부터 본다.

| 용어 | 뜻 |
| --- | --- |
| **취향 벡터 / user_taste_vector** | 한 사람의 취향을 (차원,코드,무게) 성분들로 나타낸 것의 버전 하나. 버전이 올라갈 때마다 새로 열리고 옛 것은 닫힌다(supersede) |
| **성분 / user_taste_weight** | 취향 벡터 하나를 이루는 행 한 줄 — "이 차원의 이 코드를 -1~+1 중 얼마나 좋아하는가" |
| **접기(fold)** | 설문 답·행동 이벤트라는 원본 데이터를, 위 성분 형태로 요약·변환하는 작업 |
| **watermark** | 배치가 "여기까지는 이미 봤다"고 기억해 두는 시각 표시. 다음 실행 때 그 이후 것만 본다 |
| **evidence (SURVEY/INTERACTION/BLENDED)** | 그 성분이 어디서 왔는지 — 설문에서 직접 답함 / 행동으로 추정함 / 둘을 섞음 |
| **support** | 그 성분을 뒷받침한 관측(행동) 횟수. 설문 답은 0 이어도 되고, 행동 추정은 1 이상이어야 함 |
| **EAV (Entity-Attribute-Value)** | 표 구조를 미리 다 안 정해도 되게, "누구-무엇-값" 세 칸으로 아무 종류의 데이터나 담는 설계 방식 |
| **사전 강제 (dictionary enforcement)** | EAV 표의 "값" 칸에 미리 정한 낱말 목록 밖의 것이 못 들어오게 DB 가 막는 것. 값이 하나면 외래키로, 목록이면 트리거로 |
| **event_outbox** | 클라이언트/서버가 만든 이벤트를 일단 담아 두는 표. 나중에 별도 중계가 읽어 진짜 목적지(분석 시스템 등)로 보낸다 |
| **taste signal (취향 신호)** | 취향 벡터가 실제로 세는/접는 이벤트 종류 (7종). |
| **behavior signal (행동 신호)** | 개인화 on/off 스위치의 영향을 받는(끄면 안 쌓고 지우는) 이벤트 종류 (10종). taste signal 을 포함하는 더 넓은 집합 |
| **aggregate axis** | 이 이벤트가 "누구/무엇에게 일어난 일인가"의 축. 지금 셋 — 추천 요청(request_id) · 여행(trip_id) · 사용자(user_id) |
| **producer (CLIENT/SERVER)** | 이 이벤트를 누가 만들어 보냈는가. 신뢰 경계 표시 — 클라이언트가 보낸 값은 조작될 수 있어 구분해서 남김 |
| **supersede** | 옛 버전을 고쳐 쓰지 않고 "닫음" 표시만 하고, 새 버전을 새로 여는 방식. 이력이 남는다 |
| **개인화 모드 (PersonalizationMode)** | `EXPLICIT_ONLY`(직접 답만 씀) / `BEHAVIOR_ENABLED`(행동도 씀) |
| **MLOps Phase 1** | 이 저장소가 취향 벡터 파이프라인을 부르는 이름 — 787 티켓 제목에 등장. 지금 조사로는 Phase 2(벡터를 실제로 소비하는 것)와 아직 안 이어져 있음 |
