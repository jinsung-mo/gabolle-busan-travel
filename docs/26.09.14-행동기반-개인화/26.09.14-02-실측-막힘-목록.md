# 02 — 실측 막힘 목록 (성격별로 가름)

원본: 01 문서와 동일 5개 원본 파일 전부.

세 가지 성격으로 갈랐다. **"만들면 안 됨"과 "아직 안 만듦"을 섞으면 안 된다** — 앞의 것은
지금 당장 코드를 써도 데이터 품질 사고가 나고, 뒤의 것은 그냥 시간과 결정이 필요할 뿐이다.

## A. 제품/설계 결정이 먼저 필요한 것 (사람이 정할 일)

| 번호 | 무엇 | 왜 코드로 못 정하나 |
| --- | --- | --- |
| A1 | 행동 신호를 **무게로 바꾸는 규칙** — 좋아요=+1.0 같은 건 자명한데, "일정 건너뛰기"나 "노출됐는데 안 누름" 같은 약한 신호는 negative 로 볼지, 기존 취향에서 가중치만 낮출지 결정 안 됨(대화에서 나온 원 질문) | `fromInteraction(weight, support, ...)` 시그니처는 있는데 그 weight 를 계산하는 공식이 어디에도 없다. PLACE_LIKE 처럼 오래된 신호조차 이 공식이 없다 |
| A2 | 여행(scope=TRIP) 취향 답을 계정(scope=USER) 벡터에 반영할지 (918 의 ②) | 수집 명세 2.2 "여행 답이 계정 기본값을 덮어쓰면 안 된다"와 정면으로 얽힘. 운영 답이 지금 전부 TRIP 이라 이 결정 없이는 배치가 돌아도 결과가 0개다 |
| A3 | `user_taste_weight.code='SCORE'` (점수형 성분)를 916 의 외래키에 어떻게 태울지 — 사전에 `SCORE` 를 실제 값으로 넣을지, 점수형 행만 외래키 검사에서 뺄지 | 둘 다 구현 가능한 선택지라 코드가 임의로 고를 수 없다 |
| A4 | 벡터(`user_taste_vector`/`user_taste_weight`)를 **언제/무엇이 소비할지** — 지금 추천 채점기는 이 벡터를 안 읽는다(01 문서) | 확인 못 함 — 로드맵 문서(`docs/gabolle/` 안)에 있을 수 있으나 이번 조사에서 열지 않음 |

## B. 그냥 아직 아무도 안 만든 것 (결정은 필요 없거나 이미 내려져 있음, 공수만 필요)

| 번호 | 무엇 | 근거 |
| --- | --- | --- |
| B1 | 접기 배치(`TasteVectorFoldService.fold`)를 **정기적으로 부르는 스케줄러/DAG** (918 의 ①) | `infra/personalization/airflow/dags/` 에 스모크 테스트 DAG 하나뿐, 실제 파이프라인 DAG 0건 |
| B2 | 행동 신호 7종(PLACE_*, ITINERARY_*, ROUTE_SKIP)을 **실제로 보내는 코드** — 서버 발행분(ITINERARY_LOCK/REMOVE)도, 클라이언트 호출분(PLACE_VIEW 등)도 전부 | grep 0건, 프론트엔드 이벤트 호출 자체가 0건 |
| B3 | A1(무게 변환 규칙)이 정해진 뒤, `foldSurvey` 옆에 **행동을 접는 짝 메서드**(`foldBehavior` 류)를 만들고 `fromInteraction` 을 실제로 호출 | 지금 `fold()` 는 개수만 세고 버림 |
| B4 | 916(취향 성분 사전 강제)의 "기존 행 재점검" 단계 | 787 머지 후에만 의미 있는 숫자가 나옴(이미 알려진 순서, 새로 발견한 것 아님) |

## C. 지금 만들면 안 되는 것 (데이터 품질 사고)

| 번호 | 무엇 | 왜 위험한가 |
| --- | --- | --- |
| C1 | `PLACE_LIKE`·`PLACE_DISLIKE`·`PLACE_VISIT`·`PLACE_VIEW` 를 **지금 그대로 켜서 보내기 시작** | 홈/장소상세 화면의 `place_id` 가 목업값, 체크인 화면은 식별자 자체가 없음(원본 02). 지금 켜면 가짜 place_id 가 붙은 "진짜 행"이 쌓이고, 나중에 진짜 ID 체계가 생겨도 그 행들은 고아가 되거나 엉뚱한 곳에 잘못 매칭됨 |

## 우선순위에 대한 관찰 (사실 아님 — 관찰)

C1 을 풀지 않으면(진짜 place_id 체계) 장소 관련 4종은 다른 무엇을 고쳐도 의미가 없다.
반대로 **일정 3종(ITINERARY_REMOVE/REPLACE, ROUTE_SKIP)은 C1 같은 차단 사유가 확인되지
않았다** — 일정 편집 API 자체는 버전·ID 를 갖추고 이미 동작 중이다(원본 05). 그래서
"완전히 막힌 것"과 "그냥 안 만든 것"이 섞여 있다는 게 이 목록의 핵심 발견이다.
