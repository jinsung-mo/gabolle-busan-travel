# axMap 사본을 걷어냈다 — 내 브랜치에서는 언제 사라지나

**2026-09-07 실측.** 이 문서는 두 가지만 답한다.

1. `ci/axmap/` 사본이 **내 브랜치에서 언제, 어떻게 사라지는가**
2. 이번 **1.1.0** 에서 뭐가 달라졌는가

---

## 0. 한 줄

`ci/axmap/`(**팀 저장소 안에 복사해 두고 돌리던 axMap 사본**)을 없앴다.
이제 axMap 은 **npm 꾸러미 `axmap-cli`** 하나이고, CI 도 각자의 PC 도 그것을 부른다.

> **npm**(Node Package Manager) — Node 프로그램을 인터넷에서 받아 설치하는 곳이자 그 명령.
> **`npx`** — 설치하지 않고 그 자리에서 한 번만 실행하는 명령. CI 는 매번 새 컨테이너에서
> 도니까 설치할 곳이 없어서 `npx` 를 쓴다.

---

## 1. 각자 지금 바로 (한 번, 1분)

```bash
npm i -g axmap-cli     # 전역 설치 — 이 PC 의 어느 폴더에서든 axmap 명령이 뜬다
axmap setup            # 장부 + 커밋 훅 + AI 도구(MCP) 등록을 홈 설정에 붙인다
axmap doctor           # 실제로 도는지 본다. 종료 코드 0 이면 끝
```

**안 하면 무엇이 깨지나** — 사본이 사라진 브랜치로 옮긴 순간 이 둘이 죽는다.

| | 증상 |
|---|---|
| **커밋 훅**(git 이 커밋 직전에 자동으로 돌리는 검사) | 심을 때의 경로가 절대 경로로 박혀 있다. 그 경로가 없어지면 커밋마다 오류가 나거나, 더 나쁘게는 **조용히 안 돌아서** claim 없이 고친 파일이 그대로 들어간다 |
| **MCP 연결**(AI 도구가 axMap 을 "도구" 로 부를 수 있게 해주는 통로) | `ax_claim` 같은 도구가 목록에서 사라진다 |

`axmap setup` 은 저장소가 아니라 **각자의 홈 설정**을 고친다. 그래서 저장소가 대신 해 줄
수 없고, 각자 한 번씩 돌려야 한다.

**2026-09-07 실측** (`git cat-file -e origin/<브랜치>:ci/axmap`):

| 브랜치 | 사본 |

| `main` | 있다 |

npm 판이 돈다. 어느 쪽이든 하는 일은 같으니 그동안 일이 막히지는 않는다.

## 3. 사본은 이 순서로 사라진다

```
 ① common/dev ──MR──> main          ← 지금 여는 것. 표 2개 필요
 ② main ──내려받기──> <파트>/dev     ← 각 파트가 각자 한 번
```

### ① `common/dev → main`

여기서 사본과 그것을 검사하던 잡이 함께 빠진다. **최상위 `main` 으로 가는 MR 이라
정족수**(**통과에 필요한 최소 찬성 수**)**를 채워야 한다 — 표 2개이고, 올린 사람의 표는
안 세어진다.** `/ax-vote` 로 던진다.

### ② `main` 을 각 파트로 내려받기

**여기가 헷갈리는 자리다. 내려받는 MR 은 못 연다.**

```bash
npx -y axmap-cli@latest mr-target --source main --target back/dev
# → [2] MR 대상 거부 — 한 칸씩만 올라갑니다.
```

사다리 검사(`verify:mr-target` 잡)는 **올라가는 방향만** 규정하고, 내려오는 것은 전부
거부한다. 그래서 길이 둘이다.

| | 누가 | 어떻게 |
|---|---|---|
| **(가) 바로 머지** | Maintainer(`masdf13` · `rleaderjoon`) | `<파트>/dev` 에서 `main` 을 머지하고 그대로 push. 보호된 브랜치에 직접 push 할 수 있는 권한이 있어야 한다 |
| **(나) 기능 브랜치로 우회** | **누구나** | `<파트>/dev` 에서 브랜치를 하나 따고, 거기에 `main` 을 머지한 다음 `<파트>/dev` 로 MR 을 연다. 기능 브랜치 → 파트 dev 는 사다리가 허용하는 정상 경로다 |

**충돌은 안 난다** — 2026-09-07 에 여섯 파트 브랜치 전부에 대해 미리 머지해 봤고
(`git merge-tree`), 한 건도 안 났다. 사본 삭제는 양쪽이 다투는 변경이 아니다.

(나) 를 쓸 때:

```bash
git checkout back/dev && git pull
git checkout -b chore/back/S15P21E201-000-drop-axmap-vendor
git merge origin/main          # ci/axmap/ 18개 파일이 삭제로 들어온다
git push -u origin HEAD -o merge_request.create -o merge_request.target=back/dev
```

> 🔴 **삭제도 파일을 고치는 것이다.** `claims` 잡은 선점 없이 고친 파일을 잡는다.
> 머지 커밋으로 들어오는 삭제는 원본 커밋이 이미 선점된 상태로 들어오므로 통과하지만,
> **손으로 지운다면 먼저 `ci/axmap` 을 claim 한다.**

### ②가 끝나면

그 브랜치에서 `ci/axmap/` 이 사라지고, `axmap doctor` 의 MCP 줄이 이렇게 바뀐다.

```
  OK  MCP 설정     홈에 등록돼 있습니다 (claude · agy) — 저장소에 파일이 없어도 됩니다
```

사본이 있는 동안에는 저장소 쪽이 홈 등록을 **이겨서**, npm 판을 깔아도 여기서는 안 쓰였다.
그것이 사본을 걷어낸 이유 중 하나다.

## 4. 왜 사본을 버렸나

사본을 둔 이유는 하나였다 — **axMap 이 깨진 날 팀 파이프라인까지 빨개지지 않게.**
팀 코드는 한 줄도 안 바뀌었는데 남의 저장소 사정으로 CI 가 죽는 것을 막는 장치였다.

그런데 값을 더 크게 치렀다.

- **고칠 때마다 두 곳을 맞춰야 한다.** 한쪽만 고치면 지문 검사가 어긋나 팀이 멈춘다
- **사본의 핀이 며칠씩 뒤처졌다.** 원본에 있는 기능이 팀에는 없는 상태가 반복됐다
- **사본이 홈 등록을 이겼다.** npm 판을 깔아 놓고도 팀 저장소에서는 옛 코드가 돌았다

npm 쪽 위험(꾸러미가 안 받아지면 CI 가 죽는다)은 세 곳에서 나눠 막는다 — 자세한 것은
[CI-RESILIENCE.md](CI-RESILIENCE.md).

## 5. 1.1.0 에서 뭐가 달라졌나

사본이 박혀 있던 지점(`4556679`)부터 `1.1.0` 까지 **커밋 43개**다. 팀이 실제로 체감하는
것만 묶었다.

### 쪽지함이 실패를 숨기지 않는다

**이게 제일 크다.** 그동안 쪽지가 **오고도 안 보였고, 도구는 "쪽지 없음" 이라고 답했다.**
아무도 고장 났다는 걸 몰랐다.

- 쪽지함을 못 열고도 "쪽지 없음" 이라고 답하던 것을 **실패로 말하게** 했다
- 화면에 접혀서 한 번도 안 뜬 쪽지가 있었다 — 그린 쪽이 그린 것만 찍게 했다
- 읽음 표시를 **읽기만 하고 쓰는 곳이 없었다**
- 미읽음 수가 두 곳에서 다르게 세어졌고, 이제 새 쪽지를 스스로 가져온다
- 여러 명에게 보낼 때 같은 쪽지를 두 번 보내던 것을 한 통으로
- 쪽지함이 매번 전부를 낸다 — 에이전트의 컨텍스트에는 스크롤이 없다

### 사람을 이메일로 알아본다

이름을 주소로 쓰면 `janghyojoon` 과 `장효준` 이 다른 사람이 된다. **그래서 쪽지가 묻혔다.**
이제 **이메일이 정본 주소**다. 그리고 "어디까지 읽었나" 가 그 PC 안에 갇혀 있던 것을
고아 브랜치(**커밋 이력이 따로 노는 브랜치**)로 옮겨서, PC 를 바꿔도 따라온다.

### 한 PC 의 창 둘이 서로를 덮지 않는다

레코드의 임자가 **이름 하나**가 아니라 **(이름, 세션) 짝**이 됐다.

- 같은 이름의 창 둘이 같은 파일을 **함께 잡을 수 있었다** — 겹침 검사가 자기 것으로 봤다
- 반납(`release`)이 **남의 창이 잡은 것까지 풀었다**
- 이제 `release` 는 이 세션 것만 푼다. 다른 창이 두고 간 것까지 풀려면 `--all-sessions`

### 감사가 쓸수록 느려지지 않는다

`audit`(**장부 이력을 처음부터 재생해 "아무도 안 잡은 파일이 고쳐진 적 있나" 를 사후에
증명하는 검사**)이 매번 처음부터 다시 읽어서, 장부가 길어질수록 느려졌다. 이제 **이미 본
구간은 체크포인트로 건너뛴다.**

같이 고친 것:

- 한글 경로를 못 읽어서 **잡아 둔 파일을 위반으로 세고 있었다**
- 경고 한 줄에 겹침 판정이 통째로 무너져서, **판정을 못 했는데 통과시키고 있었다**
- `audit` 이 코드 커밋을 본다 — 그 전에는 검사기가 없어서 claim 이 사실상 권고였다

### 사본을 지울 수 있게 만든 것들

- **딸린 프로그램을 경로가 아니라 이름으로 부른다.** `node ci/axmap/tools/bus.mjs list` 가
  `axmap bus list` 가 됐다. 경로가 박혀 있으면 사본을 지울 수 없다
- 설치본이 **남의 저장소에서도 돈다** — 프로그램의 위치는 저장소가 아니다
- `npx` 한 줄로 설치된다 (설치 5단계 → 1단계)
- `doctor` 가 **홈 등록도 본다** — 붙어 있는데 "안 붙었습니다" 라고 말하던 것
- 버전을 박지 않고 `@latest` 로 간다

### 투표와 사다리

- **명단 없이도 판정한다** — 저장소에 커밋한 사람이 곧 투표권자다
- 표에 **이유를 남기게** 했고, 그 이유를 머지 커밋에 싣는다 (MR 댓글은 clone 에 안 따라온다)
- 자기 표 배제의 범위를 정책이 정한다 — 그 전에는 **`dev` 브랜치가 영구히 잠겼다**
- `common` 처럼 제품 코드가 없는 파트를 **버전 축과 파트 사다리에서 뺐다.**
  그래서 `common/dev` 는 `common/main` 을 거치지 않고 최상위 `main` 으로 바로 간다
- 훅이 경로를 하나만 박아 두어서 **브랜치를 옮기면 모든 커밋이 막혔다**
- `--version` 이 버전이 아니라 도움말을 찍고 있었다

## 6. 안 달라진 것

- **선점 규칙은 그대로다.** 고치기 전에 claim, 끝나면 release
- **장부와 쪽지함의 자리도 그대로다.** `.axmap/ledger` · `.axmap/votes` — 커밋되지 않는다
- **`governance/policy.json` 은 팀 저장소에 남는다.** 도구는 나가고 데이터는 남는다
- 슬래시 명령(`/ax` · `/ax-start` · `/ax-done` · `/ax-inbox` · `/ax-tell` · `/ax-vote`)도 그대로다.
  안에 적힌 CLI 대체 명령만 새 이름으로 바뀌었다

| **npm** | Node 프로그램을 인터넷에서 받아 설치하는 곳이자 그 명령 |
| **`npx`** | 설치하지 않고 그 자리에서 한 번만 실행하는 명령 |

| **사다리** | 기능 브랜치 → 파트 dev → 파트 브랜치 → main. 한 칸씩만 올라간다 |
