# GABOLLE 프론트엔드 디자인 시스템

| 항목 | 결정 |
|---|---|
| 상태 | 확정 · 2026-09-05 현행 코드 기준 |
| 화면 소스 | Expo Router의 같은 화면·컴포넌트를 웹과 앱에서 함께 사용 |
| 디자인 토큰 | `frontend/src/design/tokens.ts` |
| 공용 컴포넌트 | `frontend/src/components/Button.tsx`, `Screen.tsx`, `Text.tsx` |
| 상세 토큰 규칙 | `docs/DESIGN_TOKENS.md` |

## 현재 결정

GABOLLE은 별도 웹 디자인 시스템 패키지를 설치하지 않는다. 웹과 앱을 같은 Expo
Router 소스로 빌드하고, 브랜드 색·간격·반경·타이포그래피는
`frontend/src/design/tokens.ts` 한 곳에서 가져온다. 화면은 공용 컴포넌트를 우선
사용하며 플랫폼 차이가 필요한 경우에만 `Platform` 또는 반응형 레이아웃으로 분기한다.

이 결정은 문서의 희망사항이 아니라 현재 제품 코드와 CI가 실제로 사용하는 구조다.
`frontend/README.md`의 실행 명령과 `.gitlab-ci.yml`의 `frontend:build`,
`frontend:smoke`가 동일 프로젝트의 웹 번들을 설치·빌드·실행한다.

## 선택한 이유

- 웹·앱의 색과 간격을 한 번만 정의해 한쪽만 바뀌는 사고를 막는다.
- 화면, API 클라이언트, 타입, 인증 상태를 두 벌로 복제하지 않는다.
- Expo Router가 웹·Android·iOS 라우팅을 한 구조에서 제공한다.
- React Native에서 동작하지 않는 웹 전용 CSS·컴포넌트에 앱이 종속되지 않는다.
- 현재 공용 컴포넌트와 여러 화면이 이미 이 구조로 구현돼 있어 교체 비용과 회귀 위험이 작다.

## 검토 후 채택하지 않은 선택지

### Astryx

웹 컴포넌트 수가 많고 완성도가 높으며 CLI로 사용법을 확인할 수 있다는 장점이 있다.
그러나 CSS와 StyleX 기반의 웹 전용 패키지라 React Native 앱에서 사용할 수 없다.
웹만 Astryx로 바꾸면 토큰과 컴포넌트가 다시 두 벌이 되므로 채택하지 않는다.

### Material Design 3

웹과 React Native 양쪽에 구현체가 있고 접근성 관행이 성숙했다는 장점이 있다.
다만 플랫폼별 구현체가 서로 다른 패키지이며, 현재 GABOLLE의 해안·여행 브랜드와
기존 공용 컴포넌트를 대체하려면 시각 체계와 상호작용을 다시 맞춰야 한다. 지금은
직접 관리하는 소규모 토큰·공용 컴포넌트가 더 단순하고 일관적이다.

## 구현 규칙

1. 화면에서 브랜드 색·간격·반경을 새로 하드코딩하지 않고 디자인 토큰을 사용한다.
2. 새 버튼·텍스트·화면 여백은 공용 `Button`, `Text`, `Screen`을 우선 조합한다.
3. 토큰의 숫자 값을 문서에 복제하지 않는다. 값의 정본은 코드이며 문서에는 이름과 경로만 적는다.
4. 토큰 변경 MR은 웹과 앱 화면을 함께 확인하고 `frontend:build`, `frontend:smoke`를 통과한다.
5. 웹 전용 또는 네이티브 전용 동작은 공용 정보 구조를 유지한 채 최소 범위로 분리한다.

## 이전 검토 기록

2026-08-27에는 Astryx와 Material Design 3를 비교했고 Astryx 실험용 프로젝트의
빌드도 확인했다. 당시에는 웹과 앱을 별도 코드베이스로 만들 계획이어서 웹 전용
Astryx 채택이 후보가 될 수 있었다. 이후 실제 제품이 단일 Expo Router 구조로
구현되고 공용 토큰 위치가 확정되면서 그 전제가 사라졌다. 과거 실험 수치와 패키지
버전은 현재 제품의 의존성이나 완료 기준으로 사용하지 않는다.
