| `ontology/**` (규칙·어휘) | REC/AI | DATA |

# 4. 역할별 상세 지침

각 절은 같은 형식이다 — **소유 · 첫 산출물 · 하는 일 · 하지 않는 일 · DoD · 막히면**.

## 4.1 INFRA — 배포 경로가 먼저다

| | |
|---|---|
| 소유 | `infra/**` · `.gitlab-ci.yml` · `docker/**` |
| 첫 산출물 | **9/2 18:00 — 빈 앱이 스테이징 URL 에서 응답** |
| 필수 리뷰 | BE |

**하는 일**

- **9/1~9/2**: 기능 없는 상태로 화면–API–DB–배포를 한 번 관통시킨다. `/health` 하나만 응답해도 된다.
- CI 는 **빌드 + 테스트 + 배포** 세 단계만. 정적 분석·커버리지 게이트는 후속.
- PostgreSQL · Redis 인스턴스 기동. Kafka·Spark 는 **M3 전까지 세우지 않는다**.
- 외부 API 키를 환경변수로 외부화하고 저장소에 넣지 않는다 (NFR-03).
- 로그에 `requestId` · `errorCode` · `fallbackMode` 가 남게 한다 (NFR-07).

**하지 않는 일**

- 쿠버네티스·오토스케일링·멀티리전. 17일짜리 일정에서 이건 순수 비용이다.
- 관측 대시보드 미화. 숫자가 로그에 남기만 하면 M3 까지 충분하다.

**DoD**  ① 스테이징 URL 이 외부에서 열린다 ② `main` 머지가 자동 배포된다 ③ 롤백이 한 명령이다 ④ 비밀값이 저장소에 없다

**막히면**  9/2 18:00 에 배포가 안 뚫리면 **그 사실을 즉시 공유한다.** 나머지 다섯 명의 M1 완료 기준이 여기 걸려 있다.

## 4.2 BE — 계약을 가장 먼저 고정한다

| | |
|---|---|
| 소유 | `backend/**` |
| 첫 산출물 | **9/1 18:00 — ERD 초안** · **9/2 18:00 — 추천 DTO** |
| 필수 리뷰 | REC/AI (추천·일정) · DATA (스키마) · 기획 (인증) |

**하는 일**

- **ERD 를 오늘 안에 낸다.** 완벽하지 않아도 된다. DATA·REC/AI 가 그 위에서 시작해야 한다.
- 인증: 14세 게이트 → Google OAuth(PKCE) → Access/Refresh JWT (FR-ACC-01·02). **M1 은 Google 만.** Naver·Kakao 는 M2.
- 여행 생성 → 추천 Job(202 + jobId) → 상태 조회 (FR-REC-13). **동기/비동기 경계를 M1 에 지킨다.** 나중에 바꾸면 FE·APP 이 다시 붙어야 한다.
- 일정 버전: 모든 편집이 새 `ItineraryVersion` 을 만들고, `baseVersion` 이 최신이 아니면 **409 + latestVersion** (FR-ITN-08). **M1 에 넣는다** — 나중에 넣으면 편집 로직을 다시 짠다.
- Outbox: 서비스 트랜잭션과 이벤트 발행 의도를 한 트랜잭션에 (DR-05). **M1 은 PostgreSQL 테이블까지만.** Kafka 연결은 M3.
- fallback: 추천 서버 실패 시 규칙 → 기준선 순으로 내려가고 `fallbackMode` 를 응답에 남긴다 (FR-REC-11).
- 객체 권한: `tripId` · `itineraryId` · `jobId` 마다 실제 소유·참여 관계를 검증한다 (FR-SEC-01).

**하지 않는 일**

- 캐시 최적화. Redis 는 M3 부터.
- 세밀한 예외 계층. `GB-API-001` 5장의 enum 오류 코드만 지킨다.

**DoD**  ① M1 필수 API 가 스테이징에서 응답 ② 409 충돌이 실제로 재현된다 ③ 추천 서버를 죽여도 기준선 결과가 나온다 ④ 하드 제약 위반 0건

## 4.3 REC/AI — 안전이 먼저, 최적화는 나중

| | |
|---|---|
| 소유 | `rec-server/**` · `ontology/**` |
| 첫 산출물 | **9/3 18:00 — PASS/FAIL/UNKNOWN 판정 계약** |
| 필수 리뷰 | DATA · BE |

**하는 일**

- **하드 제약부터 만든다.** 알레르기·식단 위반은 점수로 되살리지 않는다 (FR-REC-02). 이건 M1 에서 자르지 않는 유일한 추천 기능이다.
- `UNKNOWN` 은 **제외하지 않고 경고한다.** 근거가 없다고 배제하면 후보가 말라붙고, 근거 없이 통과시키면 사람이 다친다 (`GB-PLAN-001` 4장 "모르면 모른다고 표시").
- 콜드스타트: 행동 데이터 0인 상태에서 설문 + 장소 속성만으로 순위를 낸다 (FR-REC-03). **M1 사용자는 전원 콜드스타트다.**
- 순서 계산: M1 은 **영업시간 + 이동시간 휴리스틱**. OR-Tools 는 M2.
- 예산 110% · 보행 115% 상한을 지킨다. 목표 내 해가 있으면 초과하지 않는다 (FR-REC-14).
- 모든 결과에 `requestId` · `modelVersion` · `featureVersion` · `ontologyVersion` (FR-REC-12).

**하지 않는 일**

- LightGBM 등 학습 랭커. 데이터가 0이다. 규칙 기반이 M3 까지 운영 기준선이다.
- 온톨로지 전체 어휘 구축. **식단·알레르기 규칙만** M1. 경사·그늘은 M2.

**DoD**  ① 알레르기 시나리오에서 위반 0건 ② UNKNOWN 이 경고로 표시된다 ③ 행동 데이터 없이 결과가 나온다 ④ 판정 근거(`violations` · `unknownFacts`)가 응답에 담긴다

**DoD**  ① 장소 200곳이 조회된다 ② 식단 태그 채움률과 결측률을 **수치로 보고**한다 ③ 이벤트 스키마가 FE·APP 에 전달됐다 ④ 노출-행동이 `requestId` 로 연결된다(M3)

## 6.2 브랜치와 커밋

```
feat/GB-123-recommendation-job      기능
fix/GB-124-itinerary-409            수정
chore/GB-125-ci-deploy              그 외
```

- 커밋 메시지 앞에 **대괄호 이슈 키**: `[GB-123] feat: 추천 Job 생성 API`
- MR 은 `main` 이 아니라 **자기 파트의 통합 브랜치**로 올린다
- MR 은 **하루 안에 리뷰**한다. 압축 일정에서 리뷰 대기는 그대로 손실이다

## 6.3 남의 경로를 고쳐야 할 때

1. 3.2절에서 주인을 확인한다
2. **먼저 말한다** — 같은 파일을 두 사람이 동시에 고치면 둘 다 시간을 잃는다
3. 주인이 자리에 없으면 고치되 **MR 에 주인을 리뷰어로 지정**한다

## 6.4 결정 기록

## 7.1 🔴 프로덕션 출시는 필요 없다

M3 목표는 **사용자 100명**이지 스토어 정식 출시가 아니다. 이 구분이 일정 전체를 좌우한다.

| Play 비공개 테스트 | 2,000명 | 표준 정책 검토 | 몇 시간 | 이메일·그룹스 |
| Play 공개 테스트 | 무제한 | 표준 정책 검토 | 몇 시간 | 공개 링크 |

## 7.2 권장 조합

> **Android는 Play 내부 테스트, iOS는 TestFlight 외부.**

**이유**

- Play **내부 테스트 상한이 정확히 100명**이다. 목표와 같아서 **여유가 0**이다. 중도 이탈이 한 명이라도 나오면 목표 미달이 된다. 그래서 iOS 를 병행해 머릿수를 나눈다.
- TestFlight **외부**는 10,000명까지지만 **베타 앱 심사**를 통과해야 한다. 그래서 **9/8~9/9 에 먼저 올린다**(5.2절).
- 100명을 넘길 여지를 두려면 Play 를 **비공개 테스트(2,000명)** 로 올린다. 다만 표준 정책 검토가 붙으므로 **하루 여유**를 잡는다.

## 7.3 🟢 앞선 우려 정정

> 이전 논의에서 *"신규 개인 개발자 계정은 테스터 12명 × 14일 연속 테스트가 필요해 9월 출시가 불가능하다"* 고 판단한 적이 있다. **그 요건은 프로덕션 출시의 전제조건이고, 테스트 트랙 배포와 100명 모집에는 적용되지 않는다.**
>
> 즉 **M3(9/18 100명)는 그 요건과 무관하게 달성 가능하다.** 다만 **프로덕션 정식 출시를 하려면 그 요건이 그대로 살아 있다** — 이번 마감(9/23) 안에는 들어가지 않는다. 정식 출시는 후속으로 둔다.
