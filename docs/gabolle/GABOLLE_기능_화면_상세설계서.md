## FR-ACC-01 · 만 14세 이상 필수 가입

| 항목 | 내용 |
|---|---|
| 사용자 스토리 | 서비스는 만 14세 미만의 가입을 받지 않아야 한다. 사용자는 생년월일이 서비스에 남지 않기를 원한다 |
| 구현 방법 | ① 가입 화면에서 생년월일 입력 ② 서버가 가입일 기준 만 14세 이상 여부만 계산 ③ 미만이면 가입 차단하고 사유 안내 ④ **생년월일 원본은 저장하지 않고** `ageVerifiedAt` · `ageGatePolicyVersion` 만 보존 |
| 필요 기술 | Spring Validation · 서버 시각 기준 계산(클라이언트 시각 신뢰 금지) |
| 데이터 | `User.ageVerifiedAt` · `User.ageGatePolicyVersion` |
| API | `POST /api/v1/auth/signup` |
| 화면 | `S-02` |
| 예외·폴백 | 만 14세 미만 → `AGE_RESTRICTED` 오류와 안내. 재시도로 우회할 수 없게 서버에서 판정 |
| 수용 기준 | ① 만 14세 미만 생년월일로 가입이 차단된다 ② DB 어디에도 생년월일 원본이 없다 ③ 정책 버전이 기록된다 |

## FR-ACC-02 · 로그인과 토큰

| 항목 | 내용 |
|---|---|

| 구현 방법 | ① OAuth authorization code + **PKCE**(모바일 필수) ② 제공자 프로필로 계정 생성 또는 조회 ③ Access/Refresh JWT 발급 ④ Refresh **회전** · **재사용 탐지** · 세션 폐기. **M1 은 Google 만, Naver·Kakao 는 M2** |

| 데이터 | `AuthIdentity(provider, providerUserId, userId)` · `RefreshSession(tokenHash, rotatedAt, revokedAt)` |
| API | `POST /api/v1/auth/oauth/{provider}` · `POST /api/v1/auth/token/refresh` · `POST /api/v1/auth/logout` |
| 화면 | `S-02` |
| 예외·폴백 | 제공자 오류 → 다른 제공자 안내. Refresh 재사용 탐지 시 **해당 계정 전 세션 폐기** |
| 수용 기준 | ① Google 로그인 후 새로고침해도 로그인 유지 ② 탈취된 Refresh 재사용 시 전 세션이 끊긴다 ③ Access 만료 후 자동 갱신 |
| 담당 · 마감 | BE · FE · APP / **M1**(Google) · **M2**(Naver·Kakao) |

# 3. REC — 추천·온톨로지·동선

이 장이 GABOLLE 의 본체다. `GB-PLAN-001` 6장의 파이프라인 6단계가 여기에 대응한다.

```
후보 생성 → 하드 필터 → 콜드스타트 → 개인화 → 재정렬 → 동선 최적화
```

# 9. 공통 화면 상태

`GB-UX-001` 6장을 구현 기준으로 옮긴 것이다. **모든 화면이 이 여섯 상태를 갖는다.** 나중에 넣으면 화면마다 다시 열어야 한다.

| 상태 | 언제 | 표시 원칙 | 하지 말 것 |
|---|---|---|---|
| **Loading** | 응답 대기 | **진행 단계**와 취소/뒤로 가능 여부 | 스피너만 무한히 돌리기 |
| **Empty** | 결과 0건 | **빈 이유와 다음 행동** | "결과가 없습니다" 한 줄로 끝내기 |
| **Partial** | 일부 데이터만 사용 | 어떤 데이터가 없는지 명시 | 없는 값을 0이나 추정치로 채우기 |
| **Fallback** | 모델·최적화 실패 | 서비스는 계속하되 **추천 방식과 주의사항** 표시 | 조용히 다른 결과 보여주기 |
| **Error** | 내부 오류 | 재시도 또는 대안 제공 | 스택트레이스·내부 코드 노출 |
| **Offline** | 네트워크 없음 | 저장된 일정·핵심 장소 정보 우선 | 흰 화면 |

## 9.1 상태별 문구 원칙

| 원칙 | 예 |
|---|---|
| **무엇이 없는지 말한다** | ❌ "데이터를 불러올 수 없습니다" → ✅ "그늘 정보가 아직 확인되지 않았습니다" |
| **다음 행동을 준다** | ❌ "조건에 맞는 곳이 없습니다" → ✅ "예산 8만원과 필수 장소 A 가 충돌합니다. 어느 쪽을 조정할까요?" |
| **모르는 것을 아는 척하지 않는다** | ❌ 영업시간 추정값을 그냥 표시 → ✅ "영업시간 확인 필요" |
| **사용자 탓으로 만들지 않는다** | ❌ "잘못된 요청입니다" → ✅ "날짜가 거꾸로 입력되어 있어요" |
