> 🔴 **맥이 없고 윈도우 노트북뿐이라면 이 문서는 못 쓴다.** Xcode 도 Appium 의 iOS 드라이버도 macOS 전용이다. 윈도우에서는 [IOS-TEST-ON-WINDOWS.md](IOS-TEST-ON-WINDOWS.md) 로 간다 — TestFlight 로 아이폰에 깔아 손으로 보는 길이고, 맥이 아예 필요 없다.

작성 2026-09-17 · 대상 `S15P21E201-250`(실기기 시나리오 × 2회 크래시 세기)

이 문서 하나만 들고 맥북 앞에 앉으면 끝나도록 적었다. 저장소를 못 받아도 되게
**필요한 값은 전부 이 안에 있다.**

## 0. 🔴 이 문서가 「빌린 맥북」을 전제로 쓰인 이유

내 기계가 아니면 **남기는 것이 곧 민폐이자 사고**다. 그래서 순서를 이렇게 잡았다.

1. **설치가 필요 없는 길을 먼저 쓴다** — macOS 에 이미 있는 QuickTime·Console·Finder 만으로
   이 시험의 완료 기준(크래시 0건)을 채울 수 있다
2. 설치는 **정말 필요할 때만**, 그리고 **지울 방법을 먼저 적어 두고** 한다
3. 끝나면 **5절의 뒷정리를 반드시 한다** — 페어링 기록·로그·계정이 남는다

> 🔴 **애플 계정을 그 맥북에 로그인하지 않는다.** TestFlight 설치는 *아이폰에서* 하고,
> 맥북은 로그를 받는 용도로만 쓴다. 맥북에 Apple ID 를 넣으면 그 기계에 기기 신뢰와
> 계정이 함께 남는다.

## 2. 설치 없이 되는 길 (권장 · 맥북에 아무것도 안 남기는 쪽)

### 2-1. 기기 신뢰 맺기

1. 아이폰을 USB 로 꽂는다
2. 아이폰에 **"이 컴퓨터를 신뢰하시겠습니까?"** → **신뢰** → 암호 입력
3. 맥북에서 **Finder** 를 열면 왼쪽 사이드바에 아이폰이 나타난다

> 나타나지 않으면 케이블 문제이거나 잠금 해제가 안 된 것이다. 아이폰 잠금을 풀고
> 다시 꽂는다.

### 2-2. 로그 받기 — **Console.app** (macOS 기본 탑재)

1. `⌘ Space` → `Console` → 실행
2. 왼쪽 **Devices** 에서 아이폰을 고른다
3. 오른쪽 위 검색창에 `gabolle` 을 넣고 **Start** 를 누른다

이제 앱이 뱉는 로그가 실시간으로 흐른다. **크래시가 나면 여기 먼저 보인다.**

> 저장: 로그가 흐르는 동안 `⌘ A` → `⌘ C` 로 복사해 텍스트 파일에 붙인다.
> 또는 `File → Save a Copy As…`.

### 2-3. 크래시 리포트 받기 — 설치 없이

아이폰 안에 먼저 쌓인다. **아이폰에서** 확인하는 것이 가장 확실하다.

```
설정 → 개인정보 보호 및 보안 → 분석 및 향상 → 분석 데이터
```

목록에서 **`gabolle`** 로 시작하는 항목을 찾는다.

* **하나도 없으면 그것이 「크래시 0건」의 증거다** — 목록 화면을 캡처해 둔다
* 있으면 그 항목을 열어 공유 버튼으로 내보낸다 (파일명·시각을 그대로 남긴다)

> 🔴 이 목록에는 다른 앱 것도 섞여 있다. **`gabolle` 로 시작하는 것만** 센다.
> `JetsamEvent`(메모리 부족으로 시스템이 앱을 끈 것)는 크래시와 성격이 다르니
> 발견하면 **따로 적는다** — 그것도 보고할 가치가 있다.

### 2-4. 화면 보기·녹화 — **QuickTime Player** (macOS 기본 탑재)

1. QuickTime Player 실행 → `파일 → 새로운 동영상 녹화`
2. 녹화 버튼 **옆 화살표**를 눌러 카메라를 **iPhone** 으로 바꾼다
3. 아이폰 화면이 맥북에 그대로 뜬다. 필요하면 녹화 버튼을 눌러 **영상으로 남긴다**

이것이 빌린 맥북에서 **가장 쓸모 있는 도구**다. 설치가 없고, 시나리오를 도는 모습을
통째로 남길 수 있어 나중에 「몇 번째 시도에서 났는지」를 되짚을 수 있다.

> 🔴 QuickTime 의 아이폰 화면은 **보기와 녹화만** 된다. 맥북에서 탭·스와이프는 못 한다.
> 조작은 아이폰을 직접 만져서 한다.

## 3. 설치가 필요한 길 (자동화 · 꼭 필요할 때만)

2절만으로 완료 기준은 채워진다. 아래는 **로그·크래시를 파일로 자동 수집**하고 싶을 때만.

### 3-1. Xcode Command Line Tools

```bash
xcode-select --install
```

* 맥북에 **이미 깔려 있을 확률이 높다.** 먼저 확인:
  ```bash
  xcrun --version && xcrun devicectl list devices
  ```
  기기가 목록에 나오면 추가 설치가 필요 없다
* 🔴 **지우기 어렵다.** 빌린 기계라면 이미 깔려 있을 때만 쓰는 편이 낫다

쓸 수 있는 것:

```bash
# 붙어 있는 기기
xcrun devicectl list devices

# 기기 정보 (iOS 버전 확인)
xcrun devicectl device info details --device <UDID>
```

### 3-2. 크래시 리포트를 파일로 (Xcode 가 있을 때)

Xcode 를 열 수 있으면 가장 편하다.

```
Xcode → Window → Devices and Simulators → 기기 선택 → View Device Logs
```

여기서 `gabolle` 로 걸러 **우클릭 → Export Log** 로 파일을 뽑는다.

### 3-3. 🔴 화면 캡처 자동화는 기대하지 않는다

`pymobiledevice3`·`libimobiledevice` 로 스크린샷을 뽑으려면 **개발자 디스크 이미지**가
필요하고, iOS 17 이후로는 그 경로가 바뀌어 **관리자 권한과 터널**이 든다.
빌린 기계에서 할 일이 아니다. **2-4 의 QuickTime 녹화로 대체한다.**

> 참고 — 윈도우에서 같은 것을 시도했다가 막힌 기록이 있다(2026-09-17):
> `pymobiledevice3` 는 Python 3.14 에서 의존성(`backports.zstd`)이 아직 안 맞고,
> `ios-deploy` 는 macOS 전용이다. 맥북에서는 3-1 의 `devicectl` 이 정식 경로다.

## 4. 무엇을 시험하는가

### 4-1. 필수 — 시나리오 10종 × 2회 (`S15P21E201-250`의 완료 기준)

각 시나리오를 **연달아 두 번** 돈다. 한 번만 돌리면 가끔 나는 크래시를 놓친다.

| # | 시나리오 | 보는 것 |
|---|---|---|
| 1 | 첫 실행 → 앱 소개 → 비회원 둘러보기 | 사진·스와이프·버튼 잘림 |
| 2 | 이메일 회원가입 → 인증 메일 → 링크 → 로그인 | 메일이 **앱으로** 돌아오는가 |
| 3 | 구글 로그인 | 아래 4-2 ① 을 함께 본다 |
| 4 | 여행 만들기 4단계 → 일정 생성 | 결과 화면까지 가는가 |
| 5 | 일정 열람 (1·2·3일차 전환) | 시각·이동 시간 표시 |
| 6 | **여행 지도** | 아래 4-2 ② 를 함께 본다 |
| 7 | 현장 도구 (장소별 한국어·읽어주기) | **소리가 나는가** (`-1126` 회귀) |
| 8 | 기록 작성 (사진 올리기 포함) | 사진이 실제로 올라가는가 (`-1121` 회귀) |

## 4-3. 🔴 자동화로 돌릴 때 — 2026-09-17 에 7회차가 통째로 날아간 이유

> 🟢 **돌리는 사람은 이 절을 읽지 말고 [`docs/ios-automation/`](ios-automation/README.md) 를 열면 된다.**
> 그쪽에 **바로 돌아가는 스크립트**(`gabolle_ios_test.py`)와 준비부터 보고까지의 안내가 있다.
> 이 절은 **왜 그렇게 만들었는지**를 남긴 기록이다.

첫 시도(2026-09-17 밤, iPhone 12 Pro · iOS 26.6.2 · build 22)는 **7회차 모두 온보딩을
못 넘어 기능 검증이 0%** 였다. 스크린샷 95장 중 앱 메인 화면은 **0장**이다.

이유가 셋이었고, **셋 다 아래 절차로 막을 수 있다.**

### ① 글자로 요소를 찾으면 안 된다

이 앱은 **5개국어**다. 영어로 바꾸면 탭 이름이 `Home`·`Feed`·`Create`·`My trips`·`Profile`
로 전부 달라진다. 그때 자동화는 온보딩 **본문 글자**를 탭바로 착각했다.

```
❌ 요소 없음: 홈              ← 진짜 탭바는 화면에 없었다
✅ 탭: 여행                   ← 온보딩 소개문의 「AI 여행」을 누른 것
```

그때 쓴 선택자는 이것이었다 (`complete_feature_test_round4_final.py`).

```python
(AppiumBy.XPATH, f"//*[contains(@label, '{text}')]")        # ❌ 부분일치
tab_keywords = ["여행", "일정", "현장", "부슈랭"]                    # ❌ 없는 탭 이름
```

🔴 **진짜 탭 이름은 `홈 · 피드 · 여행 만들기 · 내 여행 · 마이페이지` 다.**
위 네 개는 **앱에 없는 이름**이고, 그중 「부슈랭」은 온보딩 3페이지 **본문**에 있었다 —
「…마음에 든 곳은 **부슈랭**과 꼭 갈 장소에 담을 수 있어요」. 그게 걸렸고, 스크립트는
「부슈랭 탭을 눌렀다」고 적었다. **같은 순간 스크린샷은 온보딩 3페이지였다.**

→ **`testID` 로만 찾는다.** `S15P21E201-1191`·`-1193` 에서 아래 이름들을 박아 뒀다.

| 화면 | testID |
|---|---|
| 언어 선택 | `lang-ko` `lang-en` `lang-ja` `lang-zh-Hans` `lang-zh-Hant` · `start-gabolle` |
| 앱 소개(3장) | `app-intro-primary` (다음/시작하기) · `app-intro-skip` (건너뛰기) |
| 나이 확인 | `age-gate-check` · `age-gate-continue` |
| 권한 안내 | `permissions-continue` · `permissions-browse-guest` · `permissions-later` |
| 탭바 | `tab-home` `tab-feed` `tab-schedule` `tab-map` `tab-me` |

이 이름들은 `frontend/src/components/__tests__/entryTestIds.test.tsx` 와
`frontend/app/__tests__/appIntroAccessibility.test.tsx` 가 지킨다. 누가 조용히 바꾸면
프론트 CI 가 먼저 빨개진다.

### ② 안 보이는 페이지가 눌리던 문제 — 고쳤다

앱 소개는 가로 캐러셀인데 세 장을 동시에 그려 둔다. 예전에는 **안 보이는 장까지
접근성 트리에 있어서**, 3장에 있는데 2장의 글자가 눌려 캐러셀이 뒤로 밀렸다.

`S15P21E201-1191` 에서 보이는 장만 남기도록 고쳤다. **build 23 이후**에서만 유효하다 —
그 전 빌드로 돌리면 같은 일이 또 난다.

### ③ 🔴 로그가 「완료」를 찍었다고 통과가 아니다

첫 시도의 5~7회차는 **모든 항목에 `✅ 완료`** 를 찍었는데, 그 회차 마지막 화면은
**언어 선택 첫 화면**이었다. 아무 데도 못 갔는데 성공만 출력한 것이다.
그래서 보고서 하나는 「20/20 성공·완료 기준 충족」이라고 썼고, 다른 하나는
「기능 테스트 0%·미달성」이라고 썼다. **뒤엣것이 사실이었다.**

4회차 로그의 끝은 이렇게 끝난다.

```
  ✅ 탭: 부슈랭
✅ 시나리오 6 완료
완료된 시나리오: 6/6
```

그 줄이 가리키는 스크린샷(`test_s6_booshurang_233743.png`)을 열면
**「장소를 찾고 저장해 내 여행으로 이어가요」 — 온보딩 3페이지**다.
오른쪽 위에 「건너뛰기」가 그대로 보인다 — 한 번도 안 눌렸던 그 단추다.

→ **못 찾으면 그 자리에서 실패시킨다.** 아래 `tap_id`·`must_see` 가 그 규칙이다.

### 들어가는 길 — 이 순서 그대로

```
언어 선택  lang-ko 또는 start-gabolle
   ↓
앱 소개    app-intro-skip  (건너뛰기 한 번이면 3장을 다 건너뛴다)
   ↓
나이 확인  age-gate-check → age-gate-continue
   ↓
권한 안내  permissions-browse-guest  (비회원으로 먼저 둘러보기)
   ↓
메인       tab-home 이 보이면 도착한 것이다   ← 여기까지 와야 시나리오를 시작한다
```

### 최소 뼈대 (Python · Appium)

```python
from appium.webdriver.common.appiumby import AppiumBy

def tap_id(driver, test_id, timeout=10):
    """testID 로 찾아 누른다. 못 찾으면 **그 자리에서 실패**시킨다."""
    el = WebDriverWait(driver, timeout).until(
        lambda d: d.find_element(AppiumBy.ACCESSIBILITY_ID, test_id))
    el.click()
    return el

def must_see(driver, test_id, timeout=10):
    """이 화면에 도착했는지 확인한다. 없으면 실패 — 로그만 찍고 넘어가지 않는다."""
    return WebDriverWait(driver, timeout).until(
        lambda d: d.find_element(AppiumBy.ACCESSIBILITY_ID, test_id))

def enter_app(driver):
    tap_id(driver, "lang-ko")
    tap_id(driver, "app-intro-skip")
    tap_id(driver, "age-gate-check")
    tap_id(driver, "age-gate-continue")
    tap_id(driver, "permissions-browse-guest")
    must_see(driver, "tab-home")          # 🔴 여기서 실패하면 그 뒤는 볼 필요가 없다
```

> **`ACCESSIBILITY_ID` 로 찾는다.** React Native 의 `testID` 는 iOS 에서
> accessibility identifier 로 나간다.

### 시나리오를 어떻게 자동화에 나누는가

**자동화가 대신할 수 있는 것은 「돌아다니기」뿐이다.** 크래시 0건을 세는 데는
그것으로 충분하다 — 그게 `S15P21E201-250` 의 완료 기준이다.

| # | 자동화로 | 사람 눈이 필요한가 |
|---|---|---|
| 1 첫 실행 | `enter_app()` | 사진·글자 잘림 |
| 2 회원가입 | 화면 진입까지 | **메일이 앱으로 돌아오는가** |
| 3 구글 로그인 | 화면 진입까지 | **테스터 목록 밖 계정** (4-2 ①) |
| 4 여행 만들기 | `tab-schedule` → 4단계 | 결과가 말이 되는가 |
| 5 일정 열람 | `tab-map` → 여행 → 일차 전환 | 시각·이동 시간 (4-2 ②) |
| 6 여행 지도 | 지도 보기 진입 | **지도가 그려지는가** (4-2 ②) |
| 7 현장 도구 | 홈 → 현장 도구 | **소리가 나는가** |
| 8 기록 작성 | `tab-feed` → 작성 | **사진이 올라가는가** (4-2 ④) |
| 9 내 여행·부슐랭 | `tab-map` → 부슐랭 | **이름 고치기 반영** (4-2 ③) |
| 10 설정·약관 | `tab-me` → 약관 | 열리는가 |

**오른쪽 칸은 자동화로 판정하지 않는다.** 소리·사진·지도 타일은 요소가 있다고 해서
동작한 것이 아니다. 자동화는 **거기까지 데려다주는 일**만 하고, 판정은 화면 캡처와
사람이 한다.

### 크래시를 세는 법

```python
before = driver.query_app_state("com.gabolle.app")   # 4 = 앞에서 돌고 있음
... 시나리오 ...
after  = driver.query_app_state("com.gabolle.app")
assert after == 4, "앱이 꺼졌다 — 크래시"
```

안드로이드 쪽은 프로세스 번호가 안 바뀌는 것으로 셌다. iOS 는 위 `query_app_state`
가 같은 역할을 한다. **로그가 아니라 이 값으로 판정한다.**

## 5. 🔴 뒷정리 — 빌린 기계에서 반드시 한다

끝나면 **순서대로** 한다. 하나라도 빼먹으면 남의 기계에 내 기기 기록이 남는다.

1. **기기 페어링 해제**
   ```
   Finder → 사이드바에서 아이폰 우클릭 → "○○의 iPhone 제거"
   ```
   또는 아이폰에서: `설정 → 일반 → 전송 또는 iPhone 재설정 → 재설정 → 위치 및
   개인 정보 보호 재설정` (모든 컴퓨터의 신뢰가 해제된다)

2. **로그·녹화 파일 회수** — 맥북에 저장한 것을 전부 내 저장소로 옮기고 **원본을 지운다**
   (휴지통도 비운다). QuickTime 녹화는 기본 저장 위치가 `~/Movies` 다

3. **Console.app 저장본 확인** — `File → Save a Copy As…` 로 저장한 것이 있으면 지운다

4. **Apple ID 를 넣었다면 로그아웃** — 0절이 말한 대로 애초에 안 넣는 것이 최선이다

5. **3절의 도구를 깔았다면** — `xcode-select --install` 로 깐 것은 되돌리기 어렵다.
   그래서 0절이 「이미 깔려 있을 때만 쓰라」고 적어 두었다

## 8. 이 문서가 확인하지 못한 것

**나는 맥북에서 이 절차를 직접 돌려 보지 않았다.** 윈도우 PC 에서 작성했고,
iOS 기기를 조작할 수단이 없었다(2026-09-17 실측: `idevice_*`·`ios-deploy` 없음,
`pymobiledevice3` 는 Python 3.14 의존성 문제로 설치 실패).

그래서 아래는 **확인 못 한 것**으로 남긴다 — 실제로 해 보고 다르면 이 문서를 고쳐 주기 바란다.

* macOS 버전에 따라 **메뉴 경로가 다를 수 있다**(특히 Finder 의 기기 제거, Console 의 Devices)
* iOS 26 에서 `분석 데이터` 목록의 항목 이름 형식
* `xcrun devicectl` 의 정확한 하위 명령 이름 (Xcode 판마다 바뀐 이력이 있다)

**확실한 것은 하나다** — QuickTime 화면 녹화와 아이폰의 `분석 데이터` 목록만으로도
`S15P21E201-250` 의 완료 기준(시나리오별 결과 표 + 크래시 0건)은 채울 수 있다.
설치가 막히면 그 둘로 간다.
