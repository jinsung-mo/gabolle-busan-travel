# 04 — 오늘 순서 (2026-09-14)

앞 세 장이 "무엇이 막혀 있나" 였다면 이 장은 **"그래서 어느 순서로 푸나"** 다.
단계마다 **성공 기준**을 먼저 적는다. 재는 방법이 없는 단계는 넣지 않았다.

---

## 🔴 0단계 — 시험용 계정 하나. 이게 오늘의 열쇠다

**왜 첫 번째인가.** 지금 "안 된다" 고 적힌 것의 **대부분이 「확인 못 함」 이다.**
추천도 지도도 로그인 뒤에 있어서 아무도 눈으로 못 봤다. 계정 하나면 **둘이 한꺼번에
풀린다.** 이걸 건너뛰고 코드를 고치면 **없는 병을 고치게 된다.**

| | |
|---|---|
| 하는 일 | 시험용 계정 하나로 로그인 → 온보딩 취향 답 → 여행 만들기 → 추천 받기 → 지도 화면 열기 |
| 성공 기준 | **추천이 몇 건 나오는지 숫자를 본다.** 지도가 그려지는지 눈으로 본다 |
| 걸리는 시간 | 30분 |
| 막는 것 | 없음 |

이 단계가 끝나면 아래 표의 물음표가 사실로 바뀐다.

| 지금 | 0단계 뒤 |
|---|---|
| 추천이 뜨나? — 확인 못 함 | 몇 건인지 안다 |
| 웹 지도가 그려지나? — 확인 못 함 | 안다 |
| 갈래를 바꾸면 결과가 달라지나? — 확인 못 함 | 안다 |

---

## 1단계 — 오늘 재고를 잰다 (5분)

어제 숫자는 있는데(01 장) **오늘 값이 없다.** 운영 DB 읽기가 도구 권한에 막혀 있어
사람이 한 번 돌려야 한다.

```bash
ssh -i <이 PC 의 pem> ubuntu@j15e201.p.ssafy.io \
  "docker exec local-route-personalization-postgres-1 psql -U app_user -d app_db \
   -c \"SELECT feature_key, count(*) FROM gabolle.place_feature \
        WHERE feature_type='CATEGORY_TAG' GROUP BY 1 ORDER BY 2 DESC;\""
```

| | |
|---|---|
| 성공 기준 | 갈래 여섯의 오늘 행 수가 나온다 |
| 왜 필요한가 | 2단계의 판단이 이 숫자에 달려 있다 |

---

## 2단계 — 「고를 수는 있는데 줄 게 없는」 갈래를 막는다

어제 기준 **바다 2곳 · 자연 23곳 · 카페 26곳**이다. 온보딩에서 이걸 고른 사람은
「맞는 장소 없음」을 본다. **코드 버그가 아니라 재고 부족이다.**

길이 둘 있고, 오늘 할 수 있는 것은 앞의 것이다.

| | 무엇 | 오늘 되나 |
|---|---|---|
| 가 | **줄 게 없는 갈래를 화면에서 못 고르게 한다** — 서버에 이미 갈래 목록 API 가 있다 | ✅ |
| 나 | 장소를 더 넣는다 (적재기를 돌린다) | ⚠️ 입력 파일이 다른 갈래에 있어 찾아야 함 |

| | |
|---|---|
| 성공 기준 | 재고가 적은 갈래가 온보딩 화면에 안 뜬다. 고른 갈래로는 **추천이 1건 이상** 나온다 |

> 🔴 **이건 증상 가리기다.** 근본 해결은 「나」다. 다만 오늘 앱을 돌아가게 하는 것이
> 목적이라면 「가」가 맞는 순서다. **가린다는 사실을 티켓에 적어 둔다.**

---

## 3단계 — 피드는 코드가 아니라 팀에 묻는다

되살리는 것은 **두 줄**이다. 그런데 그 두 줄은 **어제 팀이 내린 제품 결정을 뒤집는다**
(02 장). 먼저 정할 것 둘.

1. 어제 걱정한 "기능 오류" 가 무엇이었나 — **아무 데도 안 적혀 있다.** 뺀 사람에게 묻는다
2. 로그인 안 한 사람에게 피드를 보여줄 것인가 — 지금 설계와 설정이 어긋나 있다

| | |
|---|---|
| 성공 기준 | 되살릴지 말지가 **정해진다**. 되살리기로 했으면 탭에 피드가 보이고 글 목록이 뜬다 |
| 막는 것 | 🔴 **사람의 결정.** 코드는 준비돼 있다 |

---

## 4단계 — 지도는 웹부터 판정하고, 폰은 따로 뗀다

| | 오늘 | |
|---|---|---|
| 웹 지도 | **0단계에서 이미 판정된다.** 보이면 끝 | 새로 만들 것 없음 |
| 폰 지도 | 오늘 시작하기엔 큼 | 웹뷰 방식 · 키의 주소 검사 함정 (03 장) |
| 3D | 건드릴 것 없음 | 앱 밖의 별도 페이지 |

## 🔴 이 순서가 이렇게 생긴 이유

**모르는 것을 줄이는 단계를 앞에 두었다.** 0·1단계는 고치는 게 하나도 없는데 제일
앞에 있다. 지금 목록의 절반이 「확인 못 함」이라서, 안 재고 고치면 **고친 것이
맞는지도 알 수 없다.**

2·3·4단계는 **서로를 안 막는다.** 0·1만 끝나면 셋은 동시에 갈 수 있다.
