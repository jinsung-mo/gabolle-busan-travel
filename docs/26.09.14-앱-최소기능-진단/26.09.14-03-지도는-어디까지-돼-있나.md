# 03 — 지도는 어디까지 돼 있나 (2026-09-14 실측)

원본: `원본/26.09.14-원본-02-서버-보안헤더-실측.md`

---

## 0. 한 문장

**이미 카카오다. 3D 는 앱 밖에 있다. 빈자리는 「휴대폰에 지도가 없다」 하나다.**

---

## 1. 지금 들어 있는 것

지도 컴포넌트는 **하나뿐**이고 모든 화면이 그것을 공유한다 — 여행 동선(발표 핵심
화면) · 경로 상세 · 기념품샵 핀 · 출발 전 장소 핀 · 일정 만들기 미리보기.

그 하나가 **카카오 지도 스크립트를 직접 불러서** 그린다. npm 꾸러미가 아니라
`<script>` 를 페이지에 꽂는 방식이다.

서버도 이미 카카오를 쓴다.

| | 쓰는 것 | 비고 |
|---|---|---|
| 자동차 경로 | 카카오모빌리티 | |
| 출발지 검색 | 카카오 로컬 | |
| **대중교통·도보 경로** | ❌ | **카카오가 API 를 공개하지 않는다.** 코드가 직접 밝혀 놓았다 |

키가 없으면 죽지 않고 **직선거리 추정으로 대체**하도록 설계돼 있다.

---

## 2. 🔴 3D 부산은 앱 안에 없다

`city3d-spike` 는 **따로 배포되는 웹페이지 한 장**이다. 앱은 그 주소를 브라우저 탭으로
열어 줄 뿐이고, 앱 용량에 3D 엔진이 들어가지 않는다. 코드 주석이 그 원칙을 적어 두었다 —
*"앱 안에 3D 엔진을 넣지 않는다."*

페이지 제목 자체가 **"부산 3D — 사양 판정 실험"** 이다. 팀이 스스로 실험이라고 이름
붙였고, 빌드·배포 자동화도 아직 없다(그 자리는 빈 자리표시자다).

> **그래서 "3D 말고 카카오로 바꾸자" 는 작업이 존재하지 않는다.** 둘은 경쟁 관계가 아니다.

---

## 3. 🔴 진짜 빈자리 — 휴대폰에는 지도가 없다

| | 웹으로 열었을 때 | 휴대폰 앱 |
|---|---|---|
| 지도 | ✅ 그려진다 | 🔴 **없다** |
| 그 자리에 나오는 것 | — | *"앱 지도 연동을 준비하고 있어요"* 라는 글자와 방문 순서 목록 |

**고장난 게 아니라 안 만들어진 것이다.** 코드가 스스로 그렇게 밝힌다.
"지도가 안 된다" 고 느끼는 실체가 이것일 가능성이 크다.

---

## 4. 웹 지도를 막던 원인은 풀려 있다

예전에 안 떴던 진짜 원인은 **서버가 카카오 스크립트를 차단하던 것**이었고 9/10 밤에
고쳤다는 기록이 있다. 오늘 서버 응답을 직접 확인해 보니 그 설정이 살아 있다
(원본 02). 배포된 앱 안에 키도 빈 값이 아닌 채로 들어 있다.

🔴 **다만 눈으로 확인은 못 했다.** 지도 화면이 로그인 뒤에 있고 시험용 계정이 없었다.
카카오 콘솔의 등록 도메인과 키 유효 여부도 **확인 못 함**.

---

## 5. 휴대폰에 지도를 넣는다면

웹뷰(**앱 안에 작은 브라우저 창을 띄우고 거기에 웹페이지를 그리는 것**) 방식이
이 저장소 구조에 맞다. 이유 셋:

1. 카카오 지도를 그리는 로직이 **이미 웹 기준으로 완성돼 있다.** 다시 안 짜도 된다
2. 3D 페이지를 브라우저로 여는 지금 방식과 **같은 철학**이다
3. 네이티브 방식은 카카오가 이 앱 틀에 맞는 공식 SDK 를 내놓지 않았고, 넣으려면
   지금 없는 네이티브 빌드 파이프라인을 새로 만들어야 한다

🔴 **함정 하나.** 카카오 지도 키는 **"어느 주소에서 불렀는가" 를 검사한다.**
앱 안에 HTML 파일을 넣고 띄우면 그 검사를 통과 못 할 공산이 크다. 안전한 길은
**이미 등록된 서버 주소의 페이지를 웹뷰가 불러오게** 하는 것이다.

> 이 판단은 구조에 근거한 권고이고 **실제로 재 본 사람이 없다 — 확인 못 함.**
