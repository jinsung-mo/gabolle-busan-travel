### 커밋 표를 여기서 뺐다

전에 이 자리에는 `chore/axmap-bootstrap` 브랜치의 커밋 목록이 있었다. **그 목록은
지금 브랜치의 이력이 아니다.** `chore/S15P21E201-15-axmap-split` 은 `origin/main`
위에서 새로 시작했고, axMap 을 걷어내고 사본으로 대체하는 변경 하나로 다시 올린다.

커밋 해시를 문서에 적으면 브랜치를 새로 딸 때마다 그 줄이 낡는다.
**이력은 `git log` 가 언제나 정확하다.** 여기에는 *무엇을 정했는가* 만 적는다.

### 2.1 axMap 은 이제 별도 저장소다 (2026-08-26)

**이것이 이번 인수인계에서 제일 중요한 한 가지다.**

| | |
|---|---|
| axMap 본체 | `https://lab.ssafy.com/rleaderjoon/axmap` — CLI · MCP 서버 · 뷰어 · 데스크톱 셸 · 코퍼스 실험 장비 · `docs/`(SPEC · DECISIONS · THREADS · INVARIANTS · BENCH · CLUSTER · VERSIONING · GOVERNANCE · bench-runs) 전부 |
| 팀 저장소에 남은 것 | `ci/axmap/` — 팀 CI 와 선점이 **실제로 부르는 파일만** 골라 복사한 사본 |
| 팀 저장소에 남긴 데이터 | `governance/policy.json` — 도구는 나가고 데이터는 남는다 |
| 어느 커밋의 사본인가 | `ci/axmap/SOURCE.json` |

**벤더링**(vendoring — 남의 코드를 내 저장소 안에 복사해 두고 그 사본으로 돌리는 것)
으로 둔 이유는 하나다. CI 가 돌 때마다 axMap 을 내려받게 만들면, axMap 이 잠깐
깨지거나 접근 권한이 만료된 날 **팀 코드는 한 줄도 안 바뀌었는데 팀 파이프라인이
빨개진다.** 사본은 그 연결을 끊는다.

#### 사본을 갱신하는 법 — 여기서 직접 고치지 않는다

```bash
# 1. axMap 저장소에서 고치고 커밋한다
# 2. 거기서 이 명령을 돌린다
node tools/vendor.mjs --to <이 저장소의 루트>
# 3. 여기 생긴 변경(사본 + manifest.sha256 + SOURCE.json)을 MR 로 올린다
```

> 🔴 **`ci/axmap/` 아래를 손으로 고치면 `ci:vendor` 잡이 빨개진다.**
> `manifest.sha256`(파일마다의 지문 목록)과 실제 파일을 대조하기 때문이다.
> 이걸 모르면 다음 사람이 사본을 고쳐 놓고 파이프라인이 왜 빨간지 못 찾는다.

> **막지는 못한다.** manifest 까지 다시 만들면 통과한다. 다만 그때는 `SOURCE.json` 과
> `manifest.sha256` 이 diff 에 떠서 리뷰어가 *"업스트림 커밋은 그대로인데 사본만
> 바뀌었다"* 를 본다. 거버넌스 층과 같은 태도다 — 강제 장치가 아니라 **부인 불가능성
> 장치**다.

#### 사본에 안 들어온 것 — 실제로 물린다

벤더 도구는 **CI 진입점에서 import 로 닿는 파일만** 따라간다. 자식 프로세스로
경로를 찍어 부르는 것은 못 따라간다. 2026-08-26 실측으로 둘이 빠졌다.

| 빠진 것 | 증상 |
|---|---|
| `tools/bus.mjs` (에이전트 쪽지함) | MCP 도구 `ax_inbox` · `ax_send` 가 "파일을 찾을 수 없다" 로 죽는다. `ci/axmap/mcp/server.mjs` 가 `SELF/tools/bus.mjs` 를 자식 프로세스로 띄우는데 그 파일이 없다 |
| `tools/mcp-register.mjs` (다른 AI CLI 에 MCP 등록) | `setup.sh` 5단계가 `!!` 경고로 끝난다. Codex · Antigravity 사용자가 손으로 넣어야 한다 |

**둘 다 axMap 저장소에서 벤더 목록에 넣고 다시 돌리면 풀린다.** 4.6절에 남겼다.

#### 개인 저장소의 옛 이력

2026-08-26 오전에 개인 저장소(`rleaderjoon/blastmap`)를 팀 저장소 안으로 한 번 접었다가,
같은 날 오후에 axMap 을 다시 `rleaderjoon/axmap` 으로 분리했다. **접었던 것을 되돌린
것이 아니라, 팀 저장소가 axMap 을 품지 않는 쪽으로 방향을 바꾼 것이다.**

옮기지 않은 것은 **반환된 AWS 의 죽은 절차**뿐이다 — `PUBLIC.md` ·
`run-worker.sh` · `serve-public.mjs`, 그리고 `SSOT.md` 의 "운영 — 배포와
재시작" 절. `SSOT.md` 의 나머지(코퍼스 원칙)는 axMap 저장소에 있다.

`blastmap` 저장소는 GitLab 에 그대로 남아 있다.

### 검증 — 끝내기 전에 전부 통과해야 한다

## 3. 🔴 다음 사람이 반드시 밟는 함정

여기 적힌 것은 전부 **실제로 한 번씩 밟은 것**이다.

### ① 커밋할 때 `AXMAP_AGENT` 를 안 넘기면 훅이 막는다

```bash
AXMAP_AGENT=<내이름> git commit -m "..."      # ← 이렇게
```

claim 은 `AXMAP_AGENT=X` 로 해 놓고 커밋을 그 변수 없는 셸에서 하면, 이름이
`git config user.name` 으로 떨어져 **훅이 당신을 다른 사람으로 본다.**

### ② 🔴 분리 뒤 커밋 훅이 죽은 경로를 가리킨다 — 2026-08-26 실측

**분리 전에 `setup` 을 돌린 PC 는 전부 이 상태다.** 훅은 절대 경로를 박아 두는데,
그 경로가 옛 `axmap/bin/axmap.mjs` 라 이제 없다.

```
!!  커밋 훅   가리키는 파일이 없습니다: .../axMap/axmap/bin/axmap.mjs
```

`doctor` 가 이 줄을 내고 **종료 코드 1로 끝난다.** 고치는 것은 한 줄이다.

```bash
node ci/axmap/bin/axmap.mjs hook install
```

**안 고치면 선점 강제가 이 PC 에서 사라진다** — 훅이 못 도니 claim 없이 고친 파일도
그냥 커밋된다. CI 의 `claims` 잡이 나중에 잡아내지만, 그때는 이미 MR 이 빨간 상태다.

### ③ 절대 경로가 폴더 이름에 묶여 있다

폴더 이름이 바뀌면 조용히 깨진다 — **오류창이 안 뜬다.**

| 무엇 | 어디 | 증상 |
|---|---|---|
| pre-commit 훅 | `.git/hooks/pre-commit` | 모든 커밋이 알 수 없는 이유로 거부 |
| 전역 MCP 등록 | `~/.gemini/config/mcp_config.json` | CLI 도구 목록에서 axmap 이 사라진다 |

훅은 위 ②의 명령으로 다시 심으면 된다. 전역 MCP 등록은 손으로 고친다 —
등록 도구가 axMap 과 함께 나갔다 (2.1 "사본에 안 들어온 것").

Claude Code 는 저장소 안 `.mcp.json` 을 **상대 경로**로 읽어서 안 깨진다.

> 바탕화면 바로가기(`axMap 실행.lnk`)와 `Desktop\axmap-migrate.ps1` 은 axMap 의
> 데스크톱 셸에 딸린 것이라 **이 저장소의 관심사가 아니게 됐다.** axMap 저장소 쪽 문제다.

### ④ `setup.ps1` 의 UTF-8 BOM 을 지우면 안 된다

Windows PowerShell 5.1 은 BOM 없는 스크립트를 CP949 로 읽고, 한글 뒤의 따옴표를
삼켜 **파일 전체가 문법 오류**가 된다. 그리고 오류가 **고친 줄과 무관한 줄 번호**에
뜬다. 파일 머리말에 이유를 적어 뒀다.

### ⑤ 단위 테스트가 초록이어도 화면은 죽어 있을 수 있다

단위 테스트는 브라우저 코드를 실행하지 않는다. 실제로 하룻밤에 두 번 겪었다 —
주석 안의 `*/` 가 파일을 닫았고, `let` 선언이 첫 사용처보다 아래에 있어 부트스트랩이
통째로 죽었다. **둘 다 문법 검사와 단위 테스트를 전부 통과했다.**

지금은 이 저장소에 화면이 없지만, **`frontend/` 가 붙는 순간 같은 함정이 돌아온다.**
화면을 만드는 파트는 화면이 실제로 뜨는지 보는 잡을 따로 가져야 한다.

### ⑥ 데모가 초록이어도 안심하지 않는다

### 4.5 MCP 를 다른 사람·다른 제품에 붙이는 일

**한 것 (2026-08-26).** MCP 가 겨누는 저장소를 **도구를 부를 때마다 다시 정한다.**
근거와 버린 대안은 **MCP 가 어느 저장소를 겨누는지를 요청마다 다시 정하기로 한 결정**
(axMap 저장소 `docs/DECISIONS.md` 의 `D19`)에 있다.

- `FE/` 같은 **하위 폴더에서 CLI 를 켜도 저장소 루트**를 겨눈다 (전에는 그 하위 폴더를
  겨눠서 팀원과 다른 장부를 봤다)
- 앱에서 [폴더 열기] 로 고른 저장소를 **따라간다** — `~/.axmap/current.json` 을 앱이 쓰고
  MCP 가 읽는다. **사람에게는 아무것도 묻지 않는다**
- 대상이 바뀌면 **떠나는 저장소의 claim 을 전부 반납한다.** 안 하면 그 잠금을 풀 창구가
  사라져 TTL(45분)까지 팀원이 막힌다

| 결정할 것 | 지금 상태 |
|---|---|
| **MCP `roots` 를 구현할까** | 안 했다. 버린 것이 아니라 **아직 안 만든 것**이다. `roots` 는 클라이언트가 서버에게 *"지금 열려 있는 폴더는 여기"* 를 알려주는 **MCP 규격의 표준 통로**이고, 넣으면 우리 앱 없이 AI CLI 만 써도 따라간다. 위 `D19` 사다리의 두 번째 칸 |
| **`ax_init` 에 안전장치를 넣을까** | 전역 등록(**절대경로로 이 PC 의 모든 폴더에서 뜨게 하는 것**)을 하면 **팀 저장소가 아닌 폴더에서도 MCP 가 뜬다.** 장부가 없으니 claim 이 실패하고, 에이전트가 `ax_init` 을 불러 **남의 저장소에 장부를 만든다.** 원격이 팀 저장소가 아니면 `confirm` 없이는 거부하는 안이 후보 |

npm 이 설치하지 못한다"* 가 근거였는데, **axMap 이 저장소 루트를 갖게 된 지금 그 근거는
