## 1. 🔴 출시 차단

### ~~B-01 — 약관·고지에 들어가면 앱 안에서는 빠져나올 수 없다~~ → 🔴 **취소 (2026-09-22)**

> **이 항목은 오판이었다.** build 41 에서 다시 재니 **우측 상단 「내리기」 버튼이
> 정상적으로 닫는다.** `내리기` 라벨을 가진 요소가 셋(배경 덮개·iOS 손잡이·실제 버튼)이고
> 자동화가 **전체 화면 덮개**를 집었던 것이다. 아래 근거 중 「저장소에 `내리기` 문자열이
> 없다」도 틀렸다 — `tx('내리기','Close')` 로 감싸여 평문 grep 에 안 걸렸을 뿐이다.
> 경위는 [../qa-ios-build41/README.md](../qa-ios-build41/README.md) 8 절에 적었다.
>
> 아래 원문은 **기록으로 남긴다.**

**무엇이 잘못됐나.** 마이페이지 › 설정 › 약관·고지 로 들어가면 **뒤로 갈 수단이 화면에 없다.**
탭바도 같이 사라져서 다른 탭으로도 못 간다. iOS 의 **왼쪽 가장자리 스와이프**를 아는
사람만 빠져나온다 — 그걸 모르면 앱을 강제 종료해야 한다.

**재현 (100%, 3회 모두 재현)**

```
마이페이지 탭 → 「설정」 → 「약관·고지 ›」
  → 화면에 ‹ 뒤로가기 없음 · 하단 탭바 없음
```

**증거.** 접근성 트리에 뒤로가기가 **하나도 없다.** `screenshots/52-terms.png`

```
모달 화면의 Button 전체:
  프로필 편집 / 기록 보기 / 팔로워 보기 / 팔로잉 보기 / 저장한 기록 /
  여행 취향 / 연결된 소셜 계정 / 회원 탈퇴 / 알림 / 차단된 계정 /
  도움말·문의 / 약관·고지 / 로그아웃      ← 전부 뒤쪽 설정 화면의 것
  내리기 · 내리기 · 내리기                  ← iOS 시스템 grabber (앱 버튼 아님)

'뒤로' · '‹' · 'Go back' 으로 검색한 결과: 0건
```

🔴 **「내리기」는 앱이 만든 버튼이 아니다.** 저장소 전체에 `내리기` 문자열이 없다
(`grep -rn "내리기" src/ app/` → 0건). iOS 가 시트에 자동으로 붙이는 손잡이이고,
**눌러도 닫히지 않는다**(실측). 자동화가 버튼으로 읽을 뿐이다.

**원인으로 의심되는 자리.** `src/me/MyPageShell.tsx:128-140` 의 폰 분기에는 `‹` 뒤로가기가 있다.

```tsx
if (!desktop) {
  return (
    <Screen scroll>
      <Pressable accessibilityLabel={tx('뒤로 가기', 'Go back')}
        onPress={() => (router.canGoBack() ? router.back() : router.replace('/me'))}
        style={...}><Text variant="title">‹</Text></Pressable>
```

폭 402pt 인 iPhone 16 Pro 는 `isAtLeast(width,'lg')`(lg=1439)가 **false** 라 이 분기를
타야 하고, 그러면 `‹` 가 나와야 한다. **그런데 실기기 트리에 없다.** 왜 안 그려지는지는
이 QA 에서 특정하지 못했다 — 같은 `MyPageShell` 을 쓰는 **도움말·문의는 뒤로가기가 정상
동작**했으므로(3절), 약관·고지 경로만의 문제로 좁혀진다.

**왜 심각한가.** 약관·개인정보처리방침은 심사에서 반드시 열어 보는 화면이다.
심사자가 여기서 갇히면 그 자체로 리젝 사유가 된다.

### B-09 — 가로모드에서 탭바가 화면 한가운데 떠서 내용을 가린다

**무엇이 잘못됐나.** 기기를 가로로 돌리면 하단에 고정돼야 할 탭바가 **콘텐츠 위에 떠서**
그 아래 글자를 가린다. **확인한 모든 탭에서 같다.**

**재현 (100%)**

```
아무 화면에서나 기기를 가로로 돌린다 (402×874 → 874×402)
```

| 화면 | 무엇이 가려지나 |
|---|---|
| 홈 | 체크리스트 「첫 기록 남기기」의 설명 「한 줄이면 돼요」가 탭바에 잘림 |
| 마이페이지 | 이메일이 `ssafy0121+livetest0907@gma…` 로 잘리고 「팔로잉」 칩이 통째로 가려짐 |

`screenshots/A2-home-landscape.png` · `screenshots/A3-tab-me-landscape.png`

**짚어 둘 것.** 회전 자체는 정상이다 — 요소 수가 176개로 같고 탭바도 5개 그대로이며
크래시도 없다. **배치만 틀렸다.** 세로에서는 멀쩡하다.

`app.json` 의 `"orientation": "default"` 라서 가로가 허용된다. 가로를 지원할 생각이
없다면 `"portrait"` 로 잠그는 것이 가장 싼 수습이고, 지원한다면 탭바를 세이프에어리어
하단에 붙이고 콘텐츠에 그만큼 `paddingBottom` 을 줘야 한다.

## 2. 🟠 접근성

### B-02 — 화면의 모든 글자가 접근성 트리에 두 번 들어간다

VoiceOver 사용자는 **모든 문장을 두 번** 듣는다. 확인한 **모든 화면**에서 나타난다.

```
[StaticText] '현지인이 다니는 부산으로,\n취향과 이동 조건에 맞춰 떠나요.'
[StaticText] '현지인이 다니는 부산으로,\n취향과 이동 조건에 맞춰 떠나요.'   ← 같은 글자 두 번
[StaticText] '2026년 9월'
[StaticText] '2026년 9월'
```

`src/components/Text.tsx` 가 바깥 `View` 와 안쪽 `Text` **양쪽에** 접근성 요소를 남기는
구조로 보인다. 바깥을 `accessible={false}` 로 두거나 안쪽을 `importantForAccessibility="no"`
로 두면 한 번만 읽힌다. 눈으로 보는 화면은 멀쩡해서 **스크린샷으로는 안 보이는 결함**이다.

### B-03 — 「맞춤 추천」 스위치에 이름이 없다

마이페이지 › 설정 맨 아래. VoiceOver 가 **"스위치"** 라고만 읽는다 — 무엇을 켜고 끄는
스위치인지 알 수 없다. 개인정보 동의 스위치라 더 중요하다.

```
[StaticText] '맞춤 추천'
[StaticText] '저장·제외·일정 수정·체크인 후기 같은 활동을 바탕으로 …'
[Switch]     ''          ← 🔴 label 이 비어 있다
```

**원인.** `app/(tabs)/me.tsx:141`

```tsx
<Toggle value={behaviorPersonalization} onValueChange={setBehaviorPersonalization} />
```

글자는 형제 `View` 에 있어서 스위치와 묶이지 않는다. `accessibilityLabel={tx('맞춤 추천','Personalized picks')}`
를 주면 된다. `screenshots/44-me-settings.png`

### B-04 — `place-photo-credit` 이라는 개발용 이름이 소리로 읽힌다

장소 상세에서 접근성 트리에 **`place-photo-credit`** 이라는 글자 요소가 실제 출처 문구와
**따로** 들어 있다. VoiceOver 가 영어 알파벳 그대로 읽는다. 화면에는 안 보인다.

```
[StaticText] 'place-photo-credit'                        ← 🔴 개발용 testID 가 글자로
[StaticText] '사진 제공: 한국관광공사 공공누리 제3유형'      ← 실제 보여줄 내용
```

`app/place/[id].tsx:158` 의 `testID="place-photo-credit"` 가 iOS 에서 별도 텍스트 노드로
새어 나온다. `screenshots/40-place-detail.png`

### B-19 — 챗봇에서 말한 조건이 「새 여행 만들기」로 전달되지 않는다

AI 챗봇에 **「해운대와 광안리 2명 맛집 일정 짜줘」**라고 하면 답변과 함께
**「새 여행 만들기」** 단추가 붙는다. 눌러 보면 여행 만들기 화면으로 가기는 **간다.**
**그런데 말한 조건이 하나도 안 들어가 있다.**

| 챗봇에 말한 것 | 일정 화면 상태 |
|---|---|
| 해운대·광안리 | 지역 선택지 **6개 전부 그대로**(해운대·광안리·남포동·서면·영도·송정) — 고른 것이 아니라 **기본 목록**이다 |
| 2명 | 인원 표시 없음 |
| 맛집 | 반영 없음 |
| — | 출발지가 **「출발지를 골라야 일정을 만들 수 있어요」** · 「필수 1 / 3」 |

즉 **빈 화면으로 이동할 뿐**이다. 사용자는 방금 말로 다 알려 줬는데 처음부터 다시 고른다.
챗봇 소개가 「**앱 기능을 실행하는** 부산 여행 도우미」라 기대가 더 크다.

화면 이동 자체는 되므로 치명적이진 않지만, **대화가 실행으로 이어지지 않는다**는 점에서
이 기능의 값어치를 많이 깎는다. `screenshots/W2-chat-action.png`

### B-12 — 여행 지도에서 「목록으로 돌아가기」가 축척·Kakao 로고를 가린다

지도 좌하단에서 버튼이 **축척 표시(2km)와 Kakao 로고 위에 겹친다.** 지도 제공처 표기는
이용약관상 가려지면 안 되는 자리다. `screenshots/I1-map.png`

같은 화면에서 **마커 1과 4가 거의 포개져** 서로 구분이 어렵다 (광안리 일대에 장소가
몰려서 생긴 일이다). 지도 자체는 정상 렌더링된다 — 고유 색 35,312개, 타일·경로선·마커
모두 그려진다.

### B-13 — 여행이 시작도 안 했는데 「예정보다 8시간 47분 빠름」이라고 한다

여행 상세 상단에 **「지금 00:52 · 예정보다 8시간 47분 빠름」**이 뜬다. 첫 일정이
9.22 09:39 이고 현재가 00:52 이니 **계산은 정확하다**(검산함). 하지만 아직 시작도 안 한
여행을 「예정보다 빠름」이라고 하면 **진행 중인 것처럼 읽힌다.**
「9시간 뒤 시작」 쪽이 맞는 말이다. `screenshots/G2-trip.png`

### B-10 — 일정 생성 완료 화면의 제목과 부제가 서로 어긋난다

### ~~B-08 — 어디서도 들어갈 수 없는 화면 2개~~ → 🔴 **취소한다 (오판이었다)**

1차에서 `app/field/transit.tsx`(버스)·`app/field/exchange-rate.tsx`(환율)를
**「준비 중」 화면이고 유입 경로도 없다**고 적었다. **둘 다 틀렸다.**

**② 「준비 중」은 정상 화면이 아니라 오류 대체 화면이다.** 실제로 눌러 보니 둘 다 **산다.**

### B-18 — 일본어에서 「記録 を見る」처럼 조사 앞에 공백이 붙는다

일본어로 바꾸면 마이페이지 숫자 칸 라벨이 이렇게 읽힌다.

```
'記録 を見る'      ← 조사(を) 앞에 공백
'フォロワー を見る'
'フォロー中 を見る'
```

일본어는 어절을 띄우지 않으므로 **어색하다.** 사전(`src/i18n/translations.ts:114`)은
`利用規約を見る` 처럼 **공백 없이** 제대로 들어 있다 — 이 공백은 사전이 아니라
**iOS 가 자동 생성한 라벨**에서 나온다.

**중국어도 같다.** 간체 `查看 记录`·`查看 粉丝`, 번체 `查看 記錄`·`查看 粉絲` —
중국어도 어절을 띄우지 않으므로 똑같이 어색하다.

**원인.** `src/me/ProfileCard.tsx:74-86` 의 숫자 칸 `Pressable` 에 `accessibilityLabel` 이
없다. 그래서 iOS 가 자식 글자(`記録`)와 동작(`を見る`)을 **공백으로 이어 붙인다.**
B-03(맞춤 추천 스위치)과 **같은 뿌리**다 — 명시적 라벨을 주면 셋 다 없어진다.

### B-16 — 「맞춤 추천」 스위치 설명이 실제 동작과 어긋난다

스위치 옆 설명은 이렇게 적혀 있다.

> 저장·제외·일정 수정·체크인 후기 같은 활동을 바탕으로 **추천을 맞춰요.**

읽으면 «지금 끄고 켜면 추천이 달라진다»로 읽힌다. **실측해 보니 안 달라진다.**

개인화를 켠 뒤 **1차와 똑같은 조건**(부산역·9.22–9.23·해운대+광안리·예산 10만·대중교통)으로
다시 만들었더니 결과가 **완전히 같았다.**

| | 1차 (스위치 꺼짐) | 2차 (스위치 켬) |
|---|---|---|
| 첫 일정 | 09:39 민락어민활어직판장 | **09:39 민락어민활어직판장** |
| 마지막 일정 | 16:23 카운트다운 부산 | **16:23 카운트다운 부산** |
| 이동 합계 | 249분 (8구간) | **249분 (8구간)** |

**버그는 아니다.** 코드를 따라가 보면 이 동의값은 **가입·소셜 로그인 때만** 서버로 간다
(`src/auth/authApi.ts:60,117` — `signup` 과 OAuth 경로). 일정 추천 요청
(`src/api/tripApi.ts`)에는 개인화 필드가 **아예 실리지 않는다**(`grep` 결과 0건).
그러니 나중에 스위치를 만져도 그 세션의 추천이 바뀌지 않는 것이 **설계대로**다.

다만 사용자는 설명을 읽고 «바뀐다»고 기대한다. 문구를 실제 동작에 맞추거나,
바꾼 뒤 언제부터 반영되는지를 적어 주는 편이 정직하다.

### B-11 — 「저장」이 두 종류인데 이름으로는 구분되지 않는다

### 5-7. 5차 확인 — AI 챗봇 문답과 다국어
