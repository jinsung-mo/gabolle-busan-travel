# 03 — 「60」이라는 숫자의 근거를 따라갔다 (2026-09-16)

원본: `원본/26.09.16-원본-04-코드에서-그대로-옮긴-것.md`

---

## 한 줄

> **「갈래마다 60곳은 있어야 한다」고 두 번 전달받았는데, 코드의 60은 갈래당이 아니었다.**

틀린 근거가 **어떻게 돌았고 어떻게 잡혔는지**를 그대로 적는다. 이게 다음 사람에게 제일
쓸모 있다 — 숫자보다 경로가 중요하다.

---

## 1. 어떻게 돌았나

```
인수인계 문서          「갈래별 후보 … (추천 엔진 최소 60)」
   ↓ 그대로 옮김
조율 세션 → 데이터 세션  「목표선은 갈래당 60 이다」          (1회차)
   ↓ 그대로 옮김
조율 세션 → 데이터 세션  「갈래당 60 을 목표로」              (2회차)
   ↓
데이터 세션            갈래표를 설계하면서 코드를 열어 봄
   ↓
                     🔴 코드의 60은 갈래당이 아니다
```

아무도 거짓말하지 않았다. **한 문서의 표현이 그대로 복사되며 두 번 더 단단해졌을 뿐이다.**

## 2. 코드에 실제로 뭐라고 적혀 있나

```java
/**
 * 범위 안 후보가 이보다 적으면 출발지 기준으로 채운다.
 *
 * 하루에 네 곳씩 최대 이레를 배정하므로 스물여덟이 상한이고, 그 두 배쯤은 있어야
 * 갈래를 섞어 고를 수 있다. 정확한 근거가 있는 값은 아니고 운영을 보고 조정할 값이다.
 */
private static final int MIN_AREA_CANDIDATES = 60;
```

두 가지가 드러난다.

1. **「범위 안 후보」는 여행 범위(지역)다.** 갈래가 아니다. 이름부터 `AREA` 다
2. 🔴 **주석 스스로 「정확한 근거가 있는 값은 아니다」라고 적고 있다**

## 3. 무엇이 달라지나

| | 「갈래당 60」이라고 믿으면 | 실제 |
|---|---|---|
| 바다 32곳 | **실패다.** 엔진이 요구하는 수를 못 채웠다 | 60은 엔진 요구가 아니다. 32는 그냥 32다 |
| 목표를 정할 때 | 엔진이 시킨 것이라 **못 바꾼다** | 우리가 정하는 것이라 **바꿀 수 있다** |
| 문서에 적을 때 | 「엔진 최소치 미달」 | 「이 원천에서 뽑히는 상한이 32곳」 |

**60을 목표로 쓰는 것 자체는 괜찮다.** 다만 **「엔진이 요구한다」고 적으면 틀린 근거**가
되고, 그 틀린 근거로 다음 사람이 판단한다.

## 4. 어떻게 처리했나

- 갈래 판정표와 문서에 **「엔진 상수에서 빌려온 임시 눈금, 근거 없음」**이라고 함께 적었다
- 갈래마다의 목표를 **「이 원천에서 실제로 뽑히는 상한」**으로 바꿔 적었다
- 조율 세션에 알렸고, **틀리게 전달했다는 것을 그쪽이 받아들였다.** 티켓에 그 숫자를
  근거로 안 적어 둔 것이 다행이었다

## 5. 같은 일이 그날 두 번 더 있었다

**① 「2단계 분류로 충분해 보인다」** — 재지 않고 한 말이었다. 실제로는 걷는 길과 골프장이
한 칸에 섞여 있어 못 가른다.

**② 「1,350에서 쇼핑 980을 빼면 370」** — 멈추기 전에 쇼핑 145곳을 이미 받은 것을
안 본 계산이었다. 실제로는 560곳이다.

셋 다 같은 모양이다 — **코드나 파일을 안 보고 한 산수·추정이 그대로 다음 사람에게 전달됐다.**
그리고 셋 다 **실제로 세어 보는 것**으로 잡혔다.

## 6. 그림으로 그린다면

- **전달 경로 그림** — 문서 → 세션 → 세션으로 내려오며 「추정」이 「사실」이 되는 과정.
  마지막에 코드를 열어 되짚는 화살표
- 나란한 두 칸 — **「엔진이 요구한다」 대 「우리가 정한다」**. 같은 숫자인데 뜻이 다르다

## 7. 이 일에서 남는 규칙

> **기호와 숫자는 출처를 열어 보기 전까지 「그렇게 전달받았다」일 뿐이다.**

그리고 재지 않고 한 말은 **재지 않았다고 표시**한다. 조율 세션이 그날 이후로 그렇게 하기로
했다. 그것만으로도 다음 사람이 어디를 의심할지 알 수 있다.
