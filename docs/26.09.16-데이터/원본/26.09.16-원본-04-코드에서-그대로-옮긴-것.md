# 원본 04 — 코드에서 그대로 옮긴 것 (2026-09-16)

가공하지 않았다. 저장소의 파일에서 그대로 옮긴 것이다.

## 1. 「60」이라는 숫자가 실제로 무엇인가

`backend/src/main/java/com/gabolle/backend/recommendation/adapter/BaselineRecommendationEngine.java`

```java
/**
 * 범위 안 후보가 이보다 적으면 출발지 기준으로 채운다 — S15P21E201-980.
 *
 * <p>하루에 네 곳씩 최대 이레를 배정하므로 스물여덟이 상한이고, 그 두 배쯤은 있어야
 * 갈래를 섞어 고를 수 있다. 정확한 근거가 있는 값은 아니고 운영을 보고 조정할 값이다.
 */
private static final int MIN_AREA_CANDIDATES = 60;
```

**「범위 안 후보」** 는 여행 범위(지역)를 말한다. 갈래가 아니다.
그리고 주석 스스로 **「정확한 근거가 있는 값은 아니다」** 라고 적고 있다.

근거가 전부 `cat1`·`cat3`(옛 분류)와 `contenttypeid` 다. `lclsSystm` 은 안 쓴다.

같은 파일에 왜 이름으로 맞히지 않는지도 적혀 있다.

```
이름으로 맞히지 않는다. InterestTagCode 주석이 같은 것을 적어 뒀다 — "남포동 야시장"
이라는 이름에 야시장이 들어 있다는 이유로 갈래를 정하면 이름에 그 말이 없는 야시장은 영원히
안 나온다. 여기서 쓰는 것은 원천의 콘텐츠 유형(contenttypeid)과 분류 코드(cat1·cat3)뿐이다.
```

## 3. 행동 이벤트를 내보내는 쪽

`backend/src/main/java/com/gabolle/backend/event/infra/NoOpEventPublisher.java`

```java
/**
 * 아무것도 내보내지 않는 발행자 — M1·M2 용.
 *
 * <p>🔴 개발계획서 4.4 가 못 박았다 — "M1·M2 에서 Kafka·Spark 기동"은 하지 않는 일이고,
 * "그 전에는 PostgreSQL Outbox 테이블에 <b>쌓아만 둔다</b>".
 *
 * <p>{@link #isAvailable()} 이 {@code false} 라서 릴레이가 조용히 물러난다.
 * 그동안 이벤트는 {@code published_at = null} 로 계속 쌓인다.

 */
```

`EventPublisherPort` 를 구현한 클래스는 저장소 전체에서 이것 하나다.

## 4. 수집본 파일이 무시되면서 동시에 추적되는 것

```
$ git add bigData/data/raw/tourapi/tourapi-busan.ndjson
The following paths are ignored by one of your .gitignore files:
bigData/data
hint: Use -f if you really want to add them.

$ git check-ignore -v bigData/.env
bigData/.gitignore:9:.env	bigData/.env
```

`bigData/data` 는 `.gitignore` 에 있는데 그 안의 파일은 `git status` 에 `M` 으로 뜬다 —
예전에 누가 `-f` 로 넣어서 추적 중이기 때문이다. 둘 다 사실이다.
