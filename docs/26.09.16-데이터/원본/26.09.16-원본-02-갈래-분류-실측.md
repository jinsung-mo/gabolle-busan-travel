# 원본 02 — 갈래 분류 실측 (2026-09-16)

가공하지 않았다. 부른 명령과 돌아온 출력 그대로다.

---

## 1. 갈래마다 두 지역 필터로 세어 봤다 — 예상과 반대가 나왔다

기존 갈래 판정(`TourApiExploreFacet`)이 쓰는 근거 그대로 걸었다. 이름으로 맞히지 않았다.

```
갈래                        areaCode=6   lDongRegnCd=26     차이
TRADITIONAL_MARKET 전통시장          33             33        0
NATURE 자연                        23             23        0
ACTIVITY 액티비티                    28             28        0
FESTIVAL 축제                      14             71      +57
WALK 산책 (걷기길)                    10             10        0
NIGHT_VIEW 야경 (전망대)               5              5        0
```

축제만 늘고 나머지는 **똑같다.** 축제는 분류 코드가 아니라 `contentTypeId` 로 가른다.

## 2. 왜 같은지 확인했다

```
관광지(12) — lDongRegnCd=26 으로 351곳
  areacode 가 빈 것            216곳
  그중 cat1 도 빈 것           216곳
  areacode 가 있는 것 중 cat1 빈 것 0곳
  cat1 이 있는 것 전체          135곳  ← 갈래로 가를 수 있는 몫
  cat1 분포: A02:112 A01:23
  lclsSystm1 이 있는 것        351곳  ← 새 분류체계

쇼핑(38) — lDongRegnCd=26 으로 980곳
  areacode 가 빈 것            933곳
  그중 cat1 도 빈 것           933곳
  areacode 가 있는 것 중 cat1 빈 것 0곳
  cat1 이 있는 것 전체          47곳  ← 갈래로 가를 수 있는 몫
  cat1 분포: A04:47
  lclsSystm1 이 있는 것        980곳  ← 새 분류체계
```

`areacode` 가 빈 수와 `cat1` 이 빈 수가 **정확히 일치**한다. 216 = 216, 933 = 933.
