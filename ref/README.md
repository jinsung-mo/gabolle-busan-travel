# `ref/` — 팀의 참고 자료 자리

**여기에 올리는 것은 규칙 검사를 지나지 않는다.** 명세 초안, 화면 스케치, 회의 메모,
경쟁 서비스 캡처, 데이터 샘플 — 팀이 서로의 맥락을 맞추려고 올리는 것 전부.

## 왜 예외인가

이 저장소의 규칙(단계별 MR · 정족수 · 선점)은 **제품 코드**를 위해 있다.
같은 문을 참고 자료에도 세우면, 그 문이 지키는 것은 없고 **자료를 안 올리게 되는
효과**만 남는다. 안 올라온 맥락은 나중에 아무도 못 찾는다.

그래서 `ref/` 는 문 밖에 둔다.

## 무엇이 예외인가

| | `ref/` 만 바뀐 MR | 그 밖 |
|---|---|---|
| 정족수 (`governance`) | **안 돈다** | 돈다 |
| 선점 감사 (`claims`) | **안 돈다** | 돈다 |
| 사본 검사 (`ci:vendor`) | **안 돈다** | 돈다 |
| 단계 검사 (`verify:mr-target`) | 돈다 | 돈다 |

`verify:mr-target`(기능 브랜치는 `<파트>/dev` 로만)만 남긴 이유: 이건 **어느 브랜치로
올리는가**의 규칙이라 파일 종류와 무관하고, 지키는 비용이 0이다.

`ref/` 만 바뀌면 `ref:only` 잡 하나가 초록으로 끝난다. 잡이 하나도 안 돌면
파이프라인 자체가 안 만들어져서 **머지가 오히려 막히기 때문**에 일부러 남긴 것이다.

> 🔴 **한 MR 에 `ref/` 와 코드를 같이 담으면 예외가 사라진다.** 그때는 코드 쪽
> 규칙이 전부 적용된다 — 애매하면 닫는 쪽이 이 저장소의 기본값이다.
> 자료만 올릴 거면 자료만 담은 MR 을 따로 연다.

## 최상위 `main` 에 직접 push 는 여전히 안 된다

`main` 은 보호 브랜치이고 **누구도 직접 push 할 수 없다**(`Allowed to push: No one`).
그건 GitLab 설정이라 저장소 안의 파일로 바꿀 수 없다.

대신 `ref/` 만 담은 MR 은 **파이프라인이 즉시 초록**이라 열자마자 머지된다.
표를 기다릴 일도, 검사가 도는 것을 기다릴 일도 없다.

## 무엇을 여기 두지 않나

- **제품 코드** — `frontend/` · `backend/` 로
- **팀이 지키기로 한 규칙** — 규칙은 검사를 지나야 한다. `docs/` 로
- **비밀** — 토큰·비밀번호·개인정보. 저장소는 private 이지만 git 이력은 지워지지 않는다

## 자리 잡는 법

정하지 않았다. 날짜든 주제든 사람 이름이든 편한 대로 쓴다.
**폴더 규칙을 만드느라 자료를 안 올리는 것보다, 어수선하게라도 올라와 있는 편이 낫다.**
어수선해지면 그때 정리한다.
