부산 음식점 53,716곳에서 고른 **2,000곳**(`process/select-2000.mjs`)에,

조사원(사람이든 AI 든)이 이 대기열에서 몇 곳씩 잡아 가 **웹에서 무엇이라고 하는지**를 적는다.

## 0. 한 번에 읽는 요약

| | |
|---|---|
| 조사원이 하는 일 | **증거를 모은다.** 사람들이 왜 간다고 하는지, 어떤 곳이라고 하는지 |
| 🔴 조사원이 **안 하는** 일 | **판정.** *"맛집인가"* · *"몇 점인가"* · *"추천할 만한가"* 는 묻지도 답하지도 않는다 |

| 못 찾으면 | **"못 찾았다" 를 파일로 남긴다.** 빈칸과 "없다" 는 다르다 |

> 🔴 **왜 판정을 시키지 않나.**
> *"이 집 맛집이야?"* 를 물으면 답은 온다. 그럴듯하기까지 하다. 그런데 그건 **조사원의
> 취향**이지 우리 기준이 아니다. 한번 섞이면 **나중에 「우리 기준이 맞았나」 를 잴 수 없다** —
> 채점표와 답안지를 같은 쪽이 쓴 셈이 된다.

| ❌ 묻지 마라 | ✅ 물어라 |
|---|---|
| "맛집인가" · "몇 점" · "추천할 만한가" | 사람들이 **왜 간다고** 하나 |
| | **몇 년 됐다고** 하나 |
| | 줄이 긴가 · 주차가 어려운가 · 현지인이 가나 관광객이 가나 |

| ③ | 🔴 **원문 후기를 그대로 옮겨 적는다** | 남의 글이다. 우리가 남기는 것은 **요약한 속성**과 **출처 주소**뿐이다 |

**대신 남기는 것**: *"왜 갔다고 하나"* · *"어떤 곳이라고 하나"* 를 **요약한 속성**과,
되찾을 수 있게 **출처 주소**. 원문 문장은 안 남긴다.

## 2. 명령 넷

```bash
# 대기열을 만든다 (한 번)
node research/queue.mjs init

# 아직 아무도 안 잡은 10곳을 잡는다 — 조사원마다 다른 이름을 쓴다
node research/queue.mjs claim --worker haiku-1 --n 10

# 끝났다고 표시한다 (결과 파일이 있어야 받는다)
node research/queue.mjs done --worker haiku-1 --ids <id1>,<id2>,…

# 남은 것 · 진행 중 · 끝난 것
node research/queue.mjs status
```

`claim` 은 잡은 곳을 **한 줄에 하나씩 JSON 으로** 내보낸다. 조사원이 보는 칸은 이게 전부다:

```json
{"id":"MA…","name":"팁시펍","branch":null,"roadAddr":"부산광역시 수영구 남천바다로33번길 99",
 "gu":"수영구","hdong":"광안2동","category":"경양식","lon":129.11,"lat":35.15}
```

> 🔴 **일부러 안 주는 것이 둘 있다.**
> **① 어느 규칙으로 뽑혔나** · **② 인허가 개업일.**
> 개업일을 보여 주면 조사원이 근거 없이 *"오래된 집"* 이라고 적는다. **연차는 글에서
> 찾아야 하는 것이지 우리가 알려 줄 것이 아니다.** 두 값은 우리 파일에 그대로 있고,
> 나중에 `id` 로 이어 붙인다.

### 겹침을 어떻게 막나 — 셋

| | |
|---|---|
| **잠금**(lock — *한 번에 한 프로세스만 들어가는 문*) | `fs.openSync(…, "wx")` 는 파일이 이미 있으면 실패한다. 만들기와 검사가 운영체제 안에서 **한 동작**이라 둘이 동시에 성공할 수 없다 |
| **덧붙이기만 하는 기록**(append-only) | 상태를 덮어쓰지 않는다. `events.ndjson` 에 "누가 무엇을 잡았다/끝냈다" 를 한 줄씩 붙이고, 지금 상태는 그 줄을 다시 읽어 계산한다. 반쯤 쓰다 죽어도 앞 기록이 안 깨진다 |
| **시간 제한**(TTL — *잡은 것이 살아 있는 시간*) | 기본 **30분**. 그 안에 `done` 이 안 오면 그 자리는 대기열로 **되돌아온다.** 조사원이 죽어도 그 10곳이 영영 안 잡히는 일이 없다 |

시험: `node research/queue.mjs` 옆의 **`queue.test.mjs`** 가 프로세스를 **동시에** 띄워
겹침·찢어진 줄·시간 제한·거부 규칙을 검사한다. 판정은 종료 코드다.

```bash
node research/queue.test.mjs                                   # 조사원 3명
Q_ITEMS=1000 Q_WORKERS=8 Q_ROUNDS=12 node research/queue.test.mjs   # 더 세게
```

## 3. 조사 결과의 칸

한 가게에 파일 하나: `research/data/results/<id>.json`.
**세 갈래**로 나뉜다.

### ① 정량 — 🔴 조사원이 쓰지 않는다

영업 지속기간 · 인허가일자 · 폐업 여부 · 영업시간 · 좌표 · 업종 · 구·동.
**우리 데이터에 이미 있고**, 나중에 `id` 로 이어 붙인다.
🔴 **조사원이 이 칸을 채우면 그건 웹에서 본 것이 아니라 지어낸 것이다.** 결과 파일에 넣지 않는다.

### ② 정성 — 조사원이 웹에서 찾아온 것

### ③ 우리 분류에 맞춘 것 — **19가지 이유 유형**

`data/truth/raw/why-signals-busan-2026.tsv` 에 있다. 공개 글 448곳이 *"이 집이 맛집이다"* 라고
말할 때 **무엇을 근거로 드는지**를 사람이 분류해 센 표다. **조사원이 찾은 이유를 이 19가지에
맞춰 적는다.** 그래야 정성 자료가 정량과 **같은 표에서** 비교된다.

| 유형 | 뜻 | 유형 | 뜻 |
|---|---|---|---|
| `연차·역사` | 몇 년 됐는지 | `동네·시장 지목` | 그 동네를 아는 사람에게만 통하는 위치 표식 |
| `대물림` | 가업을 이어받았다 — 몇 대째 | `곁들임·차림` | 반찬·양념·먹는 방식이 그 집의 표식 |
| `원조·최초` | 처음 만들었거나 본가다 | `간판 메뉴 지목` | 여러 메뉴가 아니라 하나로 불린다 |
| `조리·재료` | 재료·조리에 눈에 보이는 수고 | `메뉴 희소성` | 여기서만 먹을 수 있다 |
| `미디어 노출` | 방송·유튜브에 나왔다 | `분위기·전망` | 경치나 공간이 좋다 |
| `기관 선정` | 평가기관·정부가 공식 인정 | `가격·가성비` | 값에 비해 푸짐하거나 싸다 |
| `혼잡·수요` | 웨이팅·오픈런·품절 | `운영·접근 편의` | 언제 열고 가기 쉬운가 |
| `현지인 지지` | 관광객이 아니라 동네 사람이 간다 | `서비스·사람` | 사장·직원이 좋다 |
| `투표·독자 선정` | 독자·시민이 투표해 뽑았다 | `맛 묘사` | 그냥 맛있다는 서술 |
| `플랫폼 순위·평점` | 다른 앱의 순위·별점을 근거로 든다 | | |

> 🔴 **19가지 중 어디에도 안 맞으면 억지로 끼워 맞추지 말고 `newTypes` 에 적는다.**
> 억지로 끼우면 그 유형의 통계가 조용히 오염되고, 우리는 그것을 못 알아챈다.

> 🟡 `플랫폼 순위·평점` 은 **"글이 그것을 근거로 들었다" 는 사실만** 적는 것이다.
> 🔴 **별점 숫자 자체를 옮겨 적지 않는다** (1절 ②).

### 결과 파일의 모양

```json
{
  "id": "MA0106202605A2141207",
  "worker": "haiku-1",
  "researchedAt": "2026-09-09T01:23:45.000Z",
  "queries": ["부산 수영구 팁시펍", "팁시펍 광안리 후기"],

  "found": true,
  "confidence": "high",
  "sources": [
    "https://example.com/busan-food-1",
    "https://example.com/busan-food-2"
  ],
  "stillOpen": true,

  "whyPeopleGo": [
    { "type": "연차·역사",   "note": "1975년에 열었다고 여러 글이 적는다", "sources": [0, 1] },
    { "type": "현지인 지지", "note": "동네 사람이 온다고 한다",            "sources": [1] }
  ],
  "newTypes": [
    { "label": "반려동물 동반", "note": "개를 데리고 갈 수 있다고 적는다", "sources": [0] }
  ],

  "descriptors": {
    "yearsClaimed": 50,
    "generations": null,
    "queueing": "long",
    "parking": "hard",
    "audience": "local",
    "signatureDishes": ["돼지국밥"],
    "priceBand": "cheap"
  },

  "notFound": null,
  "notes": ""
}
```

| 칸 | 값 | 뜻 |
|---|---|---|
| `id` | 대기열의 id 그대로 | 파일 이름과 같아야 한다 |
| `worker` · `researchedAt` | | 누가 언제 |
| 🔴 `queries` | 문자열 배열, **비면 안 된다** | **무엇으로 검색했는가.** 없으면 `done` 이 거부한다 — 아래 |
| 🔴 `found` | `true` / `false` | **웹에서 이 가게에 대한 글을 하나라도 찾았나** |
| 🔴 `confidence` | `high` · `medium` · `low` · `none` | 아래 표 |
| `sources` | 주소 배열 | 🔴 **원문은 안 옮긴다. 주소만.** 아래 `sources: [0,1]` 은 이 배열의 번호다 |
| `stillOpen` | `true` / `false` / **`null`** | 아직 영업하나. **모르면 `null`** — `false` 와 다르다 |
| `whyPeopleGo[]` | `{type, note, sources}` | ③ 의 19가지 중 하나. `note` 는 **한 줄 요약**(원문 복사 금지) |
| `newTypes[]` | `{label, note, sources}` | 19가지 어디에도 안 맞는 것 |
| `descriptors` | 아래 표 | 어떤 곳이라고 말하나. **모르는 칸은 `null`** |
| `notFound` | 문자열 / `null` | `found: false` 일 때 **왜 못 찾았나** 한 줄 |
| `notes` | 100자 이하 | 위 칸에 안 들어가는 것. 🔴 **원문 복사 금지** |

**`confidence` 를 어떻게 정하나** — 세는 것은 **서로 다른 출처의 수**다. 느낌이 아니다.

| 값 | 언제 |
|---|---|
| `high` | 서로 다른 출처 **3개 이상**이 같은 것을 말한다 |
| `medium` | **2개** |
| `low` | **1개**, 또는 출처가 서로 어긋난다 |
| 🔴 `none` | **찾은 것이 없다.** 이때 `found: false` · `whyPeopleGo: []` · `notFound` 에 이유 |

**`descriptors`** — 있으면 적고, **없으면 `null`.** 빈 문자열이나 0 으로 채우지 않는다.

| 칸 | 값 | 뜻 |
|---|---|---|
| `yearsClaimed` | 숫자 / `null` | 글이 **몇 년 됐다고** 하나 |
| `generations` | 숫자 / `null` | **몇 대째**라고 하나 |
| `queueing` | `long` · `some` · `none` / `null` | 줄이 긴가 |
| `parking` | `easy` · `hard` · `none` / `null` | 주차 |
| `audience` | `local` · `tourist` · `mixed` / `null` | 🔴 **글이 그렇게 말하는가**이지 조사원의 판단이 아니다 |
| `signatureDishes` | 메뉴 이름 배열 | 글이 지목한 메뉴 **이름만** |
| `priceBand` | `cheap` · `mid` · `high` / `null` | 글이 값에 대해 말한 방향 |

### 🔴 "모른다" 를 반드시 답할 수 있다

찾은 게 없으면 이 파일 하나면 된다. **이것도 `done` 이 받는 정상적인 결과다.**

> 🔴 **단, `queries` 는 비울 수 없다.** *"못 찾았다"* 는 **찾아보고 나서만 할 수 있는 말**이고,
> 무엇으로 찾았는지가 안 적혀 있으면 **안 찾아본 것과 구별할 방법이 없다.**
>
> 2026-09-09 새벽에 조사원 둘이 검색을 건너뛰고 `found: false` 파일 2,283개를 찍어냈다.
> 그때 `done` 이 본 것은 *"파일이 있는가"* 하나뿐이었고, 파일은 한꺼번에 만들면 생긴다.
> **파일의 존재는 조사의 증거가 아니다.** 그래서 관문이 둘 늘었다 —
> **무엇으로 검색했는지**(`queries`)와 **시간**(가게 하나에 최소 15초).
> 되짚어 보는 것은 `node research/audit.mjs`, 지워진 것은 `data/quarantine-2026-09-09/`.

```json
{
  "id": "MA…", "worker": "haiku-1", "researchedAt": "2026-09-09T01:23:45.000Z",
  "queries": ["부산 사하구 삼거리식당", "삼거리식당 하단 맛집"],
  "found": false, "confidence": "none", "sources": [], "stillOpen": null,
  "whyPeopleGo": [], "newTypes": [], "descriptors": {},
  "notFound": "상호로 검색해도 이 가게를 다룬 글이 없다. 같은 이름의 다른 지역 가게만 나온다",
  "notes": ""
}
```

> 🔴 **`done` 은 결과 파일이 없으면 거부한다.** 못 찾은 것도 파일로 남겨야 끝난 것이다.
> 그래야 *"아무도 안 본 곳"* 과 *"보았는데 없던 곳"* 이 구별된다.

## 4. 🔴 조사를 채점한다 — 이 장치가 없으면 2,355곳을 조사해 놓고도 쓸 만한지 모른다

대기열 2,355곳 중 **355곳은 정답지에 실린 집**이다 — 택슐랭(*부산 길을 10년 넘게 누빈
택시기사가 고른 원도심 밥집 60곳*) · 공개 글 448곳 · 블루리본 · 블로그100 · 백년가게.
**우리는 그 집들의 답을 이미 안다.**

> 🔴 **조사원에게는 어느 집이 정답지인지 알려주지 않는다.** 알면 그쪽으로 답을 맞춘다.
> 그래서 대기열(`queue.ndjson`)에 그 표시가 **없다.** 짝은 `data/staged/truth-linked.ndjson`
> 에 따로 있고, 채점할 때 `id` 로 잇는다.

조사가 끝나면 이렇게 묻는다 (**실행은 나중이다. 여기 적은 것은 방법이다**).

| # | 검사 | 무엇을 잡나 |
|---|---|---|
| **가** | 🟢 **답안지 대조** — 공개 글 448곳 중 **272곳**에는 사람이 이미 이유 유형을 매겨 놓았다(`truth.whyTypes`). 조사원이 같은 집에 매긴 `whyPeopleGo[].type` 과 얼마나 겹치나 | **가장 직접적인 채점.** 정답이 있는 272곳에서 조사원의 정확도를 바로 잰다 |
| **나** | **택슐랭 리프트** — 조사원이 `현지인 지지` 를 적은 집 중 택슐랭에 든 비율 ÷ 안 적은 집 중 든 비율 | **1 이면 조사가 아무것도 못 가른 것이다.** 목표에 가장 가까운 목록으로 잰다 |
| **다** | **유형별 판별력** — 19가지 유형마다 위와 같은 리프트를 낸다 | 어느 유형이 실제로 맛집을 가르나. 🔴 **아직 아무도 모른다** |
| **라** | 🔴 **위약 검사**(placebo test — *효과가 없어야 하는 곳에 효과가 나오면 실험이 틀린 것*) — `맛 묘사` 는 거의 모든 글에 있어 **판별력이 낮아야 한다** | 그것이 가장 잘 가르면, 조사원이 정답지를 알아봤거나 표본이 너무 작은 것이다 |
| **마** | **`confidence` 가 실제로 뜻이 있나** — `high` 인 집이 `low` 인 집보다 정답지에 잘 드나 | 확신도가 장식이면 뺀다 |

**나쁜 결과도 값지다.** 안 맞으면 **나머지 2,000곳의 조사를 믿으면 안 된다는 것을 싸게** 알게 된다.
