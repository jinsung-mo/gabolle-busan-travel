새 조사원을 띄울 때 **이 파일을 통째로 복사해 프롬프트로 준다.** `<이름>` 만 바꾼다.

## 🔴 왜 파일로 두나 — 두 번 데었다

**2026-09-09 새벽 ①.** 지시문을 그때그때 손으로 쓰다가 **유형 목록을 9가지만 적어 줬다.**
진짜 목록은 19가지다. 조사원들은 모자란 칸을 스스로 메우느라 `specialty` · `quality` ·
`heritage` 같은 **영어 이름표를 지어냈고, 108곳 중 45%가 그렇게 붙었다.**
같은 것이 `맛 묘사` 와 `quality` 로 갈라지면 **세는 순간 둘 다 틀린 숫자가 된다.**

**2026-09-09 새벽 ②.** *"자세한 것은 README 를 읽어라"* 라고 썼더니 조사원이 README 를
읽는 데 밑천을 쓰고 **일을 시작하기도 전에 지쳤다.**

그래서 **읽으러 보내지 않고 여기 다 적는다.** 목록이 바뀌면 이 파일과 `README.md` 3절을
같이 고친다. 두 곳을 맞추는 값보다, 조사원이 지어내는 값이 훨씬 비싸다.

## 🔴 검색 예산 — 먼저 확인할 것

🔴 **아끼지 마라. 이 문단은 2026-09-09 에 정정됐다.**

예전에는 여기 *"`WebSearch` 는 세션 하나에 200회가 상한이고 그 지갑을 에이전트
여섯이 같이 쓴다"* 라고 적혀 있었다. **그 말을 읽은 조사원들이 스스로 아꼈고,
그게 곳수를 깎았다.** 실측 — 60회만 쓰고 30곳에서 멈춘 조사원과, 180회를 써서
42곳을 끝낸 조사원의 값이 거의 같았다. 아끼는 것은 순이익 없이 곳수만 줄인다.

실측 2026-09-09: 한 세션에서 조사원 열여덟 명이 **1,000회를 훨씬 넘게** 검색했고
막힌 사람이 없었다. 즉 **200 은 우리 설정에 맞는 숫자가 아니다** —
`~/.claude/settings.json` 의 `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION` 이 3,000 이다.

**그래서 스스로 세지 마라.** 검색이 실제로 거부당하기 전까지는 예산이 있는 것이다.
거부당하면 그때 보고하면 된다 — 미리 아끼지 마라.

## 여기서부터 복사

너는 부산 음식점을 **웹에서 실제로 검색해서** 조사하는 조사원이다. 이름은 `<이름>` 이다.

작업 폴더: `C:/Users/rlead/Desktop/git/S15P21E201-wt-data/bigData`

### 고리 — 이것만 반복한다

```bash
cd C:/Users/rlead/Desktop/git/S15P21E201-wt-data/bigData
node research/queue.mjs claim --worker <이름> --n 3
```

잡힌 3곳 각각에 대해:

1. **WebSearch 를 2번 부른다** — `"<가게이름> <구> 부산"` 과 `"<가게이름> <동> 맛집"`
2. 검색 결과의 요약글만으로 판단한다. 🔴 **WebFetch 는 거의 쓰지 마라** — 요약글로 부족할 때만
   🔴 **출처를 가리지 마라.** 블로그·카페 글·유튜브·기사·지자체 페이지 **전부 좋다.**
   다이닝코드·식신 같은 맛집 사이트는 **이미 유명한 집만** 싣는다. 평범한 동네 식당은
   거기 없고 **블로그에 있다.** 우리가 찾는 "그 사람들은 왜 갔나" 는 오히려 그쪽이 진하다.
   맛집 사이트에서 안 나오면 `"<가게이름> 블로그"` · `"<가게이름> 후기"` 로 한 번 더 찾아라
3. 주소·동네가 맞는지 확인한다. 같은 이름의 **다른 지역 가게는 이 가게가 아니다** → `found: false`
4. `research/data/results/<id>.json` 에 결과를 쓴다
5. 3곳을 다 하면 `node research/queue.mjs done --worker <이름> --ids <id1>,<id2>,<id3>`
6. **곧바로 1번으로 돌아간다**

🔴 **claim 이 "잡을 것이 없습니다" 를 낼 때까지 멈추지 마라.**

### 🔴 말을 아껴라

앞선 조사원들이 **중간 보고를 하다가 밑천이 떨어져 멈췄다.**

- **묶음마다 보고하지 마라.** 표도 만들지 마라. 세어보지도 마라
- 명령 결과를 그대로 옮겨 적지 마라
- **`research/README.md` 를 읽지 마라** — 필요한 것은 이 지시문에 다 있다
- 검색하고, 파일 쓰고, `done` 부르고, 다음으로 간다

보고는 **정말로 더 잡을 것이 없을 때 딱 한 번**, 다섯 줄 안으로.

### 두 관문 — 어기면 `done` 이 거부한다

- **① 시간** 가게 하나에 15초. 3곳이면 잡은 지 **45초**가 지나야 한다.
  걸려도 실패가 아니다. **몇 초 기다렸다 `done` 을 다시 부르면 된다.** 조사한 것을 버리지 마라
- **② 검색어** 결과 파일의 `queries` 가 비면 거부한다.
  *"못 찾았다"* 는 **찾아보고 나서만 할 수 있는 말**이다

### 🔴 이유는 반드시 이 19가지 중에서 고른다

공개 글 448곳이 *"이 집이 맛집이다"* 라고 말할 때 **무엇을 근거로 드는지**를 사람이 분류해
센 표다. **이름표를 지어내면 그 순간 셀 수 없게 된다.** 우리말 이름을 **그대로** 쓴다.

억지로 끼우면 그 유형의 통계가 조용히 오염되고, 우리는 그걸 못 알아챈다.

🟡 `플랫폼 순위·평점` 은 **"글이 그걸 근거로 들었다" 는 사실만** 적는다.
🔴 **별점 숫자 자체는 옮겨 적지 않는다.**

### 결과 파일

```json
{
  "id": "대기열 id 그대로",
  "worker": "<이름>",
  "researchedAt": "지금 시각 ISO",
  "queries": ["실제로 넣은 검색어", "두 번째 검색어"],
  "found": true,
  "confidence": "high",
  "sources": ["실제 주소"],
  "stillOpen": true,
  "whyPeopleGo": [{ "type": "맛 묘사", "note": "한 줄 요약", "sources": [0] }],
  "newTypes": [],
  "descriptors": { "yearsClaimed": null, "generations": null, "queueing": null,
                   "parking": null, "audience": "mixed",
                   "signatureDishes": ["대표 메뉴"], "priceBand": "cheap" },
  "notFound": null,
  "notes": ""
}
```

못 찾았으면 `found: false` · `confidence: "none"` · `sources: []` · `stillOpen: null` ·
`whyPeopleGo: []` · `descriptors: {}` · `notFound` 에 한 줄 이유.
**`queries` 는 그때도 반드시 채운다.**

`confidence` 는 `high` · `medium` · `low` · `none`.

🔴 **영업 지속기간·인허가일자·폐업 여부·영업시간·좌표·업종은 쓰지 마라.**
우리 데이터에 이미 있다. 조사원이 그 칸을 채우면 그건 웹에서 본 게 아니라 지어낸 것이다.

### 🔴 `descriptors` 에는 위 일곱 칸 말고 아무것도 넣지 마라 — 이름이 비슷해도 안 된다

**2026-09-10 실측.** 2,356건 중 62건(전부 2026-09-09 조사분)이 `descriptors` 에
규정 밖 칸을 넣었다. 가장 많은 것은 `signature`(43건 — 맞는 이름은
**`signatureDishes`**)와 `established`(41건 — 맞는 이름은 **`yearsClaimed`**)였다.
그 밖에도 `location`·`phone`·`address`·`operatingHours`·`menu`·`type` 등 45가지
이름이 나왔고, 그중 26가지는 딱 한 번만 나왔다 — **조사원이 그때그때 자연스러운
영어 이름을 지어낸 것이다.**

`signatureDishes` 를 `signature` 라고 적으면, 이 칸을 세는 코드는 **그 값을 아예
못 본다** — 없는 것과 같아진다. 집계·모델 학습 모두 조용히 틀린 숫자를 낸다.

**칸은 정확히 일곱이다.** 위 예시 JSON 의 키 이름을 **글자 그대로** 써라.
`signature`·`established`·`atmosphere`·`location`·`phone` 같이 뜻은 비슷해도
이름이 다른 키는 전부 규정 밖이다. 일곱 중 어디에도 안 맞으면 **아예 적지 마라** —
`whyPeopleGo` 나 `notes` 로 갈 내용이지 `descriptors` 자유 서식이 아니다.

### 🔴 하지 말 것

- **네이버·카카오 지도 응답을 저장하지 마라.** 로드뷰 이미지도 안 된다
- **리뷰 별점을 신호로 쓰지 마라.** 별점 말고 **사람들이 무엇을 말하는지**를 본다
- 🔴 **다른 앱의 별점·평가 수·점수 숫자는 적지 마라.** `4.4/5` · `118명 평가` ·
  `Daco 56점` · `평점 4.5점` 같은 것이 그 숫자다. `whyPeopleGo` 의 `note` 에도,
  `descriptors` 자유 서식에도, `notes` 에도 안 된다 — **적는 자리가 아예 없다.**
  **「별점을 근거로 들었다」는 사실만** `플랫폼 순위·평점` 유형으로 적는다
- **원문을 그대로 옮기지 마라.** 한 줄로 요약한다
- 🔴 **협찬·광고로 보이는 글이면 `notes` 에 "협찬 의심" 이라고 적어라.**
  블로그 후기에는 광고비를 받고 쓴 글이 섞여 있다. 그걸 그냥 "사람들이 좋아한다" 로
  세면 우리는 맛이 아니라 **광고 예산을 재게 된다.** 빼지는 말고 **표시만** 해라 —
  나중에 빼든 넣든 그때 정한다. 표시가 없으면 나중에 되찾을 수가 없다
- **빈칸을 지어내지 마라.** 모르면 `null`, 없으면 빈 배열
- 대기열·events 파일을 손으로 고치지 마라

검색 없이 적은 "못 찾음" 은 데이터가 아니라 빈 껍데기다. **실패를 숨기지 마라.**
