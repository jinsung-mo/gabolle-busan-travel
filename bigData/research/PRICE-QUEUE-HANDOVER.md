## 1. 🔴 청크 번호를 직접 고르지 않는다 — `work-chunk.mjs` 가 대신 고른다

예전엔 아래 표에서 안 맡은 번호를 사람이 직접 고르고 `axmap claim` 을 손으로
불러야 했다. **이제 그럴 필요 없다.**

```bash
cd <저장소>/bigData
node research/work-chunk.mjs
```

이 한 줄이 다 한다 — `git pull` 로 최신 체크포인트를 받고, `axmap status` 로 지금
아무도 안 잡고 있고 아직 안 끝난 청크를 번호가 가장 앞선 것부터 찾아 스스로
선점하고, 오래 걸려도(청크 하나가 30분을 넘길 수 있다) 15분마다 자동으로 TTL 을
늘리고, 끝나면 반납한다. **`axmap` 을 몰라도 된다** — 누가 몇 번을 잡고 있는지
신경 쓸 일이 이제 없다.

Gemini 할당량이 막히면 모델만 바꿔서 다시 부른다 (뒤는 그대로):

```bash
node research/work-chunk.mjs --model claude-sonnet-4-6
```

끝나면 화면에 커밋 명령이 그대로 찍힌다 — 그걸 그대로 실행해서 올리면 된다:

```bash
git add -f bigData/research/data/combined-results
git commit -m "[S15P21E201-1414] chore: [Data] 가격 조사 청크 <번호> 결과"
git push origin bigData/dev
```

> 🔴 **정정 (2026-09-22) — 위 `git add -f` 줄이 전에는 `.../combined-results/*.json`
> (글롭)이었다.** 결과 파일이 1,000개를 넘어가면서 **`Argument list too long`** 으로
> 죽는다(이예승·장효준 실측) — 이미 커밋된 파일까지 글롭이 전부 잡아서다. 디렉터리로
> 주면 git 이 실제로 바뀐 것만 골라 담는다.

🔴 **표(governance)는 이 조사와 무관하다.** `bigData/dev` 로 바로 가는 커밋이라
정족수 없이 바로 push 하면 된다. `work-chunk.mjs` 는 git add·commit·push 까지는
안 한다 — 실제로 올리는 것은 사람이 마지막에 확인하고 직접 한다.

**한 창에서 여러 번 돌리려면** `AXMAP_SESSION` 을 서로 다르게 준다 — 안 주면
`work-chunk.mjs` 가 스스로 하나 만들어 쓰지만, **같은 창의 루프 둘**이 각자 자동으로
만들면 매번 값이 달라 문제 없다. 다만 **손으로 여러 개를 띄울 때는 직접 지정**하는
게 안전하다:

```bash
AXMAP_SESSION="wc-$$-$(date +%s)" node research/work-chunk.mjs
```

**여러 명이 동시에 여러 번 돌려도 된다.** 청크 인덱스가 서로 안 겹치게 미리
잘라둔 것이라 번호만 다르면 절대 겹치지 않는다.

> 🔴 **정정 (2026-09-22) — "같은 번호를 동시에 잡으려 하면 axmap 이 하나만
> 통과시킨다"만으로는 부족했다.** 번호를 고르는 단계(`axmap status` 조회)는
> **그 순간의 스냅샷**이라, 조회 뒤 실제로 선점하기까지 몇 초 사이에 남이 같은
> 번호를 먼저 잡을 수 있다(진미리·이예승 실측). **선점 관문은 정상적으로 막아
> 데이터는 안 깨지지만**, 예전 `work-chunk.mjs` 는 "거부됨"과 "더 이상 남은 청크가
> 없음"을 구분하지 못해 **자동화를 돌리면 조용히 멈췄다.** 지금은 거부되면 그
> 번호를 빼고 스크립트 안에서 바로 다음 번호로 다시 시도한다(3번 연속 거부면
> 그만두고 이유를 찍는다) — 사람이 다시 실행할 필요가 없다.

## 2. `agy` 는 무엇이고 어떻게 부르나 — 몰라도 되지만, 알아두면 좋다

`work-chunk.mjs` 가 내부에서 `price-queue.mjs` 를 부르고, 그 안에서 `agy`
(Antigravity CLI — 웹검색이 되는 외부 모델을 터미널에서 헤드리스로 부르는 도구)를
가게 한 곳마다 이렇게 부른다 (`price-queue.mjs` 의 `callAgy()`):

```bash
agy --model gemini-3.8-flash-low --effort low \
    --dangerously-skip-permissions \
    -p="<위에서 만든 조사 프롬프트>" \
    --json-schema price-schema.json --output-format json
```

- **`--effort low`** — Gemini 만 받는 옵션. 실측으로 토큰 -22%·시간 -41%, 정확도는
  거의 그대로였다 — **토큰을 아끼는 핵심**. 다른 모델에 붙이면 "충돌한다" 며 죽는다.
- **`--dangerously-skip-permissions`** — **"헤드리스 모드"**(사람이 옆에서 승인
  버튼을 누를 수 없는 배치 실행이라, 매번 묻지 않고 바로 실행하게 하는 옵션).
  이 프롬프트는 **읽기 전용 웹검색만** 시키고 파일·셸 접근을 요구하지 않아서 여기
  붙여도 안전하다. **다른 목적의 agy 호출에 이 옵션을 그대로 복사해 쓰지는 마라** —
  프롬프트가 다르면 위험도 다르다.
- **`--json-schema`** — 답을 자유 텍스트가 아니라 정해진 칸(`price-schema.json`)으로
  강제한다 — 그래야 결과가 프로그램이 읽을 수 있는 모양으로 나온다.

**설치·로그인이 안 됐으면** 먼저 그것부터 해야 `work-chunk.mjs` 가 돈다.
절차를 몰라 막힌 사람이 있으면 janghyojoon 에게 물어보라 — 쪽지로 이미 한 번
온 요청이다.

## 3. 무엇이 같이 수집되나 — 가격만이 아니다

한 곳을 조사하면 `research/data/combined-results/<id>.json` 에 **한 번에** 이게
다 담긴다. 청크를 하나 돌리면 이 전부가 같이 올라간다 — 가격만 따로 더 돌 필요가

- 가격(`price`) · 영업시간(`hours`) · 혼잡/줄서기(`crowding`)
- 현지인/관광객 비중(`localVsTourist`) · 메뉴 다양성(`menuDiversity`)
- **"왜 가는지" narrative**(`whyPeopleGo` — 9가지 유형 중 하나 + 한 줄 요약)
- descriptors 7칸(연차·대물림·줄서기·주차·이용층·간판메뉴·가격대)
- **사진 주소**(`photoUrls`, 🔴 2026-09-22 부터) — 아래 4절

## 4. 🔴 사진은 "주소만" — 이미지 자체는 안 받는다

카카오·네이버·구글 지도로 사진을 직접 받는 건 이미 막혀 있다 — 카카오·네이버는
장소 사진을 주는 API 자체가 없고, 구글은 사진 응답을 캐시(저장)하는 것 자체가
약관 위반이다(`place.photo_url` 칸에 넣는 방식이 그래서 안 된다).

대신 `agy` 가 읽는 블로그·리뷰 페이지에 실제로 실린 사진이 있으면, **그 이미지
파일의 주소(URL)만** `photoUrls` 에 적게 했다. **이미지를 내려받거나 우리
서버에 옮기지 않는다** — 링크 하나가 전부다. 이것도 `sourceExcerpts` 와 같은 이유로
**내부 분석용**이지, 화면에 그대로 걸 수 있는 건 아니다 (링크가 깨지거나, 원저작자
허락 없이 우리 화면에 직접 거는 것 자체가 별개 문제라서 — 쓰려면 그때 다시 검토).

🔴 **청크 1~16(이미 끝난 806곳)에는 이 칸이 없다.** 그 전에 끝난 것들을 사진 때문에
다시 돌리지는 않는다 — 새로 도는 청크(17번부터)부터 붙는다.

## 5. 🔴 DB 적재는 우리가 한다 — 팀원은 push 까지만

결과 파일을 모아서 실제 서비스 DB(EAV 형태로 들어가는 장소 속성)에 넣는 것은
**janghyojoon 쪽에서 일관되게** 한다. 매핑 규칙이 한 곳에서만 바뀌어야 나중에
"이 값이 왜 이렇게 들어갔지"를 추적할 수 있어서다 — 각자 알아서 적재하면 같은
칸이 사람마다 다른 규칙으로 들어갈 수 있다.

**팀원이 할 일은 결과 파일을 커밋해서 `bigData/dev` 에 올리는 것까지다.**
`--aggregate`(`data/staged/` 로 모으는 단계)나 그 뒤 적재 스크립트는 몰라도 된다.
