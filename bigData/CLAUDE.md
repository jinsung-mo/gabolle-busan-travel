# bigData — 부산 이동성 데이터

이 폴더는 **"이 길을 걸을 만한가 / 버스를 탈 만한가 / 택시를 타야 하나"** 를
판정하는 데이터를 만든다. 화면은 여기 없다. 여기서 나온 것을 FE/BE 가 쓴다.

루트 [CLAUDE.md](../CLAUDE.md) 가 이 문서보다 위다. 용어 설명 규칙(0절)이 여기도 적용된다.

---

## 🔴 1. 절대 하지 않는 것

**네이버·카카오 지도 데이터를 저장하지 않는다.**

카카오 공식 답변 기준으로 Local API(**카카오가 제공하는 장소 검색 API**) 응답은
별도 저장이 금지되고, 로드뷰 이미지의 수집·재배포도 금지다. 네이버도 같다.
두 API 모두 **화면에 띄우는 것만** 허용된다.

| | |
|---|---|
| ✅ 되는 것 | 카카오 로드뷰 SDK 를 화면에 임베드해서 사용자에게 보여주기 |
| ❌ 안 되는 것 | 그 이미지를 내려받아 DB·디스크에 넣기, AI 로 분석하기 |

분석용 거리 이미지는 **Mapillary**(CC BY-SA — 출처를 밝히면 다운로드·가공 가능)를
쓰거나 **직접 촬영**한다. 직접 찍은 것은 우리 것이라 제약이 없다.

`config/sources.json` 의 `banned` 에 이유와 대체 경로가 적혀 있다.
**새 출처를 추가할 때 `license` 필드가 없으면 `npm run verify` 가 실패한다.**

## 🔴 2. 리뷰 별점을 신호로 쓰지 않는다

리뷰 이벤트로 오염되어 있다. 약관 문제 이전에 품질 문제다.
대신 **조작할 수 없는 관측 신호**를 쓴다 — 영업 지속기간, 유동인구, 카드매출,
정류장 하차인원. 리뷰는 관광객이 쓰고, 우리가 찾는 것은 현지인이다.

## 3. 폴더

```
collect/    바깥에서 데이터를 가져온다 (네트워크 O, 계산 X)
process/    가져온 것으로 계산한다 (네트워크 X)
config/     area.json = 대상 구역 · sources.json = 출처 레지스트리
test/       verify.mjs — 판정은 종료 코드
data/       ⚠️ .gitignore. 커밋하지 않는다 (OSM 만 285MB)
```

`data/` 를 커밋하지 않는 이유: git 은 큰 파일을 넣으면 되돌릴 수 없다.
히스토리에서 빼려면 전원이 다시 clone 해야 한다. `collect/` 가 언제든 다시 만든다 —
그게 재현 가능하다는 말의 뜻이다.

## 4. 인증 없이 되는 것 / 사람이 신청해야 하는 것

```bash
npm run collect:overpass    # 바로 됨 — 도로·보행로·계단·정류장·POI
npm run collect:terrain     # 바로 됨 — 고도 타일
npm run collect:osm         # 바로 됨 — 전국 OSM 285MB
npm run slope               # 계산 — 구간별 경사

npm run collect:bims        # 🔴 키 없으면 종료 코드 2 로 멈춘다
```

키가 필요한 것은 [docs/SOURCES.md](docs/SOURCES.md) 에 신청 절차가 있다.

> 🔴 **BIMS 실시간 버스는 소급 수집이 안 된다.** 오늘 안 켜면 오늘치가 영영 없다.
> 다른 데이터는 늦어도 따라잡지만 이것만은 못 메운다.

## 5. 경사를 왜 계산하나 — OSM 태그를 믿지 않는다

대상 구역에서 실측한 태그 보유율:

| `surface` | `incline`(경사) | `step_count` | `width`(폭) | `wheelchair` |
|---|---|---|---|---|
| 12.7% | **1.2%** | 0.5% | **0.2%** | 0.0% |

- **경사** → 태그로는 불가능. DEM(**땅 높이를 격자로 적어둔 데이터**)에서 계산한다
- **폭** → 계산으로도 못 만든다. **도로명주소 실폭도로가 필수다** (심사 소요, 빨리 신청)
- **계단 단수** → 고도차 ÷ 표준 단높이 0.17m 로 추정

### 🔴 경사 기준선은 실측으로 정한다

지금 쓰는 고도는 SRTM ~30m 를 보간한 것이라 **수직 오차가 ±5m** 다.
30m 간격으로 차분하면 5m 오차가 곧 17% 경사가 된다 — **없는 언덕이 생긴다.**

그래서 **해안 매립지(실제로는 평지)를 대조군으로 놓고** 거짓 양성이 사라지는
기준선을 고른다. `process/calibrate-slope.mjs` 가 그 측정이다.

```
기준선  30m → 평지의 6% 가 "8% 이상" 으로 나온다 (전부 거짓)
기준선 100m → 0%   ← 채택. 같은 기준선에서 산지는 58% 가 남는다
```

**국가 5m DEM 으로 교체하면 이 스크립트를 다시 돌려 기준선을 다시 정한다.**
`test/verify.mjs` 가 이 불변식을 지킨다 — 거짓 양성이 1% 를 넘으면 실패한다.

## 6. 대표값은 최댓값이 아니라 p90 이다

최댓값은 잡음 표본 하나에 끌려간다. 실제로 첫 계산에서 "8% 이상이 78.4%" 가
나왔는데, 기준선을 고치고 p90 으로 바꾸니 46.9% 였다. **31.5%p 가 잡음이었다.**

## 검증

작업을 끝내기 전에 통과해야 한다.

```bash
npm --prefix bigData run verify
```

데이터가 없으면 해당 검사는 건너뛰고 통과한다 — clone 직후에도 돌아야 하기 때문이다.
데이터가 있으면 디코딩과 보정 불변식까지 본다.

**개수를 여기에 적지 않는다.** 적어 두면 검사를 늘릴 때마다 이 줄이 낡고,
낡은 기준은 없는 기준보다 나쁘다. 판정은 언제나 종료 코드다.
