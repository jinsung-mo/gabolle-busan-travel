# bigData — 부산 이동성 데이터

이 폴더는 **"이 길을 걸을 만한가 / 버스를 탈 만한가 / 택시를 타야 하나"** 를
판정하는 데이터를 만든다. 화면은 여기 없다. 여기서 나온 것을 FE/BE 가 쓴다.

루트 [CLAUDE.md](../CLAUDE.md) 가 이 문서보다 위다. 용어 설명 규칙(0절)이 여기도 적용된다.

---

## 🔴 1. 절대 하지 않는 것

**네이버·카카오 지도 데이터를 저장하지 않는다.**

카카오 공식 답변 기준으로 Local API(**카카오가 제공하는 장소 검색 API**) 응답은
별도 저장이 금지되고, 로드뷰 이미지의 수집·재배포도 금지다. 네이버도 같다.
두 API 모두 **화면에 띄우는 것만** 허용된다.

| | |
|---|---|
| ✅ 되는 것 | 카카오 로드뷰 SDK 를 화면에 임베드해서 사용자에게 보여주기 |
| ❌ 안 되는 것 | 그 이미지를 내려받아 DB·디스크에 넣기, AI 로 분석하기 |

분석용 거리 이미지는 **Mapillary**(CC BY-SA — 출처를 밝히면 다운로드·가공 가능)를
쓰거나 **직접 촬영**한다. 직접 찍은 것은 우리 것이라 제약이 없다.

`config/sources.json` 의 `banned` 에 이유와 대체 경로가 적혀 있다.
**새 출처를 추가할 때 `license` 필드가 없으면 `npm run verify` 가 실패한다.**

## 🔴 2. 리뷰 별점을 신호로 쓰지 않는다

리뷰 이벤트로 오염되어 있다. 약관 문제 이전에 품질 문제다.
대신 **조작할 수 없는 관측 신호**를 쓴다 — 영업 지속기간, 유동인구, 카드매출,
정류장 하차인원. 리뷰는 관광객이 쓰고, 우리가 찾는 것은 현지인이다.

## 3. 작업 범위 — 부산 전역

`config/area.json` 이 정한다.

| | 범위 | 쓰임 |
|---|---|---|
| `target` | **부산광역시 전역** | 실제 작업 범위. bbox 3,040 km2 (바다·인접시 포함) |
| `focus` | 중구·동구 | 데모와 검증. 외국인 실동선이고 경사가 극단적이라 판정이 눈에 보인다 |

> 🔴 **전역을 Overpass 로 긁지 않는다.** 공용 서버에 241배 부하를 주는 짓이고,
> 막히면 팀 전체가 몇 시간 못 쓴다. 전역은 **이미 받아둔 PBF 에서 뽑는다** —
> `py collect/pbf_extract.py` 가 64초에 끝낸다.
> `collect/overpass.mjs` 에는 **면적 상한 200km2 가 코드로 걸려 있어** 전역을
> 부르면 종료 코드 2 로 거부한다. 문서로 부탁하지 않고 코드가 막는다.

**PBF** — OpenStreetMap 전체를 담은 압축 바이너리 파일. 우리가 받은 것은 대한민국
전체 286MB 짜리다. 여기서 부산만 잘라 쓴다.

## 4. 폴더

```
collect/    바깥에서 데이터를 가져온다 (네트워크 O, 계산 X)
process/    가져온 것으로 계산한다 (네트워크 X)
config/     area.json = 대상 구역 · sources.json = 출처 레지스트리
test/       verify.mjs — 판정은 종료 코드
data/       ⚠️ .gitignore. 커밋하지 않는다 (OSM 만 285MB)
```

`data/` 를 커밋하지 않는 이유: git 은 큰 파일을 넣으면 되돌릴 수 없다.
히스토리에서 빼려면 전원이 다시 clone 해야 한다. `collect/` 가 언제든 다시 만든다 —
그게 재현 가능하다는 말의 뜻이다.

## 5. 인증 없이 되는 것 / 사람이 신청해야 하는 것

```bash
npm run collect:osm         # 전국 OSM 286MB (한 번)
npm run collect:extract     # ⭐ 전국 PBF → 부산 전역 NDJSON (64초, Python)
npm run collect:terrain     # 고도 타일 3,127개 (부산 전역)
npm run collect:overpass    # focus 구역만. 전역은 거부한다

npm run calibrate           # ⭐ 경사 기준선을 실측으로 정한다 — slope 보다 먼저
npm run slope               # 구간별 경사 (전역 67,676개 / 7초)

npm run collect:bims        # 🔴 키 없으면 종료 코드 2 로 멈춘다
```

`collect:extract` 만 Python 이다 (`py -m pip install -r requirements.txt`).
PBF 를 제대로 읽는 라이브러리가 osmium 계열뿐이고 그 바인딩이 Python 에 있다.

키가 필요한 것은 [docs/SOURCES.md](docs/SOURCES.md) 에 신청 절차가 있다.

> 🔴 **BIMS 실시간 버스는 소급 수집이 안 된다.** 오늘 안 켜면 오늘치가 영영 없다.
> 다른 데이터는 늦어도 따라잡지만 이것만은 못 메운다.

## 6. 경사를 왜 계산하나 — OSM 태그를 믿지 않는다

부산 전역 way 68,765개에서 실측한 태그 보유율:

| `surface` | `sidewalk` | `lit` | `width`(폭) | `incline`(경사) | `handrail` | `wheelchair` | `step_count` |
|---|---|---|---|---|---|---|---|
| 16.7% | 1.2% | 0.9% | **0.6%** | **0.3%** | 0.2% | 0.1% | **0.0%** |

범위를 넓힐수록 나빠진다 — 중구·동구만 볼 때 `incline` 은 1.2% 였는데 전역은 0.3% 다.
관광지 주변만 사람 손이 닿아 있다는 뜻이고, 그래서 **태그에 기대는 설계는 전역에서 무너진다.**

- **경사** → 태그로는 불가능. DEM(**땅 높이를 격자로 적어둔 데이터**)에서 계산한다
- **폭** → 계산으로도 못 만든다. **도로명주소 실폭도로가 필수다** (심사 소요, 빨리 신청)
- **계단 단수** → `step_count` 가 68,765개 중 32개다. 고도차 ÷ 표준 단높이 0.17m 로 추정

### 🔴 경사 기준선은 손으로 정하지 않는다 — 측정이 정한다

지금 쓰는 고도는 SRTM ~30m 를 보간한 것이라 **수직 오차가 ±5m** 다.
30m 간격으로 차분하면 5m 오차가 곧 17% 경사가 된다 — **없는 언덕이 생긴다.**

그래서 **해안 매립지(고도 12m 이하 = 실제로는 평지)를 대조군으로 놓는다.**
거기서 나오는 "8% 이상 경사" 는 전부 거짓이다. 그것이 0.5% 아래로 내려가면서
산지 신호는 살아있는 가장 짧은 기준선을 고른다 — 짧을수록 실제 지형을 덜 뭉갠다.
문턱을 1% 가 아니라 0.5% 로 두는 것은 여유폭이다 — 문턱에 붙은 기준선은 원본(OSM·타일)이
갱신될 때마다 판정이 흔들린다. 문턱 값은 `process/calibrate-slope.mjs` 의 `FLAT_FP_MAX` 하나뿐이다.

```bash
npm run calibrate     # → data/staged/_calibration.json
npm run slope         # 그 권장값과 어긋나면 종료 코드 1
```

**수치를 이 문서에 적지 않는다.** 범위를 바꾸거나 DEM 을 5m 로 교체하면 값이
달라지고, 여기 적힌 숫자는 그 순간 낡는다. 근거는 언제나 `_calibration.json` 이고
`npm run verify` 가 그것을 불변식으로 검사한다:

- 어느 기준선에서도 거짓양성이 문턱(`FLAT_FP_MAX`) 아래로 안 내려가면 → **실패** (DEM 을 바꿔야 한다)
- 잡음은 죽었는데 산지 신호까지 죽었으면 → **실패** (기준선이 너무 길다)
- 계산에 쓴 기준선 ≠ 보정 권장 기준선 → **실패** (그럴듯한데 틀린 숫자다)

## 7. 대표값은 최댓값이 아니라 p90 이다

최댓값은 잡음 표본 하나에 끌려간다. 실제로 첫 계산에서 "8% 이상이 78.4%" 가
나왔는데, 기준선을 보정하고 p90 으로 바꾸니 46.9% 였다. **31.5%p 가 잡음이었다.**

무서운 것은 그때도 **문법 검사와 단위 테스트가 전부 초록이었다는 것**이다.
bigData 가 죽는 방식은 화면이 깨지는 게 아니라 **그럴듯한 숫자가 나오는 것**이다.
그래서 검증이 값 자체가 아니라 **값을 만든 절차**를 붙잡는다.

## 검증

작업을 끝내기 전에 통과해야 한다.

```bash
npm --prefix bigData run verify
```

데이터가 없으면 해당 검사는 건너뛰고 통과한다 — clone 직후에도 돌아야 하기 때문이다.
데이터가 있으면 디코딩과 보정 불변식까지 본다.

**개수를 여기에 적지 않는다.** 적어 두면 검사를 늘릴 때마다 이 줄이 낡고,
낡은 기준은 없는 기준보다 나쁘다. 판정은 언제나 종료 코드다.
