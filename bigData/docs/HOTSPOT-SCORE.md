# 어디가 부산의 핵심 여행지인가 — 열린 데이터로 점수를 매기는 설계

**질문 두 개를 가른다.** 섞으면 답이 안 나온다.

| | 뜻 | 이미 있나 |
|---|---|---|
| **끌림** (인기) | 사람이 실제로 거기 **간다** | ❌ 아직 없다 |
| **뚫림** (유동성) | 거기까지 **가기 쉽다**, 거기서 다른 데로 가기 쉽다 | ✅ 절반 있다 |

---

## 🔴 0. 이미 한 것부터 — 새로 만들지 않는다

`process/bims-score.mjs` 가 **290개 노선 전부에 0~100 점**을 이미 매겼다.
결과는 `data/staged/_bims-route-score.json`, 거기서 **관광거점정류소 30곳**이 나왔다 —
부산역 · 남포동 · 자갈치 · 서면이 위에 온다. 손으로 고른 것이 아니다.

무엇을 근거로 매겼나:

| 신호 | 만점 | 왜 믿을 만한가 |
|---|---|---|
| **관광정류소 경유** | 35 | BIMS 가 정류소마다 붙여 주는 `stoptype` 이 `관광` 인 곳. **부산시가 직접 분류한 1차 자료**라 우리가 추정한 것이 아니다. 전 부산에 42개뿐 |
| 관광 POI 도보권 | 25 | 정류소 반경 300m(보통 걸음 4분) 안에 OSM 관광 목적지가 있나 |
| 중구·동구 통과 | 15 | 대상 구역 |

정류소 22,408곳의 좌표를 **완전일치**(exact ID join — `nodeid` = `bstopid`)로 붙였고
커버리지 100%다. 이름 맞추기를 안 썼다는 것이 중요하다 — 그건 실패율이 높다.

> 🔴 **그런데 이것은 전부 "뚫림" 쪽이다.** *관광지가 거기 있다* 와 *노선이 거기 선다*
> 뿐이고, **사람이 실제로 얼마나 갔는지는 한 건도 안 들어 있다.**

## 1. 끌림 — 실제 방문량을 열린 데이터로 채운다

| 출처 | 무엇을 주나 | **어느 단위까지** | 받는 법 |
|---|---|---|---|
| **한국관광 데이터랩** `datalab.visitkorea.or.kr` | 관광객 **방문자 수** (통신사 이동데이터 기반) | 🔴 **시군구** | 무료 가입 |
| 부산 도시철도 역별 승하차 (공공데이터포털) | 역별·시간대별 인원 | **역** | 인증키 |
| 소상공인 상가정보 (`SOURCES.md` 5번) | 업종 · **영업 지속기간** | **점포 좌표** | 파일 내려받기 |
| **우리 BIMS 폴링** | 노선별 실제 운행 | **정류소** | 지금 모으는 중 |

**영업 지속기간이 왜 방문량의 신호인가** — 관광지 앞 가게가 3년을 버텼다면 손님이
있었다는 뜻이다. 리뷰 수와 달리 **조작할 수 없다.**

### 🔴 시군구 데이터를 격자로 쪼개지 않는다

데이터랩은 구 단위다. 이걸 면적이나 POI 수로 나눠서 500m 격자에 뿌리고 싶어진다.
**하지 않는다.** 나눈 값은 데이터가 아니라 **우리의 가정**인데, 표에 들어가는 순간
관측값처럼 보인다. 다음 사람은 그것을 실측으로 읽는다.

대신 **검증에만 쓴다.**

```
격자 점수를 구 단위로 합친다  →  데이터랩의 구 순위와 대조한다
어긋나는 구가 있으면  →  그 구를 다시 본다 (버리지 않고 표시한다)
```

## 2. 산출물은 순위표가 아니라 **2×2** 다

```
        뚫림 낮음              뚫림 높음
끌림  ┌──────────────────┬──────────────────┐
높음  │ 🔴 우리 자리      │  이미 다 안다     │
      │ 가고 싶은데       │  해운대·서면      │
      │ 가기 어렵다       │                  │
      ├──────────────────┼──────────────────┤
끌림  │  후순위           │  숨은 곳          │
낮음  │                  │  가기는 쉽다      │
      └──────────────────┴──────────────────┘
```

**왼쪽 위가 이 서비스가 존재하는 이유다.** 순위표 1등(해운대)은 우리가 없어도
누구나 간다. *가고 싶은데 가기 어려운 곳*을 찾아 주는 것이 값이 나가는 일이다.

그리고 이 그림은 **발표 한 장으로 그대로 쓸 수 있다.**

---

## 3. 단위 — 500m 격자

정류소 단위는 너무 잘고(22,408개) 구 단위는 너무 굵다(16개). 그 사이를 500m
정사각 격자로 잡는다. 도보 6분 거리라 "이 동네" 라고 부를 수 있는 크기다.

> 육각형 격자(H3 등)가 이론적으로 낫지만 라이브러리가 하나 늘고, 이 프로젝트에서
> 그 차이가 결론을 바꿀 자리가 없다. **정사각형으로 간다.**

## 4. 순서 — 앞이 없으면 뒤가 없다

| | 무엇을 | 왜 이 순서인가 |
|---|---|---|
| 1 | 격자를 만들고 **이미 있는** 노선 점수·POI 를 격자에 붙인다 | 새 데이터 없이 오늘 된다 |
| 2 | 소상공인 상가정보를 받아 **영업 지속기간**을 얹는다 | 로그인만 하면 받는 파일이다 |
| 3 | 도시철도 승하차를 얹는다 | 인증키가 필요하다 |
| 4 | 데이터랩 구 단위로 **대조한다** | 위 셋이 있어야 대조할 것이 생긴다 |

---

## 5. 아직 모르는 것 — 지어내지 않는다

| 무엇 | 왜 |
|---|---|
| 데이터랩이 **월 단위인지 일 단위인지** | 화면을 안 봤다. 일 단위면 요일 편차까지 본다 |
| 도시철도 승하차의 **연·월 범위** | 오퍼레이션 문서를 안 받았다 |
| 상가정보 부산분의 **좌표 정확도** | 받아서 표본을 찍어봐야 안다 |
| 관광 POI 태그가 **외국인 기준인지** | OSM 태그는 지역 주민 기준일 수 있다. 데이터랩 외국인 방문 값과 대조해야 판단된다 |
