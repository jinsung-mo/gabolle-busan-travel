# 경치 — 어디서 무엇이 보이는가

2026-09-01 시작. **아직 숫자가 하나도 없다.** 이 문서는 재료를 어디까지 모았고
무엇이 막혀 있는지를 적은 것이다.

---

## 0. 🔴 이 작업의 전부도 선을 긋는 것이다

[ONTOLOGY.md](ONTOLOGY.md) 0절이 그은 선이 여기서도 그대로 간다.
다만 경치는 **한 덩어리로 다루면 반드시 실패한다.** 셋으로 쪼갠다.

| 쪼갠 것 | 무엇인가 | 어디로 |
|---|---|---|
| ① **보이는가** | 지형·건물 높이로 계산되는 **물리량** | 데이터 (`data/staged/`) |
| ② **무엇이 보이는가** | 바다·산·야경·랜드마크 | **온톨로지** |
| ③ **얼마나 좋은가** | 사람마다 다름 | **계수. 온톨로지에 넣지 않는다** |

③을 온톨로지에 넣으면 0절의 선을 넘는 것이다. `bm:verdict` 가
`infeasible`·`feasible` 둘로 닫혀 있는 것과 같은 이유다.

### 뷰는 속성이 아니라 **관계**다

`엘시티.바다뷰 = 참` 으로 박으면 안 된다. 같은 건물인데 **층과 방향에 따라**
도시뷰이기도 바다뷰이기도 하다. 그래서 관계 자체를 개체로 만든다.

```
bm:Vista   엘시티 → 광안대교 · 지상 120m · 방위 95~140° · 수평선의 32°
```

`Leg` 이 *"시각은 축이다"* 라며 관계를 개체로 만든 것과 같은 모양이다
(ONTOLOGY.md 2.2). 뷰는 축이 셋(층·방향·대상)이라 더 그렇다.

`광안대교` 는 **갈래가 아니라 개체**다. 랜드마크가 100개로 늘어도 구조는 그대로다.

> 🔴 **아직 `Vista` 를 온톨로지에 넣지 않았다.** 숫자가 나온 뒤에 넣는다.
> 담을 것이 없는데 그릇부터 만들면 그 그릇이 맞는지 알 수 없다.

## 2. 🔴 실측으로 알아낸 것 — 다시 재보지 말 것

### 2.1. DEM 에는 건물이 없다

**DEM/DTM 은 땅만, DSM 은 땅+건물**이다. 우리 것은 앞의 것이다.
그래서 *"고지대인데 바로 앞 건물이 가린다"* 를 **DEM 만으로는 못 잡는다.**
DEM 위에 건물 높이를 얹어야 비로소 DSM 이 된다.

한 칸이 약 30m 라 건물은 격자에 못 담는다. **폴리곤 + 높이**로 따로 다룬다.

### 2.2. 그림자 가설을 경치에 그대로 쓰면 안 된다

[WALKABILITY.md](WALKABILITY.md) 2.2 는 *"빈 층수 70% 는 대체로 그림자를 못 만드는
작은 건물"* 이라고 넘겼다. **그림자에는 맞고 경치에는 정반대다.**

| | 그림자 | 가시권 |
|---|---|---|
| 결정하는 건물 | **크고 높은 것** | **가장 가까운 것** |
| 2층 상가 | 그늘 5m — 무시 가능 | 🔴 **수평선을 통째로 가림** |

눈높이 1.6m 에서는 바로 앞 2층 건물이 바다를 다 지운다.
**그래서 건물 높이 결측이 경치에서는 치명적이다.**

> 다행히 이미 풀려 있다 — OSM 의 `height` 보유율은 **2.1%**(52,556채 중 1,098채)
> 였고, 그래서 팀이 V-World 실측 높이를 가져왔다. `collect/shp_buildings.py` 참고.

### 2.3. 지형 해상도는 경치에 덜 아프다

DEM 이 SRTM 30m 보간이라 *"6m 골목 경사는 뭉개진다"* 고 `terrain.mjs` 가 경고한다.
**경치에는 그 약점이 별로 안 아프다** — 바다가 보이느냐는 넓은 지형이 정한다.
산복도로에서 바다 보이는 것은 30m 로도 잡힌다. **아픈 곳은 지형이 아니라 건물이다.**

### 2.4. 필요한 것은 해안선(선)이 아니라 바다(면)다

OSM 의 `natural=coastline` 은 **닫힌 면이 아니라 선**이다. 광선을 쐈을 때 필요한
판정은 *"끝점이 물인가"* 인데, **선만 있으면 어느 쪽이 물인지 모른다.**

대안 — **바다 면을 안 만드는 것.** 가시권은 *"광선이 육지를 벗어나는가"* 만 알면
되므로 **육지 마스크**로 충분하다. `config/boundary.geojson` 과 성격이 같다.

### 2.5. 미리 만든 폴리곤은 이득이 없었다

`osmdata.openstreetmap.de` 의 land/water polygons 를 후보로 봤다.
**land 883MB · water 862MB — 전 세계 것**이다. PBF(약 1GB) 대비 이득이 없다.
부산만 잘라 파는 형태가 아니다. (2026-09-01 실측)

### 2.6. 🔴 `tourism=viewpoint` 217개를 그대로 쓰면 안 된다 (2026-09-06 실측)

*"사람이 전망대라고 적어 둔 곳"* 이 217개 있으니 계산 없이 쓰자는 생각이 나오기 쉽다.
**갈라 보면 남는 것이 40개가 안 된다.**

| | 개수 | |
|---|---:|---|
| `tourism=viewpoint` 총 | **217** | `data/raw/pbf/poi.ndjson` (POI 13,003개 중) |
| 🔴 부산 행정경계 **밖** | **49** | 웅천왜성·제포성지·망산도(진해) · 초선대 마애불(김해) 등 |
| 부산 안 | 168 | |
| ↳ 이름조차 없음 | **101** | 좌표만 있는 점 |
| ↳ 이름 있음 | 67 | |
| ↳↳ 노거수(보호수) | **18** | 팽나무·느티나무·푸조나무·회화나무 … |
| ↳↳ 나무 아님 | **49** | 여기에도 천성진성·가덕진성·두문지석묘·진지동굴이 섞여 있다 |

`config/boundary.geojson` 으로 점-다각형 판정해 센 값이다.

**왜 이렇게 되나.** OSM 의 `tourism=viewpoint` 는 *"여기서 뭔가 볼 만하다"* 정도의 태그이고
**누구나 달 수 있으며 인기 기준도 심사도 없다.** 그래서 노거수와 성곽이 같은 태그를 단다.
**POI 는 좋은 곳이 아니라 갈 수 있는 곳**이라는 성질이 그대로 드러난 것이다.

> 🔴 **이 표가 드러낸 별개의 결함 — POI 추출에 행정경계가 안 걸려 있다.**
> `WALKABILITY.md` 가 *"부산 행정경계 적용 — 구간 35.1% 제거"* 라고 적어 둔 것은
> **길 구간** 얘기였다. **POI 에도 같은 문제가 있다** — 추출이 bbox(사각형)로 잘려서
> 진해·김해·양산이 딸려 들어왔다. viewpoint 만 보면 **23%** 다. 전체 POI 13,003개 중
> 얼마가 밖인지는 아직 안 세었다. 고칠 곳은 이 문서가 아니라 `collect/pbf_extract.py` 다.

**그래서 쓰는 법.** 추천 후보 목록으로 쓰지 않는다. **가시권 계산을 검증할 대조점**으로 쓴다 —
*"사람이 전망대라 부르는 곳인데 우리 계산도 트였다고 나오는가"* 를 재는 것이다.

> 작은 수확 하나 — **217개 중 37개에 `direction` 태그가 있다.** 그 전망대가 어느 방위를
> 보는지다. 0절이 뷰의 축을 셋(어디서·어느 방향·무엇이)이라고 했는데 그중 **"어느 방향"**
> 이 이미 데이터에 있다. 37개뿐이지만 계산 결과를 대조할 정답지로는 쓸 수 있다.

## 3. 서버 — 이미 준비해 뒀다

전역 작업을 각자 노트북에서 하지 않는다. 서버에서 받고 뽑고, **원본은 지우고
산출물만 남긴다.** 그러면 매일 갱신되는 PBF 사본을 붙들 필요도 없다.

| | |
|---|---|
| 접속 | `ubuntu@j15e201.p.ssafy.io` (SSAFY 기본 계정. `E201` 계정은 **없다**) |
| 사양 | 4코어 · 15GB · **여유 303G** |
| 작업 폴더 | `~/axmap-viewshed/` |
| 도커 이미지 | **`axmap-osm:1`** — python3.12 + pyosmium 4.3.1 |
| 받는 스크립트 | `~/axmap-viewshed/fetch.sh` |

> 🔴 **이미지에 `libexpat1` 을 넣어야 한다.** 없으면 `import osmium` 이
> `libexpat.so.1: cannot open shared object file` 로 죽는다. `python:3.12-slim`
> 에는 없다. Dockerfile 에 이유와 함께 적어 뒀다.

> 🔴 **`pkill -f <문자열>` 을 SSH 로 보낼 때 조심한다.** 그 문자열이 명령줄에
> 들어 있으면 **자기 세션까지 죽인다.** 실제로 두 번 조용히 죽었다.
> 그래서 URL 을 `fetch.sh` 로 빼내 실행한다.

## 6. 못 한 것 · 정하지 못한 것

1. **`Vista` 의 필드 이름을 확정하지 않았다.** 위 예시는 제안이고,
   실제 데이터를 보기 전에 정하지 않는다 (ONTOLOGY.md 5절 원칙)
2. **가시권 계산 비용을 재보지 않았다.** "경로 표본만" 이 실제로 얼마나 가벼운지
   측정해야 안다
3. **야간 가시성**(광안대교 조명 점등 등)은 낮 가시권과 다른 문제다. 손대지 않았다
4. **랜드마크 3D 형상**을 확보하지 않았다
5. **바다 면 vs 육지 마스크** 중 무엇으로 갈지 정하지 않았다 (2.4 참고)
6. **강수**는 여전히 없다. 기온만 있다 (ONTOLOGY.md 7절과 같은 항목)
