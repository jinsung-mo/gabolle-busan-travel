# 해운대 → 광안리: 그늘을 고려하면 얼마를 더 걷고 얼마를 얻나

**2026-09-01 실측.** 산출물은 `data/staged/shade-route-<시각>.json` 이고, 이 문서는
**왜 이렇게 쟀는지와 무엇을 배웠는지**다.

```bash
node process/shadow.mjs                     # 구간별·시각대별 그늘 (먼저)
node process/shade-route.mjs --hour 17      # 두 경로와 곡선
```

---

## 1. 🔴 왜 네이버·카카오와 비교하지 않았나

두 가지다.

**① 못 한다.** 공개된 **보행자** 경로 API 가 없다. 카카오는 2026-08-13 공식 답변으로
지도 데이터의 2차 가공이 **약관 위배**다.

**② 해도 답이 안 나온다.** 남의 도로망과 우리 도로망이 다르면, 두 선의 차이가
*"우리가 그늘을 고려해서"* 인지 *"애초에 다른 길을 알고 있어서"* 인지 **구별할 방법이
없다.** 게다가 남의 API 가 준 선에는 **way id 가 없어서** 어느 구간이 왜 골라졌는지
말할 수 없다 — 우리 제품의 핵심이 그건데.

**그래서 같은 그래프 위에서 비용 함수만 바꿨다.** 지도도 데이터도 같고 바뀌는 것이
하나뿐이면, 차이는 그 하나 때문이다.

```
비용 = 길이 × (1 + λ × (1 − 그늘비율))
       λ=0 이면 순수 최단거리.  λ 를 키우면 볕을 피해 돌아간다.
```

## 2. 🔴 그늘 %만으로는 "유용한가" 에 답 못 한다

그늘을 10%p 더 얻으려고 800m 를 더 걷는다면 좋은 경로가 아니다.
그래서 숫자 하나가 아니라 **λ 를 0→8 로 키우며 곡선**을 낸다.
어느 점이 좋은지는 사람마다 다르고, **그것은 짝 비교 실험([FIELD-STUDY.md](FIELD-STUDY.md))의 몫**이다.

## 3. 실측 — 2026-09-01 · 여름(7/15) 기준 · **OSM 건물**

출발·도착은 좌표를 손으로 적지 않고 **추출본에서 이름으로** 확정했다
(해운대해수욕장 · 광안리해수욕장). 최단거리는 어느 시각이든 같은 길이다.

| 시각 | 해 고도 | 최단 경로의 그늘 | 그늘 우선 | 더 걷는 거리 | 얻는 그늘 |
|---|---|---|---|---|---|
| 9시 | 42.5° | 6.1% | 25.4% | +274m (6.7%) | **+19.3%p** |
| **12시** | **74.9°** | **0.0%** | **0.6%** | +4m (0.1%) | **+0.6%p** |
| 15시 | 54.5° | 4.8% | 14.0% | +321m (7.8%) | +9.2%p |
| **17시** | 30.1° | 15.9% | 30.8% | **+212m (5.2%)** | **+14.9%p** |
| 18시 | 18.1° | 25.4% | 54.0% | +1,167m (28.4%) | +28.6%p |

### 🔴 배운 것 셋

**① 정오에는 이 기능이 할 일이 없다.** 해가 거의 머리 위라 60m 건물의 그림자가
16m 밖에 안 된다. 최단 경로의 그늘이 **0%** 이고, 아무리 돌아도 **0.6%** 다.
**이건 실패가 아니라 결과다** — 화면에서 정오에는 이 옵션을 꺼야 한다는 뜻이다.

**② 17시가 가장 값싸다.** 5% 더 걸어 그늘이 거의 **두 배**가 된다. 반면 18시는
28.6%p 를 얻지만 **1.17km(약 15분)를 더 걷는다.** 같은 "그늘을 얻는다" 라도
치르는 값이 완전히 다르다.

**③ 곡선이 계단 모양이고 결국 포화한다.** λ 를 키워도 한동안 같은 경로가 나오다가
어느 지점에서 뚝 바뀐다 — 도시 격자에서 대안 경로가 유한하기 때문이다.
그리고 **더 내도 더 살 것이 없는 천장**이 있다.

## 4. 🔴 이 숫자를 믿을 때 주의할 것

| | |
|---|---|
| **건물이 OSM 이다** | GIS건물통합정보(472,608동)가 이 PC 에 없어 전국 PBF 에서 직접 뽑았다 — **부산 52,556동, 층수 보유 30.7% · 높이 태그 2.1%.** 높이를 모르는 건물은 그림자를 안 만든다. **그늘이 실제보다 적게 나왔을 것이다** |
| **가로수가 빠졌다** | 여름 그늘의 큰 몫이다. 데이터(778개소 18만 그루)는 있는데 키가 아직 없다 |
| **날짜가 7/15 고정** | 겨울은 답이 다르다. 🔴 그런데 **겨울 날짜를 넣으면 종료 코드 1 로 죽는다**(`S15P21E201-523`) |
| **모름을 평균으로 뒀다** | 0(볕)으로 치면 라우터가 측정 안 된 길을 **전부 피하고**, 1(그늘)로 치면 반대로 몰린다. 둘 다 *데이터가 없다*를 *선호*로 바꿔치기하는 것이다. 이번 경로에서는 **모름이 0%** 라 영향이 없었다 |

**GIS건물과 가로수가 들어오면 위 표는 전부 바뀐다.** 그때 다시 재고, **이 표는
지우지 말고 날짜와 함께 남긴다** — 다음 사람이 같은 것을 다시 재보지 않게.

## 5. 아직 안 한 것

| 경사·계단과 함께 보기 | 지금은 그늘만 본다. 그늘을 얻으려고 언덕을 오르면 손해일 수 있다 |
| 다른 구간 | 해운대→광안리 하나뿐이다. 산복도로처럼 지형이 센 곳은 답이 다를 것이다 |
