# 현장 실험 설계 — 해운대·광안리에서 외국인에게 물을 때

**결정한 사람: Claude (2026-08-27 새벽, 사용자 취침 중). 아침에 뒤집어도 된다.**
근거를 다 적어 두었으니 어디를 뒤집을지 고르기 쉬울 것이다.

---

## 0. 먼저 — 이 실험이 답해야 하는 질문은 하나다

우리는 이미 경사를 계산할 수 있다 (`process/slope.mjs`, 전역 67,676구간).
계단 단수도 추정한다 (617곳 20,106단). BIMS 로 버스 소요시간 분포도 쌓기 시작했다.

**모르는 것은 데이터가 아니라 가중치다.**

> 12% 경사 200m 와, 평지 500m 우회와, 버스 환승 1회 중
> **외국인 관광객에게 어느 것이 더 싼가?**

이 질문에 답이 없으면 우리가 만든 모든 숫자는 지도 위의 장식이다.
그래서 현장 실험의 목표는 **데이터 수집이 아니라 가중치 추정**이다.

## 1. 투표인가 앱 텔레메트리인가 — 둘 다 쓰되 역할이 다르다

| | 투표(물어본 것) | 텔레메트리(한 것) |
|---|---|---|
| 경제학 용어 | 진술선호 (stated preference) | 현시선호 (revealed preference) |
| 얻는 것 | **왜** 그렇게 고르는가 · 우리가 관측 못 하는 이유 | **실제로** 무엇을 골랐나 |
| 약점 | 말과 행동이 다르다. 예의상 답한다 | 왜 그랬는지 모른다. 대안을 못 본다 |
| 표본 | 한 사람에게 여러 번 물을 수 있다 | 한 사람이 한 경로만 간다 |

🔴 **핵심은 마지막 줄이다.**

하루에 만날 수 있는 외국인은 현실적으로 **20~50명**이다.
텔레메트리만 쓰면 **표본이 사람 수만큼**이다 — n=30. 아무것도 못 한다.

그런데 **한 사람에게 경로 두 개를 나란히 보여주고 고르게 하면**, 한 사람이
12번 고를 때 관측은 **360개**가 된다. 같은 하루에 표본이 12배가 된다.

이것이 이 설계의 전부다. 나머지는 이 결론의 각주다.

## 2. 그래서 무엇을 하나 — 짝 비교(선택 실험)

**Discrete Choice Experiment** — 대안 두 개를 나란히 놓고 하나를 고르게 하는 방법.
마케팅·교통 연구에서 "얼마나 싫은가" 를 돈 단위 없이 재는 표준 도구다.

### 화면 한 장에 이것만 보여준다

```
        A                          B
   ┌──────────────┐          ┌──────────────┐
   │ 12분 걷기     │          │ 18분 걷기     │
   │ 오르막 있음   │          │ 평지          │
   │ 계단 40단     │          │ 계단 없음     │
   └──────────────┘          └──────────────┘
        어느 쪽으로 가시겠어요?
```

- 한 사람당 **10~14쌍**. 그 이상은 집중력이 떨어져 답이 랜덤해진다
- 각 쌍은 **속성 3~4개만** 다르게 한다 (도보시간 · 경사 · 계단 · 환승)
- 속성 조합은 미리 만들어 둔다 (직교배열). 즉석에서 지어내면 상관이 생겨 추정이 안 된다

### 왜 별점이나 "얼마나 힘드셨나요 1~5" 를 안 쓰나

`bigData/CLAUDE.md` 2절이 이미 정한 것과 같은 이유다 — **리뷰 별점을 신호로 쓰지 않는다.**
5점 척도는 사람마다 기준이 다르고(어떤 사람의 4점 = 다른 사람의 2점), 문화권마다
더 다르다. 외국인 대상이면 이 편향이 신호보다 크다.

**"둘 중 어느 쪽" 은 그 편향이 없다.** 기준이 자기 안에서만 비교되기 때문이다.

## 3. 앱 텔레메트리는 무엇을 받나 — 세 가지만

물어서 알 수 없는 것만 받는다. 물어서 알 수 있는 것을 몰래 받으면 그건 그냥 감시다.

| 무엇 | 왜 |
|---|---|
| **고른 경로와 그때 보여준 대안** | 짝 비교와 같은 구조라 같은 모델에 넣을 수 있다 |
| **중간 이탈 지점** | "여기서 포기했다" 는 물어봐도 기억 못 한다 |
| **구간별 실제 통과 시간** | 우리 추정 소요시간의 오차. 경사 보정과 같은 역할 |

🔴 **받지 않는 것**: 이름 · 연락처 · 정확한 GPS 궤적 · 사진 · 기기 식별자.
익명 세션 ID 하나만 만들고 그날 끝나면 버린다. 개인정보를 안 받으면 지킬 것도 없다.

동의는 영어 카드 한 장으로 받는다. 무엇을 받고, 왜 받고, 언제 지우는지 세 줄.

## 4. 모델을 처음부터 만들까, 통계 먼저 하고 고도화할까

### 🔴 통계 먼저다. 이건 취향이 아니라 표본 크기 문제다.

n=360 관측(30명 × 12쌍)으로 할 수 있는 것과 없는 것이 명확히 갈린다.

| | 필요 표본 | 지금 가능? |
|---|---|---|
| 조건부 로짓 (속성 4개 계수) | 수백 | ✅ **된다** |
| 혼합 로짓 (개인차까지) | 수천 | ❌ |
| 딥러닝 순위 모델 | 수만~ | ❌ |

속성 4개짜리 **조건부 로짓**이면 이런 문장이 바로 나온다:

> *"경사 8% 이상 100m 는 평지 걷기 240m 와 같다"*
> *"계단 50단은 환승 1회보다 싫다"*

이 한 줄이 곧 **경로 탐색의 비용함수**다. 그게 우리가 원한 것 전부다.
딥러닝으로 가도 결국 같은 것을 배우는데, 데이터가 100배 필요하다.

### 고도화는 데이터가 늘어난 뒤에

순서를 이렇게 잡는다. **각 단계는 앞 단계를 버리지 않고 감싼다.**

```
1단계 (지금)     짝 비교 → 조건부 로짓 → 비용함수 계수 4~6개
2단계 (n 늘면)   개인 특성(연령대·동반자)을 넣어 세그먼트별 계수
3단계 (앱 운영 뒤) 텔레메트리로 계수를 온라인 갱신
4단계            그때도 딥러닝이 필요한지 **다시 묻는다**
```

4단계에 물음표를 남긴 것은 게으름이 아니다. 계수 6개로 설명되는 현상에
딥러닝을 쓰면 **성능은 같고 설명은 사라진다.** 우리 제품은 "왜 이 길인가" 를
말해야 하는 제품이다.

## 5. 표본을 어디서 얼마나

| | |
|---|---|
| 장소 | 해운대·광안리 (외국인 밀도가 높다) |
| 목표 | **30명 이상** · 1인 10~14쌍 → 관측 300~420 |
| 시간대 | 오후~초저녁. 이동 중인 사람보다 앉아 있는 사람이 답한다 |
| 소요 | 1인 3~5분. 그 이상이면 도중에 그만둔다 |

🔴 **해운대·광안리는 평지다.** 우리가 재려는 것은 경사인데 표본을 평지에서 받는다.
그래서 **화면으로 물어야 한다** — 실제로 걷게 하면 안 된다. 짝 비교가 화면 실험인
이유가 이것이기도 하다.

⚠️ 여기서 나온 계수는 **"해운대에서 쉬고 있는 외국인" 의 것**이다. 산복도로를
실제로 오르는 사람의 것이 아니다. 그 차이는 2차 실험(중구·동구 현장)에서 확인한다.
지금 적어 두지 않으면 나중에 이 계수를 전체 관광객의 것으로 착각한다.

## 6. MLOps — 여기서는 "모델 배포" 가 아니다

표본 400개짜리 로짓 모델에 서빙 인프라를 붙이는 것은 과잉이다.
이 단계에서 MLOps 가 실제로 막아야 하는 사고는 셋이다.

| 사고 | 막는 장치 |
|---|---|
| **어떤 데이터로 낸 숫자인지 모른다** | 실행마다 입력 해시·커밋·시각을 `_run.json` 에 남긴다 |
| **다시 돌리면 다른 값이 나온다** | 같은 입력 → 같은 출력. 무작위는 시드를 기록 |
| **그럴듯한데 틀린 값이 통과한다** | 계수 부호·유의성을 종료 코드로 검사 |

세 번째가 제일 중요하다. `bigData/CLAUDE.md` 7절이 이미 겪은 그것이다 —
*"bigData 가 죽는 방식은 화면이 깨지는 게 아니라 그럴듯한 숫자가 나오는 것"*.

경사에서 p90 을 쓰고 보정을 넣은 것과 **똑같은 방어를 모델에도 건다**:

- 경사 계수가 **양수면 실패한다** (오르막이 좋다는 뜻이 되므로)
- 도보시간 계수가 **0 과 구별 안 되면 실패한다** (실험이 작동하지 않았다는 뜻)
- 학습에 쓴 응답자로 검증하면 **실패한다** (사람 단위로 홀드아웃한다)

구현은 `bigData/mlops/` 에 있다. 모델 코드보다 **검사 코드가 먼저** 들어간다.

## 7. 내일 아침에 할 수 있는 것

```bash
npm --prefix bigData run choice:design    # 짝 비교 문항을 만든다 (직교배열)
npm --prefix bigData run choice:fit       # 응답이 있으면 계수를 추정한다
npm --prefix bigData run verify           # 위 검사들
```

응답 데이터가 없으면 `choice:fit` 은 **조용히 통과하지 않고** 없다고 말하고 멈춘다.
`collect/` 가 없는 것을 만들어내지 않는 것과 같은 태도다.
