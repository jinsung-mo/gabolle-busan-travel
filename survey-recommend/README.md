| **선택 사항 값**(`.env`) | *비밀번호처럼 코드에 적으면 안 되는 값을 담는 파일.* 커밋하지 않는다 |

## 1. 🔴 이 설문은 **자유 입력 칸이 있다**. 앞 설문은 없었다

[`docs/SURVEY-CONSENT.md` 1.2](../docs/SURVEY-CONSENT.md#12--안-모으는-것--이쪽이-더-중요하다) 는
*"자유 입력 칸이 하나도 없다 — 자유 입력은 사람이 스스로 신원을 적어 넣는 가장 흔한 경로다"*
라고 못 박아 뒀다.

**이 설문은 그 규칙을 이 설문에 한해서 푼다.** "왜 추천하는지" 를 안 받으면
남는 것은 장소 이름 목록뿐이고, 그건 인터넷에도 있다. **"왜" 가 이 설문의 본체다.**

규칙을 푸는 대신 **보호 장치 넷**을 넣었다. 넷 다 없으면 풀면 안 되는 규칙이었다.

| # | 무엇 | 어디에 |
|---|---|---|
| **①** | 자유 입력 칸 **위마다** 한 줄 — *"장소 이름만 적어 주세요. 사람 이름 · 연락처 · 소속을 적지 마세요"* | `index.html` 의 `.guard` |
| **②** | 제출을 **막는다.** 전화번호 · 이메일(`@`) · 8자리 넘게 이어진 숫자가 있으면 **어느 유형의 어느 칸인지** 말해 준다 | `index.html` 의 `PII` **와** `server.mjs` 의 `PII` — **두 벌이다** |
| **③** | **IP · 브라우저 정보 · 기기 식별자를 안 남긴다.** 서버가 읽지도 않고, 표에 칸도 없고, nginx 접속 기록도 이 경로만 끈다 | `server.mjs` · `schema.sql` · nginx `access_log off` |
| **④** | 이름 · 연락처 · 이메일 · 소속 반 · 학번을 **묻는 칸을 아예 안 만든다** | 화면에 그런 입력칸이 없다 |

> 🔴 **②의 검사는 화면과 서버 양쪽에 있고, 두 벌은 같아야 한다.**
> 화면에만 두면 주소창으로 직접 보내는 것을 못 막는다. 서버에만 두면 사람이
> 다 적은 뒤에야 거절당해서 처음부터 다시 적는다. **고칠 때 한쪽만 고치지 않는다.**

## 2. 🔴 왜 유형에 "야간" 과 "축제" 가 없나

장소 유형은 **일곱**이고 이 순서를 바꾸지 않는다.

```
1 맛집·로컬 음식   2 카페·디저트   3 자연·바다·산책   4 문화·역사·전시
5 시장·골목·쇼핑   6 체험·액티비티  7 술집·바
```

**"야간" 과 "축제" 를 여기에 넣지 않았다. 실수가 아니라 이 설문에서 가장 중요한 판단이다.**

| | 왜 유형이 아닌가 | 그래서 어디로 갔나 |
|---|---|---|
| **야간** | 야간은 **장소의 종류가 아니라 시간**이다. 밤에 좋은 술집도, 밤에 좋은 바다도, 밤에 좋은 시장도 있다 | 칸 3번 **"언제 가면 좋아요?"** (낮 / 밤 / 상관없음) |
| **축제** | 축제는 **날짜가 있는 사건**이다. 같은 광안리가 어느 주에는 축제고 다음 주에는 그냥 바다다 | 칸 4번 **"기간이 정해진 곳이에요"** 체크 |

섞으면 무엇이 망가지나 — **나중에 개인화를 할 때 "이 사람이 술을 좋아하는지
야경을 좋아하는지" 를 구분할 수 없다.** "야간" 을 고른 사람 안에는 술집을 좋아하는
사람과 밤바다를 좋아하는 사람이 섞여 있고, 한 칸으로 받으면 **그 둘은 영원히 안 갈린다.**
받아 놓은 데이터를 나중에 쪼갤 수는 없다 — 처음에 쪼개서 받아야 한다.

## 3. 화면이 지키는 것

**① 칸이 다섯이다. 유형이 일곱인 게 아니다.**
카드 다섯 장을 세로로 늘어놓고, 누르면 그 아래로 입력 칸이 펼쳐진다(아코디언).
펼치면 **맨 위에 유형 고르는 줄**(일곱 개 알약)이 있고 그 아래 나머지 칸이 온다.
위쪽에 `2 / 5` 로 몇 개 채웠는지 보여 준다.

> 🔴 **다섯 칸이 전부 같은 유형이어도 된다.** 맛집만 다섯 곳이어도 받는다.
> 처음에는 유형 카드 일곱 개에 한 곳씩 받았는데, 그러면 **맛집을 다섯 곳 아는
> 사람이 한 곳만 적게 된다.** 우리가 가장 원하는 응답이 네 곳 잘려나간다.
> 그래서 2026-09-08 에 칸 다섯 개로 바꿨고, `schema.sql` 의
> `UNIQUE (response_id, place_type)` 제약도 **같이 걷어냈다** — 그 제약이 남아 있으면
> 화면이 아무리 허용해도 **데이터베이스가 다섯 번째 맛집을 거절한다.**

**①-1 유형을 고르기 전에는 그 칸의 나머지가 흐리고 안 눌린다.**
유형이 그 칸의 나머지를 읽는 틀이라 먼저 정해야 한다. 안 막으면 이름만 적고
유형은 빈 칸이 생기고, 그건 세지도 쓰지도 못한다.

**①-2 잘못을 말할 때 유형 이름이 아니라 칸 번호로 말한다.**
유형은 겹칠 수 있다. 다섯 칸이 전부 "맛집" 이면 *"맛집 칸을 고쳐 주세요"* 는
어느 칸인지 못 가린다. 그래서 화면도 서버도 **"3번째 추천의 …"** 라고 말한다.

**② 흑백만 쓴다. 강조색이 없다.**
색을 하나라도 넣으면 사람은 색이 있는 쪽을 먼저 누른다. "골랐다" 는 색이 아니라
**밝기의 반전**(검정 바탕 + 흰 글자)으로만 말한다.

**③ 폰이 어두운 모드여도 이 화면은 흰 종이다** (`color-scheme: light`).
흑백 화면을 그대로 뒤집으면 "골랐다" 와 "안 골랐다" 가 서로 자리를 바꿔서
무엇이 선택된 것인지 알 수 없게 된다.

**④ 글자 크기를 16px 아래로 안 내린다** (입력칸). iOS 사파리는 그보다 작으면
칸을 누를 때 화면을 확대하고, 확대된 채로 돌아오지 않는다.

**⑤ 제출 전에는 아무것도 저장하지 않는다.** 브라우저에도 안 남긴다.
남기면 *"제출 전에는 아무것도 저장되지 않습니다"* 라는 고지가 거짓이 된다.

**⑥ 바깥에서 아무것도 안 받아 온다.** 글꼴 · 이미지 · 스크립트가 전부 파일 안에 있다.
팀 서버 nginx 가 `Content-Security-Policy`(**이 페이지가 어디서 무엇을 받아올 수
있는지 브라우저에 알려주는 규칙**)로 바깥 글꼴을 막아 두었다 — 넣으면 조용히 안 뜬다.

**⑦ 화면이 응답을 거르지 않는다.** 개인정보 검사만 막고, 성의 없는 답은 그대로 받는다.
거르는 기준은 나중에 바뀌지만 **안 받은 데이터는 못 만든다.**

## 4. 응답 한 건이 표에 들어가는 모양

응답 1건 = `response` **한 줄** + `recommendation` **다섯 줄** (외래키로 이어진다).

```
response                                recommendation  (5줄)
┌──────────────┬───────────────┐        ┌──────────────┬──────────────────────┐
│ id           │ 1             │◀──┐    │ response_id  │ 1                    │
│ submitted_on │ 2026-09-08    │   └────│ slot         │ 1 … 5                │
│ age_band     │ AGE_25_29     │        │ place_type   │ FOOD · CAFE · …      │
│ busan_years  │ Y_3_10        │        │ place_name   │ "부평깡통시장"        │
│ consented    │ true          │        │ when_good    │ DAY · NIGHT · ANY    │
│ nonce        │ "kQ3f…"       │        │ limited_time │ false                │
└──────────────┴───────────────┘        │ reason       │ "왜 좋은지 …"         │
                                        └──────────────┴──────────────────────┘
```

| 왜 이렇게 | |
|---|---|
| **`submitted_on` 이 날짜까지만이다** | 나이대 + 거주기간 + **정확한 시각**을 합치면 좁은 집단에서는 한 사람으로 좁혀진다. 시:분:초는 우리에게 쓸모가 없고 재식별에는 쓸모가 있다 |
| **`nonce` 는 사람을 안 가리킨다** | 같은 응답이 두 번 들어왔는지만 본다. 브라우저마다 다르게 만드는 값이 아니라 **서버가 매번 새로 만드는 난수**다 |
| **`consented` 에 "누가" 가 없다** | 동의를 저장하려면 누가 동의했는지를 남겨야 하고, 그건 익명을 깬다. 눌렀다는 사실만 남긴다 |
| **IP · User-Agent 칸이 없다** | **칸이 있으면 언젠가 누군가 채운다.** 안 채우는 것보다 칸을 안 만드는 것이 확실하다 |
| **다섯 줄이 따로 있다** | 한 줄에 다섯 곳을 밀어 넣으면 `place_type` 으로 세는 것부터 못 한다 |

## 5. 로컬에서 띄우고 확인하기

```bash
cp survey-recommend/.env.example survey-recommend/.env
# POSTGRES_PASSWORD 를 채운다. 손으로 짓지 말고:  openssl rand -base64 24

cd survey-recommend
docker compose up -d --build
```

→ <http://127.0.0.1:3100/>

들어갔는지 **눈으로 말고 데이터로** 확인한다. 화면이 "고맙습니다" 라고 말하는 것은
증거가 아니다.

```bash
docker exec -i survey-postgres psql -U survey -d survey -c \
  "SELECT r.id, r.age_band, count(c.*) AS 추천수
     FROM response r JOIN recommendation c ON c.response_id = r.id
    GROUP BY r.id ORDER BY r.id;"
```

개인정보 검사가 **실제로 막는지**도 확인한다 (막히면 400 과 어느 칸인지가 온다).

```bash
curl -sS -X POST http://127.0.0.1:3100/api/submit \
  -H 'content-type: application/json' \
  --data '{"consented":true,"ageBand":"AGE_25_29","busanYears":"Y_3_10","recommendations":[
    {"placeType":"FOOD","placeName":"010-1234-5678","whenGood":"DAY","limitedTime":false,"reason":"x"}]}'
```

내릴 때:

```bash
docker compose down          # 볼륨은 남는다 (응답이 지워지지 않는다)
docker compose down -v       # 🔴 볼륨까지 지운다 = 응답이 사라진다
```

## 6. 팀 서버에 올리기

```bash
ssh -i <키> ubuntu@j15e201.p.ssafy.io
cd ~/survey-recommend && docker compose up -d --build
```

nginx 는 **경로 하나만** 더 본다. 기존 블록은 손대지 않는다.

```nginx
# /etc/nginx/sites-available/default 의 443 서버 블록 안
location /survey {
    access_log off;                       # 🔴 누가 언제 들어왔는지를 안 남긴다
    proxy_pass http://127.0.0.1:3100;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

| 🔴 함정 | |
|---|---|
| **`X-Real-IP` · `X-Forwarded-For` 를 안 넘긴다** | 다른 블록은 다 넘기지만 여기서는 뺐다. 넘기면 앱이 참여자 IP 를 **알게 된다.** 안 쓸 값을 굳이 건네지 않는다 |
| **`access_log off`** | 안 끄면 nginx 기록에 `IP + /survey/ + 시각` 이 남는다. 응답에 IP 를 안 넣는 의미가 없어진다 |
| **`add_header` 를 여기에 안 쓴다** | nginx 는 어느 자리에 `add_header` 가 하나라도 있으면 **위에서 물려받은 헤더를 전부 버린다.** 하나 넣는 순간 이 경로만 보안 헤더가 사라진다 |
| **경로에 슬래시가 없다 (`/survey`)** | 블록 하나로 `/survey` 와 `/survey/` 를 다 받으려고. 슬래시 정리는 앱이 301 로 한다 — 슬래시 없이 열리면 화면 안의 `api/submit` 이 `/api/submit` 으로 풀려서 **운영 백엔드로 날아간다** |
| **`proxy_pass` 끝에 슬래시가 없다** | 있으면 nginx 가 `/survey` 를 떼고 넘긴다. 지금은 안 떼고 넘기며 **앱이 `MOUNT_PATH` 로 떼어 낸다.** 어느 경로에 붙여도 화면이 그대로 돈다 |

고치기 전에 **반드시 백업하고**, `sudo nginx -t` 가 통과할 때만 `reload` 한다.

```bash
sudo cp /etc/nginx/sites-available/default ~/nginx-default.bak.$(date +%F-%H%M)
sudo nginx -t && sudo systemctl reload nginx
```

올린 뒤 **셋 다** 확인한다 — 내 것만 보고 끝내지 않는다.

```bash
curl -sS -o /dev/null -w "survey %{http_code}\n" https://j15e201.p.ssafy.io/survey/
curl -sS -o /dev/null -w "front  %{http_code}\n" https://j15e201.p.ssafy.io/
curl -sS -o /dev/null -w "back   %{http_code}\n" https://j15e201.p.ssafy.io/api/actuator/health
```

> 🔴 **서버에 이미 도는 `local-route-personalization-postgres-1` 을 쓰지 않는다.**
> 그건 운영 백엔드와 같이 쓰는 데이터베이스고, 설문 하나 때문에 서비스가 죽은 날이 있었다.
> 이 묶음은 컨테이너(`survey-postgres` · `survey-app`) · 볼륨(`survey-pgdata`) ·
> 네트워크(`survey-net`)를 **전부 새로** 만든다. 나눠 쓰는 것이 하나도 없다.

| | |
|---|---|

| 모으는 것 | 나이대 · 부산 거주기간 · 추천 장소 다섯 곳과 그 이유 |
| 안 모으는 것 | 이름 · 연락처 · 이메일 · 학번 · 소속 반 · IP · 위치 · 기기 정보 |
| 두는 곳 | 팀 서버의 **이 설문 전용 데이터베이스**. 운영 서비스와 분리 |

`CONFIG` 에 `정해야 함` 이 하나라도 남아 있으면 **화면 맨 위에 경고가 뜬다 —
참여자에게도 보인다.** 그게 안전장치다 ([`survey-place`](../survey-place/README.md) 와 같은 방식).

지우는 날이 오면:

```bash
docker exec -i survey-postgres psql -U survey -d survey -c \
  "DELETE FROM response WHERE submitted_on < CURRENT_DATE - INTERVAL '1 year';"
# recommendation 은 ON DELETE CASCADE 로 같이 지워진다
```

지운 날짜를 팀 문서에 적는다.

## 8. 이 설문이 아직 안 하는 것

| 안 하는 것 | 왜 |
|---|---|
| 영어 화면 | 이번 표본은 SSAFY 한국인이다 |
| 다섯 곳보다 많이 · 적게 받기 | 칸이 딱 다섯이다. 여섯 곳을 알아도 다섯만 받고, 네 곳만 알면 못 낸다 |
| 중복 제출 막기 | 같은 사람이 두 번 낼 수 있다. 막으려면 사람을 구분해야 하고, 구분하는 순간 익명이 아니다. `nonce` 는 **같은 요청이 두 번 도착한 것**만 본다 |
| 응답 내려받기 화면 | `psql` 로 뽑는다. 화면을 만들면 그 화면을 누가 볼 수 있는지를 또 정해야 한다 |
| 접근성 검수 | 큰 글씨 · 44px 터치 영역 · 대비는 신경 썼지만 화면 낭독기로 확인하지 않았다 |
| 기관 심의 확인 | 🔴 [`docs/SURVEY-CONSENT.md` 3.3](../docs/SURVEY-CONSENT.md#33-이-설문이-기관-심의를-받아야-하나) 과 같은 상태다. 사람이 확인해야 한다 |
