# axMap MCP 서버

AI 도구(Claude Code 등)가 **"나는 이 파일들을 건드리겠다"를 선언하게** 만든다.
선언이 있어야 뷰어가 지금 무슨 일이 일어나는지 보여줄 수 있다.

## 붙이는 법

작업할 저장소에 `.mcp.json` 을 두거나, 도구의 MCP 설정에 아래를 넣는다.

```json
{
  "mcpServers": {
    "axmap": {
      "command": "node",
      "args": ["<axMap 을 클론한 경로>/mcp/server.mjs"],
      "env": {
        "AXMAP_REPO": "<작업할 저장소의 절대 경로>",
        "AXMAP_AGENT": "claude-1",
        "AXMAP_ACTOR": "agent",
        "AXMAP_TTL": "45m"
      }
    }
  }
}
```

| 환경변수 | 뜻 |
|---|---|
| `AXMAP_REPO` | 대상 저장소. 여기에 `axmap init` 이 되어 있어야 한다 |
| `AXMAP_AGENT` | 이 에이전트의 이름. 여럿 붙일 때 서로 달라야 한다 |
| `AXMAP_ACTOR` | `agent`(대화형) / `background`(백그라운드) / `human` / `team` — 화면 색이 갈린다 |
| `AXMAP_TTL` | 기본 선점 시간 (기본 45m) |

### 🔴 이름은 사람마다 달라야 하고, 저장소에 커밋되면 안 된다

**저장소에 커밋되는 `.mcp.json` 에는 `AXMAP_AGENT` 를 적지 않는다.**
적는 순간 그 값이 clone 한 모두의 이름이 된다. 위 예시는 개인 설정용이다.

예전 이 저장소의 `.mcp.json` 은 이름이 없으면 모두에게 `claude` 를 줬다. 팀원 다섯이
clone 하면 장부에는 `claude` 라는 **한 명**만 존재하고, 겹침 판정은 자기 claim 을
겹침으로 보지 않으므로 다섯이 서로의 영역을 아무 경고 없이 덮어쓴다.
락이 조용히 다섯 명에게 발급된 것이고, 이 프로젝트가 fail-closed 로 막겠다고 한
바로 그 실패다. 그래서 그 줄을 지웠고 **기본 이름도 없앴다.**

서버는 이름을 이 순서로 정한다. 전부 없으면 **뜨지 않는다(exit 1).**

1. `AXMAP_AGENT`
2. `git config user.name`

배경과 규격은 [docs/SPEC.md](../docs/SPEC.md) 의 "에이전트 이름을 정하는 순서" 절에 있다.

## 도구

| 도구 | 언제 |
|---|---|
| `axmap_brief()` | 이 저장소에서 처음 일할 때 가장 먼저 |
| `axmap_init()` | 장부가 없을 때 한 번. 이미 있으면 아무것도 바꾸지 않는다 |
| `axmap_claim(paths, intent, task?)` | **파일을 고치기 전에 반드시.** intent 는 사람이 화면에서 읽는다 |
| `axmap_check(paths)` | 선언 없이 겹침만 미리 확인. 계획 세울 때 |
| `axmap_status()` | 지금 누가 무엇을 잡고 있나 |
| `axmap_release(paths?)` | 끝나면. 생략하면 전부 반납 |
| `axmap_renew()` | 길어질 때 TTL 연장 |

`axmap_claim` 이 거부되면(겹침) **재시도하지 말고 다른 작업으로 옮겨야 한다.**
같은 요청은 몇 번을 보내도 같은 답이 온다. 도구 설명에도 그렇게 적어두었다.

## 에이전트에게 줄 지시문

```
파일을 수정하기 전에 axmap_claim 으로 건드릴 경로를 선언하라.
거부되면 재시도하지 말고 겹치지 않는 다른 작업으로 옮겨라.
작업이 끝나면 axmap_release 를 호출하라.
```

## 🔴 남의 저장소에 붙일 때 — 프로그램은 여기, 데이터는 거기

`AXMAP_REPO` 를 다른 저장소로 두는 것이 **정상 사용**이다. 그때 무엇을 어디에서
잡느냐가 이 서버에서 가장 자주 틀리는 곳이고, 실제로 세 군데가 동시에 틀려 있었다.

| | 어디 | 왜 |
|---|---|---|
| `bin/axmap.mjs`, `tools/bus.mjs` | **axMap 쪽** | 실행할 프로그램이다. 대상 저장소에는 없다 |
| 장부 `.axmap/`, 쪽지함 `docs/bus/` | **대상 저장소 쪽** | 그 팀의 데이터다. 그 팀 저장소에 남아야 한다 |
| `axmap_brief` 가 읽는 문서 | **대상 저장소 쪽** | 대상을 설명해야 한다 |

`axmap_brief` 는 대상 저장소의 `CLAUDE.md`·`README.md`·`docs/` 만 읽고, 없으면
**없다고 말한다.** axMap 자신의 문서로 대신 채우지 않는다 — 낡은 지도는 없는 지도보다
나쁘고, 남의 지도를 자기 지도인 양 주는 것은 그보다 한 단계 더 나쁘다.

이 조합(`AXMAP_REPO ≠ axMap`)은 `test/mcp.test.mjs` 가 고정한다.
**자기 자신을 겨눠 놓고 시험하면 이 경로는 한 번도 안 돈다.**

## 설계

판정 로직을 여기서 다시 구현하지 않고 **`bin/axmap.mjs` 를 그대로 호출한다.**
두 경로가 갈라지면 장부를 믿을 수 없게 되기 때문이다.
관문 1(push CAS)과 관문 2(겹침 판정)가 CLI 와 완전히 동일하게 적용된다.

전송은 stdio + 줄바꿈 구분 JSON-RPC 2.0 이다. SDK 의존성 없이 직접 구현했다 —
폐쇄망에서 npm 설치 없이 돌아야 한다는 제약이 여기에도 적용된다.
