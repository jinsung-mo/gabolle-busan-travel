# GABOLLE 전체 화면 A-Z 테스트 지침서

이 문서는 실기기(또는 에뮬레이터)에서 앱을 **화면 하나도 빠짐없이** 훑기 위한 체크리스트다.
경로는 전부 `frontend/app/**/*.tsx` 실제 라우팅 파일과 그 안의 `router.push`/`router.replace`
호출을 직접 grep 해서 확인한 것이다 — 지어낸 화면·버튼 이름은 없다. 못 찾은 진입 경로는
아래 "고아 라우트" 절에 따로 모아뒀다.

## 0. 실행 전 원칙

- **두 계정 상태로 전부 두 번 돈다**: (a) 게스트(비로그인) (b) 로그인(스토어 리뷰어 계정).
  이 앱은 탭 다섯 개를 전부 게스트도 둘러볼 수 있게 만들어져 있고(`app/(tabs)/_layout.tsx`
  주석 참고), 화면마다 게스트 처리가 다르므로 **한 계정 상태로만 돌면 절반만 본 것**이다.
- **화면 판정은 항상 스크린샷으로**. `uiautomator dump` 는 가끔 몇 화면 뒤처진 채로 그럴듯한
  오답을 낸다 — 탭한 뒤 반드시 `adb exec-out screencap -p` 로 실제 변화를 확인한다.
  (메모리: `reference-android-device-sweep`, `reference-adb-path`)
- **좌표는 화면 캡처 표시 배율(예: 947×2000 로 보이면 실제 1080×2280 이므로 ×1.14)을 반드시
  반영한다.** 버튼이 안 눌리는 것 같으면 uiautomator 의 실제 bounds 중앙을 찍었는지부터
  의심한다 — 좌표 계산 실수를 진짜 버그로 착각한 전례가 있다.
- **뒤로가기는 화면마다 반드시 확인한다**: 화면 안의 「‹ 뒤로」류 단추와, 안드로이드
  하드웨어 뒤로가기 둘 다. `router.canGoBack() ? router.back() : router.replace(...)` 패턴이
  코드에 많이 보이는데, 스택이 얕을 때(딥링크로 바로 들어왔을 때 등) 대체 목적지로 잘 떨어지는지가
  포인트다.
- **한글 입력이 막는 지점**(예: 새 계정 회원가입의 한글 이름 등)은 시도하지 말고
  "한글 입력 불가로 확인 못 함"이라고 정직하게 남긴다. 지어내지 않는다.
- 확인 못 한 것은 반드시 "확인 못 함"으로 남긴다 (frontend/CLAUDE.md 규칙).

## 1. 첫 실행 / 온보딩 (앱을 지우고 새로 깔았을 때만 전체 재현 가능)

| 화면 | 경로 | 비고 |
|---|---|---|
| 진입점 | `/` (`app/index.tsx`) | 언어 선택, 데스크톱이면 `/age-gate` 로, 폰이면 `/app-intro` 로 |
| 앱 소개 | `/app-intro` | 도움말(`help`) 링크 있음 |
| 나이 확인 | `/age-gate` (`(auth)/age-gate.tsx`) | 통과하면 `/permissions` |
| 권한 안내 | `/permissions` (`(onboarding)/permissions.tsx`) | `publicPaths` 로 게스트도 접근 가능. 개인정보(`legal/privacy`) 링크 |
| 소비 성향 | `/spend-profile` | **로그인 필요**(`(onboarding)` 레이아웃이 `ProtectedRoute`) — 통과하면 `/taste-profile` |
| 취향 프로필 | `/taste-profile` | **로그인 필요** |

체크: 언어 전환이 화면 문구에 실제로 반영되는지, 뒤로가기로 이전 온보딩 단계로 돌아갈 때
입력값이 유지/초기화 중 어느 쪽인지, 권한 요청 다이얼로그(위치 등) 허용/거부 둘 다.

|---|---|
| 로그인 | `/sign-in` |
| 회원가입 | `/sign-up` |
| 비밀번호 찾기 | `/forgot-password` |
| 이메일 인증 | `/auth/email/verify` |
| 비밀번호 재설정 | `/auth/password/reset` |
| OAuth 연결(이미 있는 계정) | `/oauth-link` |
| OAuth 가입 완료 | `/oauth-signup` |

체크: 이메일/비번 틀렸을 때 오류 문구, 이미 가입된 이메일 안내(→ 로그인 링크로 이동),
`returnTo` 파라미터를 달고 로그인했을 때 원래 있던 화면으로 정확히 돌아가는지(회원가입/여러
화면에서 로그인을 누르면 `returnTo` 가 다 다르게 걸려 있다 — 코드에서 `router.push({pathname:'/sign-in', params:{returnTo:...}})` 호출부를 하나씩 다 확인),
비밀번호 「보기」토글, SNS 로그인 4종(Google/Apple/카카오/네이버) 버튼 각각 최소 한 번씩,
로그인 화면 뒤로가기.

## 3. 탭바 다섯 개 — 공통 확인 (S15P21E201-1554 재확인 포함)

`src/components/TabBar.tsx` 가 모든 탭 화면 하단에 뜬다. **이번에 고친 버그**: 안드로이드에서
탭바가 뒤에 깔린 스크롤 콘텐츠에 손짓을 뺏겨 탭 전환 자체가 안 되던 것(`elevation` 추가로 수정,
`S15P21E201-1554`). 아래를 **다섯 탭 전부에서, 스크롤을 여러 위치로 내린 상태 각각에서** 확인한다:

- 홈 탭에서 "지금 부산에서 남긴 기록" 카드 줄이 있는 위치 근처
- 각 탭에서 목록을 끝까지 내렸을 때(탭바 바로 위 마지막 항목)
- 다섯 탭 버튼(홈/피드/여행 만들기/내 여행/마이페이지) 전부 눌러서 실제로 화면이 바뀌는지
- 지금 있는 탭을 다시 누르면 아무 일도 안 일어나는지(의도된 동작, `TabBar.tsx` 주석 참고)
- 피드 화면에서 탭바가 지도 시트로 늘어났다 줄어드는 애니메이션 정상 여부

## 4. 홈 탭 (`/home`)

체크리스트: 상단 날씨 배지, 알림 종 아이콘(`/notifications`), 로고 탭(브랜드 로고 링크),
검색/시작 바(여행 계획 시작 — `/plan` 이동), 빠른 칩 3종("이번 주말 1박 2일" 등),
"지금 부산에서 남긴 기록" 카드 가로 스크롤과 카드 탭(피드 상세로 이동), "로컬 탐색" 섹션,
게스트일 때 상단 로그인 유도 배지, 첫 실행 코치마크(HomeCoach — 로그인 직후에만 뜰 수 있음).

## 5. 피드 탭 (`/feed`)

3개 상위 탭: 실시간 인기(HOT) · 맞춤 추천(FOR_YOU) · 내 피드(MINE) — 셋 다 게스트도 눌러볼 수
있다("내 피드"만 로그인 유도 카드). 각 탭에서:

- 카드의 좋아요·인용·저장 버튼 3개 — 누르고 **카운트 변화·토스트·저장됨 표시**로 실제 반영을
  확인(게스트면 좋아요·저장은 로그인 유도 모달, 인용은 게스트도 링크 복사+토스트가 뜬다 —
  `app/(tabs)/feed.tsx` 참고)
- "전체 / 내 근처" 필터, 정렬(최신/인기) 칩
- 카드 탭 → `feed/[id]` 상세 → 공동 작성자 화면(`feed/[id]/coauthors`)
- 글쓰기 진입(로그인 시 연필 FAB 또는 상단 입력창 → `feed/compose`, 게스트면 로그인으로)
- 지도 보기/접기 토글(피드 화면 안에서 탭바가 지도 시트로 자란다)
- 신고하기(다른 사람 글의 "⋯"), 언팔로우(팔로잉 중인 글의 "팔로잉" 배지)
- 뒤로가기: 상세 → 목록, 공동작성자 → 상세

## 6. 여행 만들기 위저드 (`/plan/*`)

**실제 컴포넌트는 `app/(plan)/*.tsx` 에 있고 `app/plan/*.tsx` 는 그걸 그대로 재수출하는
한 줄짜리 파일이다** — 화면 이름과 URL 이름이 다르다(예: `basics` 컴포넌트가 `/plan/basic`
URL 에 뜬다). 게스트도 끝까지 작성 가능, **서버 저장 직전(생성 실행)에만 로그인을 요구**한다.

| 단계 | URL | 파일 |
|---|---|---|
| 1. 질문 | `/plan` | `(plan)/questions.tsx` |
| 2. 기본 정보 | `/plan/basic` | `(plan)/basics.tsx` |
| 3. 취향 | `/plan/taste` | `(plan)/taste.tsx` |
| 4. 제약조건 | `/plan/conditions` | `(plan)/constraints.tsx` |
| 5. 확인 | `/plan/confirm` | `(plan)/confirm.tsx` |
| 6. 생성 중 | `/plan/generating` | `(plan)/generating.tsx` |

체크: 각 단계의 필수/선택 항목, 뒤로 가서 값이 유지되는지, 앱을 강제 종료했다가 다시 열었을 때
작성 중이던 답이 복원되는지(초안 저장), 날짜 없이 다음 단계로 못 가게 막는지(`S15P21E201-1337`
가 고친 것), 생성 화면에서 게스트가 최종 실행을 누르면 로그인으로 튕기는지(어떤 안내 문구와
함께인지 — 이전 스윕에서 "안내 없이 조용히 튄다"는 지적이 있었다, 재확인), 생성 실패 시
"조건 다시 확인하기" 버튼, 코스 2·3안 미리보기(있다면) 및 선택.

## 7. 내 여행 탭 (`/trips`) 과 여행 상세

- 목록(`/trips`): 게스트 안내 카드("여행 만들기 둘러보기"/"로그인"), 빈 상태(여행 없음),
  "부슐랭"(`/collection`) · "새 여행"(`/plan`) 버튼, 트립 카드 탭.
- 여행 일정(`trips/[id]/itinerary.tsx`): Day 전환, 정류 카드 펼치기/접기, 도착·출발 찍기,
  순서 수정(재정렬 모드), 하단 고정 줄(순서 수정 등) — **`S15P21E201-1445` 가 고친
  탭바/내비게이션 바 가림 문제 재확인**, 상단 "동행 초대"(`/${id}/share`) · "참여자·역할"
  (`/${id}/collaborate`) · "날씨"(`/${id}/prepare`) 바로가기.
- 추천 코스(`trips/[id]/recommendations.tsx`): 코스 A/B/C 전환 탭, 지도, 코스 확정.
- 경로 상세(`/route-detail`): **앱 안에서 이 경로로 들어가는 버튼을 못 찾았다 — 고아 라우트
  절 참고, 직접 URL 이동으로만 확인 가능.**
- 날씨·준비물(`/${id}/prepare`, `(trip)/[id]/prepare.tsx`): **로그인 필요.** 기념품 목록으로
  가는 버튼이 있는데 **코드 주석상 "0곳이라 눌러도 항상 빈 목록만 나온다"는 알려진 상태** —
  버그로 새로 잡지 말고 그 문구가 실제로 그렇게 뜨는지만 확인.
- 동행 초대(`/${id}/share`): **로그인 필요.** 초대 링크 생성.
- 참여자·역할(`/${id}/collaborate`): **로그인 필요.** 초대 버튼(소유자만).
- 기념품(`/${id}/souvenirs`): **로그인 필요.** 앱 안에 진입 버튼이 없다(고아, 위 참고) —
  직접 URL 이동으로 접근.
- 활동 기록(`/${id}/log`), 여행 지도(`/${id}/map`, `(trip)/[id]/map.tsx`):
  **둘 다 로그인 필요, 앱 안에서 들어가는 버튼을 못 찾았다** — 고아 라우트 절 참고.
  (체크인 `/${id}/checkin` 은 예시만 있던 샘플 화면이라 지웠다 — S15P21E201-1661.)

## 8. 마이페이지 탭 (`/me`)

프로필 카드(기록·팔로워·팔로잉 숫자 — 게스트면 각각 로그인으로), 프로필 패널·기록 패널·
알림 패널·설정 열기, 도움말(`HelpBody` → `/help`), 약관(`TermsBody` → `legal/terms`,
`legal/privacy`, `legal/data-sources`, `legal/open-source`), 언어 설정, 로그아웃(확인 다이얼로그).
넓은 화면(태블릿 폭)과 폰 폭 레이아웃이 다르므로 **폭 두 가지 다** 확인.

## 9. 필드 도구 (`/field/*`)

| 화면 | 로그인 |
|---|---|
| 환율(`exchange-rate`) | 계산 자체는 게스트도, 상세 일부는 로그인 유도 |
| 메뉴 스캔(`menu-scan`) | 확인 필요 |
| 사투리(`dialect`) | 확인 필요 |
| 말하기(`speak`) | 확인 필요 — 택시카드(`taxi-card`) 링크 있음 |
| 대중교통(`transit`) | 로그인 유도 있음(코드 확인됨) |
| 번역(`translate`) | 확인 필요 |

체크: 각 도구 진입점을 홈/탐색 화면에서 실제로 찾아 들어간다(진입 버튼 위치를 먼저 찾고,
못 찾으면 "진입 경로 못 찾음"으로 남긴다 — 이 문서 작성 시점엔 홈/탐색 화면까지만 진입 경로를
확인했고 각 도구 개별 기능 버튼까지는 못 읽었다).

## 12. 공유·초대 링크 (로그인 없이 URL만으로 접근되는 것들)

- 공유 일정(`/s/[token]`): 로그인 없이 열람, "내 조건으로 새 여행 만들기" 버튼.
- 초대(`/invite/[token]`): 비로그인이면 로그인으로 튕기고 `returnTo` 로 돌아옴.
- 스토리 초대(`/story-invite/[token]`): 위와 동일 패턴.

토큰이 있어야 열리므로, 실제로 초대/공유를 발급하는 화면(여행 공유·글 인용 등)에서 만든
링크로 테스트한다. 유효하지 않은/만료된 토큰일 때 오류 화면도 확인.

## 13. 기타 단독 화면

- 알림(`/notifications`): 홈 종 아이콘·마이페이지 알림 패널에서 진입. 목록 항목 탭 시 이동.
- 챗봇(`/chat`): 도움말 링크 있음(`app-intro.tsx`), 대화 중 "일정에 적용하기" → `/plan` 이동.
- 관리자 신고함(`/admin/story-reports`): **앱 안에서 들어가는 버튼을 못 찾았다** — 관리자
  전용이라 원래 UI 진입점이 없을 수 있다. 존재 이유를 안다면 그 경로로, 모르면 "확인 필요"로.
- 없는 페이지(`+not-found`): 존재하지 않는 경로로 이동했을 때 실제로 뜨는지, 홈으로 돌아가는
  링크가 있는지.

## 14. 고아 라우트 — 앱 안에서 들어가는 버튼을 못 찾은 화면

grep 으로 `router.push`/`router.replace`/`href` 전체를 뒤졌을 때 아래는 **호출부가 하나도
없었다.** 버그가 아니라 "이 문서를 쓴 시점에 진입 경로를 못 찾았다"는 뜻이니, 고칠 대상이
아니라 **직접 URL(딥링크)로 이동해서 화면 자체가 깨지지 않았는지만** 확인하고, 실제 서비스에
필요한 화면인지는 판단하지 않는다(모르면 "확인 필요"로 남긴다):

- `/route-detail` — 파라미터 없이 열면 어떻게 되는지도 같이 본다
- `/now`
- `/${tripId}/souvenirs` (코드 주석에 "0곳이라 눌러도 항상 빈 목록"이라고 이미 적혀 있음 — 알려진 상태)
- `/${tripId}/log`
- `/${tripId}/map` (`(trip)/[id]/map.tsx` — 여행 일정 화면 안에 이미 지도가 있어서 별도 화면일 수 있음)
- `/admin/story-reports`

## 15. 버그를 찾으면

1. 코드를 읽고 원인을 확실히 파악한 뒤에만 "버그"로 취급한다 — uiautomator 결과나 스크린샷
   한 장만으로 성급히 결론 내지 않는다. 애매하면 "확인 필요"로만 남기고 고치지 않는다.
2. Jira Task 생성: `project: S15P21E201`, `issuetype.id: "10002"`, 요약은
   `[FE] ...` 형식.
3. `mcp__axmap__ax_claim` 으로 건드릴 파일을 먼저 선언(거부되면 다른 파일로 이동, 재시도 안 함).
4. `front/dev` 에서 `fix/front/S15P21E201-<번호>-<슬러그>` 브랜치.
5. 최소 수정만. 커밋 메시지 `[S15P21E201-<번호>] fix: [FE] <요약>`,
   `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`.
6. push → MR(`target_branch: front/dev`) → CI green 이면 그 자리에서 직접 머지, **red 면
   머지하지 말고 무엇이 실패했는지만 보고**.
7. `mcp__axmap__ax_release`.
8. 하나의 버그 = 하나의 티켓 = 하나의 브랜치 = 하나의 MR.
