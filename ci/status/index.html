01 데이터

아직 데이터 없음 — ci-stats.mjs 를 먼저 돌리세요

이 저장소는 비공개라 토큰 없이는 파이프라인 기록을 한 줄도 못 받습니다. 인증 없이 GitLab API 를 치면 404 가 옵니다(없다는 뜻이 아니라 “너에게는 없다”는 뜻입니다). 그래서 이 페이지는 숫자를 지어내지 않고 비워 둡니다.

  1. 토큰을 만든다. GitLab → 아바타 → Preferences → Access Tokens → Add new token. scope 는 read_api 하나면 됩니다(읽기 전용 — 아무것도 안 고칩니다).
  2. 수집 스크립트를 돌린다. 이 페이지와 같이 받은 ci-stats.mjs 가 있는 폴더에서. 
    # PowerShell
$env:GITLAB_TOKEN = "glpat-…"
node ci-stats.mjs

# bash / Git Bash
GITLAB_TOKEN=glpat-… node ci-stats.mjs
  3. 생긴 ci-status.json 을 아래에 끌어다 놓는다. 그 순간 이 화면이 실제 숫자로 채워집니다.
여기로 ci-status.json 을 끌어다 놓거나, 아무 곳에나 붙여넣기(Ctrl+V) 하세요.

05 러너 — 검사를 실제로 돌리는 기계

러너(runner) 는 CI 검사를 실제로 돌리는 서버입니다. 동시 실행 슬롯(config.toml 의 concurrent)은 그 서버가 한 번에 몇 개의 잡을 집어 가는지를 정합니다. 슬롯이 코어 수만큼 열려 있으면, 정원이 차는 순간 잡들이 서로를 느리게 만듭니다.

🔴 load average · 코어 수 · 동시 슬롯 수는 GitLab API 에 없습니다. 러너 서버 안에서만 나오는 값이라 이 페이지가 알아낼 방법이 없습니다. 지어내지 않고 비워 둡니다.
서버에서 이 한 줄을 돌리고, 나온 값을 아래 칸에 넣으세요.
nproc; cat /proc/loadavg; grep -i '^concurrent' /etc/gitlab-runner/config.toml
load average — 서버가 얼마나 밀려 있는지를 나타내는 숫자. 코어 수로 나눈 값이 1.0 을 넘으면 줄을 서고 있다는 뜻입니다. 4코어에서 4.0 은 정원, 28.7 은 정원의 7배가 대기 중이라는 뜻입니다.
06 동시 실행 수 ↔ 잡 소요시간

같은 잡이 혼자 돌 때와 이웃과 함께 돌 때 얼마나 달랐는지입니다. 옆으로 갈수록 그 잡이 도는 동안 같은 러너에서 함께 돌던 잡이 많았다는 뜻입니다 — 아래로 갈수록 막대가 길어지면 느린 원인은 그 잡 자신이 아니라 이웃입니다. 성공한 잡의 중앙값이고, n 은 표본 수입니다.

다른 조사에서 나온 실측 — 이 페이지가 잰 것이 아니라, 넘겨받은 값입니다.
러너 구성j15e201-base 4코어·슬롯 4 · EC2 4코어·슬롯 1 · SSAFY 공유 러너 0대
frontend:build 동시 3개130초 · load 0.67
frontend:build 동시 4개247초 · load 28.7
EC2 러너load 2.2 — 놀고 있음
4코어 서버에 슬롯이 4개라 정원이 차면 서로를 정확히 2배 느리게 만든다. 위 표는 이 페이지가 받은 데이터가 아니므로 03·04·05·06 의 숫자와 섞이지 않습니다.
07 어느 브랜치에서 무엇이 도는가 — git 실측

아래는 토큰 없이 확인한 것입니다. 2026-09-08 에 각 브랜치의 .gitlab-ci.yml 을 git show <브랜치>:.gitlab-ci.yml 로 직접 읽었습니다. 소요시간(초)은 여기 없습니다 — 그건 위 03·04·06 이고 토큰이 필요합니다.

MR — 머지 리퀘스트 파이프라인에서만 돈다 BR — 브랜치에 커밋이 들어오면 돈다 SC — 스케줄(정해진 시각)에만 돈다 · — 그 브랜치에 없다
