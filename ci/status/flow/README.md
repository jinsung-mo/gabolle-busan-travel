# 데이터 흐름도 — 어디가 끊겼는지 그림이 스스로 확인한다

가동 상태 페이지(`/status/`) 맨 아래 칸이다.
위의 넷이 **"지금 되나"** 에 답한다면 이 칸은 다른 질문에 답한다:

> **데이터가 어디서 와서 어디로 가고, 어디서 멈추나.**

지금까지 그 답은 저장소 어딘가에 흩어져 있었다. 문서를 열거나, 코드를 뒤지거나,
AI 에게 물어봐야 알 수 있었다. **물어볼 때마다 답이 조금씩 달랐다** — 사람도
에이전트도 모르는 자리를 그럴듯하게 메우기 때문이다.

이 칸은 묻지 않아도 보이게 한다. 그리고 **지어내지 않는다** (3절).

---

## 0. 용어

| | |
|---|---|
| **칸**(node) | 데이터가 거쳐 가는 자리 하나. 수집기 · 계산 · 표 · 화면 |
| **화살표**(edge) | 칸에서 칸으로 데이터가 실제로 건너가는 길 |
| **단계**(stage) | 그림의 가로축. 원천 → 가공 → 저장 → 서빙 → 화면 |
| **진입점** | 단계가 `source` 인 칸. 바깥에서 데이터가 들어오는 문 |
| **조각**(`dataflow.json`) | 파트마다 자기 폴더에 두는 파일. 자기 칸과 화살표만 적는다 |
| **증거**(evidence) | *"이게 있으면 이 길이 있는 것"* 이라고 지목한 **파일 경로** |

---

## 1. 파일 셋

| 파일 | 무엇 | 언제 도나 |
|---|---|---|
| `<파트>/dataflow.json` | **원본.** 파트마다 하나씩. 사람이 손으로 적는다 | — |
| `build-flow.mjs` | 조각을 모으고 **증거를 확인해** `graph.json` 을 만든다 | 설치할 때 · 사람이 부를 때 |
| `flow.js` | `graph.json` 을 그린다 | 브라우저 |

`graph.json` 은 **커밋하지 않는다** (`.gitignore`). 만들어지는 것이라 커밋하면
두 벌이 되고, 두 벌이 되는 순간 어느 쪽이 진짜인지 아무도 모르게 된다.

```bash
node ci/status/flow/build-flow.mjs          # 만든다
node ci/status/flow/build-flow.mjs --check  # 만들지 않고 검사만 한다
```

판정은 **종료 코드**다 — 0 이면 통과, 1 이면 조각이 잘못됐다.

---

## 2. 🔴 새 파트를 더할 때 — 남의 파일을 안 고친다

**자기 폴더에 `dataflow.json` 하나를 놓으면 끝이다.** 목록에 등록하지 않는다.
`build-flow.mjs` 가 뿌리의 폴더를 훑어서 알아서 찾는다.

```json
{
  "part": "myPart",
  "label": "사람이 읽을 파트 이름",
  "note": "이 파트가 무엇을 하는지 한 줄",

  "nodes": [
    {
      "id": "mp.thing",
      "stage": "process",
      "kind": "batch",
      "label": "무엇을 하는 칸인가",
      "note": "왜 있는지 · 무엇을 조심해야 하는지",
      "evidence": { "file": "myPart/do-thing.mjs" }
    }
  ],

  "edges": [
    { "from": "mp.thing", "to": "be.db.place", "label": "무엇이 건너가나", "state": "ok" }
  ]
}
```

**칸 id 는 파트 이름을 앞에 붙여 짧게 짓는다** (`bd.` `be.` `fe.` `ai.` …).
겹치면 `build-flow.mjs` 가 종료 코드 1 로 거부한다.

**화살표는 남의 칸을 가리켜도 된다.** 그게 이 그림의 요점이다 — 파트 사이가
어디서 끊기는지는 한 파트 안에서는 절대 안 보인다.
다만 가리킨 칸이 어느 조각에도 없으면 거부한다. 조용히 빠지면 그림에 구멍이 난다.

### 쓸 수 있는 값

| 자리 | 값 |
|---|---|
| `stage` | `source` 원천 · `process` 가공 · `store` 저장 · `serve` 서빙 · `view` 화면 |
| `kind` | `external` 바깥 · `batch` 배치 · `file` 파일 · `db` 데이터베이스 · `service` 서비스 · `screen` 화면 |
| `state` | `ok` 이어짐 · `partial` 반쪽 · `broken` 끊김 · `planned` 계획 · `unknown` 모름 |

`state` 를 `ok` 가 아닌 것으로 적으면 **`why`(왜 그런지 한 줄)를 반드시 같이
적어야 한다.** 안 적으면 거부한다. *"여기 끊겼음"* 만 있고 이유가 없는 표시는
다음 사람에게 아무것도 안 알려준다.

## 3. 🔴 그림이 거짓말을 못 하게 하는 장치

아키텍처 그림은 **그려 놓고 낡는다.** 코드가 바뀌어도 그림은 안 바뀌고, 아무도
안 고치고, 반년 뒤에는 아무도 안 믿는다. 그래서 여기서는 **주장에 증거를 붙이게
하고, 증거를 기계가 확인한다.**

### 증거를 적는 다섯 가지

```jsonc
{ "file":  "경로" }                 // 그 파일이 있어야 한다
{ "any":   ["경로", "경로"] }       // 하나라도 있으면 된다
{ "all":   ["경로", "경로"] }       // 전부 있어야 한다
{ "ref":   "브랜치:경로" }          // 이 브랜치 말고 다른 브랜치에 있다
{ "human": "설명" }                 // 저장소로는 확인 못 한다 (사람이 받는 파일 등)
```

### 상태를 정하는 규칙 — 한 문장이다

> **파일이 없으면 무조건 끊김. 파일이 있어도 사람이 "반쪽" 이라 적었으면 반쪽.**

파일이 없다는 것은 **잰 사실**이라 사람의 주장보다 세다.
반대로 파일이 있다는 것은 *"돈다"* 는 뜻이 아니다 — 머지는 됐는데 운영에는 안
올라간 것이 이 팀에서 실제로 여러 번 있었다. 그건 사람만 안다.

화면에는 그 차이가 **`잼` / `적음` 배지**로 나온다. 어느 쪽인지 숨기지 않는다.

### 🔴 어느 브랜치에서 만드느냐가 답을 바꾼다

**파트마다 브랜치가 다르다.** 지금 체크아웃돼 있지 않은 파트의 파일은 이 도구에게
**없는 것으로 보이고**, 그러면 멀쩡한 파트가 끊긴 것으로 그려진다.

전부 합쳐져 있는 곳은 **최상위 브랜치 하나뿐**이다. 서버에 올릴 그림은 거기서 만든다.
다른 데서 만들면 도구가 그 자리에서 경고한다 — 조용히 틀린 그림을 내주지 않는다.

아직 어느 파트 브랜치에도 안 올라간 코드라면 (한 사람 PC 에만 있는 것) `file` 로
적지 말고 **`human` 으로 적고 `state` 를 손으로 정한다.** 그게 사실이기 때문이다 —
남이 볼 수 없는 코드는 있는 것도 없는 것도 아니다.

### 🔴 증거로 적으면 안 되는 경로

**`.gitignore` 에 든 경로를 적지 않는다.** `bigData/data/` 가 대표적이다.
데이터가 있는 PC 에서는 초록이고 CI 에서는 빨강이 되어 **그림이 사람마다 달라진다.**
증거는 git 이 추적하는 파일, 즉 **누가 어디서 확인해도 같은 답이 나오는 것**이어야 한다.

지금 실제로 도는지(적재가 됐는지 · 어제 배치가 돌았는지)는 파일로 알 수 없다.
그건 `state` 에 사람이 적고 `why` 로 설명한다. 언젠가 수집기가 그것까지 재게 되면
그때 `잼` 으로 바뀐다 — 자리는 이미 만들어 두었다.

## 4. 🔴 이 그림은 실시간이 아니다

위의 가동 상태 숫자는 30초마다 새로 읽는다. **이 그림은 안 그렇다.**
`graph.json` 은 **설치할 때 한 번 만들어지고 그대로 굳는다.**

그래서 화면 아래에 *"이 그림은 언제 저장소를 읽어 만든 것"* 이라고 적어 둔다.
안 적으면 사람이 실시간이라고 믿고, 이미 고친 것이 아직 빨갛게 보일 때 혼란이 온다.

다시 만들려면 설치를 다시 돌린다:

```bash
sudo bash ci/status/install-status.sh
```

## 5. 화면에서 할 수 있는 것

| | |
|---|---|
| **진입점 칩** | 누르면 **그 문에서 뻗어 나가는 길만** 남고 나머지가 흐려진다 |
| **칸 누르기** | 그 칸을 지나는 길 전체(위·아래 모두)가 남고, 아래에 설명판이 열린다 |
| **끊긴 곳만** | 끊김·반쪽만 남긴다 |
| 끌기 · 휠 · 더블클릭 | 돌리기 · 확대 · 처음으로. 시프트를 누르고 끌면 옮긴다 |

**끊긴 곳 목록은 그림 아래에 글자로도 있다.** 그림이 안 떠도, 캔버스가 안 되는
환경에서도 읽힌다. 사람이 알고 싶은 것은 그림이 아니라 *"어디가 끊겼나"* 이고,
그 답은 글자로 읽을 수 있어야 한다.

---

## 6. 라이브러리를 하나도 안 쓴다

입체로 보이는 것은 WebGL 이 아니라 **평면 캔버스에 좌표를 직접 찍은 것**이다
(`flow.js` 3절). 3차원 좌표를 돌리고 눌러서 평면의 점 하나로 옮기는 계산 열 줄이
전부다. 원근은 일부러 안 쓴다 — 안 쓰면 **같은 크기의 칸이 어디 있든 같은 크기로
보여서** 비교가 된다. 보여주려는 것이 풍경이 아니라 구조라서 그렇다.

이 페이지는 **인터넷이 죽은 날에도 떠야 하는 페이지**다. 바깥 주소에서 무엇이든
받기 시작하면 그 존재 이유가 없어진다. 글꼴도 같은 서버에 두는 이유가 같다.

---

## 7. MR 에서 자동으로 검사한다

`.gitlab-ci.yml` 의 **`verify:dataflow`** 잡이 조각이 바뀔 때마다 `--check` 를 돌린다.
없는 칸을 가리키는 화살표, 겹치는 칸 이름, 모르는 단계, 이유 없이 "끊김" 이라고만
적은 것 — 전부 **MR 에서 빨개진다.** 설치할 때만 보면 그 사이가 통째로 비기 때문이다.

> 🔴 **"끊긴 곳이 있다" 고 빨개지지는 않는다.** 끊긴 것은 사실이지 잘못이 아니다.
> 그걸로 머지를 막으면 사람들이 그림에 거짓을 적기 시작한다 — 그러면 이 그림이
> 존재할 이유가 없어진다. 빨개지는 것은 **조각 자체가 말이 안 될 때**뿐이다.

---

## 8. 아직 안 한 것

**실제로 도는지는 안 잰다.** 적재가 됐는지 · 어제 배치가 돌았는지는 사람이 `state` 에
적는다. 재려면 각 단계가 자기 상태를 내놓는 수집기가 필요하다.

자리는 이미 있다 — 화면의 **`적음`** 배지가 **`잼`** 으로 바뀔 뿐이고, 조각도 그리는
코드도 안 고친다. 그게 이 구조를 이렇게 짠 이유다.
