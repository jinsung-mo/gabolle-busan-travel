이 페이지를 읽는 법

· MR(Merge Request — 내가 고친 코드를 팀 코드에 합쳐 달라는 요청)을 열면 자동 검사가 돕니다. MR 검사 속도는 그 검사가 다 끝날 때까지 사람이 실제로 기다리는 시간입니다 — 검사 하나하나의 시간이 아니라 전부입니다.

· 실제 배포는 서버 안에서 프론트·백엔드를 직접 두드려 본 결과입니다. 바깥에서 부르지 않고 서버 안에서 부르므로, 느릴 때 인터넷 탓인지 프로그램 탓인지가 갈립니다.

· 부하(load average — CPU 를 쓰려고 줄 서 있는 작업의 평균 개수)는 코어 수로 나눠야 뜻이 생깁니다. 1.0 이 눈금입니다 — 코어 수만큼 줄이 섰다는 뜻이고, 그보다 크면 기다리는 작업이 생깁니다.

· 못 잰 것은 “아직 안 잼”이라고 씁니다. 빈칸이 지어낸 숫자보다 낫습니다.
