## 2. 왜 — 오늘 실측

오늘 파트를 `main` 에 합치며 파트마다 충돌 10개를 풀었습니다. **아홉은 「main 쪽 받기」로 기계적으로 끝났고, 손으로 풀어야 했던 것은 `.gitlab-ci.yml` 하나뿐**이었습니다. **다섯 파트가 이 파일에서 걸렸습니다.**

원인은 한 파일에 여섯 파트 검사가 다 들어 있어서입니다.

```
.gitlab-ci.yml
  backend:build · backend:migration-order · backend:dependency-scan
  frontend:smoke · frontend:dependency-scan
  claims · governance · version · verify:mr-target       ← 공용
  … map · bigData · ai 것도 같은 파일 …
```

🔴 **부딪히는 것보다 나쁜 일이 실제로 있었습니다.** `bigData` 충돌을 풀 때 `git config core.hooksPath /dev/null` **한 줄**(LFS 훅 우회, S15P21E201-741)이 `main` 쪽에는 비어 있었습니다. 그대로 받았으면 **태그 push 가 다시 죽었을 것**입니다. **자기 파트 검사를 남이 푸는 구조 자체가 위험합니다.**

> **`include:`**(**"이 파일 내용을 여기에 끼워 넣어라" 는 GitLab 문법**) — 나눠 적어도 돌 때는 한 덩어리가 됩니다. **검사가 도는 방식은 하나도 안 바뀝니다.**

## 4. 🔴 오해하기 쉬운 것 하나

**파일은 모든 브랜치에 여섯 개가 다 있고, 어느 브랜치에서든 여섯 개가 다 읽힙니다.** 브랜치마다 자기 것만 있는 게 아닙니다.

갈리는 것은 **파일이 아니라 「고치는 사람」**입니다.

| | |
|---|---|
| 읽히는 것 | 어느 브랜치든 여섯 개 전부 |
| 고치는 사람 | 파일마다 **한 파트** |
| 충돌이 없어지는 이유 | 서로 **다른 파일**을 고치므로 git 이 안 물어보고 둘 다 가져갑니다 |

## 5. 옮기는 것은 여러분이 하십니다

**제가 안 옮겼습니다.** 제가 옮기다 하나를 빠뜨리면 그 파트는 **검사가 사라진 줄도 모릅니다.** 위 `bigData` 한 줄이 정확히 그런 모양이었습니다.

| | | 부딪히나 |
|---|---|---|
| ① 이번 MR | 빈 공책 여섯 권을 놓는다 | — |
| ② 그다음 | 각 파트가 자기 검사를 자기 공책으로 옮긴다 | 🟢 다른 파일이라 **여섯 명이 동시에 해도 안 부딪힘** |

절차는 `docs/CI-SPLIT.md` 에 있습니다.
