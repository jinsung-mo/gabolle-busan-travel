운영 화면을 눌러 보다 "내 여행" 탭이 안 열리는 것을 찾았습니다. 원인이 제가 8일에 보낸 계약 쪽지의 애매한 한 줄이라 정정합니다.

## 정정 — 목록은 배열입니다

그때 이렇게 적었습니다.

```
GET /api/v1/trips
  → { trips 배열 }
```

이게 **"trips 라는 칸을 가진 객체"** 로 읽혔습니다. 실제로는 봉투의 `data` 자리에 **배열이 그대로** 옵니다. 이 저장소의 다른 목록 응답과 같은 모양입니다(일정 판 목록·행사 목록).

```
GET /api/v1/trips
  → data: [ { tripId, startDate, endDate, dayCount, partySize, status, role, createdAt, updatedAt }, ... ]
```

앱은 `dto.trips` 를 읽고 있었고 그 값이 `undefined` 라 목록 개수를 세는 줄에서 화면이 죽었습니다. 그래서 API 오류 안내가 아니라 **"화면을 불러오지 못했어요"**(화면이 예외로 죽었을 때 뜨는 안전망)가 나왔고, **여행이 있든 없든 똑같이** 안 열렸습니다.

앞으로 목록 계약을 적을 때는 봉투를 펼쳐서 적겠습니다.

## 여행 상태 이름도 어긋나 있었습니다

앱의 `TripStatus` 에 `ACTIVE · ARCHIVED · CANCELLED` 라고 적혀 있는데 서버가 쓰는 이름은 `PLANNING · READY · IN_PROGRESS · COMPLETED` 입니다. 하나도 안 겹칩니다. 타입이 `| string` 으로 열려 있고 화면이 아직 이 값으로 분기하지 않아 드러나지 않았을 뿐이라, 상태별 배지나 필터를 붙이는 순간 조용히 어긋납니다. 앱 쪽 타입을 서버 이름으로 맞췄습니다.

## 곁들여 하나 더 — 여행 만들기 화면의 로그인 버튼

로그인한 채로 여행 만들기에 들어가면 상단에 "로그인" 버튼이 떠서 세션이 풀린 것처럼 보였습니다. `PlanWebNav` 가 로그인 상태를 아예 안 보고 버튼을 늘 그리고 있었던 것이고 **세션은 멀쩡합니다.** 로그인했으면 안 그리게 했습니다. 게스트에게는 그대로 보입니다.
