## 3. 🔴 JobStatus — 코드를 정본으로 두면 안 됩니다

여기가 답을 나눠야 할 자리입니다. **Jira 문구 대 코드가 아니라, API 명세 대 코드입니다.**
그리고 `JobStatus` 는 **공개 응답 필드**(JOB-01 의 JobDto)라서 FE·APP 이 그 값으로
분기합니다.

실측한 차이 셋입니다.

```
제 코드 + DB CHECK : QUEUED · RUNNING · SUCCEEDED · FAILED · CANCELED  · EXPIRED
API 명세 4.2       : PENDING · RUNNING · SUCCEEDED · FAILED · CANCELLED
```

| | 차이 | 위험 |
|---|---|---|
| `QUEUED` ↔ `PENDING` | 다른 단어 | FE 가 `PENDING` 으로 분기하면 안 맞음 |
| 🔴 `CANCELED` ↔ `CANCELLED` | **L 하나** | FE 가 `CANCELLED` 를 보내면 DB CHECK 가 거부하고 500 이 납니다. **두 문서를 나란히 읽어도 아무도 못 봅니다** |
| `EXPIRED` | 코드에만 있음 | FE 에 그 분기가 없습니다 |

가운데 것이 제일 나쁩니다. 한 글자라서 리뷰로도 안 잡히고, 취소를 실제로 누르는 날에야
나타납니다.
