## AWS 계정 접근권이 저에게도 없습니다

이 서버는 **SSAFY 가 제공한 것**이고, 저희가 받은 것은 **pem 키 하나뿐**입니다. AWS 콘솔 계정을 받은 적이 없습니다. "janghyojoon 이 프로젝트 AWS 계정을 관리한다" 고 들으신 것은 사실이 아닙니다 — 제가 가진 것은 EC2 에 SSH 로 들어가는 권한이지, AWS 계정 권한이 아닙니다.

그래서 요청하신 것 중 **하나도 못 합니다.**

| 요청 | 왜 불가 |
|---|---|
| SES 권한 IAM 사용자 발급 | IAM 을 열 계정이 없다 |
| 콘솔에서 도메인 인증 + SMTP 자격증명 발급 | 같은 이유 |
| 프로덕션 액세스 신청(샌드박스 해제) | 같은 이유. 이건 계정 관리자만 가능하다고 직접 적으셨습니다 |

**기다리지 마세요.** 이 길은 열리지 않습니다.

## 대신 이 길이 있습니다 — AWS 도 DNS 권한도 필요 없습니다

진단하신 원인(개인 Gmail 릴레이의 평판 붕괴 — `250 OK` 로 접수하고 조용히 버림)은 그대로 맞다고 봅니다. 바꿔야 하는 것은 **발신 경로**지 AWS 자체가 아닙니다.

**SendGrid · Brevo 같은 트랜잭션 메일 서비스**는 **이메일 주소 하나만 인증하면**(단일 발신자 인증 — Single Sender Verification) 바로 쓸 수 있습니다. 도메인 소유권도 DNS 레코드도 필요 없습니다. 저희는 `j15e201.p.ssafy.io` 의 DNS 를 못 건드리니 이게 중요합니다.

- 가입은 이메일만으로 되고, 계정 관리자 권한이 필요 없습니다 — **이예승님이 직접 끝까지 하실 수 있습니다**
- `EmailSender` 를 이미 추상화해 두셨으니 코드 교체 범위는 SES 와 같습니다
- 무료 한도(대략 하루 100~300통)가 발표·심사 규모에는 충분합니다
- 🔴 다만 발신 주소가 우리 도메인이 아니라 인증한 개인 주소가 되므로 **스팸함 확률이 0은 아닙니다.** 그래도 지금처럼 「접수만 하고 버려지는」 상태보다는 확실히 낫습니다

**어느 것으로 갈지는 이예승님이 정하시는 게 맞다고 봅니다** — 실제로 코드를 바꾸고 배포하실 분이고, 저보다 이 문제를 깊게 보셨습니다. 정하시면 제가 백엔드 쪽에서 필요한 것을 돕겠습니다.
