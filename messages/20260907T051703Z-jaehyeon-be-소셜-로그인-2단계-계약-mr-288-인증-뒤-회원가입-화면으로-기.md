진미리 님, 소셜 로그인을 "인증 → 우리 회원가입 화면 → 완료" 두 단계로 바꿨습니다. 지금 배포된 앱은 **고치지 않아도 그대로 동작합니다** — 응답의 토큰 칸 이름과 자리를 예전과 같게 뒀습니다. 아래는 새 화면을 붙일 때 쓰실 계약입니다.

## 달라진 것 한 줄

`POST /api/v1/auth/oauth/{provider}` 가 이제 세 갈래로 답합니다. 응답 `data.status` 하나만 보고 분기하면 됩니다.

## 1. `POST /api/v1/auth/oauth/{provider}` — 인증

요청은 예전과 같은데 `ageGateAccepted` 와 `consents` 가 **더 이상 필수가 아닙니다**. 소셜 버튼 전에 동의 화면을 띄우지 않아도 됩니다(그 두 값을 계속 보내면 예전처럼 한 번에 가입되고 이 흐름을 안 타니, 새 화면을 붙이실 때는 빼 주세요).

- `200 data.status = "LOGGED_IN"` — 이미 가입한 소셜 계정. `accessToken`·`refreshToken`·`expiresIn`·`sessionId`·`user` 가 예전 그 자리에 있습니다. 그대로 로그인 처리.
- `200 data.status = "SIGNUP_REQUIRED"` — 처음 보는 소셜 계정입니다. **계정은 아직 안 만들어졌습니다.** `data.signupTicket`(43글자), `data.ticketExpiresAt`(10분), `data.prefill = { email, displayName, language, emailProvided }`. 회원가입 화면을 `prefill` 로 채우고, 사용자가 닉네임·언어·14세 확인·약관 동의를 끝내면 아래 2번을 부릅니다. `emailProvided: false`(카카오 기본 동의)면 이메일 없이 가입되는 것이라 "이메일이 없으면 비밀번호 재설정을 쓸 수 없다" 를 고지해 주세요.
- `409 error.code = "OAUTH_ACCOUNT_LINK_REQUIRED"` — 같은 이메일로 이미 이메일 가입이 된 계정이 있습니다. 이 응답만 `data` 와 `error` 를 함께 싣습니다. `data.status = "LINK_REQUIRED"`, `data.linkTicket`, `data.maskedEmail`(예: `t***@example.com`), `data.provider`. 비밀번호를 받아 3번을 부르면 그 계정에 소셜이 붙습니다 — 9/4 에 막혔던 그 막다른 길이 이걸로 없어집니다.

## 2. `POST /api/v1/auth/oauth/signup` — 가입 완료 (인증 불필요)

```json
{ "signupTicket": "...", "displayName": "고른 닉네임", "language": "KO",
  "ageGateAccepted": true, "deviceId": "...",
  "consents": { "TERMS_OF_SERVICE": true, "PRIVACY_POLICY": true },
  "behaviorPersonalizationEnabled": false }
```

`201` 에 `data.status = "LOGGED_IN"` 과 토큰이 옵니다. `displayName`·`language` 를 비우면 provider 값이 그대로 쓰입니다. 티켓이 만료·재사용·없는 값이면 전부 `400 OAUTH_TICKET_INVALID` 로 같게 옵니다(구분하지 않는 것이 의도입니다) — 그때는 소셜 로그인을 처음부터 다시 시작하게 하면 됩니다. 드물게 `409 LINK_REQUIRED` 가 올 수 있습니다(티켓 받은 뒤 같은 이메일로 가입이 생긴 경우).

## 3. `POST /api/v1/auth/oauth/link` — 기존 계정에 연결 (인증 불필요)

```json
{ "linkTicket": "...", "password": "기존 계정 비밀번호", "deviceId": "..." }
```

`200` + 토큰. 비밀번호가 틀리면 `401 INVALID_CREDENTIALS` 이고, 로그인 실패 제한이 그대로 걸립니다(다섯 번 틀리면 `429 TOO_MANY_LOGIN_ATTEMPTS`). 틀렸을 때 **같은 티켓으로 다시 시도할 수 있습니다**(만료 전까지).

## 4. `POST /api/v1/auth/oauth/{provider}/link` — 설정 화면에서 연결 (인증 필요)

로그인한 상태에서 소셜 인증을 한 번 더 돌려 현재 계정에 붙입니다. 본문은 1번과 같고, `200 data = { provider, providerEmail, linkedAt, alreadyLinked }`. 이미 붙어 있으면 `alreadyLinked: true` 로 200, 그 소셜 계정이 남의 계정에 붙어 있으면 `409 OAUTH_IDENTITY_TAKEN`.

## 화면 흐름으로 정리하면

소셜 버튼 → challenge → provider 동의 → 콜백에서 `/oauth/{provider}` 호출 → `LOGGED_IN` 이면 홈, `SIGNUP_REQUIRED` 면 회원가입 화면(미리 채움), `LINK_REQUIRED` 면 비밀번호 확인 화면.

경로 이름(`/oauth/signup`·`/oauth/link`)은 명세에 없어 서버가 정한 것입니다. 이견 있으시면 붙기 전에 알려 주세요.

## 그리고 확인 부탁

구글·카카오는 9/4 에 배포 층 문제 넷을 고친 뒤 실계정으로 끝까지 재본 사람이 없습니다. 네이버만 토큰 교환까지 확인됐습니다. 새 화면을 붙이시기 전에 셋 중 하나라도 한 바퀴 돌려 보시고 어디서 멈추는지 알려 주시면 서버 쪽을 제가 봅니다. 카카오는 이메일을 안 주는 게 정상 동작이라 이제 그것도 가입이 됩니다.
