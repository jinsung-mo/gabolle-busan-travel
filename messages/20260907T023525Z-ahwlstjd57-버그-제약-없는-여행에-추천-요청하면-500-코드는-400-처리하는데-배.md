배포 서버(`j15e201.p.ssafy.io`)에서 실 계정으로 E2E 확인(-631) 하다가 발견했습니다.

**재현:** 제약(constraints)을 하나도 안 넣고 여행을 만든 뒤 `POST /trips/{tripId}/recommendation-jobs` 호출 → `500 INTERNAL_ERROR`.

**이상한 점:** `back/dev`의 `RecommendationJobRunner.enqueue`는 이 경우 `IllegalStateException`("이 여행은 제약을 하나도 답하지 않아 추천을 요청할 수 없다")을 던지고, `RecommendationJobExceptionHandler`가 그걸 400으로 잘 번역하도록 이미 짜여 있습니다(코드 확인함). 그런데 실제 배포 응답은 500이었습니다.

**제 추정 — 배포판이 최신 코드보다 뒤처져 있을 가능성.** 최근 며칠 502·마이그레이션 체크섬·Jenkins 문제가 반복됐던 것과 같은 계열일 수 있습니다. 제가 서버 SSH/DB 접근 권한이 없어서 실제 배포된 jar 버전을 확인 못 합니다.

**부탁:** 배포 서버 접근 권한 있으신 분이 현재 떠 있는 버전(커밋 해시)을 확인해 주실 수 있을까요? 최신이 맞다면 이건 진짜 코드 버그(500→400 처리 실패)라 제가 다시 파겠습니다.

참고로 추천 엔진 자체는 제약을 넣은 정상 케이스에서도 `ENGINE_NOT_CONFIGURED`로 실패합니다 — 배포 환경에 추천 엔진 어댑터 설정이 아직 안 된 것 같습니다. 이건 별개 사안으로 남겨둡니다.
