취향 화면에서 지금 고르면 반드시 실패하는 갈래가 다섯 개입니다. 화면이 그걸 알 수 있게 서버에 자리를 만들어 `back/dev` 에 머지했습니다(!698).

## 지금 무슨 일이 나나

추천 엔진은 앱이 보낸 갈래 코드를 `place.category` 와 글자 그대로 비교합니다. 운영에 적재된 장소가 음식뿐이라, 사용자가 맛집을 빼고 바다·도심·카페·문화·자연만 고르면 후보가 0 이 되고 일정 생성이 `ERROR_NO_CANDIDATES` 로 끝납니다. 후보가 모자랄 때 조건을 완화하지 않는 것이 엔진 규칙이라 다시 눌러도 안 됩니다.

2026-09-13 운영 실측(광안리 반경 15km)입니다.

```
FOOD             2,104곳
SEA_BEACH            0곳
CITY                 0곳
CAFE_HEALING         0곳
CULTURE_TEMPLE       0곳
NATURE_WALK          0곳
```

## 쓰는 법

```
GET /api/v1/places/categories
```

```json
{ "data": { "categories": [ { "code": "FOOD", "placeCount": 2355 } ],
            "generatedAt": "2026-09-13T06:10:00Z" } }
```

`app/(plan)/taste.tsx` 의 `CATEGORIES` 여섯 개 중 응답의 `code` 에 있는 것만 그려 주시면 됩니다. 목록을 지우지 말고 걸러만 주세요 — 적재가 돌면 그 갈래들이 응답에 다시 나타나고, 그때 화면은 고칠 것이 없습니다.

전부 없어지는 경우도 생각해 두시면 좋겠습니다. 지금은 `FOOD` 하나가 남지만, 응답이 비면 카테고리 섹션을 통째로 건너뛰는 편이 빈 격자를 보여 주는 것보다 낫습니다. 취향을 건너뛰면 갈래를 안 좁히고 2,104곳에서 일정이 나오니 기능은 그대로 됩니다.

## 이건 `facets` 와 다릅니다

`GET /api/v1/places/facets` 는 `place_feature` 표식이고 로컬 탐색 화면이 쓰는 쪽입니다. 이번 것은 `place.category` 칼럼이고 추천 후보를 좁힐 때 실제로 비교되는 값입니다. 이름이 비슷해서 헷갈리기 쉬운데 서로 다른 어휘라 섞으면 안 됩니다.

## 근본 해결은 따로입니다

관광공사 장소 656곳(문화·사찰 162 · 쇼핑 47 · 자연 25 등) 적재기는 이미 머지돼 있고 운영에서 한 번 도는 것만 남았습니다. 이예승 님께 상태를 여쭤 뒀습니다. 그게 돌면 다섯 갈래가 한꺼번에 살아나고 로컬 탐색 8종도 같이 삽니다.
