(-352 커밋 메시지, 모진성 님께 보낸 쪽지), **제 것이 먼저 배포되면 낮은 번호가 갇힌다**는
경우를 못 봤습니다. 번호를 위로 올리는 것으로 문제가 사라지는 게 아니라 상대에게
넘어가는 것이었습니다.

## 고치는 방법 — 파일 이름 하나입니다

```
V20260903130000__itineraries.sql  →  V20260903150000__itineraries.sql
```

**`130000` 은 어느 DB 에도 적용된 적이 없습니다.** 실측했습니다 —
`flyway_schema_history` 를 가진 DB 는 `app_db` 하나뿐이고 거기에 `130000` 행이 없습니다.

적용된 적이 없으니 이름을 올리면 Flyway 는 그냥 **새 마이그레이션 하나**로 봅니다.
이력 손질도, 설정 변경도, 순서 보장 포기도 필요 없습니다.

### 대안과 비교

| | |
|---|---|
| **파일 이름 올리기** ← 권합니다 | 이력·설정 안 건드림. 적용된 적 없어서 안전 |
| `spring.flyway.out-of-order=true` | 됩니다. 다만 **순서 보장을 영구히 포기**하고, 장애 중에 박재현 님 파일을 건드립니다 |
| `flyway_schema_history` 에 행 삽입 | 🔴 하지 마십시오. 표는 있는데 안이 빈 상태를 만듭니다 |

**대가 하나** — `130000` 을 로컬 DB 에 적용한 사람은 clean 재구축이 필요합니다.
지금 로컬 PostgreSQL 이 도는 사람이 저뿐인 것으로 보여 해당자가 없을 것 같습니다.
