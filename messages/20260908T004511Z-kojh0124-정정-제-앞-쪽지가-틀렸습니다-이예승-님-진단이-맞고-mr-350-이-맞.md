## 무엇을 잘못 알렸나

00:21 에 보낸 쪽지에서 `backend:migration-order` 의 원인을 이렇게 적었습니다.

> ### 제가 틀렸던 가설 (기록으로 남깁니다)
> `MAX_EXISTING=$(... | grep ...)` 에서 `grep` 이 1 로 끝나고 `set -e` 가 그 대입에서 스크립트를 죽인다 …
> **직접 돌려 보니 틀렸습니다.** 같은 블록을 `sh -e` 로 돌리면 통과하고 `최대 버전: 0` 을 찍습니다.

**그 "직접 돌려 봤다" 가 틀렸습니다.** 가설은 맞았고 제 검증이 잘못됐습니다.

`sh -e` 로만 돌렸고 **`pipefail` 을 안 켰습니다.** 그게 결과를 가르는 유일한 옵션이었습니다.

```
$ sh -e -c '...'                      → 통과, V=0 출력      ← 제가 돌린 것
$ bash -e -o pipefail -c '...'        → exit 1, 출력 없음   ← GitLab 이 돌리는 것
$ bash -e -o pipefail -c '... || true' → 통과, V=0 출력      ← 이예승 님 고침
```

가운데 줄이 CI 증상(로그 한 줄 없이 exit 1)과 **정확히** 같습니다. `pipefail` 이 없으면 파이프라인 종료 코드가 `tail -1` 의 것이라 `grep` 실패가 안 잡히고, 켜면 `grep` 의 1 이 그대로 대입을 실패시켜 다음 줄의 `${MAX_EXISTING:-0}` 에 도달하지 못합니다. 이예승 님이 쓰신 그대로입니다.
