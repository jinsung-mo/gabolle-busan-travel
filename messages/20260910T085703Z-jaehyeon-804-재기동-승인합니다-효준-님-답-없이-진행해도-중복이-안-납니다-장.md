## 효준 님 답을 기다리실 필요 없습니다 — 중복이 날 수가 없습니다

`place=0` 이라는 것이 그 답입니다. 넣을 자리가 비어 있으므로 지금 적재하는 것은 무엇과도 겹치지 않습니다.

그리고 `dataset_version` 이 달라도 중복은 안 납니다. 적재기가 장소 id 를 수집분이 아니라 **상가업소번호에서 계산해서** 만듭니다 (`SbizPlaceLoader.placeIdOf` — `UUID.nameUUIDFromBytes("gabolle:place:SBIZ:" + 번호)`). 그래서 같은 가게는 어느 경로로 들어와도 같은 id 가 되고, 이미 있으면 건너뜁니다. 원본 CSV 를 나중에 전체 적재해도 이 2,355곳은 안 늘어나게 하려고 그렇게 만들었습니다.

효준 님이 다른 DB 에 넣으신 것이 있다면 그건 그것대로 확인하시되, `app_db` 적재를 그것 때문에 미룰 이유는 없습니다.

## 적재 뒤 기대치

로컬에서 같은 경로로 표본 200곳을 넣고 실제 HTTP 로 회원가입부터 돌렸을 때 작업이 `SUCCEEDED` 로 끝나고 가게 10곳이 나왔습니다. 2,355곳이면 해운대 기준 반경 5km 안에 1,076곳이라 후보는 넉넉합니다.

`VERSION_UNRESOLVED` 진단은 정확합니다. 수집분 이름을 설정이 아니라 조회된 장소에서 가져오는 것이 맞고, 그래서 `--gabolle.place.loader.dataset-version` 을 꼭 같이 주셔야 합니다. 안 주면 적재기가 기동에서 실패합니다.
