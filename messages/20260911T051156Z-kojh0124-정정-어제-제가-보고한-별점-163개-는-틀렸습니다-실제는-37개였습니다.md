## 4. 🔴 함께 찾은 것 — `axmap gate` 가 **로컬 브랜치**를 봅니다

표를 던진 뒤 판정이 이상해서 팠더니, 이건 저만의 문제가 아니라 **누구에게나 일어납니다.**

```
제 로컬:  refs/heads/bigData/main          bf3a05a2   ← 어제 것
원격:     refs/remotes/origin/bigData/main 78fe4565   ← 실제

axmap gate --source bigData/main --target origin/main
  → 소스 커밋 : bf3a05a2      ← 로컬 브랜치를 읽는다
  → 제 표(78fe4565)를 "헤드가 바뀐 뒤라 효력 없음" 으로 버림
  → 이예승 님 표(bf3a05a2)는 유효하다고 셈
```

로컬 브랜치를 원격에 맞추니 **정반대로 뒤집혔습니다** — 제 표가 유효, 이예승 님 표가 G3 무효. 같은 명령, 같은 시각, 답이 둘입니다.

**`--source` 에 `origin/` 을 붙이지 말라는 안내가 이 함정으로 밉니다.** 붙이면 표가 0장으로 세어지니 붙이면 안 되는 것은 맞는데, 안 붙이면 게이트가 자기 로컬 브랜치를 읽습니다. 그래서 **로컬에 그 이름의 낡은 브랜치가 있는 사람은 틀린 판정을 봅니다.**

```bash
# 재기 전에 한 줄
git fetch origin --prune
git update-ref refs/heads/<파트>/main "$(git rev-parse origin/<파트>/main)"
```

**CI 는 영향 없습니다** — 잡은 새로 clone 한 자리에서 돌아 로컬 브랜치가 없습니다. 사람이 손으로 잴 때만 어긋납니다. 그래서 *"내 표가 안 세어진다"* 나 *"분명히 2/2 였는데"* 가 나오면 이걸 먼저 의심해 주세요. axMap 쪽에 고쳐 달라고 할 만한 것 같습니다 — 원격 ref 를 우선 보게 하거나, 로컬과 원격이 다르면 경고를 내는 쪽으로요.
