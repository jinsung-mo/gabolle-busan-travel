## 무엇을 넣는가 — 두 줄입니다

`S15P21E201-983`(무거운 CI 잡을 운영 서버에서 빼 백업 러너로 보낸다)의 조치가 2026-09-15 에 파트 브랜치에 들어갔는데, 그 뒤로 `back/main`·`front/main` 이 `main` 으로 올라간 적이 없어 **뿌리 main 에만 안 들어갔습니다.**

## 🔴 판단에 필요한 사실 — 급하지 않습니다

표를 던지시기 전에 알고 계셔야 할 것을 그대로 적습니다. **대부분의 경우 이 줄은 안 쓰입니다.**

1. **main 의 push 파이프라인은 무거운 잡을 아예 안 돌립니다.** 최근 main 파이프라인(198640)이 실제로 돌린 것은 `jira`·`version`·`claims:checkpoint`·`claims` 넷이고 전부 초 단위입니다.
2. **`<파트>/main → main` MR 은 소스 브랜치 설정을 씁니다.** 파트 쪽에는 이미 태그가 있습니다.
3. 그래서 실제로 쓰이는 자리는 **`hotfix/... → main` 하나**입니다. hotfix 는 main 에서 갈라지니 main 의 설정을 그대로 들고 갑니다.

드뭅니다. 다만 **드문 만큼 그때가 운영이 바쁜 순간**이라(긴급 수정을 올린다는 건 대개 뭔가 잘못 돌고 있다는 뜻) 넣는 편이 맞다고 봤습니다. 「급하지 않으니 다음 승격 때 자연히 들어오게 두자」도 충분히 타당한 판단이고, 그러면 이 MR 을 닫으면 됩니다.

다음 `back/main → main` 승격은 **이 파일에서 충돌합니다**(`git merge-tree` 로 결과 트리를 떠서 확인). `ai/main → main`(!731)이 이 파일을 건드리고 갔고 파트들이 각자 다른 줄을 건드려 놨습니다. **이 MR 이 그 충돌을 없애지는 못합니다** — 두 줄만큼 줄일 뿐입니다. 근본 해결은 파일 주석이 이미 말하는 대로 파트 잡을 `ci/parts/*.yml` 로 옮기는 것이고, 별건입니다.
