## 스냅샷 — 정하신 대로 UUID PK + (trip_id, version)

```
preference_snapshot / constraint_snapshot
  <이름>_snapshot_id  UUID PK
  user_id             UUID NOT NULL → app_user
  trip_id             UUID NULL     → trip     (scope='USER' 이면 NULL)
  version             INTEGER NOT NULL
  scope               VARCHAR(10)  USER | TRIP
  created_at          TIMESTAMPTZ NOT NULL
```

🔴 `updated_at` 이 없습니다. 불변이라 고치는 칸을 두지 않습니다 — 입력이 바뀌면 새 행입니다.

🔴 `UNIQUE (trip_id, version)` 을 제약으로 걸면 안 됩니다. PostgreSQL 은 NULL 을 서로 다르게
보므로 `scope='USER'` 행이 전부 제약을 빠져나갑니다. **부분 색인**(**조건이 붙은 UNIQUE 색인.
MySQL 에는 없습니다**) 둘로 갑니다.

```sql
CREATE UNIQUE INDEX uq_preference_snapshot_trip
    ON preference_snapshot (trip_id, version) WHERE trip_id IS NOT NULL;
CREATE UNIQUE INDEX uq_preference_snapshot_user
    ON preference_snapshot (user_id, version) WHERE trip_id IS NULL;
```

## 답변 행 — 값과 응답 상태를 분리합니다

```
preference_answer   dimension VARCHAR(50) · value JSONB · answer_status(SELECTED|SKIPPED|UNKNOWN)
constraint_answer   constraint_type(ALLERGY|DIET|MOBILITY) · constraint_key · value JSONB
                    · hard BOOLEAN · answer_status(SELECTED|NONE|UNKNOWN)
```

DB 가 막는 것 넷:

- `CHECK ((answer_status='SELECTED') = (value IS NOT NULL))` — 건너뜀·모름이 값을 몰래 싣지 못합니다
- `CHECK (constraint_type <> 'ALLERGY' OR hard)` — 알레르기는 하드 제약입니다 (진미리 님 합의)
- `CHECK (answer_status <> 'SKIPPED')` — 제약은 건너뛰기 대신 `NONE` 을 명시합니다
- 암호문이 있으면 키 판 번호·nonce 도 있어야 합니다

`MOBILITY` 는 `constraint_key`(`MAX_WALKING_METERS`·`WHEELCHAIR`·`STROLLER`·`HEAVY_LUGGAGE`
·`STAIRS_AVOIDANCE`) 로 **사실마다 한 행**입니다. 넓은 표 한 행으로 두면 응답 상태를 사실마다
가질 수 없어서 "휠체어는 답했고 계단은 안 물어봤다" 를 표현할 칸이 사라집니다.
`slope_preference`·`shade_preference` 는 -542 4.3 대로 `preference_answer` 쪽입니다.
