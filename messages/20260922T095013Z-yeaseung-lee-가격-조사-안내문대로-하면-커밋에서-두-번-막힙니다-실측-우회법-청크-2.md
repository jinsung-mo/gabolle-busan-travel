## ① `git add -f .../combined-results/*.json` 이 죽습니다

```

그 폴더에 이미 파일이 1,000개를 넘어서, 글로브가 펼쳐지면 명령줄 길이 한도를 넘습니다.

```

지금은 1,250곳이라 앞으로 더 확실히 터집니다. 안내문의 그 줄만 바꿔 두면 될 것 같습니다.

## ② 선점 훅이 커밋을 막습니다

`work-chunk.mjs` 가 마지막에 **청크를 반납하고** 끝나는데, 커밋은 그 **뒤에** 사람이 합니다.
그래서 pre-commit 훅이 「claim 하지 않은 파일을 수정했습니다」로 거부합니다.

```
커밋 거부 - claim 하지 않은 파일을 수정했습니다.
  x bigData/research/data/combined-results/MA0101202602A0032120.json
  ...
yeaseung-lee 이(가) 현재 잡고 있는 경로:
  (없음)
```

🔴 **그리고 여기서 한 번 더 걸립니다.** 결과 파일을 다시 잡으려고 `combined-results`
디렉터리를 통째로 claim 하면 **거부됩니다** — 그 안에 남이 잡은 `chunk-23`·`chunk-24` 가
들어 있어서 부모 경로를 못 잡습니다. 그래서 **staged 된 50개 파일만** 잡아야 합니다.

## 우회법 — 이 순서로 하면 통과합니다

```bash
export AXMAP_SESSION="price-chunk-<본인이름>"     # ← 이게 핵심입니다

git add -f bigData/research/data/combined-results
npx -y axmap-cli@latest claim $(git diff --cached --name-only | tr '\n' ' ') \
  --task S15P21E201-1414 --intent "가격 조사 청크 NN 결과 커밋"

git commit -m "[S15P21E201-1414] chore: [Data] 가격 조사 청크 NN 결과"
git pull --rebase origin bigData/dev
git push origin HEAD:bigData/dev

npx -y axmap-cli@latest release
```

🔴 **`AXMAP_SESSION` 을 고정하지 않으면 반납이 안 됩니다.** `npx` 로 부를 때마다 세션이
새로 잡혀서, claim 한 세션과 release 하는 세션이 달라집니다. 저는 처음에 이걸 몰라서
파일 50개를 30분 TTL 로 걸어 둔 채 못 풀었습니다(만료로 자동 회수되긴 했습니다).

## 고칠까요?

`work-chunk.mjs` 가 **커밋까지 하도록** 고치면 위 둘이 통째로 사라집니다. 다만 안내문에
「실제로 올리는 것은 사람이 마지막에 확인하고 직접 한다」고 일부러 적어 두신 걸 봤습니다.
그 뜻이 있으실 테니 **제 판단으로 안 바꿨습니다.**

- 그대로 두실 거면 → 안내문에 위 우회법만 한 덩이 넣으면 될 것 같습니다
- 자동화해도 되면 → 제가 MR 내겠습니다 (claim → commit → release 까지, push 는 사람이)

말씀 주시는 대로 하겠습니다.
