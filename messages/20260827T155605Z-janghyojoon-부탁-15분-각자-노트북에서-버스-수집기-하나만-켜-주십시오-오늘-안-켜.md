## 이게 뭔가

우리 서비스는 외국인 관광객에게 **"이 길을 걸을 만한가 / 버스를 탈 만한가 / 택시를
타야 하나"** 를 판정합니다. 버스를 판정하려면 **정류소에서 정류소까지 실제로 몇 분
걸리는지**를 알아야 합니다.

시간표에 있는 것은 평균입니다. 우리에게 필요한 건 **최악일 때 얼마나 걸리는가** 입니다.
평균 12분인데 최악 35분인 노선은 외국인에게 추천하면 안 됩니다. 그 차이는 시간표에
절대 안 나오고, **기존 여행 앱이 못 하는 것이 정확히 이것**입니다.

부산시가 그걸 공개하는 창구가 **BIMS**(**부산 버스정보관리시스템** — 버스가 지금
어디 있는지를 알려주는 공공 API)입니다.

> **API**(**Application Programming Interface** — 프로그램이 다른 프로그램의 데이터를
> 정해진 방식으로 받아 가는 창구). 여기서는 "부산시 서버에 버스 위치를 물어보는
> 주소" 로 읽으면 됩니다.

## 🔴 왜 오늘인가 — 이것만은 나중에 못 만듭니다

**실시간 데이터는 소급 수집이 안 됩니다.**

우리가 모으는 다른 것(지도·고도·건물·관광지)은 전부 늦어도 따라잡습니다. 내일 받아도
같은 것이 옵니다. **이것만 다릅니다.** 어제 8시의 버스가 어디 있었는지는 아무도
안 알려줍니다. 안 받은 시간은 그냥 구멍으로 남습니다.

실제로 어제 노트북이 꺼져 있는 동안 **22시간이 비었습니다.** 그건 이제 못 메웁니다.
발표까지 남은 날 수가 그대로 표본 일수입니다.

## 왜 나눠야 하나 — 한도가 사람마다 따로입니다

공공데이터포털은 **하루에 부를 수 있는 횟수**를 **발급받은 키마다** 겁니다.
한 사람이 혼자 돌리면 그 사람 한도가 팀 전체의 한도입니다. 각자 키를 받아 각자
노트북에서 돌리면 **예산이 사람 수만큼 늘어납니다.** 키는 무료·자동승인입니다.

재미있는 게 하나 있습니다. **하루 종일 켜 두는 것보다 낮에만 켜는 쪽이 한 사람당 더
많은 노선을 볼 수 있습니다.** 한도는 "하루에 몇 번 부르는가" 로 걸리고, 노트북이
꺼져 있는 동안은 안 부르니 예산을 안 씁니다. 그래서 24시간이면 1인 5노선인데
9~18시만 켜면 **1인 13노선**이 됩니다.

숫자와 계산은 전부 `bigData/config/bims-assign.json` 에 있습니다. 왜 그렇게 나눴는지는
`bigData/docs/BIMS-FLEET.md` 에 있습니다. 쪽지에 숫자를 적으면 배정이 바뀌는 순간
낡기 때문에 근거 파일 쪽을 보게 해 두었습니다.

# 각자 할 일 — 순서대로

## 1단계. 자기 키를 받습니다 (제일 오래 걸립니다. 먼저 넣으세요)

1. https://www.data.go.kr 회원가입 / 로그인
2. **"부산광역시_부산버스정보시스템"** 검색 → **활용신청**
   자동승인이고 보통 1시간 안에 발급됩니다. 활용목적은 학습/개인 프로젝트로 적으면 됩니다
3. 마이페이지 → 개발계정 → 방금 신청한 것 → **"일반 인증키(Decoding)"** 복사
   🔴 **Encoding 이 아니라 Decoding 입니다.** 둘 다 보이는데 Encoding 을 넣으면
   인증이 실패하고, 증상이 "키가 틀렸다" 로 보여서 한참 헤맵니다
4. 같은 화면의 **요청주소(End Point)** 도 복사합니다. 우리가 쓰는 상세기능은
   **`busInfoByRouteId`** 입니다 (노선ID로 실시간 버스 위치를 주는 것)
   🔴 **주소를 짐작해서 적지 마십시오.** 화면에 있는 것을 그대로 붙이십시오

## 2단계. 저장소를 받습니다

```bash
git clone https://lab.ssafy.com/s15-bigdata-dist-sub1/S15P21E201
cd S15P21E201
git checkout feat/bigData/S15P21E201-23-walkability-layers
./setup.sh          # Windows 는  .\setup.ps1
cd bigData
cp .env.example .env
```

🔴 이 저장소는 **LFS**(**Large File Storage** — 큰 파일을 git 본문 대신 따로 두고
포인터만 커밋하는 방식)를 씁니다. clone 전에 `git lfs install` 을 한 번 해 주십시오.

## 3단계. `bigData/.env` 를 채웁니다

```
DATA_GO_KR_KEY=<1단계의 Decoding 키>
BIMS_ENDPOINT=<1단계의 요청주소>
BIMS_ROUTES=<아래 "내 담당 노선" 에서 자기 줄을 그대로 복사>
BIMS_INTERVAL_MS=60000
```

- `BIMS_INTERVAL_MS=60000` 은 **60초마다 한 번 물어본다**는 뜻입니다. 전원 같은 값을 씁니다
- 🔴 `.env` 는 커밋되지 않습니다(`.gitignore`). **키를 채팅·MR·커밋에 붙이지 마십시오**

## 4단계. 켜기 전 검사

```bash
node collect/bims-preflight.mjs
```

**한도를 넘는 설정으로 켜는 것을 막아 줍니다.** 한도를 넘기면 그 계정은 그날 남은
시간 동안 아무것도 못 받는데, 넘겼는지는 넘긴 뒤에야 알 수 있습니다. 그래서 켜기 전에
계산해서 거절합니다.

- **통과**면 다음 단계. **거절**이면 켜지 마십시오 — 무엇이 틀렸고 어떻게 고치는지
  같이 나옵니다
- 내가 누구인지 못 알아보면: `node collect/bims-preflight.mjs --as <내이름>`

## 5단계. 켭니다. 그리고 끄지 않습니다

```bash
npm run collect:bims
```

창을 **닫지 마십시오.** 로그가 계속 찍히는 게 정상입니다.
저녁에 퇴근하면서 끄는 것은 괜찮습니다 — 배정이 근무시간 기준입니다.

## 🔴 6단계. 노트북이 자면 수집도 죽습니다

**이게 제일 흔한 실패이고 조용히 실패합니다** — 오류가 안 나고 그냥 그 시간이 빕니다.

- **전원 어댑터를 꽂아 두십시오.** 배터리로 돌면 절전이 훨씬 공격적으로 걸립니다
- **Windows**: 설정 → 시스템 → 전원 및 배터리 → 화면 및 절전 모드 →
  "장치를 절전 모드로 전환" 을 **"안 함"** 으로 (전원 연결 시 / 배터리 사용 시 둘 다)
- **macOS**: `caffeinate -i npm run collect:bims` 로 켜면 간단합니다
- 🔴 **덮개를 닫으면 대부분 잠자기로 들어갑니다.** 설정에서 "덮개를 닫을 때: 아무 것도
  안 함" 으로 바꿔 두거나 열어 두십시오

# 🔴 아직 안 정한 것 — 밤 시간대

지금 배정은 **낮(9~18시)만** 덮습니다. **퇴근 후 러시아워(18~20시)가 통째로 빕니다.**
하필 그 시간대가 하루 중 소요시간의 **변동이 가장 큰 구간**이고, 우리가 만들려는 것이
바로 그 변동입니다.

이건 기술 문제가 아니라 **생활 문제**라 제가 정하지 않았습니다. 정해 주셔야 합니다:

1. 야간을 지금 노선 수로 둘까요, **18~20시만** 노선을 늘릴까요? (러시아워 집중이 값이 큽니다)
2. 야간 담당을 한 사람이 계속 질까요, 요일별로 돌릴까요?
3. **야간 담당자는 낮 노선을 못 받습니다** — 계산이 그렇게 나옵니다. 동의하십니까?
4. 데스크톱이나 안 쓰는 PC 를 밤에 켜 둘 수 있는 분이 있습니까? (노트북보다 훨씬 낫습니다)
