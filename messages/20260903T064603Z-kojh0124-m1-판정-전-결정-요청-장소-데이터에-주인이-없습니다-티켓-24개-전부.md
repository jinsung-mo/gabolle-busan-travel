## 2. 제가 왜 이걸 필요로 하는가 — `-545` 가 밑이 없습니다

`-545` 의 완료 기준 셋이 전부 **장소가 존재한다는 전제** 위에 있습니다.

- *"추천에 사용된 모든 피처의 출처와 데이터 버전을 찾을 수 있다"* → 피처를 담을 장소 표 필요
- *"결측값이 0 또는 안전한 값으로 변환되지 않는다"* → 결측을 잴 장소 행 필요
- *"장소 코드와 사용자 입력 코드가 자동 검사에서 일치한다"* → 장소 태그 코드 필요

사용자 쪽은 어제 다 만들었습니다 — `preference_answer` 가 "고름 / 건너뜀 / 안 물어봄" 을
DB 제약으로 구분합니다(`-554`). **`-545` 는 그것의 장소 쪽 짝인데, 짝이 없습니다.**

## 3. 🔴 프로젝트가 왜 이걸 필요로 하는가 — 이게 더 중요합니다

이건 제 티켓 문제가 아니라 **마일스톤 문제**입니다.

**(가) M1 통과 조건이 장소를 요구합니다.**
모진성 님이 적으신 M1 조건은 *"하드 제약을 지킨 부산 일정을 받는다"* 입니다. 일정은
장소를 골라 만드는 것입니다. **고를 장소가 DB 에 없습니다.**

**(나) 어제 만든 계측 장치가 영원히 0 을 잽니다.**
`-543` 후보 원장, `-546` 품질 게이트, `recommendation_exposure` 뷰가 전부 운영에 들어가
있습니다. 그런데 방금 운영에서 읽은 값입니다.

```
gabolle.trip = 0   preference_answer = 0   event_outbox = 0
```

**표는 살아 있고 안이 비어 있습니다.** 장소가 없으면 후보가 안 생기고, 후보가 없으면
노출도 없고, 그러면 개인화 Epic(`-541`, 제 티켓 29개)이 **재료 없이 서 있는 것**이 됩니다.

**(다) 🔴 안전 기능이 정직할 수 없습니다.**
`-539`(알레르기 위반 장소를 추천하지 않고, 확인 안 된 곳은 경고)와 `-92`·`-321`·`-328` 이
한 줄로 이어져 있습니다. 그 줄이 요구하는 것은 **장소마다의 알레르기 정보와 그 출처**입니다.

수집 명세는 *"장소 정보가 없으면 임의로 PASS 처리하지 않고 UNKNOWN 으로 남긴다"* 고
못 박았습니다. 지금은 **전부 UNKNOWN** 입니다. 그리고 제가 넣은 기본값
(`unknown-exclusion-threshold=REQUIRED`)은 UNKNOWN 을 제외하므로 **후보가 말라붙습니다.**
`NONE` 으로 바꾸면 후보는 나오지만 **확인 안 된 곳을 안전한 것처럼 내보내게 됩니다.**

즉 장소 데이터가 없으면 **"알레르기 사용자를 지킨다" 를 어느 쪽으로도 정직하게 구현할 수
없습니다.** 이건 데이터 문제가 아니라 안전 문제입니다.

**(라) 티켓이 MySQL 전제로 멈춰 있습니다.**
`-81`·`-262`·`-270` 이 *"우리 MySQL 로 옮긴다"* 로 쓰여 있습니다. 팀은 PostgreSQL 로
정했으므로(`-554`) 그 티켓들은 **지금 그대로는 시작할 수도 없습니다.**
`-262` 종료 근거는 MR !120 에 적어 올렸습니다.
