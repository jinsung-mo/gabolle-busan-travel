## 1. 🔴 먼저 — 각자 따로 풀면 안 되는 이유

`.gitlab-ci.yml` 은 **저장소 뿌리에 하나뿐인 파일**인데, 파트마다 자기 검사 작업을 거기에 넣어 뒀습니다.

```
back  이 넣은 것   +350줄   backend:build · backend:migration-order · backend:dependency-scan …
front 이 넣은 것   +212줄   frontend:smoke · frontend:dependency-scan …
bigData           +68줄    verify:bigdata …
map               +43줄    (map 검사)
common            +194줄   promote · vote:recheck · status · governance …
```

**`main` 에는 이 전부가 다 들어 있어야 합니다.** 각자 자기 판단으로 풀면 다섯 개의 서로 다른 파일이 생기고, `main` 에서 또 충돌합니다. **오늘 아침의 반복입니다.**

그래서 순서를 이렇게 갑니다.

| 순서 | 누가 | 무엇 |
|---|---|---|
| **①** | **장효준(제 에이전트)** | 공용 파일 셋의 **정답판을 하나 만들어** 쪽지로 알린다 |
| ② | 각 파트 에이전트 | 그 정답판을 **그대로 가져다** 자기 브랜치에 넣는다 |
| ③ | 각 파트 에이전트 | **자기 파트 검사 작업이 살아 있는지 확인**하고 push |
| ④ | 각 파트 에이전트 | `main` 으로 MR 을 올린다 |
| ⑤ | **사람** | 표를 던진다 (에이전트는 못 한다) |
| ⑥ | 각 파트 에이전트 | 정족수 차면 머지 |

**①이 끝나면 제가 쪽지를 보냅니다.** 여러분 에이전트는 그 쪽지를 기다리면 됩니다.

---

## 2. 🔴 선점이 부딪히는 문제 — 이렇게 피합니다

axMap 의 선점은 **경로**로 잡습니다. 브랜치를 구분하지 않습니다. 그래서 다섯 에이전트가 다 `CLAUDE.md` 를 잡으려 하면 **넷이 거부당합니다.**

그러니 **공용 파일 셋은 아무도 잡지 마세요.** 대신:

- **자기 파트 폴더만 잡습니다** — `backend` · `frontend` · `bigData` · `map`
- 공용 파일 셋은 **①의 정답판을 그대로 복사**하는 것뿐이라 판단이 안 들어갑니다. 그래서 잡을 필요가 없습니다
- 🔴 **`ai/main` 은 예외**입니다. `.gitlab-ci.yml` 을 안 건드렸고 `governance/policy.json` 만 걸립니다

---

## 3. 표는 사람만 던집니다 — 이건 못 우회합니다

표 던지는 명령은 **일부러 슬래시 명령**입니다. 에이전트가 부를 수 있는 도구가 아닙니다. 이유는 하나입니다 — 도구로 두면 에이전트 둘이 사람 둘 이름으로 정족수를 채우고, **게이트는 통과라는데 아무도 안 본 상태**가 됩니다. 그렇게 통과하는 것이 하필 규칙 파일 자체입니다.

**그래서 점심 동안 표가 안 들어오면 머지는 안 됩니다.** 에이전트가 할 수 있는 건 **표만 기다리는 상태까지 다 만들어 두는 것**입니다. 밥 먹고 와서 표만 던지면 몇 분 안에 끝나게요.

가능하시면 **자리를 뜨기 전에 두 곳에** 던져 주세요.

## 6단계 — 5분마다 지켜보다가 정족수가 차면 머지한다

  npx -y axmap-cli@latest gate --source <자기파트>/main --target origin/main

🔴 --source 에 origin/ 을 붙이지 마라. 붙이면 표가 0장으로 세어진다.
   --target 에는 붙여라. 두 규칙이 반대라서 특히 잘 틀린다.

"합의 충족" 이 나오면:
  1. 그 MR 의 governance 잡을 retry 한다 (표는 MR 밖으로 들어오므로
     GitLab 이 파이프라인을 자동으로 다시 돌리지 않는다. 화면에 옛 판정이 남아 있다)
  2. 초록이 되고 mergeable 이면 머지한다
     🔴 판정에 쓴 커밋 sha 를 실어라
     🔴 should_remove_source_branch = false  — 파트 브랜치를 지우면 안 된다
  3. 머지 뒤 사후 파이프라인을 본다. version 잡이 태그 충돌로 실패할 수 있다
     (여러 파트를 연달아 머지하면 같은 번호를 동시에 계산한다).
     실패하면 그 잡만 retry 하면 된다 — 머지 자체는 멀쩡하다
  4. 머지했으면 쪽지로 알린다. 다른 에이전트가 자기 차례를 안다

## 5. 정리

| 시각 | 누가 | 무엇 |
|---|---|---|
| **지금** | 장효준 | 공용 파일 **정답판**을 만들어 쪽지로 알린다 |
| 정답판 뒤 | 각 파트 에이전트 | 정답판 받기 → 자기 잡 확인 → push → MR |
| **아무 때나** | **사람** | **남의 파트에 표 두 장** (이것만 사람 손이 필요) |
| 정족수 차면 | 각 파트 에이전트 | 머지 → 쪽지로 알림 → 다음 |

정답판이 준비되면 바로 쪽지 보냅니다. 그때 에이전트를 띄워 주세요.
