## 계약 제안
`POST /api/v1/stories` 에 지금의 `placeId` 옆에 **선택 칸 하나**:
```json
"place": { "source": "KAKAO", "externalId": "<카카오 id>", "name": "…", "address": "…", "lat": 35.1, "lng": 129.0, "category": "카페" }
```
- `placeId` 가 있으면 지금처럼 그것을 쓴다(우리 DB 장소)
- 없고 `place` 가 있으면 서버가 `(source, externalId)` 로 **찾거나 만들어**(upsert) 그 id 를 `story.place_id` 에 넣는다. 같은 카카오 장소를 두 사람이 고르면 한 행
- 응답 StoryDto 의 `place` 는 지금 모양 그대로(id·name·lat·lng)

## 왜 이렇게
- 프론트 변경이 작습니다 — 카카오 후보를 골랐을 때 이미 이름·좌표·id 를 들고 있습니다(`regionSearch.ts`). 칸 하나 더 실어 보내면 끝
- «우리 표에 없는 식별자를 저장하지 않는다»는 원칙은 지켜집니다 — 서버가 만든 뒤에만 id 가 생기니까
- 적재기 장소와 섞이는 문제는 `source` 열로 가릅니다(적재기 = TOUR_API 등, 사용자 = KAKAO). 추천 후보에는 당분간 사용자 출처를 안 넣으면 품질 문제도 없습니다
- (다) 는 다리가 안 생겨서 개인화에 못 쓰고, (라) 는 범위가 큽니다

## 나눔
- BE: upsert + `source` 열 + `/places/{id}` 가 사용자 출처도 돌려주게 (사진은 없음)
- FE(저): compose 에서 `place` 스냅샷 전송, 검사 문구 갱신, 장소 없이 올리려 하면 한 번 묻기(별도)
