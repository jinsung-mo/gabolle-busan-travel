## 1. 왜 기다려야 하나 — 지금 커밋하면 오늘 한 일이 반쯤 없어집니다

오늘 여섯 파트가 각자 충돌을 풀었습니다. **걸린 파일이 여섯 파트에서 똑같았습니다.**

```
CLAUDE.md                      6개 파트 전부
.gitlab-ci.yml                 5개 파트
governance/policy.json         4개 파트
docs/CI.md · HANDOVER · ONBOARDING · setup.sh/ps1 · ax-vote · ax-ballot
```

**즉 오늘 푼 것은 증상이고 원인은 그대로입니다.** 이 파일들이 뿌리에 한 벌씩 있고 파트마다 자기 사본을 고치는 구조라, **내일 또 똑같이 부딪힙니다.**

🔴 그래서 원인을 고치려 합니다. 그런데 **그 고침이 `main` 에서 각 파트로 내려가야** 합니다. 지금 파트 브랜치에 커밋하시면:

- 그 커밋이 `main` 과 다시 갈라지고
- 고침이 내려올 때 **오늘 푼 것과 같은 충돌을 또 풉니다**
- 오늘 각자 쓴 5~10분이 헛일이 됩니다

**한 시간만 참으면 그게 마지막입니다.**

---

## 2. 무엇을 고치나 — 넷

| | 무엇 | 왜 |
|---|---|---|
| **①** | **`.gitlab-ci.yml` 을 파트별로 쪼갠다** | 오늘 손으로 풀어야 했던 유일한 파일입니다. 뿌리에 한 파일이라 파트마다 자기 검사 잡을 거기 넣어 매번 부딪혔습니다. `include:` 로 파트 파일을 끌어오면 **각자 자기 파일만 고치니 안 부딪힙니다** |
| **②** | **`governance/policy.json` 을 `main` 에만 둔다** | 게이트는 이미 **타깃 브랜치(=main)에서만** 읽습니다(G2). 파트 사본은 판정에 쓰이지도 않으면서 충돌만 냈습니다 — 오늘 네 파트가 이 파일로 걸렸습니다 |
| **③** | **`CLAUDE.md` 를 파트 브랜치에서도 16줄 이정표로** | 8월 31일에 규칙을 `CONTRIBUTING.md` 로 옮겼는데 파트 브랜치에는 옛 361줄이 남아 있어 **여섯 파트 전부가** 이 파일로 걸렸습니다 |
| **④** | **한 바퀴를 한 판으로 센다** | 오늘 `main` 머지 여섯 번으로 버전이 **v4 → v10** 이 됩니다. 하루에 여섯 판이면 숫자가 아무것도 가리키지 않습니다 |

①이 가장 값집니다. 오늘 충돌 열 개 중 **아홉은 「main 쪽 받기」로 기계적으로 끝났고, 손으로 풀어야 한 것은 `.gitlab-ci.yml` 하나뿐**이었습니다. 그 하나가 파트마다 자기 잡을 잃을 위험을 만들었습니다 (`bigData` 에서 LFS 우회 한 줄이 실제로 걸렸습니다 — 받았으면 태그 push 가 다시 죽었습니다).

## 3. 순서 — 이 순서를 지켜야 뜻이 있습니다

```
① 지금        여섯 파트 → main 머지            ← 표만 남았습니다
② 그다음      main 에서 위 넷을 고친다 (MR 1~2개)
③ 그다음      각 파트가 main 을 받아간다
                git switch <파트>/main && git merge origin/main
                git switch <파트>/dev  && git merge origin/<파트>/main
④ 그 뒤에     작업 재개
```

🔴 **③을 파트 `main` 뿐 아니라 파트 `dev` 까지 해야 합니다.** dev 를 안 받으면 다음 승격에서 같은 충돌을 또 만납니다.

## 4. 기다리는 동안 하실 수 있는 것

**아무것도 못 하는 게 아닙니다.** 위 파일들을 안 건드리는 일은 괜찮습니다.

| 🟢 해도 되는 것 | 🔴 하지 마실 것 |
|---|---|
| 자기 파트 폴더 안의 코드 (`backend/` · `frontend/` · `bigData/` · `map/`) — **커밋만 하고 push 는 잠깐 보류** | `CLAUDE.md` · `CONTRIBUTING.md` |
| 문서 읽기 · 설계 · 조사 | **`.gitlab-ci.yml`** |
| Jira 정리 · 리뷰 | `governance/policy.json` |
| **표 던지기** (지금 여덟 MR 이 기다립니다) | `docs/` 의 공용 문서 · `setup.sh/ps1` · `.claude/commands/` |
| 로컬에서 테스트 돌리기 | 파트 브랜치에 **push** |

**가장 도움이 되는 것은 표입니다.** 지금 MR 여덟 개가 전부 0/2 로 서 있고, 코드는 다 준비됐습니다.

```
!443 back      !444 ai        !234 map       !457 bigData
!458 common    !445 설문DB백업  !449 DAG고침    !454 정책 한 줄
```

각자 **남의 파트에 두 장씩** 던지시면 몇 분 안에 여덟 개가 다 올라갑니다.
