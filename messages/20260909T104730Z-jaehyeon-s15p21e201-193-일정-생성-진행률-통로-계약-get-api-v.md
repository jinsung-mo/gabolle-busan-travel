일정 생성 진행률을 서버가 밀어 보내는 통로를 열었습니다(S15P21E201-193, MR !467, back/dev 머지). 화면에서 부르실 수 있습니다.

  GET /api/v1/jobs/{jobId}/progress
  Accept: text/event-stream

접속하면 그 자리에서 지금 진행률 한 건이 옵니다. 그 뒤로는 단계가 넘어갈 때마다 옵니다.

사건 이름이 셋입니다.

  progress    도는 중
  completed   끝났고 결과가 있다
  failed      끝났는데 결과가 없다

본문은 셋 다 같은 모양입니다.

  { "jobId": "...", "status": "RUNNING", "stage": "RANKING", "percent": 70, "code": null }

percent 는 0~100 이고 실제로 오르는 값은 20 → 35 → 70 → 85 → 100 입니다. code 는 failed 일 때만 채워집니다.

알아 두시면 좋은 것 넷입니다.

1. 끊겼다 다시 붙으면 0% 가 아니라 그 시점 값이 먼저 옵니다. 진행률을 화면 상태에 그대로 넣으셔도 됩니다.
2. completed 나 failed 가 오면 서버가 연결을 닫습니다. 다시 열 필요 없습니다.
3. 같은 값이 두 번 올 수 있습니다(접속 직후와 그 직후의 단계 전환이 겹칠 때). 진행률은 덮어쓰면 되므로 문제는 없지만, 사건마다 무언가를 누적하시면 그 자리는 조심해 주세요.
4. 연결은 5분이 지나면 한 번 끊깁니다. 그때는 다시 접속하시면 이어집니다.

기존 폴링(GET /api/v1/jobs/{jobId})은 그대로 둡니다. 이 통로는 서버 한 대를 전제하고 오래 열린 연결을 끊는 망도 있어서, 두 길을 다 가지고 계시는 편이 안전합니다.

한 가지 남는 것 — 진행률이 실제로 올라가는 것을 보려면 추천 엔진이 붙은 배포여야 합니다. 엔진이 없으면 후보 생성 단계에서 바로 끝나 20% 에서 completed 나 failed 로 갑니다.
