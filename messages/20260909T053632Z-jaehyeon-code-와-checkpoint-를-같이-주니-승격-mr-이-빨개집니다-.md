## 무슨 일이 났나

`!443` (`back/main` → `main`) 의 `claims` 잡입니다.

```
코드 대조 구간: f1f21cf..bf6afe34        ← main..back/main, 556커밋
감사 실패 - 스냅샷 666개 중 위반 75건

면제 188개 - 첫 체크포인트보다 앞선 코드 커밋이라 판정하지 않았습니다
```

**장부 쪽은 체크포인트가 잘 듣습니다** — 1014개를 보증하고 666개만 재생했습니다. 문제는 **코드 대조 쪽**입니다.

`--code "$RANGE"` 의 범위가 MR 의 diff base 부터라, 기능 브랜치 MR 에서는 커밋 두세 개지만 **승격 MR 에서는 556커밋**이 됩니다. 그래서 9월 7일에 선점 없이 고쳐진 것들이 지금 한꺼번에 걸립니다.

걸린 것은 남의 것과 제 것이 섞여 있고 전부 며칠 전 것입니다.

## 무엇이 사실인가

**없던 위반이 생긴 게 아닙니다.** 지금까지 `--code` 가 작은 범위에서만 돌아서 **안 보이던 자리가 열린 것**입니다. `common/dev` 쪽(`!363`)이 초록으로 통과한 것도 그쪽 이력에 그런 커밋이 없어서지, 검사가 약해서가 아닙니다.

그러니 이건 **검사가 제 일을 한 것**이고, 백엔드 이력에 정리 안 된 것이 75건 있다는 뜻입니다.

## 다만 지금 이대로면 승격이 막힙니다

75건은 네 사람의 며칠치라 오늘 안에 못 풉니다. 넷 중 하나를 골라야 할 것 같은데 셋은 제가 정할 자리가 아닙니다.

| | 무엇 | 대가 |
|---|---|---|
| 1 | `back/main` 만 `--checkpoint` 로 되돌린다 | 오늘 승격은 되지만 코드 대조를 잃는다 |
| 2 | `--code` 를 기능 브랜치 MR 에서만 준다 (rules 로 가른다) | 승격은 열리고 평소 검사는 유지된다. 대신 승격 경로에는 코드 대조가 없다 |
| 3 | `--code` 도 체크포인트를 존중하게 한다 | 가장 옳아 보이지만 axmap 쪽 변경이라 제 손 밖입니다 |
| 4 | 75건을 정리하고 간다 | 가장 깨끗하지만 오늘은 못 한다 |

저는 **2번**이 오늘의 답이고 **3번**이 제대로 된 답이라고 봅니다. 2번은 제가 바로 넣을 수 있습니다.

어느 쪽으로 갈지 말씀 주시면 그대로 하겠습니다. 그동안 `!443` 은 빨간 채로 두겠습니다 — 초록으로 만들려고 검사를 약하게 하는 것부터 하고 싶지 않습니다.
