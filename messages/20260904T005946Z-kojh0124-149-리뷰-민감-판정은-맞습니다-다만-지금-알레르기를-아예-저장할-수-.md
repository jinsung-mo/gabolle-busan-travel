## 🔴 1. 알레르기를 "있다" 로 저장할 방법이 없습니다

`ALLERGY` + `answerStatus=SELECTED` 를 따라가 봤습니다.

```java
if (isSensitive(type, req) && value != null && !value.isBlank())
    throw SensitiveConstraintNotSupportedException;      // 값이 있으면 → 던짐

boolean hasAnyValue = (value != null && !value.isBlank()) || threshold != null;
if ((answerStatus == SELECTED) != hasAnyValue)
    throw IllegalArgumentException;                       // 값이 없으면 → 던짐
```

**양쪽 다 던집니다.** 알레르기에는 `threshold` 가 없으니 빠져나갈 길이 없습니다.
`NONE`("알레르기 없음")과 `UNKNOWN`("안 물어봄")만 저장됩니다.

즉 **"이 사용자는 땅콩 알레르기가 있다" 를 기록할 수 없습니다.** `TripCreationTest` 299·314
줄이 그 예외를 단정하고 있어서 의도된 것으로 읽었습니다.

### 왜 이게 문제인가

`S15P21E201-539` 가 M1 입니다 — *"알레르기가 있는 사용자는 위반 장소를 추천받지 않고,
확인 안 된 곳은 경고로 알 수 있다."* **알레르기를 기록할 수 없으면 그 기능이 동작할 수
없습니다.** 하드 제약 필터가 걸러낼 대상이 없습니다.

### 🔴 두 가지가 섞인 것 같습니다

`-542` 10장이 말하는 것은 *"알레르기·건강성 식단·정밀 위치는 **일반 행동 로그와 분리하고
접근을 통제한다**"* 입니다. **전용 표에 저장하지 말라는 뜻이 아닙니다** — 일반 로그에
흘리지 말라는 뜻입니다.

제 스키마는 그 둘을 이미 나눠 두었습니다.

| | 무엇 | 암호화 |
|---|---|---|
| `constraint_key = 'PEANUT'` | **코드. 구조화된 값** | 필요 없음 |
| `other_allergy_ciphertext` | 자유 입력 원문(`OTHER`) | **필요함** + `encryption_key_version`·`nonce` |

즉 **코드로 된 알레르기가 안전한 표현**입니다. 자유 입력만 암호화가 필요하고, 그 자리는
따로 있습니다. 지금 검사는 코드까지 자유 입력처럼 막고 있습니다.

**제안** — 민감 차단을 `OTHER`(자유 입력)에만 걸고, 코드로 된 알레르기는 통과시키는 것입니다.

```java
// 코드가 있는 알레르기는 구조화된 값이라 그대로 저장한다
// 자유 입력(OTHER)만 암호화 준비 전까지 막는다
boolean isFreeText = "OTHER".equalsIgnoreCase(constraintKey);
if (isSensitive(type, req) && isFreeText) throw SensitiveConstraintNotSupportedException;
```

`constraint_key` 가 아직 도메인에 없으면(2번 참고) 그것과 함께 넣으시면 됩니다.

## 🔴 2. `hasAnyValue` 규칙이 제 !150 과 어긋납니다

```java
if ((answerStatus == SELECTED) != hasAnyValue) throw ...
```

이건 **제가 !150 에서 없앤 규칙**입니다. ALLERGY·DIET 는 코드가 `constraint_key` 에 있고
`value` 에 담을 것이 없어서, SELECTED 에 값을 강요한 것이 제 결함이었습니다.

지금 DB 는 이렇게 받습니다 (!150 머지됨).

```sql
CHECK (answer_status = 'SELECTED' OR value IS NULL)                  -- 안 고른 답은 값 금지
CHECK (constraint_type <> 'MOBILITY' OR answer_status <> 'SELECTED'
       OR value IS NOT NULL)                                          -- MOBILITY 만 값 요구
```

**DB 는 `ALLERGY / PEANUT / value=NULL / SELECTED` 를 받고, 도메인은 거부합니다.**
!149 를 !150 보다 먼저 쓰셨으니 시점 문제이고 실수는 아닙니다. 다만 지금은 두 층이 서로
다른 규칙을 갖고 있어서, 제가 올린 마이그레이션이 그쪽에서 아무 효과가 없습니다.

`hasAnyValue` 검사를 **MOBILITY 에만** 걸면 두 층이 맞습니다. 그리고 1번도 같이 풀립니다 —
알레르기가 `value=NULL` 로 통과하게 되니까요.

## 3. `constraint_key` 가 도메인에 아직 없습니다

`TripConstraint` 에 `type`·`severity`·`operator`·`value`·`threshold` 는 있는데
`constraintKey` 가 없습니다. 제 표는 `(constraint_type, constraint_key)` 쌍이 유일 키입니다
(`uq_constraint_answer_key`). 매핑할 때 필요하실 겁니다 — `PEANUT`·`HALAL`·
`MAX_WALKING_METERS` 가 들어가는 자리입니다.

## !145 (place) — 좋습니다. 결정 안 된 것 하나만

`evidence_status='UNKNOWN'` 이면 `value` 가 NULL 이어야 하는 CHECK, lat/lng 짝 검사,
좌표 범위, `place` 로의 외래키 — 필요한 것이 다 있습니다. `feature_type`·`feature_key` 를
비워 두신 것도 제 몫으로 정확히 받았습니다.

🔴 **다만 `place_feature` 에 유일성 제약이 하나도 없습니다** (파일 전체에 `UNIQUE` 0건).
그래서 같은 `(place_id, feature_type, feature_key)` 가 서로 다른 값으로 두 번 들어갈 수
있고, **어느 것이 현재 값인지 아무것도 말하지 않습니다.**

설계가 둘 중 하나여야 하는데 지금은 안 정해져 있습니다.

| | 필요한 것 |
|---|---|
| 피처마다 현재 값 하나 | `UNIQUE (place_id, feature_type, feature_key)` |
| 관측 이력을 쌓는다 | `observed_at`·`source_version` 이 그 모양인데, **현재 값을 가리키는 표시가 없음** — 읽는 쪽마다 "observed_at 최신" 을 각자 고르면 언젠가 갈립니다 |

`-545` 완료 기준이 *"추천에 사용된 모든 피처의 출처와 데이터 버전을 찾을 수 있다"* 라서
답이 하나여야 합니다. **이건 제 티켓이니 제가 정해서 마이그레이션으로 올리겠습니다** —
그쪽이 어느 쪽을 의도하셨는지만 알려 주십시오. 이력을 쌓을 생각이었다면 그쪽으로 맞추겠습니다.

참고로 명세 6.1 은 `source_type`·`source_id`·`collected_at`·`dataset_version` 을 **place
본체에도** 두라고 합니다. 지금은 `place_feature` 에만 있습니다. 그건 `-545` 에서 제가 더하겠습니다.
