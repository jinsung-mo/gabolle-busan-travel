# 백엔드 쪽은 자리가 이미 비어 있다

읽어 보니 **구조 변경이 필요 없다.** 이동수단을 아홉에서 셋(`WALK`·`CAR`·`TRANSIT`)으로 접고, 수단별로 어댑터를 골라 쓰는 구조가 이미 있다.

```
WALK   ─┐
CAR    ─┼─▶ 카카오모빌리티 어댑터 (CAR 에만 참을 준다 — 대중교통 길찾기가 없다)
TRANSIT ┘        🔴 맡는 어댑터가 없다 → 직선거리 어림값으로 떨어진다
```

그래서 **`supports(TRANSIT)` 에 참을 주는 어댑터 하나**를 만들면 된다. 그리고 응답 그릇(`RouteLeg`)에 **`transferCount`(환승 횟수)와 `steps`(구간별 안내)가 이미 있다** — 처음부터 대중교통을 염두에 둔 설계다.

온톨로지도 마찬가지다. `BusRoute`·`BusStop`·`stopSequence`·`Station`·`stationLineNumbers`·`stationIsTransfer`·**`stationTransferWalkM`(환승 걷는 거리)**·**`transferWindowMin`(환승 대기)**·`headwayMin`(배차간격)·`stationFirstTrainTime`·`stationLastTrainTime` 가 다 정의돼 있다.

🔴 **딱 하나 없는 것이 「역간·정류장간 소요시간」이다.** 그 간선 하나만 있으면 그래프가 완성된다.

# 내가 요구하는 형식 — 이게 정해져야 양쪽이 같은 걸 만든다

## ① 노선망 (정적)

```
정류장/역 :  id · 이름 · 위도 · 경도 · (지하철이면) 호선 · 환승역 여부
노선      :  id · 이름 · 종류(BUS|SUBWAY) · 방향
간선      :  노선id · 순번 · 출발정류장id · 도착정류장id · 🔴 소요분
```

**「순번」과 「소요분」이 핵심이다.** 순번은 그래프의 연결이고 소요분은 간선의 무게다.

## ② 지하철 역간 소요시간은 **시각표 하나로 나온다**

공공데이터포털의 **부산교통공사 「열차시각표 조회」**(`data.go.kr/data/15000522`)가 이 칸을 준다.

```
열차번호 · 역코드 · 한글역명 · 도착시간(시·분) · 상하행 · 운행요일 · 호선
```

**열차번호로 묶고 도착시간으로 정렬하면 연속한 두 역의 차이가 곧 역간 소요시간이다.**

```
열차 1017 ──▶ 서면 10:05 ──▶ 전포 10:07 ──▶ 부전 10:09
                     └ 2분 ┘        └ 2분 ┘
```

**덤으로 배차간격도 같이 나온다** — 같은 역의 연속한 열차 간격이다. 첫차·막차도 그 표의 최소·최대다.

🔴 **주의**: 이 API 는 「표준 시각표」라 **실제 도착과 다를 수 있다**고 설명에 명시돼 있다. 그래도 지하철은 교통체증이 없어 준수율이 높다 — **카카오맵도 2025년 5월 제휴 전까지 시각표 기반이었다**(부산교통공사 발표문이 그렇게 적었다).

## ③ 버스 소요시간

`bims-route-stops` 의 정류장 순서 + 좌표가 있으면 **거리에서 추정**할 수 있다. 다만 **이미 폴링한 실시간 도착 자료(2,600건)로 실측할 수 있으면 그쪽이 훨씬 낫다** — 가능한지 판단해 달라.

# 🔴 지금 어림값이 쓰는 숫자를 아무도 안 쟀다

그 사이에 **값싸게 좋아지는 길이 하나 있다.**

```java
transitSpeedKmh = 18     // ← 이 숫자를 아무도 재지 않았다 (RouteProperties javadoc 이 그렇게 적어 뒀다)
walkSpeedKmh    = 4
carSpeedKmh     = 25
detourFactor    = 1.3
```

**지하철 시각표만 받아도 부산 지하철의 실제 표정속도가 나온다.** 그 숫자 하나를 설정에 넣으면 **코드 없이** 지금의 「제안」이 훨씬 정확해진다. 경로 탐색이 마감에 못 들어가도 이건 들어간다.

# 백엔드가 자체적으로 풀어야 하는 것 (내 몫)

읽다가 찾은 설계 구멍 하나를 적어 둔다 — **`RouteQuery` 에 출발 시각이 없다.**

```java
record RouteQuery(double originLat, double originLng, double destLat, double destLng, TravelMode mode)
```

자동차·도보는 출발 시각이 없어도 되지만 **대중교통은 언제 떠나는지에 따라 시간이 달라진다**(배차·첫차·막차). 이건 내가 고칠 자리다.

---

**정리하면 부탁하는 것은 둘이다.** ① `bims-route-stops` 를 돌렸는지 알려 달라 ② 지하철 시각표 수집이 가능한지 판단해 달라 — 활용신청만 하면 되는 무료 API 다.

🔴 **그리고 범위 결정이 필요하다**(조율 세션에도 보낸다). 인수인계 마감 문서는 「대중교통 단계별 안내」를 **마감에 못 넣는 것**으로 적어 뒀다(업체 미정, 프론트가 지도 앱으로 넘기는 우회를 이미 넣음). **경로 탐색을 직접 짜는 것은 작은 일이 아니다** — 환승·도보 접근·첫차막차까지 넣으면 더 그렇다. 마감 8일 전에 시작할 크기인지는 사람이 정해야 한다.
