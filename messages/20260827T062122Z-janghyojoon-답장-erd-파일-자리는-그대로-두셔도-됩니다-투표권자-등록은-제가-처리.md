# 1. ERD 파일 자리 — `ref/` 그대로 두시면 됩니다

지금 잡아 두신 자리를 봤습니다.

```
ref/local-route/LOCAL_ROUTE_ERD_사용자취향_부담_제안.dbml
```

**여기가 맞습니다. 옮기지 마세요.**

`ref/README.md` 에 이 폴더가 무엇인지 적혀 있는데, 요지가 이렇습니다.

| 어디 | 무엇을 두나 | 올릴 때 |
|---|---|---|
| **`ref/`** | **초안** · 스케치 · 회의 메모 | 검사가 거의 안 돎 → **MR 을 열면 바로 초록, 즉시 머지** |
| `docs/` | 팀이 **지키기로 확정한 것** | 검사 전부 통과해야 함 |

지금 만드시는 건 파일 이름부터 `..._제안` 이고, 제가 쪽지에서 "확정이 아니라 제안으로 그려 달라"고 부탁드린 것이니 **`ref/` 가 정확히 그 자리입니다.**

만약 `docs/` 에 넣으면 오히려 곤란해집니다 — 그쪽은 **정족수**(**통과에 필요한 최소 찬성 수**) 검사가 걸려서, 아직 아무도 안 본 초안에 투표를 요구하게 됩니다.

**나중에** 팀이 이 설계를 쓰기로 정하면, 그때 `docs/LOCAL_ROUTE_기획서_v7.md` 8장으로 옮기면 됩니다. 그건 제가 하겠습니다.

> `.dbml` 로 쓰시는 것도 좋은 선택이라고 생각합니다. **DBML**(**Database Markup Language — 데이터베이스 설계도를 글로 적는 문법. `dbdiagram.io` 에 붙여넣으면 자동으로 그림이 됩니다**)은 이미지와 달리 **칼럼 하나 고칠 때 그림을 다시 안 그려도 되어서** 초안 단계에 잘 맞습니다.

폴더 이름은 신경 쓰지 마세요. `ref/README.md` 가 이렇게 적어 뒀습니다 — *"폴더 규칙을 만드느라 자료를 안 올리는 것보다, 어수선하게라도 올라와 있는 편이 낫다."*

# 2. 투표권자 등록 — 두 번 물어보셨는데 답이 늦었습니다. 죄송합니다

**결론부터: 진미리 님이 하실 일은 없습니다. 제가 처리하겠습니다.**

## 지금 상태

`governance/policy.json`(**누가 투표권자인가를 적어 둔 파일**)에 진미리 님을 추가하는 브랜치를 이미 만들어서 올려 뒀습니다.

```
브랜치: chore/common/S15P21E201-33-add-voter-jinmiri
커밋:   [S15P21E201-33] chore: [Common] 진미리를 투표권자 명단에 추가한다
```

들어간 내용:

```json
{ "id": "jinmiri", "email": "wlsalfl321@naver.com" }
```

알려주신 이메일 그대로입니다. **그리고 왜 이 이메일인지를 파일 안에 주석으로 박아 뒀습니다** — 팀 안에서는 `ssafy0121@gmail.com` 으로 알려져 있었기 때문에, 나중에 누가 "틀린 것 같은데" 하고 고쳐 버리면 진미리 님이 **한 표도 못 던지는 상태**가 되기 때문입니다.

> 참고로 표를 세는 프로그램은 **커밋 저자 이메일 완전일치**로만 셉니다. 대소문자만 무시하고, 그 밖에는 한 글자라도 다르면 그 표는 없는 것이 됩니다. 그래서 로컬 저장소의 `git config user.email` 을 계속 `wlsalfl321@naver.com` 으로 유지해 주시겠다고 하신 게 정확히 맞는 조치입니다.

## 언제 실제로 효력이 생기나 — 여기는 솔직히 말씀드립니다

**바로는 아닙니다.** 이 저장소는 브랜치를 사다리처럼 한 칸씩 올라갑니다.

```
chore/common/S15P21E201-33-…   ← 지금 여기
        ↓  표 필요 없음 (오늘 처리 가능)
common/dev
        ↓  표 2장 필요
common/main
        ↓  표 2장 필요
main                            ← 여기 도착해야 실제로 효력
```

표를 세는 검사는 **대상이 `main` 으로 끝나는 MR 에서만** 돕니다. `dev` 로 가는 것은 표가 필요 없습니다. (하루 수십 건에 다 표를 걸면 사람들이 MR 자체를 안 쓰게 되기 때문이라고 CI 설정 주석에 적혀 있습니다.)

그리고 **투표권자 명단은 언제나 "받는 쪽 브랜치"의 것을 읽습니다.** 그래서 진미리 님 이름이 `main` 에 도착하기 전까지는, 아직 진미리 님이 표를 던지셔도 안 세어집니다. 이건 저희가 늦은 게 아니라 구조가 그렇습니다.

**며칠 걸릴 수 있습니다.** 다만 이것 때문에 막히는 일은 없습니다 — 코드를 올리고, 브랜치를 만들고, `dev` 로 MR 을 여는 것은 **지금도 전부 하실 수 있습니다.** 투표권은 `main` 으로 올라가는 큰 변경에만 필요합니다.
