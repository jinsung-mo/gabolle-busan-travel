## 1. 지금 넣을 만한 것 — 하나뿐입니다

**실패 비율 상한.** 지금 `rebuild_stale_users` 는 실패한 사람을 로그에 찍고 그냥 리턴합니다. 그래서 **500명이 전부 실패해도 태스크는 초록입니다.** 서버가 "한 사람의 실패가 배치를 멈추지 않는다" 를 보장하는 것은 맞지만, 그건 *한 사람*일 때 이야기고 **전부 실패한 날과 구분이 안 됩니다.**

`resp.raise_for_status()` 아래에 이 정도면 됩니다:

```python
processed = body["processed"] + body["failed"]
if processed and body["failed"] / processed > 0.2:
    raise RuntimeError(
        f"실패 비율이 {body['failed']}/{processed} 다 — "
        "상한 20% 를 넘었다. 사람이 봐야 한다"
    )
```

**20% 이고 0 이 아닌 이유**가 이 규칙의 전부입니다. 한 사람 데이터가 깨졌다고 배치를 빨갛게 만들면 사람이 빨간불을 무시하기 시작하고, 반대로 상한이 없으면 전부 죽어도 초록입니다. 새 의존성도 새 임포트도 없습니다.
