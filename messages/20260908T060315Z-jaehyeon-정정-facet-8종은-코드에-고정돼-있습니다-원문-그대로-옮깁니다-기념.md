## 여덟 갈래 — `InterestTagCode`

`facetType` 은 `INTEREST_TAG` 이고, `facetKey` 에 아래 값을 넘기시면 됩니다. **선언 순서가 곧 화면에 그릴 순서**입니다.

| facetKey | labelKo |
|---|---|
| `FESTIVAL` | 축제 |
| `NIGHT_MARKET` | 야시장 |
| `TRADITIONAL_MARKET` | 전통시장 |
| `ACTIVITY` | 액티비티 |
| `WALK` | 산책 |
| `NATURE` | 자연 |
| `NIGHT_VIEW` | 야경 |
| `SOUVENIR_SHOP` | **기념품샵** |

물어보신 기념품샵은 `SOUVENIR_SHOP` 입니다.

## 🔴 목록을 화면 코드에 박지 마세요

서버가 이 여덟을 **항상 전부** 돌려줍니다. 데이터가 없는 갈래도 `placeCount: 0` 으로 나옵니다. 아코디언이 접힌 줄로 그려야 하니까요.

그래서 화면은 `GET /api/v1/places/facets` 응답을 그대로 그리시면 됩니다. 목록을 앱에 박으면 **서버와 앱 양쪽에 같은 목록이 두 벌** 생기고, 갈래가 늘거나 이름이 바뀔 때 앱을 다시 배포해야 합니다. `labelKo` 를 서버가 같이 주는 이유가 그것입니다 — 배포된 앱은 즉시 못 고칩니다.

## 제가 앞 답장에서 틀렸던 것

"그 목록은 적재된 데이터에서 나온다" 고 적었는데, **갈래 목록은 코드에 있고 건수만 데이터에서 옵니다.** 확인이 부족한 채로 답했습니다. 위 표가 맞습니다.

즉 **부르셨는데 8종이 안 나오는 경우는 없습니다.** 건수가 전부 0 이면 그건 목록 문제가 아니라 장소 데이터에 태그가 안 붙은 것이고, 그때는 데이터 담당에게 넘길 건입니다.
