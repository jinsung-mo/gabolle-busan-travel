## 어디서 읽으면 되나

`recommendation_candidate.score_components` (JSONB) 안의 **`reasonRanking`** 키입니다. 반환된 후보(`returned = true`)에만 붙습니다.

```json
{
  "distance":  { "weight": 0.30, "value": 0.82, "dimensions": null },
  "interest":  { "weight": 0.20, "value": 0.50 },
  "reasonRanking": {
    "topAxes": [
      { "axis": "distance", "weight": 0.30, "value": 0.82, "contribution": 0.246 },
      { "axis": "interest", "weight": 0.20, "value": 0.50, "contribution": 0.100 }
    ],
    "distinctiveAxes": [
      { "axis": "slopePreference", "weight": 1.0, "value": 0.9,
        "contribution": 0.180, "cohortMean": 0.132, "delta": 0.048 }
    ]
  }
}
```

- `weight`·`value` 는 **계산에 실제로 쓰인 값 그대로**입니다 — -205 의 완료 기준 "문구의 숫자가 실제 점수 계산 결과와 일치한다" 를 위해 옮겨 적지 않고 그대로 실었습니다
- `contribution = weight × value`
- 최대 3개씩입니다
- 값을 못 구한 축은 **빠집니다**(0 으로 채우지 않았습니다 — "기여가 없었다" 와 "재지 못했다" 는 다른 사실입니다)
- 동점은 축 이름으로 가릅니다 → 같은 입력이면 순서가 늘 같습니다. -205 의 "같은 조건으로 두 번 생성하면 글자까지 같은 문구" 가 이것에 의존합니다

이유 코드에도 절대 기여 1위가 붙습니다: `TOP_CONTRIBUTOR_distance` 처럼요. 🔴 축 이름을 대문자로 바꾸지 않고 `score_components` 의 키를 **글자 그대로** 붙였습니다 — 바꿔 적으면 코드에 적힌 축 이름과 `reasonRanking` 에 적힌 축 이름이 달라져서 어느 쪽을 믿어야 할지 모르게 됩니다.

`distinctiveAxes` 는 **그 결과 안의 평균과의 차이**입니다(`delta`). 카드마다 다른 문장이 나오게 하려면 이쪽이 맞고, 명세 그대로 가려면 `topAxes` 입니다.

**지금은 명세대로 `topAxes` 를 쓰시면 됩니다.** 문장을 만들어 보시고 모든 카드가 똑같이 읽히면 `distinctiveAxes` 가 이미 옆에 있습니다. 어느 쪽을 쓸지는 문장을 만드는 쪽의 결정이라 제가 하나로 정하지 않았습니다 — 다만 정하시면 알려 주세요. 필요 없는 쪽은 빼서 JSONB 를 가볍게 하겠습니다.

## 같이 알아 두실 것 둘

**1. 순위가 이제 점수 순이 아닙니다.** 같은 카테고리·같은 1km 칸이 상위를 독점하지 않게 재정렬이 들어갔습니다(기본 켜짐). `original_rank`(점수 순)와 `final_rank`(재정렬 순)가 함께 남고, 움직인 후보에는 `DIVERSITY_RERANKED` 가 붙습니다. **점수(`final_score`)는 안 바뀝니다** — 벌점은 순서에만 씁니다. 문장이 "1위" 를 말한다면 `final_rank` 쪽입니다.
