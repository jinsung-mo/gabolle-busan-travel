## 1. 이유(note)를 안 적으면 표가 안 세어집니다 (2026-09-14 부터)

`back/dev` 판정문:

```
o masdf13  <masdf13@naver.com>
x jinmiri  <wlsalfl321@naver.com> — 이유(note)를 안 적은 표 — 정책이 이유를 요구한다
```

`hotfix/S15P21E201-937-vote-note`(!755)가 머지되면서 `governance/policy.json` 에 이게 들어갔습니다:

```json
"vote_note": { "min_chars": 20, "since": "2026-09-14T06:00:00Z" }
```

**`since` 이후에 던진 표에만** 요구하므로 그 전 표는 안전합니다. 다만 **정책 파일은 타깃 브랜치에서 읽으므로**(G2), 어느 브랜치로 던지든 `main` 의 이 값이 적용됩니다.

```bash
npx -y axmap-cli@latest vote --branch <브랜치> \
  --sha $(git rev-parse origin/<브랜치>) --vote approve --target origin/main \
  --note "<20자 이상, 무엇을 보고 왜 찬성하는지>"
```

`--note` 를 빼면 던지는 쪽(`axmap-cli`)이 막아 주긴 하는데, **옛 판을 쓰면 그냥 통과하고 세는 쪽에서만 무효**가 됩니다. 그게 이 규칙이 일부러 양쪽에서 막는 이유이기도 합니다.

## 2. git 이름이 명단과 다르면 표가 버려집니다

`common/dev` 판정문:

```
x jaehyeon <masdf13@naver.com> — 표의 이름과 email 이 명단과 어긋남 (명단은 masdf13)
```

**박재현 님이 git `user.name` 을 두 가지로 쓰고 계십니다** — `jaehyeon` 과 `masdf13`. 이메일은 같은데 `governance/policy.json` 명단에는 `masdf13` 으로만 있어서, **`jaehyeon` 이름으로 던진 표는 집계에서 빠집니다.** 표 이력에 두 이름이 다 남아 있어 세션마다 갈린 것으로 보입니다.

던지기 전에 한 줄로 확인됩니다:

```bash
git config user.name    # masdf13 여야 합니다
```

고치는 길은 둘입니다.

| | |
|---|---|
| **쉬운 쪽** | 그 PC/세션의 `git config user.name` 을 `masdf13` 으로 맞춥니다. 표만이 아니라 커밋 저자 표기도 한 사람으로 모입니다 |
| **명단 쪽** | `policy.json` 의 해당 항목이 `jaehyeon` 도 인정하게 고칩니다 — **개정 문턱이라 2표가 필요**하고, 이름이 둘로 남는 것 자체가 다음 사람에게 또 헷갈립니다 |

저는 첫 번째를 권합니다. 다만 이건 본인 결정이라 고치지 않고 알려만 드립니다.

## 공통 — 던진 뒤에 한 번 세어졌는지 보십시오

두 경우 다 **던질 때는 성공으로 뜹니다.** 세어졌는지는 판정문에서만 보입니다.

```bash
npx -y axmap-cli@latest gate --source <브랜치> --target origin/main
# '센 표' 목록에 내 이름이 있는지 봅니다
```

🔴 **로컬 브랜치가 있으면 게이트가 원격 대신 그것을 봅니다.** 던지기 전에 맞춰 두십시오 — `git fetch` 만으로는 안 고쳐집니다.

```bash
git branch -f <브랜치> origin/<브랜치>
```
