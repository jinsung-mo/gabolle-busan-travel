## 무엇이 되나

기록을 만든 사람이 초대 링크를 만들고, 받은 사람이 그 링크를 누르면 **같은 기록의 본문을 함께 고칩니다.** 여행 동행자 초대와 같은 방식입니다.

```
POST   /api/v1/stories/{storyId}/invites            초대 링크 발급 (만든 사람만)
  -> { storyInviteId, storyId, token, expiresAt, acceptPath }
     acceptPath 를 그대로 링크로 만들어 공유하시면 됩니다

POST   /api/v1/story-invites/{token}/accept         수락
  -> { storyId, alreadyJoined, joinedAt }

GET    /api/v1/stories/{storyId}/coauthors          참여자 목록
  -> { coauthors: [ { userId, displayName, author, joinedAt } ] }
     author 가 true 인 줄이 만든 사람입니다

POST   /api/v1/stories/{storyId}/coauthors          여행 동행자를 골라 넣기 (만든 사람만)
  -> 본문 { userIds: [...] }

DELETE /api/v1/stories/{storyId}/coauthors/{userId} 내보내기 / 나가기
```

## 화면에서 조심할 것 넷

**`alreadyJoined` 를 오류로 그리지 마세요.** 링크를 두 번 눌러도 성공입니다. 이미 참여 중이면 `true` 로 옵니다. "이미 참여하고 있어요" 정도로 안내하시면 됩니다.

**공동 작성자는 공개 범위와 공개 시각을 못 바꾸고 기록도 못 지웁니다.** 만든 사람만 됩니다. 참여자 목록의 `author` 로 갈라서 그 사람에게만 버튼을 보여 주세요. 안 가리고 보내면 403 이 옵니다.

**"동행자 골라 넣기" 는 그 기록에 여행이 붙어 있어야 합니다.** 여행이 없는 기록에서 부르면 400 입니다. 그리고 넣으려는 사람이 그 여행의 동행자가 아니면 역시 400 이고, 목록 중 하나만 아니어도 **요청 전체가 거부**됩니다.

**나가기 전에 사용자에게 알려 주셔야 하는 것이 하나 있습니다.** 본문이 한 덩어리라 **나가도 그 사람이 쓴 문장은 기록에 남습니다.** 누가 쓴 부분인지 갈라낼 수 없어서 지울 수가 없습니다. 이건 결함이 아니라 "한 덩어리 글을 같이 고친다" 를 고른 결과라, 나가기 버튼 옆에 한 줄 적어 주시는 편이 좋겠습니다.

## 동시에 고치면

**나중에 저장한 쪽이 이깁니다.** 충돌을 감지해서 막지 않기로 했습니다(같이 여행한 사이라면 편하게 고칠 수 있어야 한다는 판단입니다). 대신 기록 응답에 **마지막으로 고친 사람**이 실려 나가니, "방금 OO 님이 고쳤어요" 를 보여 주시면 사용자가 자기 글이 왜 바뀌었는지 알 수 있습니다.
