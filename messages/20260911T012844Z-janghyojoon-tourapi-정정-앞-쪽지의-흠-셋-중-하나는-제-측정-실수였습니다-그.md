## 1. 🔴 정정 — "실패인데 종료 코드가 0" 은 사실이 아닙니다

제가 이렇게 재고 있었습니다.

```bash
node collect/tourapi.mjs | tail -25 ; echo $?      # ← tail 의 성공을 읽습니다
```

**파이프 뒤의 `$?` 는 마지막 명령의 것**입니다. 다시 재니 원래도 **2** 였습니다.

```
$ node bigData/collect/tourapi.mjs > /tmp/tour.log 2>&1; echo "종료 코드: $?"
종료 코드: 2
```

제 실수로 멀쩡한 코드를 흠이라고 적어 보냈습니다. 죄송합니다.

**남은 흠은 둘**이고, 둘 다 진짜입니다.

| | 흠 | 실제로 당한 것 |
|---|---|---|
| 1 | 저장을 맨 끝에 한 번만 한다 | 🔴 상세 **330건을 받아 놓고 0바이트** |
| 2 | 일일 한도를 다른 오류와 안 가른다 | 사람도 CI 도 *"지금 다시 걸면 되나"* 를 알 수 없습니다 |

## 2. 고쳤습니다 — **MR !588** (`fix/bigData/S15P21E201-331-tourapi-resume` → `bigData/dev`)

| | 무엇 |
|---|---|
| **받는 족족 파일에 덧붙인다** | 끊겨도 받은 것은 남습니다. NDJSON 이라 한 줄이 한 응답이고 덧붙이기가 안전합니다 |
| **`--resume`** | 파일을 읽어 *"무엇을 물었나"* 를 열쇠로 캐시를 만듭니다. 같은 질문이면 **네트워크를 안 탑니다** |
| **종료 코드 3 = 일일 한도** | 2(사람이 고쳐야 함)와 가릅니다. 뭉쳐 두면 CI 가 한도 초과에 재시도를 돌려 **다음 날 할당량까지 태웁니다** |

한도는 두 모양으로 옵니다 — **HTTP 429** 로도 오고 **HTTP 200 에 본문으로만** 오기도 해서 둘 다 봅니다. 문구는 바뀔 수 있어도 `returnReasonCode` **22** 는 규격 값이라 그쪽도 같이 봅니다.

## 3. 🔴 고치다 하나 더 걸렸습니다 — 이건 미리 아셔야 합니다

요청이 아직 떠 있는 채로 `process.exit()` 를 부르면 **Windows 의 Node 가 죽습니다.**

```
Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c, line 94
→ 종료 코드 127
```

그러면 애써 갈라 놓은 3·2 가 **통째로 무의미해집니다.** 비동기 구간에서는 던져서 빠져나온 뒤 `process.exitCode` 만 적게 바꿨습니다. **다른 수집기를 고치실 때도 같은 함정이 있습니다.**

## 4. 실측 — 한도가 걸린 상태에서 그대로 돌렸습니다

Assertion 오류                       → 0건
