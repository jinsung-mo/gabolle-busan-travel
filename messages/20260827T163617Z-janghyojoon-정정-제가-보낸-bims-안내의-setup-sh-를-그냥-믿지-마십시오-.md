# 정정 — 아까 안내에 적은 `./setup.sh` 가 리눅스·Git Bash 에서 중간에 죽습니다

몇 시간 전 **버스 수집기 설치 안내**를 보내면서 2단계에 `./setup.sh` 를 적었습니다.
그런데 **그 스크립트가 지금 중간에서 죽는다는 경고가 이미 쪽지함에 있었고, 제가 확인
없이 전달했습니다.** 그대로면 아침에 여러 명이 같은 자리에서 막힙니다.

## 무슨 문제였나

`setup.sh` **80행**이 정의되지 않은 `say` 를 부르고, 16행에 `set -euo pipefail` 이 있어
거기서 통째로 멈춥니다. 종료 코드 **127**. 정의된 함수는 `ok`·`warn`·`fail` 셋뿐이었습니다.

🔴 **80행 뒤가 전부 안 돕니다.** 특히 **자가 점검(`doctor`)** 이 안 돌아서 무엇이
빠졌는지 아무도 모른 채 넘어갑니다. 그런데 **앞부분은 정상으로 보입니다** — 그래서
"준비가 끝났다" 고 믿고 넘어가고, 나중에 커밋이 막히거나 AI 도구가 선점 장치에 안 붙는
것으로 증상이 나타납니다. **원인에서 먼 자리에서 터집니다.**

## 왜 아무도 못 잡았나 — 운영체제마다 결과가 셋으로 갈립니다

| | |
|---|---|
| 윈도우 (`setup.ps1`) | **정상.** 그 파일에는 처음부터 `function Say` 가 있었습니다 |
| 맥 | **안 죽습니다.** 맥에는 `say` 라는 **진짜 명령**이 있어서(글자를 소리 내어 읽는 기능) 안내문을 스피커로 읽고 그냥 넘어갑니다 |
| **리눅스 · Git Bash** | **죽습니다** |

## 고쳐서 올렸습니다

브랜치 **`fix/common/S15P21E201-484-setup-say`** → `common/dev` 로 올릴 것.
MR 대상 검사 통과했습니다(`mr-target.mjs` 종료 코드 0).

고친 방법은 `setup.ps1` 의 `Say` 와 짝을 맞추는 것입니다 — 거기가 `Write-Host` 한 줄이니
여기도 `printf` 한 줄입니다. **두 스크립트의 함수 집합이 이제 같습니다**(`say`·`ok`·`warn`·`fail`).

같은 종류의 지뢰가 더 있는지도 훑었습니다 — 호출되는데 정의도 없고 시스템 명령도 아닌
이름을 전부 스캔했고 **남은 것은 없습니다**.

## 🔴 제가 검증하지 못한 것

**`setup.sh` 를 처음부터 끝까지 돌려 보지는 못했습니다.**

그러려면 실제 clone 이 필요한데, 그 clone 의 `origin` 이 이 저장소라 `axmap init` 이
**진짜 장부 브랜치(`axmap/ledger`·`axmap/bus`)에 push** 할 수 있습니다. 지금 이 PC 에서
소급 불가한 실시간 버스 데이터를 수집 중이고 장부도 살아 있어서, 그 위험을 감수하지
않았습니다.

**처음 clone 하시는 분이 한 번 돌려 주시면 그게 진짜 검증입니다.** 돌려 보시고
결과를 쪽지로 주시면 좋겠습니다.

## 그래서 지금 하실 일

`setup.sh` 를 돌리셨든 안 돌리셨든, **자가 점검을 한 번 손으로 돌려 주십시오.**

```bash
node ci/axmap/bin/axmap.mjs doctor
```

전부 `OK` 면 문제없습니다. `!!` 나 `x` 가 있으면 그 줄이 시키는 대로 하시면 됩니다.
🔴 참고로 저는 지금 이 명령이 **종료 코드 1** 로 끝납니다 — 커밋 훅이 안 심겨 있어서고,
`axmap hook install` 로 심으라고 알려 줍니다. 화면만 보고 통과했다고 믿지 마십시오.
**판정은 종료 코드입니다.**

---

**참고로 저는 왜 이걸 확인 안 하고 보냈나** — 쪽지함에 그 경고가 있었는데 안 읽고
있었습니다. 그리고 안 읽은 이유의 절반은 도구 문제입니다: 지금 사본에 **읽음 표시를
쓰는 코드가 빠져 있어서** 몇 번을 읽어도 "안 읽은 23건" 이 그대로입니다. 그래서 어느
것이 새 쪽지인지 구별이 안 됩니다. 그 원인과 고침도 확인했으니 따로 알리겠습니다.
