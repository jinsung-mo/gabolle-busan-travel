## nearby 응답

거리 칸 따로 옵니다. 페이지네이션은 없습니다 — `limit` 으로 자르고 끝입니다.

```
{
  "items": [
    { "placeId", "nameKo", "nameEn", "category", "address", "lat", "lng", "distanceM" }
  ],
  "requestedRadiusM", "effectiveRadiusM", "radiusExpanded", "expansionSteps",
  "scanTruncated", "limit", "purposeApplied", "facetKeyApplied"
}
```

`distanceM` 은 **미터, 정수로 반올림**한 값이고 items 는 이미 그 순서로 정렬돼 옵니다. 카드에 붙이실 때 프런트에서 거리를 다시 계산하지 마십시오 — 서버가 쓴 반경 사다리와 어긋납니다.

바깥 칸 중에 화면에 실제로 쓰실 만한 것 둘만 짚습니다.

`radiusExpanded` 가 참이면 **요청하신 반경 안에 결과가 모자라 서버가 넓혔다**는 뜻입니다(`effectiveRadiusM` 이 실제로 쓴 반경). 이걸 안 보여주면 사용자는 "근처" 라고 믿는데 훨씬 먼 가게가 섞입니다. "500m 안에 없어서 1km까지 찾았어요" 정도로 한 줄 띄우시는 게 맞습니다.

`facetKeyApplied` 는 보내신 `facetKey` 로 실제로 좁혀졌는지입니다. 거짓인데 목록이 오면 그건 **반경 안 전부**입니다 — 아코디언 한 갈래를 열었는데 아무 갈래나 나오는 상태이니 그때는 빈 목록으로 다루시는 편이 낫습니다.

`scanTruncated` 는 후보가 너무 많아 일부만 거리를 쟀다는 신호입니다. 오류는 아니고 반경 안의 진짜 후보를 놓쳤을 수 있다는 뜻이라 로그만 남기시면 됩니다.

## 앞서 물어보신 셋 — MR !377

CI 통과하면 `back/dev` 에 들어갑니다.

**일정 항목의 `placeId`** — `days[].items[]` 맨 뒤에 `placeId` 가 붙습니다. 그대로 `POST /api/v1/places/{placeId}/reviews` 에 넣으시면 됩니다. 제목으로 장소를 되찾는 방법은 만들지 않았습니다 — 같은 이름의 가게가 여럿이면 엉뚱한 곳에 평가가 달리고, 그때 아무도 오류를 못 봅니다.

**리뷰 목록의 `mine`** — 각 줄 맨 뒤에 참·거짓으로 옵니다. 작성자가 누구인지는 여전히 안 나갑니다. 익명 약속을 지키면서 "내 평가 수정" 을 띄우실 수 있게 서버가 판정한 결과 하나만 보내는 것입니다. 이름은 기록 피드의 `mine` 과 같습니다. 다시 제출하면 덮어쓰기라 수정 화면은 새로 만드실 것 없이 쓰기 화면을 재사용하시면 됩니다.

**여행 삭제** — `DELETE /api/v1/trips/{tripId}`, 성공은 본문 없는 **204** 입니다.

| 상황 | 응답 |
|---|---|
| 소유자 | 204 |
| 동행자(EDITOR 포함) | 403 `TRIP_FORBIDDEN` |
| 비회원 · 없는 여행 | 404 `TRIP_NOT_FOUND` |
| 이미 지운 여행을 소유자가 또 | 204 |

마지막 줄이 중요합니다. **두 번 눌러도, 오래된 목록에서 눌러도 204 입니다.** 응답이 끊겨 재시도하는 경우에 오류를 띄우면 사용자는 안 지워졌다고 믿습니다.

동행자에게 403 을 주는 것은 일부러입니다. 동행자가 목록에서 치우고 싶은 것은 "내 화면에서 안 보이게" 이고, 그건 `DELETE /trips/{tripId}/members/{userId}` 가 이미 맡습니다. 버튼을 하나로 합치면 누른 사람의 역할에 따라 결과가 달라지는 버튼이 됩니다 — 소유자에게는 "여행 삭제", 동행자에게는 "여행에서 나가기" 로 나눠 주십시오.

지운 뒤에는 그 여행의 상세·일정·초대·공유 링크가 전부 404 가 됩니다. 삭제 후 목록만 새로고침하시면 되고, 열려 있던 상세 화면이 404 를 받으면 목록으로 돌려보내시면 됩니다.
