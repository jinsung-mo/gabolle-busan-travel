## 🔴 부탁드리는 것 — 웹훅 주소

매일 **05:00(KST)** 에 아침 점검을 MatterMost 로 보내는 것까지 만들어 두고 **cron 도 등록했는데, 웹훅 주소가 비어 있어 안 갑니다.**

```bash
ssh ubuntu@j15e201.p.ssafy.io
cd ~/bims/bigData/deploy

# .env 안의 이 줄에 주소를 넣어 주십시오 (파일 권한 600, 커밋 안 됩니다)
MATTERMOST_WEBHOOK=
```

**주소는 이미 갖고 계실 겁니다** — 젠킨스 자격증명 `mattermost-webhook` (Secret text), `backend/Jenkinsfile` 이 배포 알림에 쓰는 그것입니다.

### 정해 주셔야 할 것 하나

**배포 알림과 같은 채널로 보낼까요, 다른 채널로 뺄까요?**
- 같은 채널 → 젠킨스 것 그대로 붙여넣으면 끝
- 다른 채널 → 그 채널의 Incoming Webhook 을 새로 만들어 넣어 주십시오

같은 채널이어도 봇 이름이 `BIMS`, 아이콘이 `:bus:` 라 젠킨스 알림과 섞이지 않습니다.

주소를 넣기 전에도 내용은 볼 수 있습니다. **보내지 않고 화면에만** 찍습니다.


주소를 넣은 뒤 실제로 한 번 보내 보려면 `--dry-run` 만 빼면 됩니다.

**웹훅이 비어 있으면 종료 코드 2 로 실패합니다** — 조용히 성공한 척하지 않습니다.

## 알아 두시면 좋은 것 둘

**1. cron 이 20:00 인데 알림은 05:00 에 갑니다.**
서버가 UTC 라서 그렇습니다 (05:00 KST = 20:00 UTC 전날). 나중에 이 줄을 보고 "05 00" 으로 고치면 **한국시간 오후 2시에 옵니다.** crontab 주석에도 적어 뒀습니다.

```
0 20 * * *  /home/ubuntu/bims/bigData/deploy/run-morning-report.sh >> ~/bims/morning-report.log 2>&1
```

**2. 점검을 컨테이너가 아니라 호스트 cron 으로 뒀습니다.**
7번째 컨테이너로 만들면 **컴포즈가 통째로 죽는 날 알림도 같이 죽습니다** — 가장 알아야 할 순간에 조용해집니다. 감시자는 감시 대상과 운명을 같이하면 안 된다고 봤습니다.
