## 3. AWS 로는 어떤 구조로 가나 — 🔴 **지금 만들고 있어서 확정 전입니다**

아래는 **정한 설계이고, 표 이름은 바뀔 수 있습니다.** 확정되면 다시 알리겠습니다.

PostgreSQL 로 갑니다. 핵심은 **가게 표 하나 + 잇는 표들**입니다. 한 가게가 여러 근거를 갖고, 여러 정답지에 동시에 속할 수 있어서요.

| 표 | 무엇이 들어가나 |
|---|---|
| `place` | 가게 하나에 한 줄. **정량** — 좌표·인허가일·버틴 햇수·영업시간·업종 |
| `place_truth` | 어느 정답지(택슐랭·블로그100·미쉐린·블루리본·백년가게)에 들었나 |
| `why_type` | 19가지 이유 유형 사전 |
| `place_why` | 가게 × 이유 유형. **정성이 정량과 같은 표에서 비교되는 지점** |
| `place_new_type` | 19가지에 안 맞은 것. 따로 둡니다 |
| `research_run` | 언제 어느 조사원이 조사했나 |

### 🔴 담지 않는 것 — 이유가 있습니다

| 안 담는 것 | 왜 |
|---|---|
| 정답지 다섯을 하나로 합친 점수 | **무게가 다릅니다.** 택슐랭이 주 정답표고 백년가게는 낮게 씁니다. 합치면 그 구분이 사라집니다 |
| "좋다/싫다" 가중치 | 짝 비교 실험으로 추정하기로 이미 정했습니다. 온톨로지에는 **가능/불가만** 담습니다 |
| 다른 앱의 별점 숫자 | 약관 위반입니다 |
| 네이버·카카오 API 응답, 로드뷰 이미지 | 같은 이유로 저장 자체가 금지입니다 |
