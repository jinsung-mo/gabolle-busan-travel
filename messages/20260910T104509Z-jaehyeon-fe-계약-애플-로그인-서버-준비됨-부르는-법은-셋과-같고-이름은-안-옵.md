## 부르는 법 — 구글·카카오·네이버와 같습니다

```
POST /auth/oauth/apple/challenge   → state · nonce · code_challenge 발급
POST /auth/oauth/apple             → authorizationCode 를 실어 보내면 로그인/가입 판정
```

`provider` 자리에 `apple` 을 넣는 것 말고 요청·응답 모양이 다른 곳은 없습니다. 가입 티켓(`SignupRequired`)과 연결(`LinkRequired`) 응답도 그대로입니다.

redirect URI 는 `https://j15e201.p.ssafy.io/oauth/apple/callback` 을 허용 목록에 넣어 두었습니다. 다른 주소를 쓰시려면 알려주세요 — 목록에 없는 주소는 서버가 400 으로 막습니다(그게 정상 동작입니다).

## 화면에서 달라지는 것 둘

**이름이 안 옵니다.** 애플은 이름을 최초 인증 응답에만 한 번 주고 그 뒤로는 안 줍니다. 그래서 가입 화면의 이름 칸이 애플로 들어온 사용자에게는 **항상 비어 있습니다.** 구글·네이버처럼 미리 채워지는 것을 기대하고 만든 화면이면 그 자리만 확인해 주세요.

**이메일이 없거나 가려져 있을 수 있습니다.** 애플은 사용자가 이메일을 감출 수 있게 하고, 그때는 `xxxx@privaterelay.appleid.com` 같은 주소가 옵니다. 메일은 전달되지만 사용자가 나중에 전달을 끌 수 있어서 서버는 "유효한지 모름" 으로 저장합니다. 이메일이 아예 없는 경우는 카카오에서 이미 겪은 것과 같습니다(`emailProvided=false`).

## 🔴 iOS 네이티브 버튼을 붙일 때 걸릴 자리

앱에서 애플 기본 로그인 화면을 쓰면 토큰의 대상이 **웹과 다릅니다.** 웹은 Service ID 로, 앱은 **앱 번들 id** 로 발급됩니다. 서버가 아는 대상 목록에 번들 id 가 없으면 그 토큰은 거절되고, 증상은 **"웹은 되는데 앱만 안 된다"** 로 나옵니다.

번들 id 가 정해지면(`S15P21E201-812`) 알려주세요. 서버 설정에 한 줄 더하면 됩니다.
