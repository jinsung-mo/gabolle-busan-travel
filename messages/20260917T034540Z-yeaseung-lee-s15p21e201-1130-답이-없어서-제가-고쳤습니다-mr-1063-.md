일정 시각이 이동 시간을 반영 안 하는 건(하루 끝 78분 지각), 원인이 `ItineraryDraftService` 라 넘겨 드렸는데 답을 못 받았습니다. 스프린트를 비워야 해서 **제가 고쳤습니다.** 넘겼다가 도로 가져간 셈이라 먼저 알려 드립니다.

## 원인은 계산이 아니라 순서였습니다

`buildDraft` 가 **시각을 먼저 깔고 구간을 나중에 만듭니다.** 시각을 깔 때는 구간이 아직 없으니 이동 시간이 0인 것처럼 깔립니다.

```
placeIntoSlots → slotFor   (시각)     ← 여기선 구간이 없다
legPlanner.buildLegs       (구간)     ← 이동 시간은 여기서 처음 생긴다
```

순서가 정해져야 이동을 알고, 이동을 알아야 시각을 깔 수 있습니다. 그래서 **순서를 뒤집었습니다** — 자리에 앉히고(순서만) → 구간 만들고 → 시각을 깝니다. 앉히는 규칙(영업시간 보고 후보 고르는 것)은 손대지 않았습니다.

```
머무는 시간 = (활동 시간대 - 그 날 이동 시간 합) / 그 날 항목 수
i번째 시작   = 앞 항목의 끝 + i번째로 가는 이동 시간
```

09:00~17:00 에 3곳, 구간마다 25분이면:

```
전  09:00-11:40  11:40-14:20  14:20-17:00   (160분씩, 이동할 시간이 없음)
후  09:25-11:40  12:05-14:20  14:45-17:00   (135분씩, 사이마다 25분)
```

## 봐 주셨으면 하는 자리 셋

1. **첫 구간을 이동에 포함시켰습니다.** `buildLegs` 는 항목 하나당 구간 하나를 만들고 첫 구간의 출발점이 여행 출발 좌표라, 「숙소에서 첫 장소까지」도 빼 줍니다. 그래서 첫 장소가 09:00 이 아니라 09:25 에 시작합니다. 이게 의도대로인지가 제일 자신 없습니다 — 활동 시간대가 「집을 나서는 시각」인지 「첫 장소에 도착하는 시각」인지에 따라 답이 갈립니다.

2. **재계산 경로(revise)도 같이 고쳤습니다.** 안 고치면 하루를 다시 계산하는 순간 이동 0짜리 시각표로 되돌아갑니다. 거기서는 그 날 구간을 한 번 더 만들게 됐습니다(`buildLegs` 를 하루치만 호출). 8단계가 어차피 전부 다시 만들지만, 시각을 깔려면 그 전에 알아야 해서요. 더 나은 배치가 보이시면 말씀해 주세요.

3. **영업시간 판정은 예전 눈금 그대로입니다.** 순서를 정할 때 쓰는 `slotFor` 는 남겨 뒀고(임시 눈금이라는 주석을 달았습니다), 시각이 뒤로 밀리면서 문 닫은 시간에 걸릴 가능성은 이 MR 이 안 봅니다. 알고 남긴 구멍이라 MR 본문에도 적었습니다 — 별건으로 가는 게 맞다고 봤습니다.
