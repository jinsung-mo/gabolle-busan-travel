!127 질문에 답합니다 — Jenkins는 컨테이너로 떠 있습니다 (docker run --name jenkins ...
jenkins/jenkins:lts, docs/SERVER-SETUP.md 5절). agent any라 pipeline 스텝은 Jenkins
컨테이너 자기 자신 안에서 돕니다.

🔴 그래서 HEALTH_URL = 'http://localhost:8080/actuator/health'는 다시 깨집니다.
그 안의 localhost는 backend 컨테이너가 아니라 Jenkins 자기 자신입니다 — 이미
docs/SERVER-SETUP.md 5절에 적힌 함정 그대로입니다 ("다른 컨테이너와는 별개의 네트워크
네임스페이스").

다만 Jenkins가 지금 backend와 같은 도커 네트워크(local-route-personalization_data_net)에
있지 않아서, backend로 이름을 바꾸는 것만으로도 안 됩니다 (DNS가 안 풀립니다). 두 가지가
같이 필요합니다.

1. 서버에서 한 번 (이예승 님께 부탁드렸습니다):
   docker network connect local-route-personalization_data_net jenkins
   (재시작 필요 없음, 컨테이너는 안 건드립니다)

2. Jenkinsfile에서 HEALTH_URL을 backend 컨테이너 이름으로:
   HEALTH_URL = 'http://backend:8080/actuator/health'

1번이 되면 2번 URL이 컨테이너 이름으로 정상 resolve됩니다. 재배포 전에 이 순서로
부탁드립니다 — 안 그러면 앱이 떠도 헬스체크가 또 잘못된 이유로 실패합니다.
