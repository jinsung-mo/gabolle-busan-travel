## 2. 🔴 가설 하나가 기각됐습니다 — 이게 오늘의 제일 중요한 결과입니다

`docs/WALKABILITY.md` 2.2절이 적어둔 가설: *"OSM 에 층수 태그가 없는 건물 70% 는
대체로 작아서 그림자를 못 만들 것이다. 참이면 건물통합정보를 안 기다려도 된다."*

면적으로 실제로 세어 봤습니다 (`process/building-audit.mjs`). **판정 기준은 계산
전에 고정했습니다** — 결과를 보고 기준을 고르면 그건 검증이 아니라 사후 정당화입니다.

- 태그 보유율이 **개수 30.7% / 면적 33.5%** 로 2.8%p 차이뿐이었습니다.
  "면적으로 보면 다를 것" 이라는 기대가 깨진 지점입니다
- 결정적으로 **문턱을 올릴수록 나빠집니다** — 1,000m² 이상 건물은 면적의 82.9%,
  **2,000m² 이상은 90.7%** 가 태그가 없습니다 (강서·사하 공단의 공장·창고)
- 즉 *"큰 건물에 층수가 있다"* 는 전제가 **큰 쪽 끝에서 반대로 뒤집힙니다**

**결론: 건물통합정보를 기다려야 한다.** 그리고 같은 날 받았습니다 (아래 3번).

## 3. 🟢 nsdi 막힘은 우회로 풀렸습니다 — 다음 사람이 같은 벽에 안 부딪히게

어제 기록: *"국가공간정보포털(nsdi.go.kr) 연결 자체가 안 됨 (curl 000)"*.
그 사이트는 여전히 안 열릴 수 있는데, **거기를 거칠 필요가 없었습니다.**

같은 데이터(**GIS건물통합정보** — 연속지적도형정보에 건축물대장 속성을 건물 단위로
결합한 것)를 **V-World**(`vworld.kr`, 국가공간정보 오픈플랫폼)가 **로그인만으로**
시·도 단위 SHP 로 줍니다. 라이선스 **CC BY** — 출처 표기만 하면 됩니다.

받는 법: 다운로드 → 공간정보 다운로드 → `GIS건물통합정보` →
🔴 **시·도 = 부산광역시 · 구분 = 전체데이터 · 포맷 = SHP**.
기본으로 보이는 건 일간 **변동데이터**(수십 KB)라 쓸모없습니다.

### 🔴 함정 둘 — 모르면 조용히 틀립니다

1. **컬럼 정의서와 실제 파일이 어긋납니다.** 컬럼 이름이 `A0`~`A28` 로만 되어 있는데
   배포된 정의서는 31개이고 전체데이터 파일은 29개입니다 — 전체데이터에는 `변동순번`·
   `입력구분`이 없어 `A23` 부터 **두 칸 당겨져** 있습니다. 실제 레코드로 대조해
   확정한 매핑이 `config/sources.json` 에 있습니다
2. **높이·대지면적·건폐율·용적율 칸의 `0` 은 "없음" 을 뜻합니다.** 0 을 실제 값으로
   쓰면 높이 0m 건물이 수십만 채 생기고 그림자가 통째로 사라집니다

결과: 부산 **472,608동**. 높이 보유율 **2.1% → 31.6%**, 지상층수 **30.8% → 61.1%**.
그림자 계산에서 **높이를 실제로 아는 건물이 1,098 → 149,231채(136배)** 가 됐습니다.

## 4. 오늘 잡힌 오류 넷 — 전부 "검사는 초록인데 숫자가 틀린" 종류였습니다

`bigData/CLAUDE.md` 7절이 *"bigData 가 죽는 방식은 화면이 깨지는 게 아니라 그럴듯한
숫자가 나오는 것"* 이라고 적어둔 그대로였습니다. 넷 다 **실제로 불러 보거나 아는 값과
대조해서** 잡혔습니다.

| 무엇 | 어떻게 잡혔나 |
|---|---|
| `pyosmium` 의 building 필터가 **적용되지 않아** 주차장·공원·논밭·물 **14,593개**가 건물로 섞였다 | 문서의 기존 실측(52,614개)과 대조 |
| 해저 지형이 고도 축을 **−373.8m** 로 끌어내리고 있었다 (한국해협 실제 최대 수심은 약 200m) | 값의 범위가 상식 밖 |
| 동해선 좌천역이 **26km 떨어진** 1호선 좌천역의 엘리베이터를 물려받을 뻔했다 | 역 중심 1,200m 거리 제한 |
| 시각표 데이터셋 번호 `15000522` 가 **존재하지 않는 번호**였다 | 실제로 호출 (HTTP 404) |

그래서 각 단계에 **아는 값을 붙잡는 불변식**을 넣었습니다 — 60m 건물의 그림자가
해 77°에서 14m·해 30°에서 104m, 부산 면적 약 770km², 역 중심 1,200m.
불변식은 전부 **일부러 망가뜨린 사본으로 돌려 exit 1 이 실제로 나는 것**까지 확인했습니다.

## 5. 함께 알아두실 것

- 🔴 **`config/boundary.geojson` 이 없어서 세 단계가 같은 벽에 부딪혔습니다.** 지금
  전부 사각형 bbox 를 쓰고 있어 바다·김해·양산이 섞입니다 — 실제로 **양산 소재
  2호선 역 5개**가 데이터에 들어 있습니다. 지금 만들고 있습니다
- 🔴 **`mlops/manifest.mjs` 의 `stamp()` 는 폴더당 `_run.json` 한 칸만 씁니다.** 여러
  단계가 `data/staged/` 를 공유하는 지금 구조에서는 마지막에 돈 것만 남고 앞의 실행
  지문이 지워집니다. 실제로 한 번 덮였다가 복구했습니다. 각 단계가 하위 폴더로 피해
  갔지만 **근본 수정은 팀 판단이 필요합니다**
- **환승 통로 도보 거리**는 부산에 공개 데이터가 없습니다(서울은 있음). 환승역이
  서면·연산·수영·덕천·미남·동래·사상 **7곳뿐**이라 손으로 잴 수 있는 크기입니다.
  지금은 `null` 로 열어 두고 **추정하지 않았습니다** — 걷는 비용을 재는 제품에서 그
  값을 지어내면 그게 곧 틀린 판정이 됩니다
- **실폭도로**는 신청서가 **서비스 URL** 을 요구해서 막혔습니다. 배포 서버가 뜨는 날
  가장 먼저 넣어야 합니다 — 심사가 그만큼 뒤로 밀리고, 폭 판정은 계산으로 만들 수 없습니다
- 진미리 님: **온톨로지 골격이 올라갔습니다** (`bigData/docs/ONTOLOGY.md`).
  `segment-slope.ndjson` 14필드 + BIMS 8필드의 **필드 ↔ 용어 ↔ 단위 매핑표**가 들어
  있습니다. ERD 용어를 여기에 맞추시면 됩니다
