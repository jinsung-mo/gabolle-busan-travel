## 지켜볼 MR — 전부 최상위 main 으로 가는 것이다

back/main · front/main · common/dev · bigData/main · map/main · ai/main → main

MR 번호는 다음으로 찾아라:
  glab mr list --target-branch main
  (glab 이 없으면 GitLab 웹에서 target=main 인 열린 MR 을 본다)

## 5분마다 이 고리를 돌아라

1. 각 MR 의 정족수를 확인한다:
   npx -y axmap-cli@latest gate --source <파트브랜치> --target origin/main
   🔴 --source 에 origin/ 을 붙이지 마라. 붙이면 표가 0장으로 세어진다.

2. "합의 충족" 이 나온 MR 은 판정 잡을 다시 돌린다.
   표는 MR 밖의 별도 브랜치로 들어오기 때문에 GitLab 이 파이프라인을
   자동으로 다시 돌리지 않는다. 화면에 옛 판정(빨강)이 남아 있다.
   → 그 MR 의 governance 잡을 retry 한다.

3. 파이프라인이 초록이 되고 mergeable 이면 머지한다.
   🔴 머지할 때 반드시 이렇게 한다:
      - 판정에 쓴 커밋 sha 를 실어라 (그 사이 커밋이 끼어들면 GitLab 이 거부한다)
      - should_remove_source_branch = false  ← 🔴 파트 브랜치를 지우면 안 된다

4. 머지 뒤 사후 파이프라인을 확인한다. version 잡이 태그 충돌로 실패할 수 있다
   (여러 파트를 연달아 머지하면 같은 버전 번호를 동시에 계산한다).
   실패하면 그 잡만 retry 하면 된다 — 머지 자체는 멀쩡하다.

## 🔴 절대 하지 마라

- **표를 던지지 마라.** 그건 사람만 한다. 정족수가 안 차면 그냥 기다리고 보고해라.
- **파트 브랜치를 지우지 마라.**
- **정족수가 안 찬 MR 을 머지하지 마라.** 게이트가 미달이면 그건 고장이 아니다.
- 거부당하면 재시도하지 마라. 같은 요청은 몇 번을 보내도 같은 답이 온다.
