## 1. 무슨 일이 있었나

`S15P21E201-1511`(홈 시작 바 숙소 칸)이 오늘 아침 `front/dev` 에 들어갔습니다. 그래서
앱이 숙소를 보내기 시작했는데 — **서버에 받을 칸이 없었습니다.**

```
앱이 보내는 것 (tripApi.ts:124-126)
  accommodationLat   accommodationLng   accommodationName

서버가 받는 칸 (CreateTripRequest)
  없음  →  셋 다 조용히 버려짐
```

Spring 은 모르는 JSON 칸을 **말없이 버립니다.** 오류도 안 나서, 오늘 만들어진 여행은
사용자가 고른 숙소가 **그냥 사라진 채로** 저장됐습니다.

**원인이 `-1426` 과 똑같습니다.** 숙소 검색이 출발지 검색(`searchOrigins`)을 재사용하는데
그 결과는 카카오에서 오므로 우리 `place_id` 가 없습니다. 그래서 앱이
`accommodationPlaceId` 를 못 채우고 좌표로 보낸 것입니다.

## 2. 그래서 같은 기전을 씁니다 — 계약이 두 화면에 걸립니다

`-1426` 에서 만든 upsert 를 숙소에도 씁니다. 그러면서 스냅샷 record 를
**`StoryCreateRequest` 안에서 꺼내 `place/api/PlaceSnapshotRequest` 로 올렸습니다.**

> 🔴 **기록과 숙소가 이제 한 벌을 같이 씁니다.** 두 벌로 두면 한쪽에만 칸이 늘거나 검증이
> 어긋나고, 그 어긋남은 **「어떤 화면에서 고른 장소만 안 붙는」** 모양이라 화면에서는
> 안 보입니다.

즉 **미리 님이 제안하신 계약이 이제 두 곳에 걸립니다.** 철자 하나 바꾸는 값이 지금은 한
군데, 나중엔 두 군데입니다.

```jsonc
POST /api/v1/trips
{
  "accommodationPlaceId": null,     // 우리 DB 숙소면 여기. 그러면 아래는 안 봅니다
  "accommodation": {                // 카카오/대체 목록에서 골랐을 때만
    "source": "KAKAO_LOCAL",        // 🔴 KAKAO 아님 — 앞 쪽지와 같은 이유
    "externalId": "7913306",
    "name": "해운대 어느 호텔",
    "address": "부산 해운대구 우동",  // 없어도 됩니다
    "lat": 35.1585, "lng": 129.1598, // 🔴 둘 다 있거나 둘 다 없거나
    "category": "LODGING"            // 없어도 됩니다
  }
}
```

기록(`POST /api/v1/stories`)의 `place` 와 **글자 하나까지 같은 모양**입니다.
