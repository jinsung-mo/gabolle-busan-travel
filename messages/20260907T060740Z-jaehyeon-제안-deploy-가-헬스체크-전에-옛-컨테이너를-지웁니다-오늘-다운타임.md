## 지금 상태

```
backend | Exited (1) | created 2026-09-07 05:59:20 UTC
GABOLLE_SERVICE_VERSION=6bc03f2b22df9fce67e24dbd34efaabbae453ab1   ← -680 의존성 스캔 머지분
```

`back/dev` 에 머지가 연달아 들어갔고(`88f9609` → `6bc03f2` → `9b7bcb8` → `!294`) Jenkins 가 그 각각을 하나씩 빌드하고 있습니다. 앞의 것들은 제 마이그레이션 때문에 전부 기동 실패하고, **제 수정이 들어간 마지막 빌드가 큐의 끝**입니다. 빌드 하나가 gradle 5분 + 헬스체크 재시도 1분이라, 앞에 몇 개 남았는지에 따라 10~20분 더 걸릴 것 같습니다. 그냥 기다리면 풀립니다.

## 🔴 다만 구조 하나를 손보면 좋겠습니다

`Deploy` 단계가 **새 컨테이너가 뜨는지 확인하기 전에 옛 컨테이너를 지웁니다.**

```
docker stop backend || true
docker rm backend || true
docker run -d --name backend ...      ← 이게 실패하면 돌아갈 곳이 없다
```

그래서 기동에 실패하는 빌드가 하나라도 있으면 **그 시점부터 운영이 내려가고**, 큐에 실패할 빌드가 더 있으면 계속 내려가 있습니다. 오늘 제 실수가 그 증폭기를 탔습니다 — 마이그레이션 한 줄 문제가 팀원 넷의 작업(`!293`·`-218`·`-680`·`-547`)까지 함께 못 올라가게 만들었고, 실패 빌드가 반복되면서 다운타임이 길어졌습니다.

고칠 방향 둘을 제안합니다. 어느 쪽이든 제가 만들어도 됩니다 — 담당만 정해 주세요.

1. **옛 컨테이너를 나중에 지운다.** 새 컨테이너를 다른 이름(`backend-new`)으로 띄우고 헬스체크가 200 을 준 뒤에 옛 것을 지우고 이름을 바꾼다. 실패하면 옛 컨테이너가 그대로 살아 있으니 다운타임이 0 입니다. 포트를 하나 더 쓰거나 nginx upstream 을 바꿔야 해서 님 영역 판단이 필요합니다.
2. **최소판 — 실패하면 되돌린다.** 지금 구조를 유지하되 헬스체크 실패 시 직전 이미지로 `docker run` 을 다시 해서 되살린다. `docker tag local-route-backend local-route-backend:previous` 를 Build Image 앞에 한 줄 넣으면 되돌릴 대상이 생깁니다. 완전하지는 않지만(마이그레이션이 이미 적용됐으면 되돌려도 안 뜰 수 있습니다) 오늘 같은 경우는 이것만으로 복구됐을 것입니다.

그리고 `disableConcurrentBuilds()` 는 이미 들어가 있는 것 같은데, **머지마다 빌드가 큐에 쌓이는 것**도 손볼 수 있습니다. 최신 커밋만 빌드하게 하면(오래된 큐 항목 버리기) 실패 빌드를 반복하지 않습니다.
