결정 셋 답합니다. 셋 다 정해졌으니 착수하셔도 됩니다.

## 1. 구글 클라우드 결제 계정 — 담당자를 정할 필요가 없어집니다

**한동안 구글 클라우드를 안 씁니다.** 대신 **GMS**(SSAFY 가 열어 주는 API 중계 서버 —
`gms.ssafy.io` 뒤에 OpenAI 주소를 그대로 붙여 부르면 **우리 결제 계정 없이** OpenAI
모델이 도는 것)를 최대한 활용합니다. 키는 이미 있습니다.

그래서 계정 생성·결제 등록·키 발급/보호가 통째로 사라집니다.

🔴 **이미 이 저장소에서 GMS 로 사진을 읽고 있습니다.** `visual-geocode/src/evidence/gms.mjs`
가 사진을 실어 보내고 출력 형식을 강제해서 간판 글자를 뽑아냅니다. 메뉴판도 정확히
같은 자리입니다 — 새로 만드는 게 아니라 **이미 도는 것을 메뉴판에 겨누는 일**입니다.

그리고 그 파일이 설계된 방식이 여기서 값어치가 있습니다. 주소가 **통과형 중계**
(요청을 그대로 흘려보내는 방식)라 **크레딧이 끝나면 `GMS_BASE` 한 줄만 바꾸면 진짜
OpenAI 로 갑니다. 코드는 안 건드립니다.** 구글 클라우드로 가는 문도 닫지 않았습니다.

## 2. 영어만 우선? — 아니오. 다국어로 갑니다

번역을 LLM 이 하기 때문에 **언어를 늘리는 데 드는 추가 작업이 거의 없습니다.**
영어만 먼저 하고 나중에 늘리면 오히려 두 번 일이 됩니다.

## 3. 테스트용 메뉴판 사진 30~50장 — 내일 아침 스크럼에서 정합니다

누가 어디서 몇 장을 구할지는 얼굴 보고 나누는 게 빠릅니다.

## 🔴 fail-closed 는 그대로 둡니다 — 다만 선을 어디에 긋는지 가릅니다

*"생성형 AI 를 최종 메뉴명·가격·알레르기 판정에 안 쓴다"* 는 원칙에 동의합니다.
다만 위에서 LLM 번역을 쓰기로 했으니, **어디까지가 LLM 이고 어디부터가 사전인지**를
지금 나눠 둡니다. 안 그러면 구현하다가 매번 부딪힙니다.

| | 누가 정하나 |
|---|---|
| 메뉴명 번역 | **LLM 이 해도 됩니다.** 어색해도 사용자가 원문과 나란히 대조할 수 있습니다 |
| **가격** | 🔴 OCR 신뢰도로만 확정. 불확실하면 숨기고 "가격 확인 필요" |
| **알레르기·성분** | 🔴 검수된 자료에 있을 때만. 없으면 "직원에게 확인 필요" |

이유는 **틀렸을 때의 대가가 다르기 때문**입니다. 메뉴명이 어색하면 불편할 뿐이지만,
**알레르기를 틀리면 사람이 다칩니다.** 그래서 그 둘만은 LLM 이 만지지 않게 둡니다.
나머지 fail-closed 항목(저신뢰 재촬영 요청·미등록은 원문 표기·원본 영역 나란히
보여주기)은 제안하신 그대로 좋습니다.

이견 있으면 답장 주세요. 없으면 내일 스크럼에서 사진 건만 나누고 바로 갑니다.
