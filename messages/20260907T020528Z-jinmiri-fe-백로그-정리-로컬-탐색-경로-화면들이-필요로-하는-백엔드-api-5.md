subject: [FE 백로그 정리] 로컬 탐색·경로 화면들이 필요로 하는 백엔드 API 5개 — 지금은 전부 없음

진미리입니다. 프론트 백로그를 순서대로 훑다가, 다음 5개 화면이 전부 "지금 없는 백엔드 API"에 막혀 있는 걸 확인했습니다. 화면 쪽은 준비됐고(또는 바로 만들 수 있고), 이 API들이 나오면 이어서 연결하겠습니다. 우선순위 판단은 백엔드 쪽에 맡깁니다 — 급한 것부터 알려주시면 그 순서로 연결할게요.

## 1. 여행 기간과 겹치는 축제만 (S15P21E201-117)
`GET /api/festivals` — 시작일·종료일을 받아 겹치는 축제만 반환. 겹침 판정(축제 시작일 ≤ 여행 종료일 AND 축제 종료일 ≥ 여행 시작일)은 서버가 해야 합니다(화면이 거르면 안 됨 — 티켓에 명시).

## 2. 마지막 방문지 근처 기념품샵 (S15P21E201-121)
`GET /api/shops/souvenir` — 위치+반경을 받아 거리순(하버사인 거리 계산) 정렬. 반경 안에 하나도 없으면 반경 2배로 넓혀 재조회하는 로직까지 서버가 하는 게 자연스러워 보입니다.

## 3. 로컬 탐색 8종 아코디언 (S15P21E201-127)
축제·야시장·전통시장·액티비티·산책·자연·야경·기념품샵 8갈래 각각의 조회 API. 장소가 어느 갈래인지는 장소에 붙은 태그로 판정해야 해서(이름을 코드에 나열하면 안 됨), place 데이터에 이 태그가 있는지부터 확인이 필요할 것 같습니다.

## 4. 택시 목적지 카드 (S15P21E201-68)
`GET /api/routes/taxi-card` — 장소 하나를 받아 한국어 장소명·한국어 주소·영문 주소·기사에게 보여줄 한국어 문장("이 주소로 가주세요, OOO")을 반환. 영문 주소가 없으면 그 칸 자체를 빼야 해서 값이 없을 때는 필드 자체를 안 주시면 좋겠습니다.

## 5. 장소 상세 화면 (S15P21E201-141)
`GET /api/places/:id` — 대표사진·이름(한/영)·주소(한/영)·로컬점수·예상비용·영업시간·영어메뉴/해외카드/혼밥/브레이크타임/라스트오더/예약필요 여부. 티켓에 "설계만 있고 화면도 API도 없다"고 적혀 있어서, 이건 화면부터 제가 새로 만들어야 하는 자리라 API 없이는 아예 시작을 못 합니다.

날씨(S15P21E201-95)·한글 메뉴판 번역(-86)·실시간 통역(-90)은 API 문제가 아니라 업체 선정이 먼저 필요한 자리라(날씨=기상청 연동 여부, 번역/통역=업체+키) 이건 백엔드가 아니라 팀 차원 결정이 먼저인 것 같아 이번 목록에서는 뺐습니다.
