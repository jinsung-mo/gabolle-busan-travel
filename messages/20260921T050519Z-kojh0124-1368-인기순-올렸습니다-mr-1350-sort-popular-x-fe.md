## 프론트가 바로 쓸 수 있는 것

```
GET /api/v1/stories?scope=ALL&sort=POPULAR
GET /api/v1/stories?scope=ALL              (기본값 sort=RECENT — 지금 동작 그대로)
응답 머리: X-Feed-Applied: POPULAR | RECENT
```

응답 본문은 `{items: StoryDto[], nextCursor}` **그대로**입니다. DTO 를 한 칸도 안 건드렸습니다. `sort` 는 `scope=FOLLOWING` 에도 걸립니다.

## 정한 것 셋

**1. 동점 순서를 박았습니다** — 이예승 님 지적대로입니다.
```sql
ORDER BY like_count DESC, publish_at DESC, story_id DESC
```
반응 6건이라 대부분 0 으로 동점인데, 이걸 안 정하면 새로고침마다 목록이 뒤바뀝니다.

**2. 🔴 정렬 갈래를 바꿀 때는 커서를 비워 주세요.** 인기순 커서에는 좋아요 수가 들어갑니다(정렬 열이 셋이라 커서도 셋이어야 이어집니다). 최신순에서 받은 커서를 인기순에 그대로 보내면 **400**(`FEED_CURSOR_INVALID`)입니다. 조용히 첫 쪽으로 되돌리지 않았습니다 — 그러면 화면은 이어봤다고 믿는데 같은 것을 두 번 보게 됩니다. 커서는 여전히 불투명한 문자열이라 앱이 안을 볼 필요는 없습니다.

**3. 좋아요 수는 미리 만들어 둔 칸이 아니라 반응 표를 그때그때 셉니다.** `story_reaction` 의 PK 가 `(story_id, user_id)` 라 한 사람이 한 번만 세어지고, 그 PK 가 곧 부질의의 색인입니다. 누적 칸을 두면 취소와 짝이 어긋나는 날 수와 행이 다른 상태가 남습니다.
