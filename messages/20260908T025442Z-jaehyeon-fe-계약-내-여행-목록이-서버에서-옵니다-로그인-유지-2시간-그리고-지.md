## 무엇이 생겼나

"내 여행" 목록을 서버가 줍니다. 지금 앱은 목록을 기기(`gabolle:my-trips:v1`)에 적어 두고 있는데, 그걸 서버 값으로 바꿀 수 있습니다.

```
GET /api/v1/trips
  → { trips 배열 }  각 줄: tripId · startDate · endDate · dayCount
                            · partySize · status · role · createdAt · updatedAt
     내가 만든 여행과 초대받은 여행이 함께 옵니다. 최근에 손댄 순, 50개까지.

GET /api/v1/trips/{tripId}/itineraries
  → { tripId, role, itineraries: [ { itineraryId, latestVersion } ] }
     여행 하나를 눌렀을 때 "무엇을 열지" 를 답합니다.
```

## 🔴 왜 목록에 일정 번호를 안 넣었나

목록 한 줄마다 최신 일정 번호를 싣는 안으로 시작했는데, 그렇게 하면 여행 쪽 코드가 일정 표를 직접 알게 됩니다. 그래서 경로를 나눴습니다. **요청 수는 안 늘어납니다** — 목록을 그릴 때가 아니라 여행을 눌렀을 때 한 번 부르는 것이라서요.

즉 흐름이 이렇습니다. 목록 화면은 `GET /api/v1/trips` 한 번. 사용자가 카드를 누르면 그때 `…/itineraries` 를 불러 `itineraryId` 를 받고, 그 번호로 지금 쓰던 일정 상세 화면을 엽니다.

## 목록에 없는 것 둘 — 지금처럼 채우셔야 합니다

**제목이 없습니다.** 여행 자체에 제목 칸이 없어서입니다(지금 앱이 보여 주는 제목도 여행이 아니라 일정에서 가져온 값입니다). 일정을 연 뒤에 채우거나 날짜로 대신 보여 주시면 됩니다.

**방문지 수도 없습니다.** 그 값은 일정의 최신 판에 달린 항목을 세야 나와서, 목록 한 줄 때문에 표 셋을 더 훑는 것은 값이 안 맞는다고 봤습니다. 필요하시면 넣겠습니다 — 말씀만 주세요.

## 🔴 순서를 믿지 마세요

`itineraries` 배열의 순서는 계약이 아닙니다. 지금 여행 하나에 일정이 하나뿐이라 사실상 한 줄이고, 여럿이 되는 날 "어느 것이 최신인가" 를 정하려면 서버를 더 고쳐야 합니다. **하나면 그 하나를 열고, 여럿이면 사용자에게 고르게** 하는 편이 안전합니다.

## 같이 바뀐 것 — 로그인 유지 시간

**2주에서 2시간으로 줄였습니다.** 쓰는 동안에는 안 끊깁니다(갱신할 때마다 만료가 다시 밀립니다). 손 놓고 2시간이 지나면 풀립니다.

시연이나 긴 테스트 중에 로그아웃되면 그건 정상 동작입니다. 거슬리면 배포 설정값 하나(`GABOLLE_REFRESH_TOKEN_TTL`)만 늘리면 되고 재빌드는 필요 없습니다.

## 🔴 화면 쪽에 남은 것 — `S15P21E201-740`

**로그아웃해도 앞사람의 여행 목록과 취향이 기기에 남습니다.** 지우는 코드가 "계정 삭제" 에만 붙어 있고 로그아웃에는 없습니다. 같은 기기에서 A 가 로그아웃하고 B 가 로그인하면 B 에게 A 의 여행과 취향이 보입니다 — 시연용 기기와 공용 PC 에서 바로 재현됩니다.

지울 것 셋입니다.

| 저장 키 | 무엇 |
|---|---|
| `gabolle:my-trips:v1` | 여행 목록 |
| `gabolle:onboarding-preferences` | 처음에 고른 언어·이동 성향 |
| `PlanProvider` 의 저장 키 | 여행 조건 4단계 입력값 |

`deleteAccount` 가 이미 하는 일을 `signOut` 에서도 하시면 됩니다. 위 목록 API 를 붙이면 첫 번째는 구조적으로 사라지지만, **그걸 기다리지 말고 지우는 것부터 넣는 편이 낫습니다** — 지금도 재현되고 고치는 양이 몇 줄입니다.
