## 1. 리뷰 중복 — 화면에서 판정 안 하셔도 됩니다

표에 `UNIQUE (place_id, user_id)` 가 걸려 있어서 **한 사람이 한 장소에 평가 하나**입니다. 그리고 서비스가 이미 있으면 오류를 내지 않고 **덮어씁니다**(`rewriteExisting`).

그래서 화면은 그냥 보내시면 됩니다 — 처음이면 새로 쓰이고, 두 번째면 고쳐집니다. "이미 쓰셨습니다" 를 띄울 필요가 없습니다.

### 🔴 다만 "내가 쓴 평가인지" 는 지금 알 수 없습니다

목록에 작성자 칸이 없는 게 **일부러 그런 것**입니다. 앱 설정 화면에도 "리뷰는 익명으로 남아요" 라고 적혀 있고, 그 약속대로 응답에 작성자를 안 넣습니다.

그런데 그 때문에 **"내 평가를 수정하기" 화면을 만들 수가 없습니다.** 목록에서 어느 게 내 것인지 못 고르니까요.

익명을 지키면서 푸는 방법은 하나입니다 — 목록의 각 줄에 **`mine` 같은 참·거짓 칸 하나**를 넣는 것입니다. 작성자가 누구인지는 여전히 안 나가고, 요청자 본인 것만 표시됩니다. 기록 피드가 이미 그렇게 하고 있고요(`StoryResponse.mine`).

**제가 만들겠습니다.** 필요하시면 지금 티켓 만들어서 다음 MR 에 싣겠습니다.

## 2. 🔴 일정 항목에 `placeId` 가 없습니다 — 제가 넣어야 합니다

지금 일정 항목이 주는 것은 이렇습니다.

```
id                 항목 키 (판이 바뀌어도 같은 항목을 가리킴)
startsAt           계획된 시각
title              장소 이름
description        항상 null
estimatedCostKrw
walkingMeters
locked
dataStatus         VERIFIED · ESTIMATED · UNKNOWN
actualArrivedAt    실제 도착
actualDepartedAt   실제 출발
```

**`placeId` 가 없습니다.** 그래서 일정 화면에서 평가 버튼을 눌러도 어느 장소를 평가할지 서버에 알려줄 수가 없습니다. 정확히 짚으셨습니다.

`title` 로 장소를 되찾는 것은 **하지 마세요** — 같은 이름의 가게가 여럿이면 엉뚱한 곳에 평가가 달립니다.

**이것도 제가 넣겠습니다.** 항목에 `placeId` 를 실으면 됩니다. 데이터는 이미 표에 있고 응답에만 안 나가는 상태라 작은 작업입니다.

## 3. facets 전체 목록 — 제가 지어낼 수 없습니다

`GET /api/v1/places/facets` 를 부르면 **지금 데이터에 실제로 있는 목록**이 그대로 나옵니다. 응답 모양은 이렇습니다.

```
facets       배열
generatedAt  생성 시각

facets 한 줄:
  userInputCode      사용자 입력 코드
  placeFeatureType   특성 종류
  matchKind          대조 방식
  placeCount         이 facet 에 걸리는 장소 수
  keys               배열
     featureKey   실제로 넘기실 facetKey 값
     placeCount   그 키에 걸리는 장소 수
     labelKo      한국어 표시 이름
```

🔴 **제가 여기에 8종의 값을 적어 드리면 그건 지어낸 것이 됩니다.** 그 목록은 적재된 데이터에서 나오는 것이라 코드에 박혀 있지 않고, 제가 운영 데이터를 안 봤습니다. 한 번 부르시면 `keys[].featureKey` 에 쓰실 값이 그대로 있고 `labelKo` 로 화면 문구까지 됩니다.

**부르셨는데 8종이 안 나오거나 기념품샵이 없으면 알려 주세요.** 그건 화면 문제가 아니라 데이터가 안 들어온 것이고, 데이터 담당에게 넘길 건입니다.
