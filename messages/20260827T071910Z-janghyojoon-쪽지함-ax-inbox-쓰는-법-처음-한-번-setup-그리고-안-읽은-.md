쪽지함을 쓰려면 무엇이 필요한지 한 곳에 정리합니다. **처음 한 번만 하면 되는 것이 하나**, 오늘 고친 것이 하나 있습니다.

---

## 1. 처음 한 번 — 쪽지함을 만든다

clone 만 해서는 쪽지함이 없습니다. 한 번 만들어야 합니다.

```bash
node ci/axmap/bin/axmap.mjs init
```

(저장소 루트의 `setup.sh` / `setup.ps1` 을 돌리셨다면 이미 되어 있습니다.)

**왜 필요한가** — 쪽지는 코드와 같은 브랜치에 쌓이지 않습니다. `axmap/bus` 라는 **고아 브랜치**(orphan branch — 코드 이력과 아예 이어지지 않은 별도 갈래)에 있고, 그걸 `.axmap/bus` 폴더로 펼쳐 두고 씁니다. `init` 이 그 펼치는 일을 합니다.

이 덕분에 **쪽지는 커밋도 MR 도 없이 바로 갑니다.** 예전에는 쪽지 한 통이 MR 한 사이클이었습니다.

> 🔴 쪽지함이 없는 상태에서 보내면 **일부러 거부합니다.** 그때 쓴 쪽지는 아무에게도 안 가고, 나중에 지워야 할 파일로만 남기 때문입니다. "왜 안 보내지지?" 싶으면 대개 이것입니다.

확인은 이걸로 합니다.

```bash
node ci/axmap/bin/axmap.mjs doctor
```

`MCP 설정` · `커밋 훅` · `선점 판정` 이 전부 OK 로 나오면 됩니다. 판정은 종료 코드입니다 — 0 이면 정상.

## 2. 읽는 법 — 세 가지 길이 있습니다

**(a) AI 도구를 쓰신다면** — 저장소 루트의 `.mcp.json` 이 자동으로 붙여 줍니다. 승인만 누르면 됩니다.

- 도구 이름은 `ax_inbox` 입니다. 목록만 보려면 인자 없이, 본문을 보려면 `id` 를 줍니다
- 슬래시 명령도 다섯 개 있습니다: `/ax`, `/ax-start`, `/ax-inbox`, `/ax-tell`, `/ax-done`
- **요청하지 않아도 알려줍니다.** 나에게 온 쪽지가 있으면 `ax_status` 든 `ax_claim` 이든 **아무 도구를 불러도** 결과 끝에 배너로 붙습니다

**(b) 손으로 쓰신다면**

```bash
node ci/axmap/tools/bus.mjs list --mine        # 나에게 온 것
node ci/axmap/tools/bus.mjs read <아이디>       # 본문 전체
node ci/axmap/tools/bus.mjs post --to <상대> --subject "<제목>" < 본문.md
```

**(c) 아무것도 안 하셔도** `axmap status` 를 부르면 안 읽은 쪽지를 알려줍니다.

---

## 3. 🔴 이름이 어긋나면 자기 쪽지가 안 보입니다

쪽지의 받는 사람은 **선점(claim)에 쓰는 이름과 같은 값**입니다. `AXMAP_AGENT` 환경변수가 있으면 그것, 없으면 `git config user.name` 입니다.

그래서 **`git config user.name` 을 확인해 두십시오.**

```bash
git config user.name
```

여기 나온 이름이 남들이 나에게 쪽지를 보낼 때 쓰는 주소입니다. 이게 서로 다르면 **보낸 쪽은 성공을 보고 받는 쪽은 "쪽지 없음" 을 봅니다.** 양쪽 다 오류가 안 나서 아무도 실패를 못 봅니다 — 실제로 2026-08-26 에 팀원 쪽지가 이 종류의 어긋남으로 묻혀 있었습니다.

## 4. 오늘 고친 것 — 안 읽은 개수가 이제 줄어듭니다

지금까지 배너가 **"안 읽은 쪽지 21건"** 처럼 뜬 뒤, 다 읽어도 그 숫자가 안 줄었습니다. 오히려 계속 늘었습니다.

원인은 읽음 표시를 **읽기만 하고 아무도 안 쓰고 있었던 것**입니다. 그래서 기준값이 늘 비어 있었고 모든 쪽지가 영원히 "안 읽음" 이었습니다. 알림이 매번 전부를 찍으니 사람은 그걸 배경으로 여기고 안 읽게 됩니다. **반쪽짜리 알림은 없는 알림보다 나쁩니다.**

고쳐서 MR 로 올려 뒀습니다 (**MR !23**, `chore/common/S15P21E201-25-bus-seen-marker` → `common/dev`).

**여러분이 하실 일은 머지된 뒤 두 가지입니다.**

1. `git pull` — 사본을 받습니다
2. **AI 도구에서 `/mcp` 로 재연결** (또는 세션을 새로 열기)

2번이 꼭 필요합니다. MCP 서버는 **세션이 시작될 때 한 번 뜨고 계속 살아 있어서**, 파일이 바뀌어도 지금 돌고 있는 프로세스는 옛 코드를 물고 있습니다. 손으로 쓰는 `bus.mjs` 는 부를 때마다 새 프로세스라 바로 반영됩니다.

그 뒤로는 배너에 뜬 것만 읽음이 됩니다. 배너는 3건만 보여주므로 **3건씩 줄어들고**, 접혀서 안 보인 쪽지는 다음에 다시 뜹니다.

⚠️ 대가도 적어 둡니다 — **제목만 보고 넘기면 그 쪽지는 다시 안 뜹니다.** 다만 파일은 그대로 있어서 `bus.mjs list --all` 로 언제든 다시 봅니다. **안 뜨는 것과 사라지는 것은 다릅니다.**
