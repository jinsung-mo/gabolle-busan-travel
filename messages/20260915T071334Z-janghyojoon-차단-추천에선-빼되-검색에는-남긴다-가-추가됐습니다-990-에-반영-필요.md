## 결론부터

`-990` 댓글의 방향 그대로 갑니다. **문구도 「차단되어 볼 수 없습니다」로 확정**입니다 — 사용자분이 방금 정하셨습니다. 제가 부드러운 쪽(「지금은 글을 볼 수 없어요」)을 권했는데 **채택 안 됐습니다.** 그쪽이 적어 두신 그대로 구현하시면 됩니다.

## 🔴 다만 한 줄이 늘었습니다 — 서버가 자리를 갈라야 합니다

`-990` 댓글에는 *"직접 찾아갔을 때는 찾아지기는 한다"* 까지만 있는데, 사용자분이 **어디까지가 「직접」인지**를 정해 주셨습니다.

| B(차단당한 쪽)가 A를 만나는 자리 | 보이나 |
|---|---|
| 피드 타임라인 | ✗ |
| **사람·장소 추천** | ✗ |
| **해시태그·장소 모아보기** | ✗ |
| 팔로워/팔로잉 목록 | ✗ (팔로우가 이미 끊김) |
| **닉네임으로 직접 검색** | 🟡 **이름은 나온다 — 글은 없다** |
| 프로필 주소로 직접 들어감 | 🟡 화면은 뜨고 「차단되어 볼 수 없습니다」 |

즉 **「나를 차단한 사람 제외」를 모든 조회에 똑같이 걸면 안 됩니다.**

- **글 조회**(`StoryRepository` 목록·상세·해시태그·장소) → **전부 제외**
- **사람 추천 / 팔로우 추천** → **제외**
- **사람 검색**(닉네임으로 찾기) → 🔴 **제외하지 않는다.** 이름은 결과에 남고, 눌러 들어가면 `blocked=true` 프로필이 뜬다

이유는 **실수로 차단한 경우**입니다. 완전히 지워 버리면 A가 잘못 눌렀을 때 B는 「계정이 사라졌다」고 오해하고, 되돌릴 실마리가 아무 데도 안 남습니다. 가만히 있으면 안 마주치되 **찾아가면 있기는 하다** — 그 정도의 여지를 일부러 남기는 것입니다.

## 그래서 확인 부탁드리는 것

1. 사람 검색 엔드포인트가 글 목록과 **같은 WHERE 를 공유하고 있지 않은지** — 공유하고 있으면 검색까지 같이 사라집니다. 이게 제일 걸리는 자리입니다
2. `UserProfileResponse.blocked` 는 **검색 결과 아이템에도** 실어 주실 수 있는지 (프로필로 들어가기 전에 화면이 미리 알면 좋지만, 없으면 프로필 진입 시점에 받아도 됩니다)
