## 🔴 1. 취향 값이 JSONB 에 안 들어갑니다

```
ERROR: invalid input syntax for type json
insert into preference_answer (answer_status, created_at, dimension,
                               preference_snapshot_id, value, preference_answer_id)
```

**매핑은 맞습니다. 값이 틀렸습니다.**

`@JdbcTypeCode(SqlTypes.JSON)` 을 `String` 필드에 붙이면 Hibernate 는 그 문자열의 **내용을
JSON 으로 그대로** 보냅니다. 테스트가 넘기는 것은 `"RELAXED"` — 따옴표 없는 맨 단어라
PostgreSQL 이 JSON 으로 못 읽습니다. 유효한 JSON 이려면 따옴표까지 포함해
`"\"RELAXED\""` 이거나 `{"code":"RELAXED"}` 여야 합니다.

🔴 **왜 다른 테스트는 통과하는가** — 이게 이 결함의 성질을 보여 줍니다.

| 테스트 | 왜 통과하나 |
|---|---|
| 같은 테스트의 MOBILITY 제약 | 값이 `threshold`(숫자 칸)로 가서 **JSONB 를 안 지납니다** |
| `codedAllergyConstraintRoundTrips()` | 코드 알레르기는 `value=NULL` 입니다 — !150 이 막 허용한 그것 |

**JSONB 를 실제로 지나는 경로가 이 하나뿐이고, 그게 깨진 것입니다.**

### 같은 줄에 하나 더 있습니다

```java
new PreferenceSnapshot.PreferenceAnswer("pace", "RELAXED", SELECTED)
                                         ↑
```

`pace` 는 취향 차원이 아닙니다. `ck_preference_answer_dimension` 이 여덟만 받습니다 —
`CATEGORY` · `ATMOSPHERE` · `LOCALITY` · `QUIETNESS` · `TOURIST_PREFERENCE` ·
`FOOD_PREFERENCE` · `SLOPE_PREFERENCE` · `SHADE_PREFERENCE` (명세 4.3).

JSON 을 고쳐도 **그 다음 CHECK 에서 또 걸립니다.** 둘 다 고치셔야 합니다.

### `evidenceStatus`·`operator` 유실은 괜찮습니다

javadoc 에 한계로 적어 두신 것 봤습니다. **그대로 두시는 게 맞습니다.**

- `operator` 는 `constraint_key` 가 이미 말합니다 — `MAX_WALKING_METERS` 자체가 "이하" 입니다
- `evidence_status` 는 **장소 데이터의 속성**이지 사용자 입력의 속성이 아닙니다
  (명세 6.2). 사용자가 "내 알레르기가 검증됐다" 고 말할 자리는 없습니다

칸이 없는 게 설계이고 유실이 아닙니다. 그 주석만 그렇게 다듬어 주시면 좋겠습니다.
