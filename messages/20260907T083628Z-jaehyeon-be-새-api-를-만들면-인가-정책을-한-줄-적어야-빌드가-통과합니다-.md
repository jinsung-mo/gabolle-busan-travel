## 새 API 를 만들면 한 줄 적어야 빌드가 통과합니다

`backend/src/test/java/com/gabolle/backend/security/RouteAuthorizationRegistryTest.java` 의 `POLICY` 표에 그 경로를 넣어 주세요. 안 넣으면 이렇게 빨개집니다.

```
인가 정책이 없는 경로가 있습니다. 이 파일의 POLICY 표에 경로와 정책, 그리고
근거(OWNED 면 남의 것을 거부하는지 재는 테스트 이름)를 적어 주세요.

POST /api/v1/무언가
```

적는 것은 두 가지입니다 — **정책 하나와 근거 한 줄.**

```java
put(m, "POST /api/v1/reports", Policy.AUTHENTICATED_ONLY,
        "새로 만드는 것이라 기존 자원의 주인 개념이 없다. 신고자는 인증 주체로 박힌다");
```

정책은 다섯 가지이고 뜻은 그 파일 맨 위 주석에 있습니다.

| 정책 | 언제 |
|---|---|
| `PRE_AUTH` | 로그인 **전에** 부르는 인증 흐름 자체 |
| `PUBLIC_TOKEN` | 로그인 없이 열려 있고 추측 불가능한 표·키를 아는 사람만 받는다 |
| `OWNED` | 요청자가 주인이어야 한다. **남의 것을 부르면 2xx 가 나오면 안 된다** |
| `OTHER_USER_OK` | 남의 자원을 보는 것이 기능이다(프로필 보기). 위험은 비공개가 섞이는 것 |
| `AUTHENTICATED_ONLY` | 로그인만 하면 누구나 같은 답. 자원에 주인이 없다 |

경로 변수 이름은 `{}` 로 적습니다 — `GET /api/v1/reports/{}`. 이름까지 적으면 변수 이름만 바꿔도 빨개지고 그건 인가와 무관한 변경입니다.

## 왜 이런 걸 넣었나

인가는 엔드포인트를 **하나 빠뜨리면** 뚫립니다. 그런데 빠뜨렸다는 사실은 아무 테스트도 빨갛게 만들지 않습니다 — **없는 검사는 실패하지 않으니까요.**

이 저장소가 그 증거입니다. 여행·일정 API 가 `X-User-Id` 헤더로 사용자를 정해 인가가 우회되던 것(`-607`·`-610`)은 사람이 손으로 찔러 보다 발견됐고, 그때까지 통과하던 테스트 수백 개 중 하나도 그것을 가리키지 않았습니다.

그래서 기능을 재는 대신 **빠뜨림을 재게** 만들었습니다. 표에 한 줄 적는 순간 그 사람은 인가를 한 번 생각한 것이고, 검사의 목적이 그것입니다.

## 로그인 없이 열려면 숫자도 고쳐야 합니다

`SecurityConfig` 허용 목록에 경로를 추가하면 같은 파일의 `routesReachableWithoutLoginArePinned` 에 박힌 개수도 고쳐야 통과합니다. 귀찮게 만든 것이 의도입니다 — 인증 없이 열린 경로가 **조용히** 늘어나는 것이 이 시스템에서 가장 비싼 실수라서, 그 변경이 diff 에 남아 리뷰에서 보이게 했습니다.

## 점검에서 찾은 것 둘

**허용 목록에 없는 경로 셋이 열려 있었습니다.** `/auth/web/refresh`·`/auth/web/logout`·`/auth/oauth/*/challenge` 인데 그 경로를 매핑하는 컨트롤러가 없습니다. 웹 쿠키는 별도 경로가 아니라 기존 `/auth/login`·`/auth/refresh` 가 `Set-Cookie` 로 처리하고 있었습니다.

지금은 뚫을 게 없어 무해합니다. 위험은 나중입니다 — 누가 그 경로로 컨트롤러를 만들면 인증을 켤지 끌지 **결정한 적도 없이 첫 커밋부터 열립니다.** 그 MR 은 `SecurityConfig` 를 안 건드리니 리뷰에도 안 보입니다. 세 줄을 지웠고 `SecurityAllowlistMatchesRoutesTest` 가 앞으로 이걸 잡습니다.

**🔴 `POST /api/v1/events` 가 본문의 `userId` 를 그대로 믿고 있었습니다.** 컨트롤러가 `Authentication` 을 아예 안 받고 `req.userId()` 를 저장했습니다. 즉 **로그인한 사람 누구나 임의의 사용자 ID 로 행동 이벤트를 넣을 수 있었습니다.** 행동 이벤트는 개인화 입력으로 들어가니 남의 추천 결과를 오염시킬 수 있었습니다.

`-607`·`-610` 과 **같은 종류의 세 번째**입니다. 헤더 대신 본문이라는 점만 다릅니다. `-705` 로 티켓 만들고 고쳤습니다 — 인증 주체를 쓰고 본문 값이 다르면 `403 EVENT_SUBJECT_MISMATCH` 입니다.

이벤트를 보내는 코드가 있으시면 확인 부탁드립니다. 자기 자신의 ID 를 보내고 있으면 그대로 동작하고, **배포 뒤에 403 을 받기 시작하면 남의 ID 를 보내고 있다는 뜻**이니 알려 주세요.

## 사람이 정할 것 하나

**장소 API 전체가 로그인을 요구합니다.** 컨트롤러는 비로그인을 전제로 쓰여 있는데(`PlaceDetailController` 가 `optionalId`, `NearbyPlaceController` 주석이 "좌표만으로 답이 정해진다") `SecurityConfig` 허용 목록에 없어서 문 앞에서 401 입니다.

뚫린 게 아니라 **반대로 잠긴 것**이라 임의로 열지 않았습니다. 여는 것은 노출을 늘리는 변경이라 사람이 정할 일입니다. 지금 상태로도 FE 화면은 동작합니다(로그인 상태로 부릅니다).

정할 것은 "**가입 전에 장소·축제를 둘러볼 수 있게 할 것인가**" 입니다. 그렇게 하기로 하면 `optionalId` 를 쓰는 코드가 그때 의미를 갖고, 안 하기로 하면 그 코드와 주석이 도달할 수 없는 상태이므로 정리하는 것이 맞습니다.

## 이예승 님께
