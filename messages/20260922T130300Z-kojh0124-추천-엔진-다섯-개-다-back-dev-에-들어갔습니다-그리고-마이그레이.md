## 1. 🔴 마이그레이션 번호 — 「머지 가능」이라고 떠도 운영은 죽습니다

`!1460`(구간 선형)에 마이그레이션이 하나 있었습니다. 브랜치를 딸 때 `back/dev` 최대가
`20260922100000` 이라 **`20260922110000`** 으로 지었습니다. 맞는 번호였습니다.

그런데 작업하는 동안 **`-1499`(취향 무게, 효준 님)가 `20260922150000` 을 들고 먼저
들어왔습니다.** 그 순간 제 것이 **「나중에 들어가는데 번호가 더 작은」** 상태가 됐습니다.

```
back/dev 최대 : 20260922150000   ← -1499 가 먼저 들어옴
내가 추가     : 20260922110000   ← 더 작다
```

Flyway 는 이미 적용한 것보다 작은 번호를 **out-of-order 로 거부하고, 운영 기동이 실패합니다.**

### 🔴 무서운 것은 «아무것도 경고하지 않았다» 는 점입니다

| 신호 | 그때 뭐라고 했나 |
|---|---|
| GitLab MR 상태 | **`mergeable`** — 충돌만 보기 때문입니다 |
| `!1460` 의 초록 배지 | 초록 — 다만 그 파이프라인은 **`-1499` 가 들어오기 전**에 돈 것입니다 |
| `backend:migration-order` | 그 초록도 **옛날 기준**이었습니다 |

**CI 는 이걸 구조적으로 못 잡습니다.** 파이프라인은 매번 **빈 DB** 에서 전부 순서대로
적용하므로 어긋남이 안 보입니다. `150000` 이 이미 적용돼 있는 **운영에서만** 터집니다.
(`.gitlab-ci.yml` 624행 주석이 정확히 이 얘기를 적어 뒀더군요.)

### 그래서 부탁

> **마이그레이션이 든 MR 은, 머지 직전에 대상 브랜치의 최대 번호를 다시 보십시오.**
> 내 브랜치를 딴 뒤에 남이 더 큰 번호를 넣었으면 내 것을 위로 올려야 합니다.

```bash
git ls-tree -r --name-only origin/back/dev -- 'backend/src/main/resources/db/migration' \
  | grep -oE 'V[0-9]+' | grep -oE '[0-9]+' | sort -n | tail -1
```

저는 `20260922160000` 으로 올려서(`기존 최대 + 10000`, 그 잡이 일러 주는 대로) 통과시켰습니다.
지금 `back/dev` 는 `…100000 → 150000 → 160000` 으로 오름차순입니다.

`-1251` 과 `-1498` 이 같은 두 줄을 건드려 충돌이 났는데, 둘 다 같은 생성자에 인자를 하나씩
더하는 것이라 **둘 다 남기는 것**이 해소였습니다.

## 3. 곁다리 — 충돌 해소는 «머지 커밋» 말고 «리베이스» 가 낫습니다

충돌을 머지 커밋으로 풀었더니 **axmap 커밋 훅이 거부**했습니다. 머지 커밋은 대상 브랜치에서
들어온 **모든 파일**을 품어서, 훅이 그것을 전부 「선점 안 한 수정」으로 읽습니다.

리베이스로 바꾸니 **내 커밋만 다시 얹혀서 내 파일 둘만** 남고 통과했습니다.
충돌 만나시면 이쪽이 편합니다.

## 4. 🔴 아직 «사용자 눈에는» 안 보입니다

머지됐다고 화면이 바뀌지 않습니다. 각 MR 설명에 「확인한 것 / 확인 못 한 것」으로 적어 뒀고,
요약하면 이렇습니다.

| 무엇 | 앱 쪽 남은 일 |
|---|---|
| 사진 | `photoSource`·`photoSubject` 를 읽어야 합니다. **안 읽으면 출처 없이 사진만 걸립니다**(공공누리 표기 의무) |
| 선형 | `travelPath` 를 읽어야 지도에 실제 길이 그려집니다 (`-1234`) |
| 이유 말하기 | `blockedBy` 를 읽어야 「땅콩 때문입니다」라고 **이름을 댑니다**. 지금은 갈래를 뭉뚱그린 문구까지입니다 |
| 식단 경고 | 🟢 **앱 준비 끝**(`!1503`). 이건 바로 보입니다 |
| 요금 | 이 판으로 만든 **새 일정부터** 값이 생깁니다. 기존 1,572건은 그대로 비어 있습니다 |
