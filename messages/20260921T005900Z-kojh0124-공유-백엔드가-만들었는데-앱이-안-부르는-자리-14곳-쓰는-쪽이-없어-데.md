## 1. 앱이 안 부르는 14곳

**일정 — 진행 기록 (4)**
```
POST /api/v1/itineraries/{id}/progress/start
POST /api/v1/itineraries/{id}/progress/pause
POST /api/v1/itineraries/{id}/progress/stops/{stopId}/arrive
POST /api/v1/itineraries/{id}/progress/stops/{stopId}/skip
```
🔴 **앱은 `GET /progress` 로 읽기만 합니다.** 쓰는 쪽을 아무도 안 불러서 **그 화면은 영원히 빈 값을 봅니다.** 이 목록에서 가장 시급해 보이는 자리입니다 — 화면에 「출발·도착·건너뜀」을 붙일 계획이 있는지 알려주세요.

**피드 (2)** — `GET /feed/home` · `GET /feed/community`
→ **1368 로 이미 요청돼 있습니다**(진미리 님). 붙일 예정이니 그대로 둡니다. 지금 피드 탭은 `/api/v1/stories` 를 씁니다.

**추천 액션 수정·삭제 (2)** — `PUT`·`DELETE /trips/{id}/recommendation-actions/{placeId}`
→ 생성·조회는 앱이 씁니다. 「좋아요 취소」·「판단 바꾸기」가 화면에 없는 건지 확인 부탁드립니다.

**facet-view (3)** — `GET /admin/facet-views` · `POST /facet-views/{id}` · `POST /trips/{id}/facet-views/{id}`
**관리자·기타 (3)** — `GET /admin/analytics/kpis` · `GET /events/catalog` · `GET /course-categories`
→ 관리자 화면 계획이 있으면 살아날 자리, 없으면 당분간 잠자는 자리입니다.

## 2. 쓰는 쪽이 없어 데이터가 비는 기능 5개

클래스·메서드 단위로도 훑었습니다. **참조 0인 클래스는 0개**입니다(`package-info` 10개 제외 — 원래 참조 안 됨). 메서드는 후보 417개가 나왔지만 `setXxx`(설정 주입)·`get/is`(JPA·직렬화)·`handle*`(예외 처리기)·컨트롤러 핸들러를 빼면 실질 다섯입니다.

```
AppUser.changeFrequentOrigin        자주 가는 출발지를 바꾸는 코드가 없다
AppUser.clearFrequentOrigin         지우는 코드도 없다
RecommendationJob.increaseRetryCount 재시도 횟수를 아무도 안 올린다 → 영원히 0
FeedBuild.recordInputs / recordVersions
```

🔴 **`increaseRetryCount` 는 죽은 코드가 아니라 버그로 보입니다.** 재시도 횟수가 안 올라가면 그 값을 보고 판단하는 자리가 전부 틀린 값을 봅니다. 추천 담당자분 확인 부탁드립니다.
