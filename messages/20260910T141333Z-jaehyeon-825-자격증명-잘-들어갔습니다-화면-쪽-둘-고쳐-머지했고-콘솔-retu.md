## 걸린 것 하나 — 화면 번들에 Service ID 가 없었다

버튼을 누르면 "APPLE 로그인 설정이 필요해요" 가 떴습니다. 서버가 아니라 화면 문제였습니다 — `EXPO_PUBLIC_APPLE_CLIENT_ID` 가 빈 채로 구워져 있었습니다. 이 값은 실행 중에 읽는 것이 아니라 빌드하는 순간 번들에 박혀서, 컨테이너에 넣어 주는 것으로는 안 됩니다.

Dockerfile 과 Jenkinsfile 에 인자를 열어 `gabolle-apple-client-id` 를 그대로 넘기게 했습니다(`!541`). 백엔드가 쓰는 것과 같은 자격증명입니다 — Service ID 는 비밀이 아니지만 한 군데서만 관리하는 편이 어긋날 일이 없어서 그렇게 했습니다. 비어 있으면 빌드 로그에 경고가 뜨도록 검사 목록에도 넣었습니다.

## 걸린 것 둘 — 애플이 요청을 거절했다

```
invalid_request
response_mode must be form_post when name or email scope is requested
```

코드 주석은 "이름을 요청하면 form_post 가 되므로 이메일만 요청한다" 라고 적어 뒀는데, 실제 규칙은 **이름이든 이메일이든 하나라도 요청하면** form_post 를 요구하는 것이었습니다. 이 프런트는 정적 SPA 라 POST 본문을 받을 서버가 없습니다.

애플에는 `scope` 를 아예 안 보내도록 고쳤습니다(`!543`).

## 그래서 애플로 가입하면 이메일이 안 옵니다

서버는 원래 이메일 없는 소셜 가입을 지원합니다 — `auth_identity.provider_email` 이 NULL 허용이고 가입 화면에 `emailProvided=false` 로 알려 줍니다. 사용자가 가입 화면에서 직접 적습니다. 애플은 **첫 인증에서만** 이메일을 주므로 원래도 기댈 수 있는 값은 아니었습니다.

이메일을 애플에서 받아 오려면 `redirect_uri` 를 POST 를 받는 서버 경로로 옮기고 거기서 화면으로 다시 넘겨야 하는데, **콘솔에 그 주소를 새로 등록하는 일이 따라옵니다.** 필요하다고 보시면 알려 주십시오 — 서버 쪽은 제가 만들겠습니다.
