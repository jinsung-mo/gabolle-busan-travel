## 3. 자동 승격이 **한 번도 안 돌고 있었습니다**

`<파트>/dev` → `<파트>/main` 은 **하루 한 번**, `<파트>/main` → `main` 은 **주 한 번** 자동으로 돌기로 설계돼 있었는데, **그걸 깨우는 예약 실행이 만들어져 있지 않았습니다.** 코드는 멀쩡했고 설정만 없었습니다.

오늘 등록했습니다 — **매일 09:00 KST** · **월요일 09:00 KST**. 내일 아침부터 봇이 승격 MR 을 만듭니다.

오늘 치는 손으로 열었습니다. **표 2장씩 기다립니다.**

| MR | 올릴 것 | 빌드 |
| --- | --- | --- |
| **!247** `front/dev → front/main` | 커밋 209개 | `frontend:build` ✅ `frontend:smoke` ✅ |
| **!248** `back/dev → back/main` | 커밋 180개 | `backend:build` ✅ |
| **!249** `bigData/dev → bigData/main` | 커밋 48개 | ✅ — **표 2/2 이미 찼습니다** |
| **!263** 투표 명령 → `main` | | 표 필요 |

🔴 **표는 커밋 하나에 묶여 있습니다.** 표가 찬 브랜치에 커밋이 하나라도 더 올라가면 앞의 표가 무효가 됩니다. `bigData/dev` 에는 당분간 아무것도 올리지 마세요.

## 4. 오늘 드러난 "한 브랜치에만 있던 것" 넷

전부 같은 뿌리입니다 — **우리 사다리는 아래에서 위로만 흐르므로 `main` 에 직접 넣은 것은 아래로 안 내려옵니다.**

| 무엇이 | 어디에만 있었나 | 어떻게 했나 |
| --- | --- | --- |
| 빌드 검사 잡 | `dev` 에만 (파트 `main` 엔 없음) | 승격 MR 로 올림 (위 3번) |
| 투표권자 명단 | `main` 6명 / 파트 4명 / `bigData` 3명 | **세 `dev` 전부 6명으로 맞춤** (모진성·고지혁 포함) |
| `/ax-vote` · `/ax-ballot` | `common/dev` 에만 | **네 `dev` 전부에 넣음** (머지 완료) |
| `ci/axmap` 걷어내기 | `common/dev` 에만 | 진행 중 (위 1번) |

이예승 님이 아침에 *"front/dev·back/dev CI 에 빌드 잡이 없어졌다"* 고 물으셨는데 — **`dev` 에는 있고 `main` 계열에만 없었습니다.** 승격이 그 차이를 없앱니다.
