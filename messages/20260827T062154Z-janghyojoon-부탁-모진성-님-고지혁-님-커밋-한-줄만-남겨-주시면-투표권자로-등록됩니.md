> (대소문자만 무시하고, 그 밖에는 한 글자라도 다르면 그 표는 없는 것이 됩니다.)

즉 명단에 적힌 이메일과 실제로 커밋에 찍히는 이메일이 다르면, **그 사람은 투표해도 아무 일이 일어나지 않습니다. 그리고 본인은 그 사실을 모릅니다.**

**사람에게 들은 이메일은 후보일 뿐이고, 실제 커밋에 찍힌 것만이 사실입니다.**

# 어떻게 하면 되나 — 아주 간단합니다

## 0단계. 먼저 이름과 이메일을 확인해 주세요

```
git config user.name
git config user.email
```

값이 안 나오거나 이상하면 아래로 설정하세요. **앞으로 계속 쓰실 이메일**을 넣어 주세요. (SSAFY 계정이든 개인 계정이든 상관없습니다. **바뀌지 않는 것**이 중요합니다.)

```
git config user.name  "본인 이름"
git config user.email "본인이_계속_쓸_이메일"
```

> `git config` 는 **git 에게 "내가 누구인지" 알려주는 설정**입니다. 커밋할 때마다 이 값이 기록에 찍힙니다.

## 1단계. 브랜치를 하나 만듭니다

**브랜치(branch)** — 저장소를 건드리지 않고 **내 작업만 따로 담아 두는 갈래**입니다. 여기서 뭘 하든 다른 사람 작업에 영향이 없습니다.

```
git fetch origin
git checkout -b chore/common/S15P21E201-XX-hello-본인이름 origin/common/dev
```

`XX` 자리에는 Jira(**작업 티켓 관리 도구**) 번호를 넣으시면 되는데, 없으시면 그냥 새 티켓을 하나 만들거나 저에게 쪽지 주세요. 제가 만들어 드리겠습니다.

## 2단계. `ref/` 폴더에 파일 하나를 만듭니다

`ref/` 는 **참고 자료 자리**라서 규칙 검사가 거의 안 돌고, 여기만 바꾼 MR 은 **열면 바로 통과**됩니다. 첫 커밋으로 가장 안전한 자리입니다.

```
ref/팀원/고지혁.md      ← 또는 ref/팀원/모진성.md
```

내용은 정말 아무거나 괜찮습니다. 예를 들면:

```markdown
# 고지혁

- 담당: (아직 미정)
- git 이메일: kojh0124@gmail.com
```

## 3단계. 커밋하고 올립니다

```
git add ref/팀원/고지혁.md
git commit -m "[S15P21E201-XX] chore: [Common] 고지혁 자기소개를 추가한다"
git push -u origin chore/common/S15P21E201-XX-hello-고지혁
```

> 🔴 **커밋 메시지 맨 앞의 대괄호 Jira 번호는 정확히 적어 주세요.** 그래야 티켓에 코드가 자동으로 연결됩니다.

## 4단계. 알려만 주세요

push 하시면 저희 쪽에서 커밋에 찍힌 이름과 이메일이 보입니다. **그걸 확인해서 투표권자 명단에 넣겠습니다.** 그 이후로는 아무것도 안 하셔도 됩니다.
