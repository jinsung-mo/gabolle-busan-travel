## 🔴 티켓과 다른 것 둘

### ① `source` 는 `"KAKAO"` 가 아니라 **`"KAKAO_LOCAL"`** 입니다

티켓에 `{"source": "KAKAO", ...}` 로 적혀 있는데 **`KAKAO_LOCAL`** 로 받습니다.

이유는 이미 그 값이 쓰이고 있어서입니다. `V20260916210000`(S15P21E201-76)이
`source_type='KAKAO_LOCAL'` + 카카오 id 로 **해운대해수욕장·광안리해수욕장·감천문화마을·
범어사** 넷을 장소 정본에 넣어 뒀습니다. 여기서 `KAKAO` 라는 새 철자를 들이면 같은 것을
가리키는 값이 두 벌이 되고, 제가 새로 건 유일 제약(`uq_place_source`)이 **그 둘을 다른
장소로 봅니다.**

> 🟢 **그 대신 좋은 일이 하나 생깁니다.** 사용자가 카카오 검색에서 해운대해수욕장을 고르면
> `(KAKAO_LOCAL, '7913306')` 이 **이미 있는 그 큐레이션 행에 그대로 붙습니다.** 새 장소가
> 안 생기고 기록이 진짜 장소에 이어집니다. 시험으로 못 박아 뒀습니다.

`INTERNAL_FALLBACK`(카카오가 죽었을 때 쓰는 우리 대체 목록)도 그대로 받습니다.
**앱이 고른 값을 그냥 그대로 실어 주시면 됩니다** — 변환하지 마세요.

### ② 실제 본문 모양

```jsonc
POST /api/v1/stories
{
  "body": "...",
  "placeId": null,                 // 우리 DB 장소를 골랐으면 여기에. 그러면 아래는 안 봅니다
  "place": {                       // 카카오/대체 목록에서 골랐을 때만
    "source": "KAKAO_LOCAL",       // 🔴 KAKAO 아님. OriginCandidate.source 그대로
    "externalId": "7913306",       // OriginCandidate.externalId
    "name": "해운대해수욕장",
    "address": "부산 해운대구 우동",   // 없어도 됩니다
    "lat": 35.1585,                // 🔴 lng 와 «함께» 있거나 «함께» 없어야 합니다
    "lng": 129.1598,
    "category": "SEA_BEACH"        // 없어도 됩니다
  }
}
```

- `placeId` 가 있으면 **`place` 는 안 봅니다.** 둘 다 보내도 되고, 그때는 `placeId` 가 이깁니다
- 둘 다 없으면 지금처럼 장소 없는 기록입니다
- 응답 `StoryDto.place` 는 **지금 모양 그대로**입니다(id·name·lat·lng). 화면 코드는 안 바뀝니다

## 🟢 앱 쪽 일이 생각보다 작아 보입니다

`OriginCandidate` 에 **필요한 값이 이미 다 있습니다** (`frontend/src/plan/origins.ts`):

```ts
export type OriginCandidate = {
  name; address; lat; lng;
  externalId: string;                                 // ← 있습니다
  source: 'KAKAO_LOCAL' | 'INTERNAL_FALLBACK';        // ← 있습니다
};
```

막고 있는 건 **합칠 때 좁혀 버리는 한 줄**입니다 —
`frontend/src/social/regionSearch.ts:34` 가 카카오 쪽을
`Pick<OriginCandidate, 'name' | 'address'>` 로 받아서 `externalId`·`lat`·`lng`·`source` 가
그 자리에서 버려집니다. 거기만 넓히시면 `compose.tsx` 에서 그대로 실을 수 있습니다.
