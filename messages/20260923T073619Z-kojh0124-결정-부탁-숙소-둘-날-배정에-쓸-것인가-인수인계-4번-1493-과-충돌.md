## ① 숙소를 날 배정의 중심으로 쓸 것인가 (인수인계 「먼저 정해야 하는 것」 4번)

인수인계에는 이렇게 적혀 있습니다.

> 숙소를 받으면 **그것이 날마다의 중심**이 되어야 한다 — 매일 거기서 나가고 거기로 돌아오니까

🔴 **그런데 이게 `S15P21E201-1493` 과 정면으로 충돌합니다.**

- `-1493` 은 날마다 **다른 지역**이 되게 중심을 벌립니다(순위 1위가 첫 날, 그다음은 이미
  잡힌 중심들에서 **가장 먼 곳**). 영도·해운대가 섞여 왕복 104분 나오던 것을 고친 그 로직입니다
- 숙소를 **매일의 중심**으로 쓰면 그 벌리기가 통째로 무너집니다. 숙소가 해운대면 **7일이 전부
  해운대 옆**이 됩니다

지금 `seedDayAnchors(places, coords, days)` 는 **후보 장소만** 받고 숙소를 아예 안 봅니다.

**고를 수 있는 것 셋으로 보입니다.**

| | | 대가 |
|---|---|---|
| **가** | 숙소가 매일의 중심 | 인수인계 글자 그대로. 지역 다양성이 사라짐 — 7일이 한 동네 |
| **나** | 지금대로 지역을 벌리되 **숙소에서의 거리로 제한** | 「매일 거기서 나간다」는 지키면서 다양성도 남음. 임계값(몇 분? 몇 km?)을 정해야 함 |
| **다** | 배정에 안 쓴다 (표시·기록용) | 지금 상태. 값은 쌓이니 나중에 바꿀 수 있음 |

**제 의견은 「나」입니다.** 사람은 숙소에서 나가지만 **매일 같은 동네에 있고 싶어 하지는
않습니다.** 다만 임계값은 자료가 아니라 **판단**이라 제가 정할 자리가 아닙니다.

참고로 7일이 지금 실제로 어떻게 나오는지는 **특성화 시험으로 못 박아 뒀습니다**
(`sevenDayTripKeepsEachDayInOneRegion` 외 1건, `-1251`). 그래서 바꾸면 **무엇이 달라지는지
시험이 바로 말해 줍니다.**

숙소 자료가 얇은 것도 그대로입니다 — `CHECK_IN_OUT` **65곳**.

## ② 추천 「동네」를 어디로 받을 것인가 — 🔴 미리 님이 여기 막혀 있습니다

앱의 숙소 칸은 검색어가 없을 때 **추천 동네 4개**를 먼저 보여 줍니다. 가장 많이 눌릴 자리입니다.

```
{ name: '해운대', externalId: 'lodging-haeundae', source: 'INTERNAL_FALLBACK',
  lat: 35.1587, lng: 129.1604 }
```

이걸 그대로 보내면 서버에 **장소 행 「해운대」**가 하나 생깁니다. 그런데 재 보니 —

| 앱 추천 동네 | 서버 `TravelArea` | |
|---|---|---|
| 해운대 `35.1587, 129.1604` | `HAEUNDAE("해운대", 35.1587, 129.1604, 2500)` | **완전 동일** |
| 남포동·중앙동 `35.0980, 129.0306` | `NAMPO("남포동", 35.0980, 129.0306, 2000)` | **완전 동일** |
| 서면 · 광안리 | `SEOMYEON` · `GWANGALLI` | 소수점 넷째 자리만 차이 |

**같은 동네를 앱은 `lodging-haeundae`, 서버는 `HAEUNDAE` 로 부릅니다. 어휘가 이미 두 벌입니다.**
장소까지 만들면 **세 벌**이 되고 셋이 서로 조인이 안 됩니다. 그리고 `TravelArea` 주석이 정확히
이 상황을 경고해 두셨더군요 — *"같은 「해운대」가 여행마다 다른 곳을 뜻하게 된다."*

**미리 님께는 「동네는 안 싣기」로 답했습니다**(한 줄이면 된다고 하셔서). 다만 그건
**신호를 버리는 것**이라, 제대로 받을 자리를 정해 주셨으면 합니다.

| | | |
|---|---|---|
| **A** | 안 싣는다 (지금 답한 것) | 신호가 사라짐. 되돌리기는 쉬움 |
| **B** | 기존 `travelAreas` 에 넣는다 | 어휘 하나로 유지·서버가 이미 받음. **다만 「묵는 곳」과 「다니는 곳」은 다른 뜻**이라 겹치는 판단이 필요 |
| **C** | `trip` 에 동네 칸 신설 (`TravelArea` 코드) | 뜻이 정확함. **①이 정해져야** 엔진이 그걸 어떻게 쓸지가 정해짐 |

**C 가 옳아 보이는데 ① 없이 만들면 「쓰임을 모르는 채로 만드는 칸」**이 됩니다. 이번 주에
그런 칸을 하나 만들어 봤고(`blockedBy`), **읽는 쪽이 없어 그대로 묻혔습니다.** 같은 일을
반복하고 싶지 않습니다.
