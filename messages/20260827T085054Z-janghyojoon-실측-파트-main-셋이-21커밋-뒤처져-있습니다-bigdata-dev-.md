# 결론 먼저

**`back/main` · `bigData/main` · `front/main` 셋이 전부 최상위 `main` 보다 21커밋 뒤처져 있고, 그 안에 `governance/policy.json`(누가 투표권자인가를 적어 둔 파일)이 없습니다.**

그래서 파트 `dev` 에서 파트 `main` 으로 올라가는 MR 은 **표를 못 세는 것이 아니라 판정 자체가 안 됩니다.**

지금 실제로 막혀 있는 것은 **`bigData/dev` 의 34커밋**입니다.

# 실측

```
back/main    : main 보다 21커밋 뒤처짐 · governance/policy.json 0개
bigData/main : main 보다 21커밋 뒤처짐 · governance/policy.json 0개
front/main   : main 보다 21커밋 뒤처짐 · governance/policy.json 0개
```

`bigData/dev → bigData/main` 에 게이트를 돌린 결과:

```
합의 판정 불가 — 타깃 브랜치에서 정책 파일을 읽을 수 없습니다: governance/policy.json
종료 코드 1
```

**종료 코드 1 은 "표가 모자라다"(2)가 아니라 "내가 판정을 못 했다"** 입니다. 투표로는 안 풀립니다.

# 왜 이렇게 되었나

정책 파일은 **언제나 받는 쪽 브랜치에서 읽습니다.** 내미는 쪽에서 읽으면 *"정족수를 2에서 1로 낮춥니다"* 라는 변경이 **자기가 방금 쓴 1이라는 숫자로 통과**해 버리기 때문입니다. 이 설계 자체는 옳습니다.

문제는 파트 `main` 셋이 **합의 장치가 생기기 전 시점에서 멈춰 있다**는 것입니다. 읽을 정책이 거기 없습니다.

# 나가는 길 — 셋 중 하나. 팀이 정할 일입니다

**1. 파트 `main` 셋에 `main` 을 머지해서 따라잡힙니다.**
가장 곧은 길입니다. 다만 이 머지 자체가 `main` 으로 끝나는 대상이라 표 2장을 요구하고, `.gitlab-ci.yml` 과 `ci/` 가 21커밋만큼 바뀌므로 **개정 문턱**이 걸립니다. 그리고 그 표를 던질 수 있는 사람이 남아 있는지 먼저 세어 봐야 합니다.

**2. 파트 `main` 을 지금 지우고 `dev` 에서 다시 만듭니다.**
21커밋 뒤처진 브랜치가 무엇을 지키고 있는지 먼저 확인해야 합니다. 지금 아무도 안 쓰고 있다면 이쪽이 훨씬 쌉니다. **다만 되돌리기 어려운 조치라 혼자 하면 안 됩니다.**

**3. 사다리에서 파트 `main` 을 뺍니다.**
`dev` 에서 최상위 `main` 으로 바로 갑니다. 지금 `common` 을 버전 축에서 빼는 작업(S15P21E201-35)이 하고 있는 판단과 같은 종류입니다.

**저는 어느 쪽도 혼자 정하지 않겠습니다. 숫자만 올립니다.**

# 곁가지 — 확인하실 때 주의

게이트를 로컬에서 돌리실 때 **`--target` 에 `origin/` 을 붙여 주세요.**

```
node ci/axmap/governance/gate.mjs --source bigData/dev --target origin/bigData/main
```

그냥 `bigData/main` 이라고 하면 **낡은 로컬 브랜치**를 봐서 틀린 답이 납니다. 제 PC 에서는 로컬 `main` 이 초기 설정 시점(`893a0f3`)에 멈춰 있어서, 멀쩡한 저장소를 "정책 파일이 없다" 고 보고했습니다. axMap 저장소에 알려 뒀습니다.

**즉 위 숫자 중 "정책 파일 0개" 는 그 버그가 아닙니다** — `git ls-tree` 로 원격 브랜치를 직접 뒤져서 확인한 값입니다.
