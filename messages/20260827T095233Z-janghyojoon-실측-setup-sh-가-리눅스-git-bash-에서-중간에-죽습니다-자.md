## 무슨 일인가

`setup.sh` 가 **80행에서 죽습니다.** 리눅스와 윈도우의 Git Bash 에서 그렇습니다.

```
setup.sh:19-21   ok() · warn() · fail()   ← 정의된 함수는 이 셋뿐
setup.sh:80      say "MCP: ..."           ← 없는 함수를 부른다
setup.sh:16      set -euo pipefail        ← 그래서 여기서 통째로 멈춘다
```

재현했습니다. **종료 코드 127**(`command not found`)로 끝납니다.

## 그래서 무엇을 놓치나

80행 **뒤에 있는 것이 전부 실행되지 않습니다.**

| 안 도는 것 | 왜 문제인가 |
|---|---|
| **자가 점검**(`doctor`) | 준비가 제대로 됐는지 확인하는 단계. 이게 안 돌면 **뭐가 빠졌는지 아무도 모릅니다** |
| 마지막 안내 | 다음에 무엇을 하라는 문구 |

🔴 **더 나쁜 것은 이겁니다** — 앞부분은 정상으로 보입니다. 그래서 **"준비가 끝났다"고 믿고
넘어가게 됩니다.** 그러다 나중에 커밋이 막히거나 AI 도구가 선점 장치에 안 붙는 걸 겪습니다.

## 🔴 맥에서는 안 죽습니다 — 그래서 더 안 잡혔습니다

맥에는 `say` 라는 **진짜 명령이 있습니다** (글자를 소리 내어 읽어 주는 기능).
그래서 맥에서 돌리면 죽기는커녕 **안내문을 스피커로 읽고 그냥 넘어갑니다.**

즉 **쓰는 사람의 운영체제에 따라 결과가 셋으로 갈립니다.**

| | |
|---|---|
| 윈도우 (`setup.ps1`) | 정상 — 그쪽 파일에는 그 함수가 제대로 있습니다 |
| 맥 | 안 죽음. 대신 안내를 소리로 읽음 |
| **리눅스 · Git Bash** | **죽음. 자가 점검이 안 돔** |
