오늘 새로 나온 기획입니다. 기존 자유형 피드(Post/Story)를 "추천 코스" 중심으로 좁히는 방향이에요. 확정 범위만 정리해서 계약을 제안드립니다 — 프론트는 이 계약을 가정하고 화면을 먼저 만들고 있어서, 다르게 가야 하면 빨리 알려주시면 바로 맞추겠습니다.

## 확정 요구사항 (부슐랭·공유·코스 발행 후 수정 등은 이번 범위 아님)

1. 피드 게시물은 두 종류뿐입니다 — RECOMMEND(코스 소개) / REVIEW(받아본 코스 후기). 자유 게시물은 없습니다.
2. Course는 Trip과 별개 엔티티입니다. 발행 시점 스냅샷(장소 목록+순서, 제목)이고, 이후 원본 Trip이 바뀌어도 Course는 안 바뀝니다. `originTripId`는 출처 참고용으로만 둡니다.
3. 코스 장소 구성/순서를 바꾸면 **새 코스로 재발행**(새 id)합니다 — 제목/설명만 고치는 건 원본 수정 허용. 이러면 REVIEW가 가리키는 courseId가 절대 안 바뀌어서, 별도 버전 스냅샷 필드가 필요 없습니다.
4. "받아보기"(저장) 관계가 필요합니다 — `SavedCourse{userId, courseId}` 같은 것. REVIEW 작성과 스토리의 장소 선택 둘 다 "내가 받아본 코스"로 범위를 좁혀야 해서요.
5. 스토리는 `courseId` + `placeId`(그 코스에 실제로 속한 장소만) + 미디어 + 짧은 문구입니다.
6. 신규 게시물 생성은 courseId 없이 서버가 거부해야 합니다(타입이 RECOMMEND/REVIEW인 이상 필수). 기존 자유형 게시물의 courseId는 nullable로 남겨서 마이그레이션 없이 갑니다.

## 필요한 API (제안)

```
POST   /api/v1/courses                 코스 발행 (title, places[](placeId, order), originTripId?)
GET    /api/v1/courses/{id}            코스 상세 (장소 스냅샷 포함)
POST   /api/v1/courses/{id}/save       받아보기(저장)
DELETE /api/v1/courses/{id}/save       저장 취소
GET    /api/v1/courses/saved           내가 받아본 코스 목록

POST   /api/v1/posts                   { type: RECOMMEND|REVIEW, courseId, body, media[] }
GET    /api/v1/posts?scope=ALL|FOLLOWING

POST   /api/v1/stories                 { courseId, placeId, media, caption }  — placeId가 그 코스에 없으면 400
```

지금 당장 답 안 주셔도 됩니다 — 프론트는 부슐랭(백엔드 무관, 로컬저장)부터 먼저 실제로 끝냈고, 이 계약은 여유 있을 때 검토 부탁드립니다. 급한 건 아니라 표시만 남깁니다.
