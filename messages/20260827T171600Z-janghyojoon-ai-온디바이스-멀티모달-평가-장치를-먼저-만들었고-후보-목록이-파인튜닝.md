# ai/ 파트를 새로 만들었습니다 (2026-08-28)

**목표**: 로밍 데이터가 없는 외국인 관광객이 **인터넷 없이** 사진 한 장으로
"이게 뭔지" 알 수 있게 한다. 그러려면 **온디바이스**(서버에 안 보내고 **폰 안에서**
도는 것) **멀티모달**(글자만이 아니라 **이미지도 같이 넣을 수 있는**) 모델이 필요합니다.

`ai/` 밖은 하나도 안 고쳤습니다. `bigData/` 는 읽기만 했습니다.

---

## 1. 왜 모델부터 안 고르고 자부터 만들었나

*"성능이 제일 좋은 걸 찾아줘"* 는 **무엇으로 재느냐**가 정해져야 답이 됩니다.
MMMU·OCRBench 같은 공개 시험지는 우리 질문에 답하지 않습니다. 우리 질문은
*"남포동에서 찍은 어묵 사진을 보고 외국인에게 영어·일본어·중국어로 말해 주는가"* 이고,
**그런 평가용 사진이 우리에게 한 장도 없었습니다.**

그래서 순서를 뒤집었습니다: **자 → 사진 → 모델 비교 → (필요하면) 파인튜닝.**
모델은 몇 달마다 바뀌지만 자는 남습니다.

`node ai/eval/test.mjs` — 모델도 사진도 없이 도는 자가검사입니다 (종료 코드 0).

## 2. 🔴 가장 중요한 실측 — 후보 목록이 파인튜닝보다 싸다

MiniCPM-V 4.6 을 실제로 받아서 이 PC 에서 돌렸습니다. 사진 11장 × 언어 2~3개 = 27회씩.

| | 형식 강제만 (`json`) | + **주변 후보 4개를 프롬프트에 넣음** (`hint`) |
|---|---|---|
| 고유명사 정확도 | 29.6% | **40.7%** |
| 🔴 환각률 | 28.0% | **11.1%** |
| 간판 읽기(OCR) | 50% | **100%** |
| 응답시간 중앙값 | 13.4s | 21.5s |

**바꾼 것은 프롬프트뿐입니다. 가중치는 한 바이트도 안 바뀌었습니다.**

폰은 인터넷이 없어도 **GPS 는 압니다.** 그리고 부산 POI 는 우리에게 있습니다
(`bigData/data/raw/pbf/poi.ndjson`, 13,003개). 그러면 문제가 *"부산의 모든 것 중에서
맞히기"* 에서 **"네댓 개 중에서 고르기"** 로 바뀝니다.

→ **파인튜닝**(이미 학습된 모델을 우리 데이터로 더 학습시키는 것)**은 아직 아닙니다.**
GPU 도 라벨도 필요 없는 수단이 오늘 이미 듣습니다. 값은 응답시간(13→21초)이고,
후보를 몇 개까지 넣을지는 폰에서 재고 정해야 합니다.

## 3. 🔴 그 밖에 실측으로 배운 것 셋 — 다음 사람이 다시 겪지 않게

**(a) mmproj 를 빼먹으면 용량 계산이 절반 틀립니다.**
GGUF(폰·PC 공통 모델 파일 형식)에서 **이미지를 보는 부분(mmproj, 비전 프로젝터)**
은 **별도 파일**이고, 언어 부분보다 클 수도 있습니다.
MiniCPM-V 4.6 은 언어부 529MB 인데 mmproj 가 728MB — **합계 1,257MB** 입니다.
블로그가 "529MB 짜리 모델" 이라고 적은 걸 믿으면 앱 설계가 처음부터 틀어집니다.

**(b) 출력 토큰 상한을 아끼면 모델이 아니라 우리 예산을 재게 됩니다.**
`-n 256` 으로 돌렸더니 형식 준수 7%. 원문을 열어 보니 모델이 길게 생각하다가
JSON 을 내기 전에 **우리가 끊은 것**이었습니다. 768 로 올리니 48%. 같은 모델입니다.
→ 지표만 남기면 이런 오류를 못 잡습니다. `run.mjs` 는 원문 출력을 통째로 남깁니다.

**(c) 함정 사진은 위키미디어 공용에서 못 구합니다.**
"이름 붙일 만한 게 없는 거리" 를 파일명(`Busan street.jpg`)만 보고 넣었는데,
열어 보니 감천문화마을 상가 골목이었습니다(한복 대여, VISIT BUSAN PASS 배너).
당연합니다 — 공용에 올라오는 사진은 정의상 **올릴 만한 것**이라 무명 골목이 없습니다.
**함정은 우리가 직접 찍어야 합니다.**

## 4. 고른 것과 버린 것

**1순위 MiniCPM-V 4.6** (1.3B, Apache-2.0, GGUF 합계 **1,257MB**)
근거: 살아남은 후보 중 **총 용량이 가장 작고**(2순위보다 300MB 작다), 상업 사용
가능하고, **iOS·안드로이드·HarmonyOS 앱 코드를 만든 쪽이 공개**해 뒀습니다.

**2순위(대조군) Qwen3.5-2B** (1,949MB) — 700MB 더 내고 얼마를 얻는지 재야 1순위가
확정됩니다. 공식 카드에 **수치가 실제로 적힌** 유일한 후보(MMMU 64.2 · OCRBench 85.4 ·
201개 언어)라는 점도 큽니다. **아직 안 받았습니다** (이번 다운로드 예산 2GB 안에 못 넣음).

🔴 **버린 것과 이유** — 이게 다음 사람에게 가장 쓸모 있을 겁니다:
- **apple/FastVLM-0.5B** → **라이선스.** `apple-amlr` = 연구용, **상업 사용 불가.**
  0.5B/1.5GB 로 크기는 제일 매력적이었지만 여기서 끝
- **LiquidAI/LFM2-VL** → **영어만 지원**(공식 카드 명시). 엣지 최적화가 아무리 좋아도
  우리 사용자는 외국인이고 한글 간판을 읽어야 함
- **Gemma 4 E2B** → **용량.** 구글 공식 4bit GGUF 가 3,349MB + mmproj 987MB = **4.3GB**.
  라이선스는 Apache-2.0 으로 바뀌었는데(예전 Gemma 커스텀 라이선스에서) 용량에서 탈락
- **Qwen3-VL-4B** → 2,951MB. 2B 를 재보기 전에는 못 고름
- **InternVL3/3.5-2B** → 공식 GGUF 없음, 계열이 2025-09 이후 갱신 없음
- **moondream2 / SmolVLM2-2.2B / Ministral-3-3B** → 각각 영어중심 / 8.9GB / 폰 대상 아님

## 5. 🔴 확인 못 한 것 — 지어내지 않았습니다

- **한국어 시각 성능을 재놓은 공개 점수가 사실상 없습니다.** MTVQA(한국어 포함
  다국어 시각 QA 시험지)가 있지만 **우리 후보들의 점수를 공식 카드에서 못 찾았습니다.**
  → **그래서 우리가 직접 재는 것 말고 방법이 없습니다.** `ai/eval` 이 그것 때문에 있습니다
- **MiniCPM-V 4.6 의 수치 벤치마크 표를 못 읽었습니다** — 공식 카드가 표를 **PNG 이미지로만** 싣습니다
- **폰 실측 지연·메모리를 1차 출처로 확인 못 했습니다.** 검색 요약에 수치가 있었지만
  다른 버전(4.0, 4B)이거나 2차 출처라 **설계 근거로 쓰지 않았습니다.**
  아래 PC 수치는 **폰 수치가 아닙니다**

## 6. 🔴 사람이 정해야 하는 것 둘

**(a) 1.2GB 를 로밍 없는 사람이 어떻게 받나 — 모델 문제가 아니라 온보딩 설계 문제입니다.**
Google Play 는 앱 기본 모듈 압축 다운로드가 200MB 이하여야 하고, 넘으면 Play Asset
Delivery 같은 별도 경로가 필요합니다. 즉 **모델은 앱 설치와 따로 받아야 합니다.**
그런데 로밍이 없는 외국인은 그걸 **여행 전에** 받아야 합니다.
갈림길: (A) 출국 전 / (B) 숙소·공항 와이파이 / (C) 안 받은 사람에겐 축소본
(SmolVLM2-500M ~358MB 후보) / (D) 온라인일 때만 서버 — D 는 제품 전제를 버리는 것.
**코드보다 먼저 정해야 합니다.**

**(b) 사진 45장 촬영.** 지금 11장(위키미디어 공용, CC0/CC BY/CC BY-SA, 출처 기록 포함)
뿐입니다. 급한 것은 **간판 10장 · 함정 8장 · 버스정류장 7장**. 절반은 **밤에** 찍어야
합니다 — 낮 사진만으로는 야간 성능을 모르고, 관광객은 저녁에 더 헤맵니다.
찍을 목록은 `ai/eval/cases.json` 의 `source.shoot` 항목이 그대로 목록입니다.
