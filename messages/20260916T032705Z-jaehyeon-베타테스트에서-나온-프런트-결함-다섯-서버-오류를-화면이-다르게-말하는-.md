## 배포 순간의 502 를 세 화면이 각각 다르게 말함

배포할 때마다 백엔드가 잠깐 끊깁니다(12:13경 실측, 그 전후 5분 60회는 전부 200). 그 구간에 들어온 사용자가 보는 것이 화면마다 다릅니다.

1. **로컬 탐색** — "로컬 탐색 API가 아직 준비되지 않았어요" 가 뜹니다. `localExplore.ts:16` 이 `INVALID_RESPONSE` 만 보고 분기하는데, nginx 의 502·503·504 는 HTML 을 주므로 전부 여기로 빠집니다. 사용자는 "이 기능은 아직 없구나" 로 읽고 나갑니다. `placeCategories.ts:15` 도 같습니다. 같은 파일의 `routeDirections.ts`·`itinerary.ts` 는 `404 || 501` 로 상태 코드를 보고 가르니 그 방식이 맞습니다.

2. **장소 저장** — `PUT /api/v1/me/saved-places/{id}` 가 502 인데 "내 여행 후보에 저장했어요" 토스트가 뜨고 버튼이 "빼기" 로 바뀝니다. `savedPlaces.ts` 의 `setSavedPlace` catch 가 기기 선택을 지키는 것은 맞지만, 서버에 안 갔는데 성공이라고 말하는 것은 다른 문제입니다.

3. **서버 연결 배너** — 이때 "서버에 연결할 수 없어요" 가 안 뜹니다. `client.ts:200` 주석대로 HTTP 오류는 "서버에 다시 연결된 상태" 로 보고 `setApiUnavailable(false)` 를 부릅니다. nginx 가 502 를 주는 동안 앱은 서버가 멀쩡하다고 판단합니다.

셋 다 한 자리에서 갈라집니다 — 5xx 를 "일시적 오류, 잠시 후 다시" 로, 404·501 만 "아직 준비 안 됨" 으로.

## 추천 제외가 서버로 안 감

추천 후보에서 "제외" 를 눌렀더니 `@gabolle/recommendation-actions:{tripId}` 에만 적히고 `/api/v1/trips/{tripId}/recommendation-actions` 호출은 0건이었습니다(Performance API 로 확인). 그 경로는 어젯밤 들어왔고 "동행자가 함께 본다" 가 목적인데 지금은 브라우저별로 따로 남습니다. `recommendationActions.ts` 머리말의 "받는 API 가 아직 없고" 가 이제 낡았습니다. 값 표기도 다릅니다 — 화면 `saved`/`excluded`, 서버 `SAVED`/`EXCLUDED`.

## 생성 완료 표시가 안 끝남

일정 생성에서 네 단계가 전부 "완료" 이고 결과 카드까지 그려졌는데 "처리 중 · 100% / 여행표 출력 중" 이 그대로 남습니다. 티켓 -1016 과 같은 증상으로 보입니다. jobId `ae437972-0ffd-4d0d-bcbd-67d3b8c596bf` 로 재현했습니다.

## 참고로 확인만 한 것

여행 이름 짓기는 화면이 붙어 정상 동작합니다. 다만 "이번엔 이름을 짓지 못했어요 — 장소 이름을 정해진 틀에 넣어 만든 후보" 가 뜹니다. 운영에 GMS 열쇠가 안 들어가 있어서이고 메뉴판 읽기도 같은 열쇠를 씁니다. 코드 문제가 아니라 서버 `.env` 설정입니다.
