## 문제 1 — 앱이 묻는 차원과 서버가 읽는 차원이 다릅니다

**앱이 계정 기본 취향에서 보내는 차원은 다섯입니다** (`frontend/src/preferences/tasteProfile.ts:21`):

```ts
const DIMENSION = {
  locality: 'LOCALITY',  quiet: 'QUIETNESS',  tourist: 'TOURIST_PREFERENCE',
  foods: 'FOOD_PREFERENCE',  slope: 'SLOPE_PREFERENCE',
};
```

**`CATEGORY` 가 없습니다.** 서버의 `PreferenceDimensions` 에는 있는데 앱이 안 묻습니다.

접기(`TasteVectorFoldService`)는 설문 차원 이름을 그대로 옮겨 적으므로 `user_taste_weight` 에 `CATEGORY` 행이 생길 수 없습니다. 실제로 **0건**입니다(이예승 님 실측).

**그런데 점수 쪽에서 이 벡터를 읽는 유일한 항이 `CATEGORY` 만 봅니다** (`BaselineCandidateScorer:511`). 거른 결과가 비면 바로 0 을 냅니다.

→ **취향 벡터가 추천 점수에 한 번도 닿은 적이 없습니다.** 배관은 다 있는데 양쪽 끝이 다른 이름을 부르고 있었습니다.

🔴 **행동 귀속(⑥)을 만들 때 그대로 걸립니다.** `INTERACTION` 성분을 써 넣어도 그게 `CATEGORY` 가 아니면 점수에 안 닿습니다. 오류 없이 조용히 0 이라, 만들고 나서 「왜 안 변하지」를 며칠 찾게 됩니다.

**정할 것 — 둘 중 하나입니다.**

| | 무엇 | 대가 |
|---|---|---|
| (가) | 앱 취향 화면에 `CATEGORY` 문항을 추가 | 화면·온보딩을 건드려야 함. 범위가 큼 |
| (나) | 점수 항이 **실제로 있는 차원**(`FOOD_PREFERENCE`·`LOCALITY`·`QUIETNESS`)도 읽게 함 | 그 셋은 설문 경로가 이미 채점하므로 **그때 비로소 진짜 두 번 세기**가 됨 → 제가 넣은 SURVEY 제외(1406)가 그때 필요해짐 |

`TOURIST_PREFERENCE` 는 짝인 `TOURIST_RATIO` 가 폐기 예정이라 맞출 대상이 없어 셈에서 뺐습니다. 이예승 님은 (나)를 권하셨고 저도 같은 생각입니다 — (가)는 설문 문항을 건드려야 합니다.

## 문제 2 — 글 순위에는 개인화 경로가 «아예 없습니다»

`story` 패키지에서 취향을 쓰는 파일이 **0개**입니다. 만들다 만 게 아니라 시도된 적이 없습니다.

두 기능이 다른 축으로 자랐습니다 — 추천 엔진은 **장소**를 받고(`PlaceCandidateResponse.Candidate`), 기록은 **사회 기능**(작성·반응·팔로우·차단)으로. 둘을 잇는 유일한 다리가 `story.place_id` 인데 그게 39건 중 3건입니다(별도 쪽지로 전체에 보냈습니다).

→ 글 순위 개인화는 **「기존 걸 켠다」가 아니라 「새로 만든다」** 입니다. 장소 스코어러를 빌려 쓸 수도 없습니다.

## 이예승 님께 — 숫자 하나만 더 부탁드립니다

`FOOD_PREFERENCE 21 / 나머지 12` 를 사람 수로 읽으면 안 될 것 같습니다. 접기 코드를 보면 **태그형 답은 고른 코드마다 한 행**이고(`TasteVectorFoldService:198` 의 `for (String code : codes)`), 점수형은 차원당 한 행(`code='SCORE'`)입니다. 그러니 `FOOD_PREFERENCE 21행`은 21명이 아닙니다.

```sql
SELECT dimension, count(*) AS rows, count(DISTINCT taste_vector_id) AS people
  FROM user_taste_weight GROUP BY dimension ORDER BY dimension;
```

이거 한 번만 재 주시면 「몇 명이 설문을 끝까지 답했나」가 확정됩니다. 지금 제 추정은 **점수형을 답한 사람이 12명**입니다.

## 제안하는 순서

2. (나)로 가면 제가 1406(SURVEY 제외)과 묶어 한 MR 로 내겠습니다
3. 글 순위 개인화는 `story.place_id` 가 채워지기 시작한 뒤에 다시 이야기하는 게 맞다고 봅니다
