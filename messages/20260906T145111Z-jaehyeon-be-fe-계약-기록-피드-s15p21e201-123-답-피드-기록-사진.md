## 경로

| 무엇 | 경로 | 응답 |
| --- | --- | --- |
| 피드 | `GET /api/v1/stories?scope=ALL\|FOLLOWING&cursor=<이전 nextCursor>&limit=20` | `{ items: StoryDto[], nextCursor: string\|null }` |
| 사진 올리기 | `POST /api/v1/uploads/story-image` (multipart, 필드명 `file`) | 201 `{ imageId, imageUrl, contentType, byteSize }` |
| 기록 작성 | `POST /api/v1/stories` | 201 StoryDto |
| 기록 상세 | `GET /api/v1/stories/{id}` | StoryDto |
| 기록 수정 | `PATCH /api/v1/stories/{id}` `{ body?, region?, visibility?, publishAt?, placeId?, clearPlace? }` | StoryDto |
| 기록 삭제 | `DELETE /api/v1/stories/{id}` | 204 |
| 팔로우 / 해제 | `PUT` / `DELETE /api/v1/users/{userId}/follow` | `{ userId, following, followerCount, followingCount }` |
| 프로필 | `GET /api/v1/users/{userId}/profile` | `{ userId, displayName, followerCount, followingCount, storyCount, following, me }` |
| 그 사람 기록 | `GET /api/v1/users/{userId}/stories?cursor=&limit=` | 피드와 같은 모양 |

전부 `ApiResponse` 봉투(`data / error / meta.requestId`) 안에 옵니다. 사진 주소(`imageUrl`)는 `/api/v1/uploads/images/...`로 시작하고 인증 없이 `<img src>`로 바로 열립니다.

## StoryDto

```
{
  id, author: { id, displayName }, body, region, place: { id, name } | null, tripId | null,
  images: [{ url, position }],           // 최대 3장, position 1..3
  visibility: "PUBLIC" | "FOLLOWERS" | "PRIVATE",
  publishAt, createdAt, updatedAt,      // ISO-8601 UTC
  mine: boolean,                        // 수정·삭제 버튼을 이걸로 켜세요
  published: boolean                    // 작성자 본인에게만 false 가 보일 수 있습니다
}
```

## 작성 본문

```
{ body (1~500자, 필수), imageUrls: [업로드 응답의 imageUrl…] (0~3), placeId?, tripId?, region?, visibility? (기본 PUBLIC), publishAt? }
```

- 사진은 먼저 올리고 받은 `imageUrl`을 그대로 넣습니다. 내가 올린 사진만 붙일 수 있고 한 사진은 한 기록에만 붙습니다. 서버는 JPEG·PNG·WebP만, 한 장 3MB까지 받고(내용으로 판단합니다. 확장자 아님), 촬영 위치 정보(EXIF)는 서버가 지웁니다. 초과·형식 오류는 413 `IMAGE_TOO_LARGE` / 415 `IMAGE_UNSUPPORTED_TYPE`.
- **좌표는 보내지 않아도 되고, 보내도 서버가 버립니다.** 위치는 `region`(지역 문자열) 하나이고, 없으면 연결한 장소 주소의 앞 두 마디("부산광역시 해운대구")가 들어갑니다.
- `publishAt`을 안 주면 여행 종료 **다음 날 0시**(여행 시간대)가 기본값이라 여행 중에는 피드에 안 뜹니다. 여행이 없으면 지금입니다. 작성 화면에서 "공개 시점"을 보여줄 때 이 기본값을 안내해 주세요.

## 피드 규칙

- `scope=ALL`은 공개 시각이 지난 PUBLIC 기록 + 내 기록. `scope=FOLLOWING`은 내가 팔로우한 사람의 PUBLIC·FOLLOWERS 기록.
- 커서는 불투명 문자열입니다. 첫 요청은 `cursor` 없이, 다음은 받은 `nextCursor`를 그대로. `nextCursor`가 `null`이면 끝입니다. 중간에 새 글이 올라와도 밀리거나 겹치지 않습니다.
- `limit` 기본 20, 최대 50.
- 팔로우가 없으면 `FOLLOWING`은 빈 `items`로 옵니다 — 그때 안내와 전체 탭 전환 버튼을 보여주는 건 화면 쪽입니다(티켓 `-123` 완료 기준).

## 오류

못 보는 기록(없음·지움·나만 보기·팔로워 전용·공개 전)은 전부 404 `STORY_NOT_FOUND`로 같은 응답입니다. 보이는 기록을 남이 고치거나 지우면 403 `STORY_FORBIDDEN`. 자기 팔로우는 400 `FOLLOW_SELF`, 없는 사용자는 404 `USER_NOT_FOUND`. 깨진 커서는 400 `FEED_CURSOR_INVALID`.

좋아요·댓글·신고는 이번에 없습니다. 좋아요를 화면에서 뺀 상태 그대로 두시면 맞습니다.
