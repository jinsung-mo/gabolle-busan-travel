소셜로만 가입한 사람이 **계정을 지울 방법이 하나도 없었습니다.** 서버를 고쳤고, 탈퇴 화면을 붙일 때 쓸 계약을 드립니다. MR !598 (`back/dev`).

## 무엇이 막혀 있었나

탈퇴 경로가 본문에 비밀번호를 **필수**로 받고 있었습니다. 그런데 소셜 가입은 비밀번호를 아예 안 만듭니다 — 가입 완료 요청에 이메일·비밀번호 칸 자체가 없습니다. 그래서 소셜 계정은 비우고 보내면 400, 아무 값이나 넣으면 409 였습니다. 비밀번호 재설정으로 하나 만들어 보는 우회로도 없습니다(재설정 표가 비밀번호 자료에 매달려 있어 시작조차 안 됩니다).

앱에 탈퇴 화면이 아직 없어서 지금까지 드러나지 않았습니다.

## 새 계약

```
DELETE /api/v1/auth/me
Authorization: Bearer <access token>
Content-Type: application/json

{ "confirmation": "DELETE", "password": "…있는 사람만…" }
```

성공하면 **204, 본문 없음**입니다.

| 칸 | 필수 | 설명 |
| --- | --- | --- |
| `confirmation` | 예 | 사용자가 입력창에 직접 친 값. 서버가 `"DELETE"` 와 **정확히** 비교합니다 |
| `password` | 아니오 | 비밀번호로 가입한 계정만. 안 보내도 되고, 보냈으면 맞아야 합니다 |

🔴 **`confirmation` 을 화면이 자동으로 채워 보내지 말아 주세요.** 그러면 확인이 아니라 형식이 됩니다. 사용자가 실제로 타이핑한 값을 그대로 보내 주세요.

🔴 **대소문자와 앞뒤 공백을 서버가 그대로 봅니다.** `delete` · `Delete` · `DELETE `(뒤 공백) 전부 거절입니다. 입력값을 다듬지 말고 그대로 보내시되, 버튼 활성화 판정은 화면에서 같은 기준으로 해 주시면 사용자가 400 을 먼저 만나지 않습니다.

## 오류

| 상태 | 코드 | 언제 | 화면에서 |
| --- | --- | --- | --- |
| 400 | `INVALID_REQUEST` | `confirmation` 을 안 보냄 | 입력창 비어 있음 — 버튼을 잠가 두면 안 납니다 |
| 400 | `DELETION_NOT_CONFIRMED` | 값이 다름 | "입력한 값이 달라요" |
| 400 | `PASSWORD_NOT_SET` | 비밀번호 없는 계정에 비밀번호를 보냄 | 비밀번호 칸을 애초에 안 그리면 안 납니다 |
| 401 | `INVALID_CREDENTIALS` | 비밀번호가 틀림 | "비밀번호가 올바르지 않아요" |
| 401 | `ACCOUNT_UNAVAILABLE` | 이미 지운 계정 | 로그인 화면으로 |

## 비밀번호 칸을 그릴지 말지

계정에 비밀번호가 있는지는 지금 조회 응답으로 알 수 없습니다. 두 가지 방법이 있는데 **뒤엣것을 권합니다.**

* 비밀번호 칸을 항상 그린다 → 소셜 사용자가 넣을 게 없어 혼란스럽습니다
* **비밀번호 칸을 아예 안 그리고 확인 값만 받는다** → 두 종류 계정이 같은 화면을 씁니다. 서버가 비밀번호를 필수로 안 보므로 이걸로 충분합니다

비밀번호 칸이 꼭 필요하시면 말씀해 주세요 — 조회 응답에 "비밀번호가 있는 계정인가" 한 칸을 더하겠습니다. 지금은 안 넣었습니다.

## 탈퇴 전 안내 화면

이미 있는 것을 씁니다 — `GET /api/v1/auth/me/deletion-preview` 가 지워질 여행 수·일정 수·기록 수를 줍니다. 이 숫자는 실제로 지워지는 것과 같은 기준으로 셉니다.

## 🔴 알고 계셔야 할 것

**되돌릴 수 없습니다.** 여행·일정·기록이 함께 사라지고 계정은 익명화됩니다. 그래서 확인 입력을 한 겹 두는 것이고, 화면에서도 무엇이 사라지는지(위 미리보기 숫자) 먼저 보여 주시는 게 맞습니다.

탈퇴 직후에는 가지고 있던 접속 표가 아직 30분 유효합니다. 서버가 두 번째 탈퇴는 막지만, 다른 경로는 그 표로 잠깐 더 불릴 수 있으니 **성공하면 화면에서 세션을 지우고 로그인 화면으로 보내 주세요.**
