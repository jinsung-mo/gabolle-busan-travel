## 각자 한 번만 해 주세요

  git lfs install

안 하면 bigData/data/raw/transit/*.ndjson 이 133바이트짜리 이상한
텍스트 파일로 보입니다. 그게 포인터입니다. 파일이 깨진 게 아닙니다.

## 왜 규칙을 예외 처리했나

bigData/.gitignore 는 data/ 를 통째로 막습니다. 그 규칙은 여전히 맞습니다 —
OSM 285MB 는 collect/ 가 언제든 다시 만드니까 git 에 넣을 이유가 없습니다.

이 파일들만 다릅니다. BIMS 는 소급 수집이 안 됩니다. 지나간 시각의 버스
위치는 어떤 스크립트로도 못 만듭니다. 폴링 480회 2,400건이 노트북 한 대에만
있었고 그 노트북이 꺼지면 사본이 없었습니다.

다시 만들 수 있는 것과 없는 것을 같은 규칙으로 다루면 안 된다 — 그게 예외의
근거 전부입니다.

## 규칙 자체는 안 뒤집었습니다

.gitignore 는 그대로 두고 git add -f 로 넣었습니다. 한 번 추적되면 .gitignore
와 무관하게 따라오므로, 재포함 패턴(data/* !data/raw/ ...)을 쓰는 것보다
사고가 적습니다. 즉 앞으로도 실수로 data/ 를 통째로 add 하는 일은 안 생깁니다.

## LFS 를 고른 이유는 크기가 아니라 clone 입니다

평범한 커밋이면 59MB 가 이력에 영구히 박히고, 빼려면 전원이 다시 clone 해야
합니다. LFS 는 이력에 포인터만 남깁니다 — 인덱스에 실제로 들어간 것은 파일당
133바이트입니다. 한 달치가 쌓여도 새로 clone 하는 사람은 현재 것만 받습니다.

## 앞으로 주의할 것

.gitattributes 의 -text 를 지우지 마세요. 루트의 `* text=auto eol=lf` 가 이
파일에도 걸리면 체크아웃 때 줄바꿈을 바꿔 쓰고, 내용이 달라지면 LFS 해시가
어긋납니다. 같은 함정을 이 저장소에서 이미 세 번 밟았습니다.
