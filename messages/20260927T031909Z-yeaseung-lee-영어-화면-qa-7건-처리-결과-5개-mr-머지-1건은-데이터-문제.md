subject: 영어 화면 QA 7건 처리 결과 — 5개 MR 머지, 1건은 데이터 문제

지혁 님, QA 주신 7건을 봤습니다. 모두 dev 에 머지했고 배포는 아직입니다.

1. 공유 페이지(/s/토큰)가 한국어로만 열림 → 브라우저 언어를 따르고, 화면 위에서 다섯 언어 중 고를 수 있게 했습니다. (S15P21E201-1777, MR !1784)
2·3. 팔로우한 뒤 팔로잉 피드가 한참 「없어요」로 남고, 글을 쓴 뒤 내 피드에 바로 안 뜸 → 원인은 앱의 목록 보관소(30초 동안 받은 목록을 다시 쓰는 곳)였습니다. 팔로우하거나 글을 쓰면 해당 목록을 비우게 했습니다. (1778, !1785)
4. 기록 달력 → 날짜는 동그라미 안에 넣었습니다. 고른 날은 채운 동그라미, 오늘은 테두리이고, 둘이 같은 날이면 채움 하나만 보입니다. 기록 표시(점·개수·작은 사진)는 숫자 아래 줄로 옮겼습니다. 사진이 있는 날은 확인하지 못했습니다. (1779, !1786)
5. 생성된 일정의 장소 이름이 한국어로만 나옴 → 코드 문제가 아닙니다. 영어 이름이 있는 장소는 이미 영어로 나옵니다. 제 계정의 일정 장소 4곳(카페·식당 등)은 DB 에 영어 이름이 없어서 한국어 옆에 로마자로 나옵니다. 영어 이름을 채울지는 데이터·제품 쪽에서 정해야 합니다.
6. 여행 이름 후보가 한국어로만 나옴 → 서버가 언어를 보지 않고 있었습니다. 이제 영어 화면이면 장소의 영어 이름으로 영어 후보를 냅니다. 영어 이름이 없는 장소는 한국어 이름을 씁니다. 영어일 때는 AI 모델을 부르지 않습니다. 모델이 지어낸 장소 이름을 거르는 검사가 한글만 보기 때문입니다. (1780, !1788)
7. 출발지·숙소 검색이 한국어로만 나옴 → 두 칸은 카카오 검색(한국어만)을 쓰고, 꼭 갈 곳은 우리 장소 목록을 씁니다. 그래서 영어 화면에서는 우리 목록도 같이 불러 같은 장소의 영어 이름을 붙이게 했습니다. 예를 들면 「Haeundae Beach (해운대해수욕장)」입니다. 우리 목록에 없는 곳은 로마자로 나옵니다. (1781, !1787)
