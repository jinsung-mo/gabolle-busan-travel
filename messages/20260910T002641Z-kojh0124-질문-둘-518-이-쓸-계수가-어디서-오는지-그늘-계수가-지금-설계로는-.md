## 1. 518 이 말하는 "앞 스토리" 가 제 쪽 -23 인가요

518 설명에 *"앞 스토리에서 나온 계수를 쓴다"* 고 되어 있습니다. 그런데 계수를 실제로 추정하는 코드는 제가 `S15P21E201-23` 으로 만들어 둔 쪽에 있습니다 — `bigData/process/choice-fit.mjs` (조건부 로짓, back/dev 에 이미 있습니다).

`-23` 은 에픽 511 밖에 있어서, 두 가지 중 어느 쪽인지 모르겠습니다.

- (a) 511 안에 계수를 뽑는 스토리를 따로 두실 계획이었다 → 그러면 **계수 출처가 둘**이 되고, 최적화 엔진이 어느 쪽을 써야 하는지 정해야 합니다
- (b) `-23` 이 그 "앞 스토리" 다 → 그러면 링크만 걸어 두면 되고 제가 이어서 하겠습니다

저는 (b) 라고 보지만 511 은 효준 님 에픽이라 제가 정할 일이 아닙니다.

## 2. 🔴 지금 설계로는 **그늘 계수가 안 나옵니다** — 이게 급합니다

518 의 완료 기준이 *"그늘 비용을 켠 일정과 끈 일정이 실제로 달라진다"* 입니다. 그런데 짝 비교 문항이 재는 속성은 넷뿐입니다 (`bigData/process/choice-design.mjs`).

```js
walkMin    [8, 12, 18, 25]
slopePct   [0, 5, 10, 15]
stairs     [0, 20, 50, 100]
transfers  [0, 1]
```

`choice-design.mjs` · `choice-fit.mjs` 둘 다 **그늘이라는 말이 한 번도 안 나옵니다.** 즉 지금 상태로 현장에 나가면 경사·계단 계수는 얻고 **그늘 계수는 못 얻습니다.** 518 이 가장 필요로 하는 그 하나가 빠집니다.

선택지는 둘로 보입니다.

| | 내용 | 비용 |
|---|---|---|
| **A. 속성을 다섯으로 늘린다** | 짝 비교에 그늘(예: 응달 비율 0·30·60·90%)을 넣는다 | 지금은 파일 한 곳 고치는 일. **나간 뒤에는 2차 조사가 필요합니다** |
| B. 그늘만 손으로 정한다 | 계수를 사람이 박고 "이것만 추정 안 된 값" 이라고 적어 둔다 | 공짜지만 518 의 근거가 약해집니다 |

문항이 12개인데 속성을 하나 늘리면 추정에 필요한 표본도 늘어납니다(`choice-fit.mjs` 의 게이트가 `관측 ≥ 속성수 × 20` 이라 80 → 100). 하루 30명 × 12문항 = 360관측이면 여전히 넉넉합니다.

**A 를 권합니다.** 다만 문항 설계는 효준 님 에픽의 완료 기준과 직결되니 결정만 주시면 제가 `choice-design.mjs` 에 넣겠습니다.

## 3. 시각별 비용은 문제없습니다 (참고)

518 의 *"같은 구간도 오전 9시와 오후 3시가 다르다"* 는 계수를 시각별로 만들 필요가 없습니다. **계수는 하나, 피처가 시각에 따라 변하면** 됩니다.

```
비용 = β_그늘 × 응달노출(구간, 시각)
```

해가 움직이니 같은 구간의 응달 비율이 시각마다 달라지고, 그것만으로 조건이 충족됩니다. 배치가 구간 × 시간대로 응달 값을 내주면 됩니다.
