## 🔴 이건 장효준 님이 담지 않겠다고 적으신 항목입니다

어제 [Haiku 조사] 쪽지의 「담지 않는 것」 표에 이렇게 있습니다.

> | 안 담는 것 | 왜 |
> |---|---|
> | 다른 앱의 별점 숫자 | **약관 위반입니다** |

**설계가 잘못된 게 아닙니다.** 별점 칸을 만드신 적이 없고, `descriptors` 가 자유 서식이라 **조사원(AI)이 거기에 적어 넣은 것**입니다. 그래서 스키마만 보면 안 보이고, 파일 안을 봐야 나옵니다 — 어제 흠 둘을 스스로 적어 두신 것과 같은 종류(지시문 밖으로 새는 것)로 보입니다.

## 어떻게 찾았나 (다시 재실 수 있게)

```bash
BASE=$(git merge-base origin/main origin/bigData/main)
git diff --name-only $BASE origin/bigData/main | grep 'research/data/results/' | while read -r f; do
  git cat-file -p "origin/bigData/main:$f" \
    | grep -oiE '[0-9]\.[0-9]/5|[0-9]+명 평가|Daco [0-9]+점|평점' | head -1 \
    | sed "s|^|$f :: |"
done
```

→ 163개 파일. 예시 25개를 이 쪽지 끝에 붙입니다.

## 제 의견 — 막을 일은 아니고, 들이기 전에 지울 일로 봅니다

보안 구멍이 아니라 **약관 문제**입니다. 그래서 저는 반대표를 던지지 않았습니다 — 반대표는 정족수 계산에 안 들어가고 판정문에만 보이는데, 이건 숫자로 막을 게 아니라 **고치면 끝나는 일**이라 글로 드리는 게 맞다고 봤습니다.

정리는 어려워 보이지 않습니다.

1. `descriptors.rating` 키를 지운다 (163개 중 별점이 이 칸에 있는 것)
2. 남은 자유 문장에서 `평점`·`N.N/5`·`N명 평가`·`Daco N점` 을 훑어 지운다
3. 지시문에 「별점·리뷰수는 적지 마라」를 넣는다 — 안 넣으면 다음 조사분에 또 쌓입니다

**지우고 다시 올려 주시면 바로 표 던지겠습니다.** 나머지는 깨끗했습니다 — 충돌 0, 잡 14개 → 14개로 CI·거버넌스 무변경, 하드코딩 비밀값 없음, 네이버·카카오 이름이 든 파일도 없었습니다.
