S15P21E201-773 에픽 정리 중 S15P21E201-827(안드로이드 에뮬레이터에서 API 요청이 서버에 안 닿는 버그)의 원인을 짐작이 아니라 확정으로 좁혔습니다. S15P21E201-815(운영 서버 도메인 장기 안정성, 담당자 확인 필요로 남겨져 있던 그 티켓)와도 바로 연결됩니다.

**실측** — `openssl s_client -showcerts`로 `j15e201.p.ssafy.io`의 인증서 체인을 직접 봤습니다:

```
리프 인증서 → Let's Encrypt "YE2" → "Root YE" → ISRG Root X2
```

오래 전부터 모든 기기·OS가 신뢰하는 RSA 루트 **ISRG Root X1**으로의 교차서명 경로가 체인에 없습니다 — 지금 서버는 ECDSA 전용 체인만 내려주고 있습니다.

**왜 이게 에뮬레이터에서만 터졌나** — ISRG Root X2는 비교적 최근(2021년 이후) 루트라, 안드로이드에서는 Google Play 시스템 업데이트(Mainline)로 CA 저장소가 갱신돼야 신뢰됩니다. 이 업데이트는 **Play 스토어가 포함된 이미지에서만** 동작합니다. 재현에 쓴 두 에뮬레이터(BlueStacks, `avdmanager`로 만든 `google_apis` — `google_apis_playstore`가 아님) 모두 이 경로가 없어 이미지 빌드 시점 CA 저장소에 고정돼 있었고, 그 시점에 X2가 없었다면 TLS 핸드셰이크 자체가 실패합니다. 크롬(자체 Root Store, 2022년부터 OS와 독립)과 PC의 curl(PC 자체의 최신 저장소)은 둘 다 성공해서 "브라우저·PC는 되는데 앱만 안 됨"이라는 증상과 정확히 맞습니다. 실기기는 보통 Play 스토어가 있어 재현 안 될 가능성이 높습니다 — S15P21E201-827의 "실기기 확인" 완료 기준과도 맞아떨어집니다.

**필요한 조치** — 서버(EC2)의 certbot/nginx 설정에서 RSA 체인(ISRG Root X1으로 교차서명)을 우선 제공하도록 바꾸는 것입니다. certbot 기준으로는 `--preferred-chain "ISRG Root X1"` 옵션 하나입니다. 이건 운영 중인 서버의 TLS 설정을 직접 건드리는 일이라 제가 자동으로 진행하지 않았습니다 — 서버 접근 권한이 있으신 분이 진행해 주시면 좋겠습니다.
