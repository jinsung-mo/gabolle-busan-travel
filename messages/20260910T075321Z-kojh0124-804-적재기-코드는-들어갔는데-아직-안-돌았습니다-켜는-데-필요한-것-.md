## 2. 왜 안 돌았나 — 설계대로입니다

`ResearchPlaceLoaderRunner` 가 이렇게 걸려 있습니다.

```java
@Component
@Profile({ "db", "dev" })
@ConditionalOnProperty(name = "gabolle.place.loader.research-queue")
public class ResearchPlaceLoaderRunner implements ApplicationRunner {
```

**속성이 없으면 빈 자체가 안 만들어집니다.** 이건 잘 잡으신 것 같습니다 — 기동마다 다시 적재되거나 실수로 도는 일이 없습니다. 다만 **누군가 한 번은 일부러 켜야** 합니다.

## 3. 켜는 데 필요한 것 셋

| | 무엇 | 누구 |
|---|---|---|
| ① | `gabolle.place.loader.research-queue` = 큐 파일 경로 | 배포 설정 |
| ② | (선택) `gabolle.place.loader.dataset-version` | 배포 설정 |
| ③ | 🔴 **큐 파일이 backend 컨테이너 안에 있어야 한다** | 아래 |

**③ 이 남은 진짜 문제입니다.** 조사 결과(2,356건)는 `bigData/dev` · `bigData/main` 에만 있습니다 — `back/dev` 와 `main` 에는 **0건**입니다. 그리고 backend 컨테이너에는 그 파일도, 그걸 볼 마운트도 없습니다.

```
조사 JSON (bigData/dev) → ⛔ 서버에 파일이 없다 → 적재기(있음, 꺼짐) → place → 후보 → 일정
```

속성만 켜면 파일을 못 찾아서 기동에서 죽거나 0건을 읽습니다. 어느 쪽이든 파일을 먼저 옮겨야 합니다.

## 4. 물어보고 싶은 것 — 파일을 어떻게 넣으실 생각인가요

제가 정할 일이 아니라 선택지만 적습니다.

* **(가) 배포 때 복사** — Jenkins/compose 가 `bigData` 산출물을 backend 컨테이너로 넣는다. 파트 경계를 넘는 마운트가 하나 생깁니다
* **(나) 이미지에 굽는다** — 데이터가 이미지에 들어갑니다. 조사가 끝났으니 자주 안 바뀌긴 합니다
* **(다) 한 번만 손으로** `docker cp` 하고 켠 뒤 다시 끈다 — 지금 가장 빠릅니다. 다만 다음 배포에서 사라집니다
* **(라) 적재기를 안 쓰고 SQL 로 한 번** — 적재기의 검증·중복 처리를 못 씁니다. 안 권합니다

재현 님이 (다) 로 이미 돌리셨다가 컨테이너가 다시 떠서 날아간 것일 수도 있겠습니다 — backend 는 오늘 06:17 UTC 에 재시작됐습니다. 그랬다면 그것도 알려 주십시오.

## 5. 왜 지금 이게 급한가

**이 저장소에서 일정이 한 번도 성공한 적이 없습니다.** 추천 요청 3건이 전부이고, 셋 다 09-07 에 `ENGINE_NOT_CONFIGURED` 로 1ms 만에 죽었습니다.

그 엔진 쪽은 지금 괜찮아 보입니다 — `BaselineEngineStartupValidator` 가 배포된 jar 안에 있고(클래스 확인), 앱이 오늘 재시작 뒤 예외 없이 떠 있습니다. 그 검사기는 엔진 빈이 없으면 **기동을 실패시키는** 것이 목적이니, 떠 있다는 건 엔진이 배선됐다는 뜻입니다.

그러면 남은 것은 **랭킹할 장소가 없다**는 것뿐입니다. `place=0` 이면 후보가 0건인 게 당연합니다.

**그래서 순서가 이렇게 보입니다.** ③ 파일 → ① 속성 → 재시작 → **누구든 일정 생성 한 번** → `place` 가 0→2,355, 후보가 0→N.

그 한 번이 도는 순간, 오늘까지 아무도 답한 적 없는 질문 하나가 처음 답이 됩니다 — 추천 경로가 끝까지 도는가.
