# 1. 왜 제가 하면 안 되는가

표를 셀 때 규칙이 하나 있습니다.

> **어떤 변경에 커밋한 사람은, 그 변경에 투표할 수 없다.**
> (자기가 올린 것을 자기가 승인하는 것을 막는 규칙입니다. 코드로는 `ci/axmap/src/governance.mjs` 673번째 줄입니다.)

제가 커밋해 버려서 **제 표가 무효**가 됩니다. 그러면 이렇게 됩니다.

| 사람 | 투표권자인가 | 이 변경에 던질 수 있나 |
|---|---|---|
| 장효준 (저) | 예 | **아니오 — 제가 커밋했으므로** |
| 박재현 | 예 | 예 — **그런데 오늘 안 계십니다** |
| 이예승 | 예 | 예 |
| 진미리 | 아직 아니오 | 아니오 |

**필요한 표는 2장인데 오늘 던질 수 있는 사람은 이예승 님 한 분뿐**입니다. 박재현 님을 기다려야 합니다.

## 진미리 님이 커밋하시면

배제되는 사람이 진미리 님이 되는데, **진미리 님은 어차피 아직 표가 없으므로 잃는 것이 없습니다.**

| 사람 | 던질 수 있나 |
|---|---|
| 장효준 | **예** |
| 이예승 | **예** |
| 박재현 | 예 (안 계셔도 됩니다) |

**저와 이예승 님 두 사람이 던지면 오늘 통과합니다.**

> 혹시 "내 투표권을 내가 올리는 게 이상하지 않나" 하고 걸리실까 봐 적습니다.
> **이상하지 않습니다.** 진미리 님은 이 변경에 투표할 수 없고, 승인은 전적으로 다른 두 사람이 합니다. 제도가 요구하는 검증은 그대로 다 지납니다.

# 2. 무엇을 하시면 되나 — 명령어 그대로

## 0단계. 선점 (파일을 고치기 전에 하는 선언)

제가 방금 반납했으니 지금 비어 있습니다.

```
node ci/axmap/bin/axmap.mjs claim governance/policy.json --task S15P21E201-33 --intent "진미리를 main 의 투표권자 명단에 올린다"
```

## 1단계. 브랜치 만들기

```
git fetch origin
git checkout -b hotfix/S15P21E201-33-jinmiri-voter origin/main
```

> **왜 `hotfix/` 로 시작하나** — 이 저장소는 브랜치를 사다리처럼 한 칸씩 올라가는데, `hotfix/` 로 시작하는 브랜치만 최상위 `main` 으로 바로 갈 수 있습니다. 지금 정상 경로(`common/dev` → 위로)가 막혀 있어서 이 문을 씁니다. **공짜 통과가 아닙니다** — 표는 그대로 2장 필요합니다.

## 2단계. 파일 내용 가져오기 — 손으로 치지 마세요

이미 `common/dev` 에 들어가 있는 파일을 **그대로 복사**하는 것이 가장 안전합니다. 오타가 날 자리가 없습니다.

```
git cat-file -p origin/common/dev:governance/policy.json > governance/policy.json
```

확인:

```
git diff --stat
```

`governance/policy.json | 4 +++-` 처럼 **파일 하나, 3줄 추가 1줄 변경**이 나오면 맞습니다.

## 3단계. 커밋

메시지를 파일로 만들어서 쓰시는 게 편합니다.

```
git add governance/policy.json
git commit -m "[S15P21E201-33] chore: [Common] 진미리를 main 의 투표권자 명단에 올린다"
```

> 🔴 **맨 앞의 대괄호 번호는 정확히 적어 주세요.** 그래야 티켓에 자동 연결됩니다.

## 4단계. 올리기

```
git push -u origin hotfix/S15P21E201-33-jinmiri-voter
```

## 5단계. 반납

```
node ci/axmap/bin/axmap.mjs release
```

# 3. 병합 요청(MR) 을 여실 때

push 하시면 터미널에 링크가 나옵니다. 없으면 이 주소입니다.

```
https://lab.ssafy.com/s15-bigdata-dist-sub1/S15P21E201/-/merge_requests/new?merge_request%5Bsource_branch%5D=hotfix%2FS15P21E201-33-jinmiri-voter&merge_request%5Btarget_branch%5D=main
```

**대상 브랜치가 `main` 인지 꼭 확인해 주세요.**

## 제목 (그대로 붙여넣기)

```
[S15P21E201-33] chore: [Common] 진미리를 main 의 투표권자 명단에 올린다
```

## 설명 (그대로 붙여넣기)

```markdown
## 무엇을

`governance/policy.json` 의 투표권자 명단에 진미리를 추가한다.

    { "id": "jinmiri", "email": "wlsalfl321@naver.com" }

내용은 `common/dev` 의 파일을 그대로 가져온 것이다. 새로 쓴 것이 없다.
팀이 이미 MR !22 에서 본 파일과 같다.

## 왜 사다리를 건너뛰나

`common/dev` 를 `main` 으로 올리는 경로가 막혀 있다. 표가 모자란 것이
아니라 **던질 수 있는 사람이 모자란다.**

    main 대비 common/dev 의 커밋 저자 : 장효준(19) · 이예승(4)
    자기 표 배제로 둘 다 무효
    main 정책의 투표권자 3명 중 던질 수 있는 사람 : 박재현 1명
    필요한 표 : 2장

판정 프로그램을 실제로 돌려서 확인한 숫자다. 자세한 것은 axMap 쪽지
"[실측] common/dev 는 지금 main 으로 승격할 수 없습니다" 에 있다.

이 브랜치는 커밋이 하나뿐이라 자기 표 배제에 저자 한 명만 걸린다.
**표를 면제받는 것이 아니다** — 정족수 2표는 그대로 요구된다.

## 이 이메일인 근거

팀 안에서는 `ssafy0121@gmail.com` 으로 알려져 있었으나, git 이력에 실제로
찍힌 저자 이메일은 `wlsalfl321@naver.com` 이다(커밋 7건, 실측). 본인 확인도
받았다(2026-08-27 쪽지 2건).

표는 커밋 저자 이메일 완전일치로만 세어지므로, 알려진 쪽을 넣었다면 이 사람은
한 표도 못 던지고 **본인은 그것을 모른다.** 그래서 근거를 파일 안에 주석으로
남겼다.
```
