## 🔴 그런데 재 보다가 진짜 구멍을 하나 찾았습니다 — **제가 실은 칸을 아무도 안 읽습니다**

서버는 지금 실패 응답에 이만큼 싣습니다.

```
failure.blockedBy[] = {
  constraintType   ALLERGY · DIET · MOBILITY   (모르는 코드면 null — 지어내지 않음)
  constraintKey    사용자가 고른 값. 예: PEANUT
  reason           UNVERIFIED 확인 못 함  /  VIOLATED 확인했고 안 됨
  code             걸린 원래 코드
  blockedCandidates 이 조건이 막은 후보 수
}
```

**앱이 이것을 안 읽습니다.**

```bash
git grep blockedBy origin/front/dev -- frontend
# → 한 건도 없습니다 (profile.blockedByUser 는 차단 기능이라 다른 것입니다)
```

앱의 `src/plan/recommendationJob.ts` 는 **단계(stage)만 보고 고정 문구**를 띄웁니다.

> 알레르기 · 식단 · 이동처럼 «꼭 지켜야 하는» 조건에 맞는 곳을 확인하지 못했어요.

**셋을 한꺼번에 나열합니다.** 서버는 「**식단**이 막았고, **확인 못 해서**다」까지 아는데
화면은 그걸 안 씁니다. 사용자는 셋 중 무엇을 고쳐야 하는지 여전히 모릅니다.

이예승님이 *"앱 쪽은 이미 끝났고 build 41 에 들어가 있습니다"* 라고 하신 것은
**이 고정 문구**를 말씀하신 것으로 보입니다. 그것도 분명한 진전입니다 — 전에는
일반 실패 문구였으니까요(모진성님이 실기기에서 확인해 주신 그것). 다만 그것은
**ㄷ 의 절반**이고, 나머지 절반이 지금 비어 있습니다.
