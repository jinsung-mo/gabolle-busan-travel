인자: $ARGUMENTS (비워도 된다)

## 이 명령이 있는 이유

**지금은 표가 기다리고 있다는 것을 알 방법이 없다.** 브랜치를 올린 사람이
쪽지로 부탁하는 수밖에 없고, 그 쪽지를 놓치면 아무도 모르는 채로 멈춰 있는다.

이 명령은 **보기만 한다. 아무것도 던지지 않는다.** 던지는 것은 `/ax-vote` 다.

## 무엇을 보나

### 1. 재료를 모은다

```bash
git fetch origin --quiet
git ls-remote --heads origin                       # 지금 살아 있는 브랜치
git ls-tree -r --name-only origin/axmap/votes      # 이미 던져진 표
```

표는 `votes/<브랜치>/<이름>-<커밋앞8자>.json` 으로 쌓인다. 경로에서 브랜치 이름이
바로 읽힌다.

### 2. 후보를 고른다

정족수를 요구하는 것은 **받는 쪽이 `main` 또는 `func` 로 끝나는 MR** 뿐이다
(`.gitlab-ci.yml` 의 `governance` 잡). `dev` 로 가는 것은 표가 필요 없다.

그래서 볼 것은 둘이다.

- `hotfix/…` 로 시작하는 원격 브랜치 — 최상위 `main` 으로 바로 갈 수 있는 것
- `<파트>/dev` · `<파트>/main` — 한 칸 위로 올라갈 차례인 것
- 그리고 **이미 표가 하나라도 던져진 브랜치** — 진행 중이라는 뜻이다

### 3. 각각을 판정한다

```bash
npx -y axmap-cli@latest gate --source <브랜치> --target origin/main
```

> 🔴 `--target origin/main` 으로 준다. 그냥 `main` 이라고 하면 판정 프로그램이
> **낡은 로컬 브랜치**를 보고 *"정책 파일이 없다 — 판정 불가"* 라는 틀린 답을 낸다.
> 알려진 버그다.

> 🔴 **`--source` 에는 `origin/` 을 붙이지 않는다. 붙이면 표가 0장으로 세어진다.**
>
> 표 파일은 `votes/<브랜치>/…` 에 쌓이는데, 게이트가 소스 이름을 **그대로** 경로에
> 넣는다. `origin/` 을 붙이면 `votes/origin/<브랜치>/…` 를 뒤지고 거기엔 아무것도 없다.
>
> **두 인자의 규칙이 서로 반대라서 특히 잘 틀린다** — `--target` 에는 붙여야 하고
> `--source` 에는 붙이면 안 된다. 사람은 둘에 같은 규칙을 적용한다.
>
> 실측 (같은 커밋 · 같은 표):
>
> ```
> --source origin/hotfix/… --target origin/main   →  표 0장 · 합의 미달 · 종료 코드 2
> --source hotfix/…        --target origin/main   →  표 2장 · 합의 충족 · 종료 코드 0
> ```
>
> 종료 코드가 **2**(= "사람이 아직 안 눌렀다, 정상 상태")로 나오는 것이 고약하다.
> 이미 다 모인 표를 없다고 하므로, 읽는 사람은 **이미 던진 사람에게 또 부탁하러 간다.**
> 통과가 잘못 나가지는 않지만 **정상 상태를 고장으로 보고한다.**

> 🟢 **판정 전에 표 브랜치를 받아 둔다.** 안 받아온 상태에서도 0장으로 나온다.
>
> ```bash
> git fetch origin refs/heads/axmap/votes:refs/remotes/origin/axmap/votes
> ```


## 어떻게 보여주나

브랜치마다 이렇게 정리한다. **기호만 쓰지 말고 뜻을 앞에 적는다.**

```
표를 기다리는 브랜치 1건

  hotfix/S15P21E201-33-jinmiri-voter          1표 / 2표 필요
    바꾸는 것 : governance/policy.json 3줄 — 진미리를 투표권자 명단에 추가
    올린 사람 : jinmiri <wlsalfl321@naver.com>
    던진 사람 : rleaderjoon
    내가 던질 수 있나 : 예
```

**"내가 던질 수 있나" 를 반드시 판정해서 넣는다.** 이것이 이 명령의 핵심이다.

셋 중 하나다.

| 답 | 언제 |
|---|---|
| **예** | 투표권자이고, 그 브랜치에 커밋한 적이 없다 |
| **아니오 — 내가 커밋했다** | 자기 표는 세지 않는다. 다른 사람을 찾아야 한다 |
| **아니오 — 투표권자가 아니다** | `main` 의 `governance/policy.json` 명단에 없다 |

두 번째·세 번째면 **누가 던질 수 있는지**를 같이 말해준다. 그래야 사람이 다음
행동을 할 수 있다.

## 아무것도 없으면

`표를 기다리는 것이 없습니다` 한 줄로 끝낸다. 억지로 후보를 만들지 않는다.

## 막혀 있으면 그렇게 말한다

던질 수 있는 사람 수가 필요한 표보다 **적으면** 그 브랜치는 기다려서 풀리지
않는다. 그때는 숫자를 그대로 보여주고 **"이 브랜치는 표로 못 푼다"** 고 말한다.

긴 수명 브랜치(`<파트>/dev`)에서 자주 생긴다 — 오래 쌓을수록 그 브랜치에 커밋한
사람이 늘고, 그만큼 던질 수 있는 사람이 줄기 때문이다. 나가는 길은 커밋이 하나뿐인
`hotfix/…` 브랜치로 그 변경만 따로 올리는 것이다.
