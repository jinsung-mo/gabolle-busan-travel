## 0. 용어

| 말 | 뜻 |
|---|---|
| **짝 비교**(paired comparison) | *조건이 다른 두 가지를 나란히 놓고 하나를 고르게 하는 것.* 12번 반복하면 각 조건에 얼마나 무게를 두는지 역산할 수 있다 |
| **함정 문항** | *한쪽이 모든 조건에서 분명히 나은 문항.* 여기서 나쁜 쪽을 고르면 안 읽고 찍은 것으로 본다 |
| **위치 편향** | *사람이 위(또는 왼쪽)에 있는 것을 더 고르는 성향.* 카드 순서를 문항마다 뒤집어서 나중에 빼낸다 |
| **응답 시간 구간** | *몇 초 걸렸는지를 초 단위가 아니라 "1.5초 미만 · 3초 미만 …" 같은 칸으로만 남기는 것* |

## 1. 🔴 올리기 전에 반드시 하는 것

`index.html` 맨 위의 `CONFIG` 세 칸을 채운다. **안 채우면 화면 맨 위에 빨간 줄이 뜬다** —
참여자에게도 보인다. 그게 안전장치다.

```js
const CONFIG = {
  facilitator: "(정해야 함 — 진행자 이름)",     // 응답 코드를 DM 으로 받을 사람 한 명
  deleteWhen:  "(정해야 함 — 언제 지우는지)",   // 고지문 문장 안에 그대로 들어간다
  contact:     "(정해야 함 — 문의 연락 방법)"
};
```

세 칸의 근거와 왜 이 문서가 지어내지 않았는지는
[설문 문서 7절](../docs/SURVEY-CONSENT.md#7-정해야-함--이-문서가-지어내지-않은-것)에 있다.

## 2. 화면이 지키는 것 — 지키지 않으면 결과가 조용히 틀린다

**① 문항을 손으로 적지 않는다.**
`index.html` 안의 `<script id="design">` 블록이 문항이고, 그걸 만드는 것은
[`design.mjs`](design.mjs) 다. 손으로 고치지 않는다.

```bash
node survey-place/design.mjs          # 문항 블록을 다시 쓴다
node survey-place/design.mjs --print  # 화면에만 찍는다
```

씨앗(seed)이 같으면 언제 돌려도 같은 12쌍이 나온다. **씨앗을 바꾸지 않는다** —
바꾸는 순간 앞 회차 응답과 뒤 회차 응답이 서로 다른 설문이 되어 합칠 수 없다.

**② 두 카드에 다른 색·크기를 주지 않는다.**
색이 다르면 사람은 눈에 띄는 쪽을 고르고, 그 편향은 취향과 분리할 방법이 없다.

**③ 위아래를 문항마다 무작위로 뒤집는다.**
그리고 **어느 쪽이 위였는지를 응답에 남긴다**(`topWas`). 남기지 않으면 나중에 위치
편향을 못 뺀다. 한 번 정해진 순서는 "이전 문항" 으로 돌아왔다 가도 안 바뀐다 —
바뀌면 방금 본 것과 달라져서 사람이 혼란스럽다.

**④ 카드에 가게 이름 · 사진 · 동네를 적지 않는다.**
적는 순간 사람은 조건이 아니라 브랜드를 고른다. 우리가 재려는 것은 조건의 무게다.

**⑤ 화면은 응답을 거르지 않는다.**
1초에 눌렀든 3분 걸렸든 그대로 적는다. 거르는 것은 나중에 계산하는 쪽이 한다 —
**거르는 기준은 바뀌지만, 안 받은 데이터는 못 만든다.**

**⑥ 자유 입력 칸이 하나도 없다.**
자유 입력은 사람이 스스로 신원을 적어 넣는 가장 흔한 경로다.

**⑦ 서버로 아무것도 보내지 않는다.**
`fetch` 도 이미지도 바깥 글꼴도 없다. 파일 하나가 전부다. 응답이 우리 손 밖으로
나가는 경로를 **아예 안 만든다.**

## 3. 응답 한 줄의 모양

완료 화면에 **JSON 한 줄**이 나온다. 참여자가 복사해서 진행자에게 DM 으로 보내거나,
`.ndjson` 파일로 내려받는다.

```jsonc
{
  "schema": "gabolle.survey.place.v1",
  "designId": "place-v1-seed-20260907",   // 어느 문항 세트에 답했나
  "nonce": "AG6JANJQVH",                  // 같은 응답이 두 번 들어왔는지만 본다. 사람을 가리키지 않는다
  "consented": true,                      // 누가 눌렀는지는 없다 — 그걸 남기면 익명이 깨진다
  "answeredOn": "2026-09-07",             // 🔴 날짜까지만. 시:분:초는 안 남긴다
  "durationMs": 214300,
  "spend": { "transport": "PRICE_FIRST", "stay": "KRW_50K_120K", "meal": "KNOWN_IN_AREA" },
  "spendSkipped": [],
  "choices": [
    { "setId": "s01", "chosen": 1, "topWas": 0, "msBucket": 3 }
    // chosen · topWas 는 문항 정의의 alternatives 색인(0 또는 1)이다
  ],
  "trap": { "setId": "tr01", "passed": true },
  "demographics": { "ageBand": "AGE_20_29", "companion": "FRIENDS", "tripsLastYear": "TRIPS_3_5" },
  "demographicsSkipped": []
}
```

| 왜 이렇게 | |
|---|---|
| **이름 · 연락처 · 기기 정보 · IP · 위치가 없다** | 애초에 안 받는다. 이 목록과 [설문 문서 1.2](../docs/SURVEY-CONSENT.md#12--안-모으는-것--이쪽이-더-중요하다) 가 어긋나면 **문서가 아니라 화면이 틀린 것이다** |
| **시:분:초를 안 남긴다** | 나이대 + 동행 + 정확한 시각을 합치면 좁은 집단에서는 한 사람으로 좁혀질 수 있다 |
| **응답 시간을 구간으로만 남긴다** | 안 읽고 찍은 응답을 거르는 데는 구간이면 충분하고, 초 단위는 그 이상을 알려준다 |
| **함정 문항이 `choices` 밖에 있다** | 취향을 재는 문항이 아니다. 계수 계산에 섞이면 안 된다 |
| **건너뛴 문항은 키가 없고 `*Skipped` 목록에 이름이 들어간다** | `null` 로 넣으면 "안 좋아한다" 와 "안 답했다" 가 같은 값이 된다 |

## 4. 🔴 응답을 어떻게 받을지가 아직 안 정해졌다

지금 화면은 **두 가지**를 낸다 — 화면의 글자(복사)와 `.ndjson` 파일(내려받기).
어느 쪽으로 받을지, 아니면 서버를 붙일지는 **팀이 정한다**
([설문 문서 7절 P6](../docs/SURVEY-CONSENT.md#7-정해야-함--이-문서가-지어내지-않은-것)).

| | **안 A — 글자를 DM 으로** (지금 기본) | **안 B — 파일을 DM 으로** | **안 C — 서버를 붙인다** |
|---|---|---|---|
| 참여자가 하는 일 | 복사 → DM 붙여넣기 | 내려받기 → DM 첨부 | 없음 (제출 버튼) |
| 진행자가 하는 일 | 한 줄씩 파일에 옮기고 DM 삭제 | 파일을 모아서 합치고 DM 삭제 | 없음 |
| 폰에서 되나 | ✅ | 🟡 브라우저마다 다르다 | ✅ |
| 응답이 우리 손 밖으로 | ❌ 안 나간다 | ❌ | 🔴 **나간다.** 서버 · 접근 권한 · 보관을 다 정해야 한다 |
| 손이 얼마나 가나 | 응답 30개면 견딜 만하다 | 중간 | 가장 적다 |
| **서버를 붙이면** | | | 🔴 [설문 문서](../docs/SURVEY-CONSENT.md) 의 5.1 · 5.3 을 **다시 써야 한다.** 지금 고지문이 *"서버로 아무것도 보내지 않습니다"* 라고 적고 있다 |

🔴 **앞선 설계 문서는 "코드 17자" 방식을 제안했다.** 답 전체를 짧은 글자 묶음으로
압축하고 검사합을 붙여 손으로 옮겨 적게 하는 방식이다. **이 화면은 그걸 안 썼다.**

| 왜 안 썼나 |
|---|
| 그 방식은 **해독기와 왕복 검사**가 짝이어야 한다. 지금 있는 해독기는 다른 설문(도보 경로)의 것이고 **이 설문의 문항 수·선택지 수가 달라서 그대로 못 쓴다** |
| 해독기 없이 압축 코드만 만들면 **응답이 조용히 어긋나도 아무도 모른다.** 현장에서 받아 온 코드가 해독이 안 되면 그날이 통째로 없어진다 |
| 여기서는 **손으로 옮겨 적지 않는다.** Mattermost 는 복사·붙여넣기가 되므로 짧게 만들 이유 자체가 약하다 |

코드 방식으로 가기로 하면 **해독기와 왕복 검사를 같이 만들어야 한다.** 화면만 만들면 안 된다.

## 5. 어디에 올리나

🔴 **[정해야 함]** — 배포 방법이 안 정해졌다
([설문 문서 7절 P5](../docs/SURVEY-CONSENT.md#7-정해야-함--이-문서가-지어내지-않은-것)).

파일 하나뿐이라 **정적 파일을 올릴 수 있는 곳이면 어디든** 된다.
바깥에서 아무것도 안 받아 오므로 인터넷이 끊겨도 첫 로딩만 되면 끝까지 답할 수 있다.

손으로 확인할 때:

```bash
node -e "const h=require('http'),f=require('fs');h.createServer((q,s)=>{s.writeHead(200,{'content-type':'text/html; charset=utf-8'});s.end(f.readFileSync('survey-place/index.html'))}).listen(8791)"
# → http://127.0.0.1:8791
```

🔴 **`file://` 로 열면 복사 버튼이 브라우저에 따라 막힌다.** 확인은 위처럼 주소로 연다.

## 6. 이 화면이 아직 안 하는 것

| 안 하는 것 | 왜 |
|---|---|
| 영어 화면 | 이번 표본은 SSAFY 한국인이다. 외국인 표본은 별도 계획이고, 그때 문항 번역이 같이 필요하다 |
| 응답 해독기 · 왕복 검사 | 압축 코드 방식을 안 썼기 때문 (4절) |
| 응답을 합치고 가중치를 계산하는 것 | 계산기는 `bigData` 파트에 이미 있다. **이 화면은 응답을 만드는 데까지다** |
| 중간에 껐다 다시 켰을 때 이어 하기 | 브라우저에 답을 저장해야 하는데, 저장하면 "제출 전에는 아무것도 저장되지 않습니다" 라는 고지가 거짓이 된다 |
| 접근성 검수 | 큰 글씨 · 대비는 신경 썼지만 화면 낭독기로 확인하지 않았다 |
