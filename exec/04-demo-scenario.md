# 4. 여행 만들기 시연 시나리오

시연 방식은 **앱에서 여행 만들기 1회**다. 로그인된 시연 계정과 네트워크를 준비하고, 시연 날짜에 실제로 선택 가능한 여행 날짜·출발지·장소를 미리 확인한다. 화면과 서버 응답은 시연 환경에서 아직 직접 확인하지 않았다.

| 순서 | 앱 화면과 조작 | 발표할 내용·확인할 결과 |
|---|---|---|
| 1 | 앱 실행 후 로그인. 홈의 여행 계획 시작 영역에서 **출발지, 날짜, 인원**을 정하고 **일정 물어보기**로 진행한다. | 한 번 입력한 기본 정보가 다음 여행 조건 화면으로 이어진다. |
| 2 | 여행 조건 화면에서 **여행 범위, 총예산, 이동 수단, 여행 카테고리, 여행 기분, 이번 여행 이동 보조·짐, 꼭 가고 싶은 장소**를 순서대로 선택한다. 화면에 추가 질문이 나오면 시연 선택값에 맞게 답하거나 건너뛴다. | 선택한 조건을 요약 화면에서 다시 확인하고 필요하면 각 항목의 **수정**을 누른다. |
| 3 | **이 조건으로 일정 만들기**를 누른다. 생성 진행 화면에서 단계와 진행률을 보여 준다. | 생성 요청은 매번 새 작업 ID를 받는다. 아래 웹 예시 URL의 `jobId`를 재사용하지 않는다. |
| 4 | 완료된 승차권을 눌러 뒤집고 뒷면의 **일정 보기**를 누른다. 추천 코스가 나오면 하나를 고른 뒤 **해당 코스 일정 보기**로 이동한다. | 생성된 여행의 날짜별 장소와 동선, 예상 비용을 보여 준다. 추천 결과가 1개라면 그 1개를 연다. |
| 5 | 일정 화면에서 **순서 수정**을 누르고 장소 순서를 바꾼 뒤 **저장**한다. 필요하면 장소 제외 등 화면에 제공되는 편집을 1회 보여 준다. | 변경 후 일정이 반영됐는지 확인한다. 앱 소스에는 별도의 **「내 여행으로 확정」 버튼이 없다**. 이미 저장된 일정이므로 확정 버튼을 누른다고 설명하지 않는다. |
| 6 | 하단의 **내 여행**으로 이동해 방금 만든 여행을 찾고 연다. | 여기서 여행 만들기 시연을 마치고 내 여행 기능 발표로 넘긴다. |

## 웹 화면 대응 경로

- 홈·로그인·여행 만들기 진입: <https://j15e201.p.ssafy.io/>
- 기본 정보와 여행 조건: <https://j15e201.p.ssafy.io/plan>
- 여행 생성 진행: `/plan/generating?jobId=<이번 요청에서 새로 받은 ID>`
- 추천 코스와 일정: 앱 내부의 `/trips/<ID>/recommendations`, `/trips/<일정 ID>/itinerary` 화면

위 웹 주소는 화면 대응을 위한 참고 경로다. 제출자가 제공한 예시 `jobId=f1082660-119d-4606-9f38-53c8daad6386`은 과거 요청 식별자로 보이므로 시연 링크로 고정하지 않는다.

## 진행이 지연되거나 실패할 때

- 생성 중 시간이 길어지면 진행 화면의 상태를 설명한다. 앱의 **백그라운드에서 계속**을 사용할 수 있고 완성된 여행은 **내 여행**에서 확인한다.
- 생성 실패 안내가 뜨면 **조건 다시 확인하기**로 돌아가 입력과 네트워크를 점검한다. 성공한 것처럼 다음 단계로 넘기지 않는다.
- 생성은 1회만 수행한다. 발표 중 재시도를 실제로 했다면 시연 횟수와 이유를 명확히 말한다.

근거 화면: `frontend/app/(tabs)/home.tsx`, `frontend/app/(plan)/questions.tsx`, `frontend/app/(plan)/generating.tsx`, `frontend/app/trips/[id]/recommendations.tsx`, `frontend/app/trips/[id]/itinerary.tsx`, `frontend/app/(tabs)/trips.tsx`.
